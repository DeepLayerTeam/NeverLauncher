# 0.49.6 — миграция авторизации и защиты: инструкция для оператора

Этот выпуск изменяет **существующие пути исполнения**, но не ABI модулей Gravit. Подтверждённые результаты: более безопасная проверка устаревших паролей, автономный механизм записи FileAuthSystem, ротация сертификатов с подписью корневым ключом, более строгие проверки Guard и более строгая проверка официальных профилей Minecraft. Это **не доказывает** двоичную совместимость всех JAR-модулей Gravit AdditionalHash / FileAuthSystem / GenerateCertificate / LauncherGuard / MojangSupport.

## FileAuthSystem Database.json — явный автономный механизм записи

1. Остановите LaunchServer/Gravit и **все другие процессы, использующие Database.json**. Работающий коннектор FileAuth в NeverLauncher доступен только для чтения и автоматически повторно считывает изменённый источник. Локальная рекомендательная блокировка автономного механизма записи не остановит стороннюю программу, которая игнорирует эту блокировку.
2. Защитите `Database.json` (обычный файл с ограниченными правами), создайте полные резервные копии отдельного `Sessions.json` (при наличии) и состояния Gravit штатными средствами и получите точный SHA-256 файла `Database.json`. Механизм записи **не читает и не изменяет Sessions.json**; перед повторным запуском источника отдельно отзовите все его сессии.
3. Для переименования:

   ```bash
   python3 tools/gravit-port/fileauth_writeback_0496.py \
      --source /srv/gravit/auth/Database.json \
      --backup /srv/gravit/auth/Database.pre-0496-20261102.json \
      --expected-sha256 <64-CHARACTER-HEX-SHA256> \
      --operation rename --uuid <EXISTING-UUID> --username NewMinecraftName \
      --writers-stopped
   ```

   Операция `disable` удаляет только выбранный аккаунт (последний аккаунт удалить нельзя). Для смены пароля в устаревшем формате SHA256 используйте `--operation set-password --password-file /secure/password.txt --password-format sha256-hex --allow-weak-legacy-hash`; **это режим только для совместимости**, не рекомендуемый для новых аккаунтов. Файл с паролем должен иметь ограниченные права; он читается как точная последовательность байтов и не попадает в отчёт. Не передавайте пароль через командную строку. По возможности переносите аккаунты в локальное хранилище NeverLauncher с Argon2id.
4. Проверьте JSON-отчёт (`sourceSha256`, `updatedSha256`, путь резервной копии, операцию, UUID), выполните вход через FileAuth NeverLauncher и проверьте отзыв старых и выдачу новых сессий NeverLauncher. Запись выполняется атомарным переименованием; неизвестные поля пользователей сохраняются, а исходный inode защищён устойчивой приватной резервной копией через жёсткую ссылку. Не используйте устаревший `--expected-sha256`: несоответствие предварительных условий прерывает операцию, не изменяя источник.
5. Если ошибка произошла до фиксации, исходный файл остаётся неизменным. Для восстановления после фиксации остановите все процессы записи и восстановите файл из закрытой резервной копии, предварительно изучив промежуточные изменения. **Не восстанавливайте старые токены Sessions.json в NeverLauncher**. Автономное изменение FileAuth само по себе не отзывает действующие сессии NeverLauncher; при необходимости используйте существующие административные операции отзыва сессий и устройств.

Этот инструмент обслуживается **только в POSIX** (`flock`, `fsync`, атомарное переименование в пределах каталога). Для изменения данных с Windows используйте поддерживаемый административный POSIX-хост с хранилищем, смонтированным в файловую систему, обеспечивающую эти гарантии. Иначе используйте существующие механизмы импорта NeverLauncher и управления аккаунтами.

## Доверие к релизу и делегированные сертификаты

`trust_certificates_0496.py` управляет **доверием к компонентам через делегированные сертификаты с подписью корневым ключом**, а не сертификатами Windows Authenticode или Mojang. Применяется существующий закреплённый корень доверия; ключ, заявленный входными данными Gravit либо созданный при запуске, не становится доверенным. Выполняйте команды только в автономном окружении подписи релизов. Храните исходные данные корневого ключа в предварительно настроенной переменной окружения `LAUNCHER_TRUST_ROOT_ED25519_SEED`, но никогда в распространяемом дереве исходников.

1. Проверьте и закрепите **точный SHA-256 существующего файла подписанной политики**. Предоставьте открытый ключ корня доверия из заранее настроенного двоичного якоря.
2. Выпустите делегированный сертификат и ключ:

   ```bash
   python3 scripts/release/trust_certificates_0496.py issue \
      --signed-policy /secure/trust/signed.json --output /secure/trust/signed.json \
      --expected-sha256 <SIGNED-POLICY-SHA256> --root-public <PINNED-ROOT-PUBLIC-HEX> \
      --key-id components-0496 --private-key-output /secure/trust/components-0496.key
   ```

   Закрытый исходный ключ Ed25519 создаётся с правами `0600` и не включается в подписанную корневым ключом политику. Эпоха доверия увеличивается. Настоящий `component_set_sign.py` может использовать этот ключ для подписи, если момент подписания попадает в срок действия политики.
3. Отзовите ключ командой `revoke` с новым SHA-256 политики и тем же закреплённым корнем доверия. Эпоха доверия увеличится ещё раз. Существующий механизм подписи будет отклонять новые подписи компонентов, сделанные отозванным ключом. Распространите обновлённую политику доверия с подписью корня через **существующий механизм подписанных обновлений**: локальная генерация политики сама по себе не отзывает доверие на ранее установленных автономных клиентах. Для подтверждения доставки и применения используйте существующие отчёты и релизные проверки.

`sign-trust-policy.py` отклоняет повторяющиеся ключи JSON и идентификаторы ключей, некорректные периоды действия, символические ссылки во входных/выходных путях и повреждённые ключевые данные. Он проверяет подпись и атомарно записывает подписанную политику с правами `0600`.

## Действующая защита во время исполнения

- **AdditionalHash:** импортированный Argon2id PHC с чрезмерными параметрами памяти, числа итераций или параллелизма отклоняется настоящим механизмом входа до выделения памяти под Argon2. Поддерживаемые проверки digest и PHPass не меняются. Слабые устаревшие хеши разрешены только для поддерживаемой миграции; после успешного входа NeverLauncher должен обновить их штатным механизмом локальной авторизации.
- **LauncherGuard:** некорректные либо переполняющиеся строки версий релиза больше не могут отключить требование политики непрерывного Guard в Windows. Проверка дайджестов списков разрешённых модулей/хуков и отзыв тикетов продолжают применяться существующими механизмами Backend. Это не означает полного античит-покрытия или одинакового уровня защиты пользовательского режима на всех платформах.
- **MojangSupport:** чтение профилей Minecraft с токеном теперь отклоняет не только неправильные UUID, но и недопустимые имена игроков Minecraft. Существующая цепочка OAuth→Xbox→XSTS→Minecraft, проверка права владения игрой и механизмы sessionserver не меняются. **Настоящий аккаунт Microsoft, право владения и вход на игровой сервер необходимо отдельно тестировать с разрешёнными учётными данными**; никогда не публикуйте токены обновления в общедоступных журналах.

## Контроль качества и продвижение релиза

Выполните целевые тесты Python:

```bash
python3 -m unittest discover -s tools/gravit-port -p 'test_fileauth_writeback_0496.py'
python3 -m unittest discover -s scripts/release -p 'test_trust_policy_*.py'
python3 -m unittest discover -s scripts/release -p 'test_trust_certificates_0496.py'
```

Для тестов Backend требуются **Go 1.27.3**, чистый кеш зависимостей, а для интегрированной авторизации и Guard — PostgreSQL и работающий API. После их успешного выполнения проверьте: внешний вход FileAuth и удаление внешнего аккаунта; выдачу подписанной политики → подпись компонента → отзыв ключа → отказ в подписи; работу Guard в Windows и защиту от повторного воспроизведения; проверку права владения Minecraft и подключение через Microsoft на окружениях, приближенных к промышленным.

**Статус:** для этого патча есть локальные подтверждения исполнения отдельного Python-кода и некоторых пакетов Go. Подписанные установщики ОС, тесты PostgreSQL, реальный вход и подключение к Minecraft, нативный Guard, все варианты модулей Gravit и независимая промышленная GA-приёмка остаются **ЗАБЛОКИРОВАНЫ** до проведения испытаний в соответствующих физических и учётных средах.
