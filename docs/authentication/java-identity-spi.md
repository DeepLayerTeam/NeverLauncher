# Launcher 0.48.5 — провайдер идентификации Java

Java-расширения с целью `backend` могут зарегистрировать реализацию `IdentityProvider` через `ctx.providers().register(new ProviderDescriptor<>(IdentityServices.CONTRACT, ...))` и выбрать её в `Extension.start()`. Необходимо реализовать `authenticatePassword`, `resolveIdentity`, `verifyProviderSession` и `revokeProviderSession`. Методы возвращают `VerifiedIdentity` с неизменными полями **`issuer` и `subject`** (не адресом электронной почты), а также `IdentityProof`, содержащим учётные данные сессии провайдера и способы аутентификации. Для ожидаемых отказов аутентификации выбрасывайте `IdentityFailure` со стабильными кодами. Никогда не записывайте секреты в журналы.

Установите подписанное расширение глобально и одобрите его разрешение **`auth:provider`**. В существующем мастере настройки провайдера аутентификации панели Admin создайте управляемого провайдера типа `java` с конфигурацией:

```json
{"id":"company","extensionId":"example.identity","displayName":"Корпоративный Java-провайдер"}
```

Проверьте и активируйте редакцию через обычную процедуру утверждения администратора. Управляемый коннектор Go сначала убеждается, что работающая JVM сообщает об активном SPI-провайдере. После этого операции входа и явной привязки учётных записей обращаются к аутентифицированному RPC через локальный интерфейс обратной петли. Новая публичная конечная точка HTTP для Java или прямой доступ к базе данных не добавляются.

**Безопасность:** хост Go проверяет манифест и действующее разрешение перед каждым вызовом `auth.*` и после него. Провайдером идентичности может выступать только глобальное расширение. Отключение/карантин расширения либо отзыв разрешения приводит к отклонению Java-запросов аутентификации по принципу запрета при ошибке. `federation.Core` остаётся единственным источником канонических связей учётных записей, политик ролей, MFA и сессий Launcher. Для управляемых Java-провайдеров автоматическое создание учётных записей отключено: пользователей необходимо связывать через существующие маршруты с недавней аутентификацией и новым подтверждением от провайдера. Проверка сессии провайдера не является проверкой сессии Launcher, а отзыв токена провайдера не заменяет существующий API отзыва сессий Launcher. Владение официальной учётной записью Microsoft/Minecraft и игровые права должны продолжать проверяться штатными механизмами. Никогда не принимайте заявление внешнего провайдера о владении официальным Minecraft за достаточное доказательство.

**Область действия:** версия 0.48.5 предоставляет парольную аутентификацию, разрешение идентичности и проверку/отзыв сессий провайдера. Браузерные потоки и OIDC по-прежнему обслуживаются существующими нативными коннекторами. Промышленный выпуск заблокирован до успешного прохождения независимого CI и исторических требований миграции и приёмки релиза.
