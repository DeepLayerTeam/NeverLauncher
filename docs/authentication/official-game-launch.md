# Launcher 0.26.9 — запуск Minecraft Java в сети и автономно

## Сценарии выполнения

Экран запуска Desktop предоставляет три **взаимоисключающих** режима аутентификации. Выбранный `authMode` передаётся команде запуска Rust; перед созданием защищённого процесса Java Rust отклоняет несогласованные учётные данные.

- **Официальный Minecraft:** ранее подтверждённые UUID Minecraft Java и токен доступа извлекаются из **нативного хранилища учётных данных**, проверяются нативным клиентом Minecraft Services непосредственно перед запуском и передаются процессу Minecraft Java. Рендерер получает только метаданные профиля. При подключении к серверу с `online-mode=true` запущенная игра самостоятельно выполняет обычный запрос `join` к Mojang sessionserver. Launcher не подделывает `serverId`, не вызывает `hasJoined` от лица клиента и не перенаправляет официальный трафик через проектный узел Yggdrasil. В Java 1.21.9+ и 26.x больше не передаётся удалённый аргумент `--userType`.
- **Проектный Yggdrasil:** Backend создаёт сеанс Minecraft, привязанный к проекту. Runtime проверяет выбранный режим, требует наличия **обязательного подписанного** JAR `authlib-injector` в проверенной установке и подключает агент до запуска Java. Отсутствующий, необязательный, дублирующийся или принадлежащий пользователю артефакт injector блокирует запуск. Пропуска ServerBridge на подключение относятся только к проекту и не могут использоваться для официальной учётной записи.
- **Автономный режим:** необходим подписанный Manifest с разрешением офлайн-игры и соответствующий проверенный локальный кэш. UUID или токен онлайн-доступа не используются повторно. Для запуска игры клиент получает только автономный заполнитель `0`, а не учётные данные Mojang. Автоматический вход на сервер и идентификаторы ServerBridge запрещены. Автономный запуск никогда не объявляется допуском на сервер с online-mode.

Перед однократной вставкой выбранной идентичности Runtime удаляет устаревшие аргументы аутентификации из разрешённых метаданных Mojang и игровых аргументов манифеста. Ни `--accessToken=...`, ни повторяющиеся `--uuid`, `--userType` или `--username` не могут переопределить выбранную учётную запись. Игровые токены скрываются в предварительном просмотре команды запуска. Аргументы authlib-injector для сетевого режима нельзя задавать проектными флагами JVM: injector определяется по подписанному и локально проверенному JAR.

## Настоящие интеграционные проверки (обязательны для GA)

1. Настройте собственное приложение Microsoft в соответствии с 0.26.1–0.26.6 и войдите в лицензионную учётную запись Java Edition. Проверьте, что UUID в нативном профиле соответствует учётной записи, а токен обновляется до запуска.
2. Запустите vanilla- и modded-сборки игры, подключитесь к неизменённому серверу с online-mode. Проверьте настоящий запрос `join` от клиента Minecraft Java и успешную серверную проверку `hasJoined` на Mojang sessionserver. Убедитесь, что настройки многопользовательской игры и семейные ограничения не обходятся переходом в автономный режим.
3. Повторите проверку с учётными данными проектного ServerBridge/Yggdrasil и подписанным injector, используя явно настроенный проектный сервер Yggdrasil.
4. Удалите или отключите подписанный injector, подмените токены провайдеров, подделайте UUID и передайте ложные аргументы `--accessToken`. Убедитесь, что запуски отклоняются.
5. Выберите автономный режим в профиле без подписанного разрешения на него и попробуйте автовход: запрос должен быть отклонён. В разрешённом подписанном офлайн-профиле проверьте работу одиночной игры и отсутствие ложного утверждения о доступе к защищённому серверу с online-mode.
6. Повторите проверки на Windows/Linux/macOS с производственной политикой процессов Guard и аппаратным доверием к устройству. Убедитесь, что журналы запуска и отчёты о сбоях не раскрывают bearer-токены.

Успешные проверки с настоящим провайдером и сервером нельзя заменять имитациями или модульными тестами. CI проверяет только локальные ветви выполнения. Одобрение собственного приложения Microsoft и реальная сертификация `online-mode=true` остаются внешними блокирующими условиями выпуска до их фактического прохождения.
