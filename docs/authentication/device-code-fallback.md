# Launcher 0.26.4 — резервная авторизация по коду устройства

## Действия оператора

Основной путь входа в официальный Minecraft — **OAuth + PKCE через системный браузер**. Если ОС блокирует такой вход, выберите **Код устройства (резервный режим)**. Desktop показывает одобренный Microsoft URL проверки и код пользователя. Откройте адрес в любом браузере, введите код и подтвердите вход в личной учётной записи Microsoft с доступом к Minecraft Java. Нативный Identity Manager автоматически ожидает результат и проверяет профиль Java через Minecraft Services. Отдельной ручной кнопки **Проверить вход** нет.

Нажмите **Отменить вход**, чтобы завершить активную попытку. Менеджер аннулирует её состояние в памяти и прервёт как запланированные паузы, так и HTTP-опрос. Код браузера/интерфейса никогда не получает `device_code`, refresh-токены, официальные игровые bearer-данные или зашифрованные билеты сеанса Backend. Пользовательский код и URL проверки специально предназначены для показа.

Просроченные, отклонённые или окончательно недействительные учётные записи вызывают ошибку и **не** привязываются. Для новой попытки требуется отдельное нажатие; она **не** перезапускается автоматически при запуске приложения или истечении срока (RFC 8628). Обрывы сети, 429/408 и ошибки Backend 5xx автоматически повторяются с ограниченной экспоненциальной задержкой; `Retry-After` и `slow_down` изменяют частоту опроса. Backend возвращает `202` с зашифрованным продолжением процесса и определённым провайдером интервалом следующего опроса; данные хранятся только нативно. Когда Microsoft уже погасил одноразовый код устройства, Backend переходит в отдельное состояние **redeemed**: токены Microsoft access/refresh запечатаны в существующем билете AES-256-GCM, который не попадает в React. Временная ошибка Xbox/XSTS/Minecraft выдаёт ротированное зашифрованное продолжение `202`, позволяя при следующем опросе возобновить цепочку без повторного погашения использованного Device Code. При успешном погашении близко к истечению Backend продлевает только уже погашенное окно завершения максимум на пять минут; ещё ожидающий исходный Device Code никогда не продлевается. Нативный ожидатель использует `expiresIn` из авторизованного продолжения Backend для контроля времени.

## Безопасность и реализация

- `official_identity_begin_0262` создаёт запрос провайдера и регистрирует нативный процесс до HTTP-вызова, чтобы отмена во время подготовки не могла возродить запрос.
- `official_identity_wait_device_0264` ожидает в Rust через `tokio::select!`, учитывая истечение срока и отмену; запускает действующую нативную операцию опроса в допустимые моменты и возвращает только проверенный `OfficialProfile`.
- `official_identity_poll_0262` — однократная нативная операция, сохранённая для совместимости. Случайный nonce каждой области и ограничитель выполняемого запроса отбрасывают старые обратные вызовы и запрещают одновременные опросы. Временные сбои сохраняют билет и планируют следующий безопасный запрос.
- `official_identity_cancel_0262` очищает ожидающий процесс и уведомляет ожидатель Rust; повторный вход создаёт новый nonce. Отмена **нового** запроса не удаляет неявно уже привязанные аккаунты.
- Официальные токены OAuth остаются у доверенного Backend внутри установленного зашифрованного билета, сохраняемого в keyring ОС Desktop согласно 0.26.2. При нескольких экземплярах Backend существующее ограничение опросов в памяти требует общего распределённого контроля частоты до заявления полной HA-поддержки.

## Тесты и условия допуска релиза

```sh
cd apps/desktop
npm ci
npm run test:official
npm run build
cd ../..
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml official_identity_0262::tests
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
cd services/api
go test ./internal/officialminecraft ./internal/httpapi -run 'TestOfficial|TestBrowserPKCE'
```

Ручная проверка на Windows/Linux/macOS: начало → подтверждение; начало → несколько циклов `authorization_pending` → подтверждение; `slow_down` от провайдера → отложенный опрос; 429 с `Retry-After`; тайм-аут/502 → автоматический повтор; отмена до ответа запроса; отмена во время сна; отмена во время сети; замена процесса новым; отказ; истечение; потеря сеанса Launcher; отсутствие прав Minecraft; восстановление прежней учётной записи и официальный запуск. Убедитесь, что журналы рендерера и сети не содержат официальных секретов. До объявления интеграции сертифицированной выполните проверку с настоящим одобренным приложением Microsoft, собственной учётной записью Minecraft Java и vanilla/modded-сервером `online-mode=true`.

Нормативные правила интервалов: [RFC 8628 §3.5](https://www.rfc-editor.org/rfc/rfc8628#section-3.5) и [Microsoft Device Code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code).
