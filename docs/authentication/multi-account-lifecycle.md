# Launcher 0.26.7 — жизненный цикл официальных учётных записей и сессий Minecraft

## Действующее поведение

- **Добавление:** авторизуйтесь в официальной учётной записи через системный браузер с PKCE либо резервный вход по коду устройства. Существующие аккаунты остаются в нативном хранилище ОС; после проверки профиля провайдером выбирается новый аутентифицированный UUID Minecraft. Повторный вход с **тем же** UUID заменяет только соответствующую запись учётных данных.
- **Выбор:** используйте сохранённые подтверждённые официальные UUID. При выборе запрашивается актуальный профиль Java и сверяется сохранённый UUID до активации аккаунта. Если проверка неуспешна, прежний активный выбор не меняется.
- **Восстановление при запуске Desktop:** прежняя запись одного аккаунта 0.26.2–0.26.6 переносится в каталог 0.26.7; выбранный аккаунт загружается, а его сеанс Launcher и профиль провайдера повторно проверяются до установления состояния готовности официального Launcher.
- **Обновление по запросу пользователя:** выдача токена обновления Microsoft (включая его ротацию) → Xbox Live → XSTS → Minecraft Services. Новый токен обновления записывается в нативное хранилище ключей **до** последующей цепочки, чтобы сбой Xbox/Minecraft не привёл к потере уже ротированного токена. Каждый успешный результат привязан к тому же официальному UUID Minecraft.
- **Выход:** из нативного хранилища удаляется только выбранная учётная запись; при наличии других выбирается первая оставшаяся. Выход является **локальным**: Microsoft может сохранить браузерный сеанс и выданные разрешения; отзыв всех сеансов у провайдера не заявляется.
- **Повторный вход:** добавляет или заменяет UUID, не затрагивая остальные аккаунты. Учётные данные никогда не передаются рендереру React.
- **Запуск и текстуры:** всегда определяют текущий выбранный аккаунт под нативной блокировкой хранилища; смена выбора не допускает смешения учётных данных или текстур аккаунтов.

## Границы безопасности и формат

Сервис keyring остаётся `Launcher Official Minecraft 0.26.2` для совместимой миграции. Идентификаторы ключей выводятся через SHA-256 из источника Backend и идентичности сеанса Launcher. Слоты аккаунтов имеют вид `<scope>.account.<minecraft-uuid>`, каталог без учётных данных — `<scope>.directory.0267`. Каждый аккаунт использует существующий ограниченный формат разбитой на части записи keyring ОС со случайным поколением и проверкой целостности SHA-256. Каталог только метаданных хранит до 16 UUID Minecraft по 32 шестнадцатеричных символа в нижнем регистре и один активный UUID. Открытые JSON-файлы, токены в результатах команд Tauri и localStorage браузера не используются.

Нативное хранилище 0.26.7 по-прежнему ограничено аутентифицированным **сеансом** Launcher, как в 0.26.2–0.26.6. Это защищает от случайного использования между сеансами, но ещё не обеспечивает общий доступ к аккаунтам из разных сеансов Launcher; связывание идентичностей между сеансами запланировано на 0.26.8. Облачной синхронизации аккаунтов здесь нет.

## Восстановление и поведение при сбое

- Повреждённый/отсутствующий фрагмент keyring либо некорректный каталог аккаунтов приводит к отказу. Нельзя автоматически активировать другой UUID или скрытно переключиться на автономную авторизацию.
- При миграции аккаунт сначала сохраняется в новом защищённом слоте, затем записываются метаданные каталога, и только после этого удаляется старый одиночный слот. Прерывание процесса оставляет старый слот доступным для повтора.
- Недействительный токен обновления и отсутствие прав/профиля Minecraft никогда не дают состояния готовности к запуску: пользователь должен явно пройти авторизацию заново.
- Временный отказ провайдера не удаляет сохранённый аккаунт. Активная запись остаётся в каталоге, но запуск блокируется до успешной проверки.
- Смена аккаунта, выход и запуск игры последовательно выполняются под нативной блокировкой хранилища. Backend и рендерер не получают токен доступа Minecraft.

## Условие допуска релиза

Запустите `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml official_identity_0262::tests`, `cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml` и `npm ci && npm run test:official && npm run test:textures && npm run build` из `apps/desktop`. Процесс CI `multi-account-lifecycle-0267.yml` выполняет эти проверки на Windows/Linux/macOS. Ручное тестирование должно покрывать две разные настоящие учётные записи Microsoft с доступом к Java, переключение, обновление, сохранение хранилища ОС после перезапуска, выход из одного аккаунта, повторный вход с тем же UUID, отзыв токена обновления и недоступность провайдера без сети.

**Блокирующее внешнее условие:** пока **собственное** зарегистрированное приложение Microsoft проекта не получило доступ к Minecraft Services и не прошли проверки настоящего провайдера, релиз нельзя объявлять прошедшим сквозную сертификацию Microsoft/Xbox/Minecraft. Отрицательные тесты с имитациями не заменяют этого.
