# Launcher 0.26.8 — привязка идентичностей Launcher и официального Minecraft

## Поведение в промышленной среде

Привязка — **явная независимая** операция. Простой вход в Microsoft или выбор учётной записи Minecraft в хранилище ОС не создаёт связь идентичностей Launcher.

1. Недавно войдите в Launcher (не более 15 минут с момента аутентификации). Необходимы проверенный неотключённый пользователь Launcher и действительный bearer сеанса.
2. Войдите в **официальную учётную запись Minecraft Java** через нативную цепочку Microsoft → Xbox → XSTS → Minecraft. Старые билеты Backend непригодны для привязки; нужна повторная аутентификация нативным способом.
3. Выберите нужную учётную запись и нажмите **Привязать к Launcher**. Проверьте показанный UUID и подтвердите. Интерфейс никогда не получает токены Microsoft или Minecraft.
4. Rust повторно проверяет выбранный UUID в Minecraft Services при удерживаемой блокировке выбора нативного аккаунта. Rust отправляет выбранный bearer Minecraft аутентифицированному Backend Launcher **только по HTTPS** (loopback HTTP допускается при локальной разработке). Токен не возвращается рендереру.
5. Backend независимо вызывает `GET https://api.minecraftservices.com/minecraft/profile` с этим bearer. Только если Java UUID действителен и совпадает с явно выбранным, в PostgreSQL атомарно создаётся/обновляется связь по официальному UUID и ID пользователя Launcher. UUID Minecraft глобально уникален; другой пользователь Launcher получает HTTP 409. Существующий владелец может повторно проверить связь и обновить имя.
6. Интерфейс показывает устойчивое состояние серверной привязки отдельно от состояния локальной учётной записи. Если Backend недоступен, показывается **Связи Launcher недоступны**, а не ложное «не привязано».

## Конечные точки

Запросы авторизованы и ограничены идентичностью Launcher:

- `GET /api/v1/minecraft/official/link` — перечисляет **только** подтверждённые привязки текущего пользователя Launcher.
- `POST /api/v1/minecraft/official/link` — подтверждение владения Minecraft только из нативного кода: `{ "minecraftAccessToken": "<native-only>", "expectedUuid": "<32hex>", "confirm": true }`. Требует недавний вход в Launcher. Токены провайдера не сохраняются. API не предназначен для рендерера или сторонней формы входа.
- `DELETE /api/v1/minecraft/official/link/{minecraftUuid}` — только для текущего владельца, с недавним входом Launcher и подтверждением в Desktop. Удаляет постоянную связь Launcher, **но не** нативные учётные данные или сеанс Microsoft.

Все ответы содержат `Cache-Control: no-store`. POST принимает не более 12 КиБ и только строго определённые поля JSON. Код привязки никогда не сериализует токен в ошибках, аудите, игровых аргументах или выводе CI.

## Постоянное хранение и развёртывание

Проверенная миграция `0075_official_identity_0268.sql` создаёт `official_identity_links_0268` с внешним ключом к `users` Launcher, уникальным владением UUID Minecraft и индексом поиска владельца. Она применяется штатной проверяемой по контрольным суммам процедурой миграции БД. **Примените миграции до подключения обновлённых клиентов Desktop.** Режим Backend только в памяти намеренно отвечает HTTP 503, а не создаёт фиктивную недолговечную связь. Ошибки БД приводят к отказу.

Пользователь может привязать несколько отдельных учётных записей Minecraft Java. Другой пользователь Launcher не может незаметно присвоить UUID Minecraft: владелец должен явно отменить связь. Локальный выход и удаление аккаунта Minecraft не удаляют серверную связь. При удалении учётной записи Launcher связи каскадно удаляются через внешний ключ БД.

## Условия допуска релиза и реальная проверка

- Проверка обновления и отката миграции на изолированном экземпляре PostgreSQL.
- Компиляция и испытания Rust/Tauri на Windows/Linux/macOS, включая хранилище ОС, отмену и переключение учётных записей.
- Настоящая авторизация через Device Code и системный браузер с одобренным идентификатором клиента Microsoft для проекта, затем реальная проверка профиля Java.
- Гонки уникального владения PostgreSQL и отрицательные случаи: уже привязанный UUID, неверный UUID, отозванный bearer Minecraft, устаревший вход Launcher, отключённый Backend, попытка другого пользователя удалить связь.
- Аудит HTTP-журналов и отчётов о сбоях на отсутствие тел запросов и заголовков Authorization. Backend временно обрабатывает токен Minecraft только для запроса Minecraft Services. Не устанавливайте недоверенный обратный прокси, записывающий тела запросов.

**Не заменяет внешнее одобрение провайдера Minecraft или настоящую аутентификацию online-mode.** Ни успешный модульный тест, ни локальные учётные данные не доказывают настоящее подключение в online-mode.
