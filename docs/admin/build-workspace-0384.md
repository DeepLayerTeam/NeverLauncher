# Сборка клиента через Admin (Launcher 0.38.4)

Требуются права `release:prepare` и `file:write` для проекта. Откройте **Release Workspace** и выберите проект, профиль, канал, версию Minecraft и версию выпуска. Сохраните черновик. На этапе **Пакет** используйте **Build Workspace** (вместо ручного вызова API).

1. Создайте workspace. Настройки Minecraft и Java берутся из закреплённой ревизии профиля; при сборке Backend проверяет её неизменность.
2. Загрузите каталог клиента или отдельные файлы. Каталог импортируется без внешнего имени папки; отдельный файл попадает в корень. `saves`, `config`, `screenshots`, `options.txt` и другие пользовательские файлы не импортируются. Файлы сохраняются зашифрованными во временном хранилище, их SHA-256 рассчитывается и проверяется Backend.
3. Если файл оказался лишним, нажмите **Удалить** до сборки. Удаление меняет серверную ревизию workspace, сбрасывает stage/validation и не выдаёт возможность изменения готового пакета. Зашифрованный content-addressed объект остаётся на хранении до отдельной уборки неиспользуемых объектов; удаление строки из рабочего набора не равно немедленной очистке физического хранилища.
4. Нажмите **Scan / SHA-256**, просмотрите ошибки. Выберите ранее опубликованный выпуск того же профиля для **Сравнить**. Diff показывает добавленные, изменённые, неизменённые и удалённые из будущего пакета пути. Отсутствующие в новом наборе файлы не удаляются у игрока автоматически: обновление подчиняется правилам клиента.
5. Выберите файлы в списке, нажмите **Stage selected**, затем **Validate staged files**. Изменение выбора требует нового stage. Сервер проверяет существование, целостность и применимость выбранных файлов, runtime и pinned profile. Неуспешная проверка блокирует создание пакета.
6. Нажмите **Создать пакет и проверить файлы**. Backend повторно выполняет validation, материализует файлы, фиксирует build digest и package ID. Admin перечитывает пакет и сравнивает путь, размер и SHA-256 каждого выбранного файла с исходным workspace. При несовпадении привязка к черновику не выполняется.
7. Готовый пакет привязывается к черновику релиза автоматически; после потери ответа можно снова открыть готовый workspace и выполнить **Сверить пакет** / **Привязать к черновику релиза**. Встроенный API загрузки файлов запрещает изменять состав материализованного Build Workspace пакета. Для изменений используйте новую версию.
8. Перейдите к штатной цепочке Release Workspace: **validate → sign (MFA/step-up) → stage → integrity-check → runtime evidence → publish**. Завершение сборки не означает разрешение публикации без обязательной проверки.

Проверка конфликтов: каждая запись и удаление требует текущую серверную ревизию; ответ HTTP 409 не следует повторять вслепую. После прерванного импорта Admin перечитывает состояние Backend. В списке workspace можно продолжить ранее сохранённую сборку.

Ограничения: отдельный файл через браузерный picker импортируется по его имени в корень; вложенную структуру сохраняет picker каталога. Для каталогов с очень большим числом файлов UI показывает первые 300 совпадений фильтра; остальные остаются доступны через фильтр. Данный релиз не удостоверяет реальные игровой запуск, полноту матрицы платформ или внешний выпуск stable.
