# Сборка клиента через Admin (Launcher 0.38.4)

Требуются права `release:prepare` и `file:write` для проекта. Откройте **Рабочая область выпуска** и выберите проект, профиль, канал, версию Minecraft и версию выпуска. Сохраните черновик. На этапе **Пакет** используйте **Рабочая область сборки** (вместо ручного вызова API).

1. Создайте рабочую область сборки. Настройки Minecraft и Java берутся из закреплённой ревизии профиля; при сборке Backend проверяет её неизменность.
2. Загрузите каталог клиента или отдельные файлы. Каталог импортируется без внешнего имени папки; отдельный файл попадает в корень. `saves`, `config`, `screenshots`, `options.txt` и другие пользовательские файлы не импортируются. Файлы сохраняются зашифрованными во временном хранилище, их SHA-256 рассчитывается и проверяется Backend.
3. Если файл оказался лишним, нажмите **Удалить** до сборки. Удаление меняет серверную ревизию рабочей области, сбрасывает подготовку и проверку и не выдаёт возможность изменения готового пакета. Зашифрованный объект с адресацией по содержимому остаётся на хранении до отдельной уборки неиспользуемых объектов; удаление строки из рабочего набора не равно немедленной очистке физического хранилища.
4. Нажмите **Проверка / SHA-256**, просмотрите ошибки. Выберите ранее опубликованный выпуск того же профиля для **Сравнить**. Сравнение показывает добавленные, изменённые, неизменённые и удалённые из будущего пакета пути. Отсутствующие в новом наборе файлы не удаляются у игрока автоматически: обновление подчиняется правилам клиента.
5. Выберите файлы в списке, нажмите **Подготовить выбранные**, затем **Проверить подготовленные файлы**. Изменение выбора требует повторной подготовки. Сервер проверяет существование, целостность и применимость выбранных файлов, среды выполнения и закреплённого профиля. Неуспешная проверка блокирует создание пакета.
6. Нажмите **Создать пакет и проверить файлы**. Backend повторно выполняет проверку, материализует файлы, фиксирует контрольный отпечаток сборки и идентификатор пакета. Admin перечитывает пакет и сравнивает путь, размер и SHA-256 каждого выбранного файла с исходной рабочей областью. При несовпадении привязка к черновику не выполняется.
7. Готовый пакет привязывается к черновику релиза автоматически; после потери ответа можно снова открыть готовую рабочую область и выполнить **Сверить пакет** / **Привязать к черновику релиза**. Встроенный API загрузки файлов запрещает изменять состав пакета, сформированного рабочей областью сборки. Для изменений используйте новую версию.
8. Перейдите к штатной цепочке рабочего пространства выпуска: **validate → sign (MFA/step-up) → stage → integrity-check → свидетельства работы Runtime → publish**. Завершение сборки не означает разрешение публикации без обязательной проверки.

Проверка конфликтов: каждая запись и удаление требует текущую серверную ревизию; ответ HTTP 409 не следует повторять вслепую. После прерванного импорта Admin перечитывает состояние Backend. В списке рабочих областей можно продолжить ранее сохранённую сборку.

Ограничения: отдельный файл через браузерный диалог выбора файла импортируется по его имени в корень; вложенную структуру сохраняет диалог выбора каталога. Для каталогов с очень большим числом файлов UI показывает первые 300 совпадений фильтра; остальные остаются доступны через фильтр. Данный релиз не удостоверяет реальный игровой запуск, полноту матрицы платформ или внешний выпуск stable.
