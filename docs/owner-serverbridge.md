# 0.38.3: сервер, профиль и канал в Admin

1. Создайте проект и профиль с заданными версиями Minecraft, загрузчика и Java; проверьте ревизию профиля.
2. Выполните команды обнаружения и установки ServerBridge (detect/install) на настоящем игровом узле, экспортируйте **только** публичный `enrollment-request.json` с `projectId` и `profileId`. Не загружайте приватный ключ.
3. Зарегистрируйте узел через Admin → ServerBridge. Backend отказывает, если указанный профиль не существует в проекте. Регистрация **не** означает работающий сервер: требуются отдельные подписанные сигналы активности и данные телеметрии.
4. Выберите узел в панели проекта: профиль автоматически устанавливается по серверной регистрации, канал выберите из существующих каналов проекта. URL сохраняет `project`, `profile`, `channel`, `server` для прямых ссылок.
5. Убедитесь, что ServerBridge сообщает актуальный сигнал активности и протокол версии 3; среда выполнения и игровое подключение проверяются отдельно. При сбое Backend или отсутствии свежего сигнала активности Admin показывает недоступность/неизвестность, не старые метрики.
6. Перейдите по ссылке «Подготовить выпуск» в мастер релизов; выбранные профиль и канал передаются туда. Публикацию всё равно ограничивают настоящие проверки Backend, права и свидетельства работы Runtime.

Привязка `server → profile` сохраняется на Backend при регистрации, а не в localStorage; изменение этой криптографической идентичности не выполняется обычным переключателем. `channel` относится к конкретному выпуску профиля и **не** является свойством ServerBridge-узла. У узлов без profileId нельзя открывать привязанный мастер релиза.

Рекомендуемые проверки: `cd apps/admin && npm test`, `python3 scripts/version/manage.py check`; Go: `cd services/api && go test ./internal/httpapi` с необходимым набором инструментов и зависимостями. Реальный успешный запуск игрового сервера здесь не заявляется.
