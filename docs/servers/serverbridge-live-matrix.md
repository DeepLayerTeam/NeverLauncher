# 0.41.13 — сертификация реальной совместимости ServerBridge

Тестовый исполнитель запускает настоящий код, а не просто перечисляет API или заявления о совместимости.

```bash
# Requires Docker Compose, upstream images and live JVM/network access,
# PostgreSQL, Go, Gradle, Cargo, Maven, Java 21 and graphical test prerequisites.
bash scripts/test/serverbridge-live-matrix-04113.sh --core
# Strict GA gate. It fails until all 14 targets have independent live evidence.
bash scripts/test/serverbridge-live-matrix-04113.sh --all
```

Настоящий E2E-исполнитель собирает производственные JAR-мосты, запускает промышленные Docker-образы Minecraft и прокси, проверяет heartbeat Bridge и готовность узлов, делает реальные попытки входа в Minecraft и проверяет отзыв сессии. Для Paper обязателен запуск настоящей клиентской JVM Mojang и вход на сервер. Для **каждой действующей службы** средство регистрации 0.41.13 дополнительно опрашивает Docker о работающем контейнере, неизменяемом ID образа, ровно одном работающем процессе JVM, основной версии JVM не ниже 21, состоянии здоровья и неизменённых журналах платформы. Валидатор проверяет SHA-256 сетевых запросов и серверных журналов, ожидаемые ID/порт узла, упорядоченные отметки успешного и отозванного входа и настоящий журнал подключения игрока Paper. Простые `status: passed` или декларации совместимости не принимаются как подтверждения действующего окружения.

## Явные границы покрытия

Существующий полный серверный E2E охватывает десять экземпляров Runtime: Velocity, BungeeCord, Waterfall, Spigot, Paper, Purpur, Folia, Fabric, Forge и NeoForge. `--core` подтверждает только эти десять при успешном настоящем тесте Docker и выдаёт `core-passed-not-full-matrix`, а не `passed`, для полной матрицы из 14 целей. Для **Bukkit (общий Runtime без независимого запуска выделенного сервера), Quilt, Sponge и Vanilla/sidecar нет равнозначного реального серверного подтверждения в этом E2E**. Тесты сборки, только клиента и имитации протокола НЕЛЬЗЯ заменять ими реальные проверки Minecraft/JVM/Proxy. `--all` запрещает приёмку и возвращает `not-certified` при неполном покрытии; сертификация всей совместимости 0.41.13 ожидает реальных тестов этих целевых платформ.

Хост, выполняющий тест, должен иметь сеть для доступа к исходным артефактам Runtime. Не используйте заглушку API, синтетическую JVM или заранее записанные положительные сертификаты. Подтверждения Runtime записываются в `e2e/runtime/` и должны сохраняться вместе с точным исходным коммитом и хешами артефактов. Закрытые учётные данные E2E в файлах Runtime нельзя публиковать в открытых артефактах.

Автономные регрессии валидатора намеренно отделены от сертификации живой игры:

```bash
python3 -m unittest discover -s serverbridge/tests -p '*04113.py' -v
bash -n e2e/scripts/run-minecraft-e2e.sh
```
