# Launcher 0.22.7 — детерминированный запуск

## Исполняемый путь

`runtime::build_launch_plan` и `build_authenticated_launch_plan` сначала проверяют Ed25519-подпись полного манифеста (`verify_manifest_signature`) с закреплённым публичным ключом. После построения плана `create_launch_plan_with_credentials` проверяет обязательные JAR-файлы и метаданные по подписанных `size`/`SHA-256`, разрешает типизированные classpath/modulepath/Java/RAM ограничения, применяет подписи к пользовательским аргументам JVM и клиента и вычисляет `LaunchPlan.deterministicSha256`. `launch_with_timeout` отдельно выполняет полную проверку установленных файлов и только затем передаёт аргументы в `tokio::process::Command` (без командной оболочки, `sh -c`, `cmd /c`, и без разбиения аргументов по пробелам).

## Контракт детерминированности

`deterministicSha256` — SHA-256 от JSON статического *разрешённого* плана (`launcher.resolved-launch-plan/1`). В идентичность входят Ed25519-подпись релиза, версия среды выполнения, ОС и архитектура, выбранная основная версия Java, дистрибутив Java, режим авторизации, точка входа Java, порядок аргументов classpath/modulepath, JVM и клиента и множество разрешённых переменных окружения. Порядок classpath из метаданных Mojang сохраняется (важен для загрузчиков); для явного classpath сохраняется авторский порядок подписанных `classpathEntries`. Автоматический v2 classpath формируется по порядку подписанных `files`, независимо от присутствия необязательных/пользовательских JAR. Выбор нативной папки для v2 основан только на подписанном списке файлов, а не на текущем содержимом диска.

При вычислении идентичности из абсолютных путей удаляется корень установки; из сессионной части — имя пользователя, UUID, токен доступа и путь исполняемого файла Java. Они **сохраняются в фактической команде запуска** и обрабатываются штатной аутентификацией. Изменение подписанных аргументов, метаданных, порядка файлов, версии Runtime или параметров разрешения, влияющих на аргументы, меняет контрольную сумму. Фактические значения разрешённых переменных окружения не включаются в контрольную сумму (это внешнее состояние запуска); их **имена** нормализуются и сортируются. Неизвестные или несовместимые настройки среды выполнения v2 отклоняются до запуска.

## Безопасность и совместимость

- Любые кастомные аргументы JVM и игры v2 находятся внутри манифеста, покрытого подписью владельца **ключа релиза**. Отдельная подпись индивидуального владельца профиля в версии 0.22.7 не добавляется: для такого утверждения нужна отдельная модель ключей/ACL. На клиенте неподписанные локальные JVM overrides не принимаются.
- У v2 с пустым `environmentAllowlist` дочерний Java-процесс получает очищенное окружение; Windows `SystemRoot` и `WINDIR` разрешаются как необходимые системные значения. Динамические значения переменных из явно заданного списка разрешённых переменных могут отличаться между машинами и сознательно не входят в статическую идентичность.
- Manifest v1 продолжает использовать прежнюю логику classpath, Java/environment и не получает deterministic SHA-256. Ранее опубликованные файлы не изменяются и не переподписываются.
- Для полных гарантий запуск на одной версии должен дополнительно пройти интеграционные и сквозные тесты на Windows, Linux, macOS и на реальных Mojang/Forge/NeoForge метаданных. Изолированные тесты Rust покрывают fingerprint, изоляцию сессий и сериализацию `features`; в CI требуется `cargo test -p runtime`.
