# Gravit → Launcher 0.44.8 — эксплуатационное переключение и откат

**Поддерживаемая область:** одновременно один запуск миграции, один профиль и один канал релиза Launcher. Переключение маршрута Backend требует PostgreSQL и подписанного опубликованного выпуска Launcher. Операции не изменяют миры Gravit, инвентарь игроков, плагины, конфигурацию прокси, DNS, хранилища аккаунтов и внешние Minecraft-процессы. Операторы обязаны остановить каждого независимого писателя, сохранить копии обеих систем и сами переключить внешние входные точки; инструмент блокирует только указанную systemd-службу. Замаскированную службу всё ещё можно обойти отдельным процессом. Успешные Go-тесты не сертифицируют реальное переключение сервера.

## Переключение

1. Завершите инвентаризацию/импорт источника, проверки идентичности и авторизации, совместимость модулей, регистрацию ServerBridge и живую Minecraft-репетицию MIG10. Сохраните копии и отдельно проверьте восстановление. Подготовьте `runId`, `stageId` репетиции, дайджест снимка источника и ID целевого релиза.
2. Выполните `nl migrate gravit cutover-stage --backend https://HOST --token ... --run RUN --confirm RUN --profile-id PROFILE --channel stable --release-id RELEASE --stage-id STAGE --head-revision REV`. Это подготавливает настоящий маршрут выпуска Launcher и ограничивает обычные публикации канала. Команда **не** останавливает Gravit и не перенаправляет игроков.
3. Запланируйте окно обслуживания. Остановите вход игроков и **всех** внешних писателей/прокси. На **исходном хосте Gravit** с правами оператора systemd выполните:

   ```sh
   nl migrate gravit fence-source --run RUN --confirm RUN --profile-id PROFILE --channel stable --stage-id STAGE --unit gravit-launchserver.service --output /var/tmp/gravit-stop-state.json
   ```

   Команда запускает `systemctl mask --runtime --now UNIT`, дважды проверяет `ActiveState=inactive` и `UnitFileState=masked[-runtime]` и долговременно записывает файл состояния с режимом `0600`, не заменяя существующий. При ошибке **не** снимайте mask автоматически. Только уполномоченный оператор исходного хоста вправе разблокировать службу после решения по миграции.
4. **После** остановки экспортируйте **новое** JSON-состояние источника в формате `gravitrehearsal.Snapshot` (SHA-256 мира, загрузчик, SHA-256 необязательного пресета, игроки с UUID, хеши инвентаря/прав/экономики/скинов, флаг администратора). Экспорт должен идти из остановленного источника, а время изменения файла — быть позже остановки. Все поля должны отражать реальную систему; копирование снимка репетиции вместо нового экспорта запрещено.
5. Сверьте новый экспорт с прежним дайджестом снимка MIG10:

   ```sh
   nl migrate gravit verify-source-fence --state /var/tmp/gravit-stop-state.json --snapshot /var/tmp/gravit-fresh-source.json --expected-snapshot-sha256 SHA256_FROM_MIG10 --output /var/tmp/gravit-fence-receipt.json
   ```

   Утилита до и после чтения снимка подтверждает неактивную замаскированную службу, вычисляет типизированный дайджест и создаёт свежую квитанцию с SHA-256. Выводятся `sourceFenceReference`, `sourceFenceEvidenceSha256`, `currentSourceSnapshotSha256`; сохраните её с журналами обслуживания. Свидетельство действительно 10 минут (состояние остановки источника — 15 минут). После истечения повторите проверку, а при истечении состояния остановки создайте новое состояние после повторной проверки.
6. Активируйте с новым `--fence-receipt` на доверенном административном компьютере:

   ```sh
   nl migrate gravit cutover-activate --backend https://HOST --token ... --run RUN --confirm RUN --profile-id PROFILE --channel stable --expected-revision ROUTE_REV --source-fenced true --fence-receipt /var/tmp/gravit-fence-receipt.json
   ```

   Backend независимо связывает квитанцию с подготовленными запуском/профилем/каналом/этапом, снимком источника и SHA-256 и снова проверяет MIG10, перечень источника, идентичность, авторизацию, модули, подписанный выпуск и ревизию вершины канала. Только после этого меняет `channel_heads` в сериализуемой транзакции. При нарушении условия канал не меняется. Администратор может вставить JSON-квитанцию и её SHA-256 в Migration Center. Квитанция **не является** подписью systemd и не свидетельствует о других писателях, отдельных JVM или сетевом переключении.
7. Проверьте доставленный манифест и настоящий вход/подключение Minecraft через промышленную точку, после чего независимо переключите DNS/прокси/трафик. При тайм-ауте HTTP используйте `cutover-list` и аудит миграции; не угадывайте, была ли фиксация. Источник Gravit остаётся заблокированным до успешной проверки и окончания окна отката.

## Безопасный откат

1. Остановите и независимо проверьте все процессы записи Launcher и реальные игровые серверы; убедитесь, что Gravit всё ещё заблокирован. Создайте свежий согласованный снимок мира/игроков/прав/экономики Launcher из промышленной резервной копии и независимо проверьте восстановление. Если состояние изменилось после MIG10, **до отката** согласуйте данные с отдельно заблокированной средой Gravit. Не восстанавливайте устаревшие снимки поверх работающих миров.
2. Запустите существующий `rollback-plan` с `--snapshot /absolute/path.json --evidence-reference ...`. CLI использует SHA-256 **точных байтов экспортированного JSON**, а не произвольную строку оператора. Если задан `--evidence-sha256`, он обязан совпасть с вычисленным хешем. Backend сравнивает смысл миров и игроков с MIG10; для согласования требуется отдельный дайджест подтверждения.
3. Новый план заменяет прежнее несохранённое утверждение под блокировками PostgreSQL проекта/запуска и отменяет старый хеш плана. План возрастом 10 минут **не** блокирует откат навсегда. Возьмите новый `planSha256` и ревизию маршрута; не используйте устаревшую квитанцию.
4. Выполните `rollback-commit --snapshot THE_SAME_FRESH_JSON --plan-sha256 APPROVED --expected-revision REV --writer-fenced true --source-writer-fenced true ...`. CLI вычисляет `currentEvidenceSha256` из фактически переданных байтов; Backend требует точного совпадения с планом, неизменности снимка и утверждённого выпуска, актуальной ревизии маршрута, обоих подтверждений остановки писателей и (для `stable`) нового одноразового сертифицированного разрешения stable.
5. Успешная транзакция возвращает прежнюю вершину канала Launcher. Она не перезапускает Gravit и не переносит новые данные миров. Предыдущий выпуск Launcher должен существовать и пройти проверки подписи/GA. Если предыдущего stable нет, автоматический откат stable запрещён: восстановление трафика на внешне сохранённый Gravit нужно планировать отдельно.

**Восстановление:** `cutover-cancel` отменяет только подготовленный, ещё не активированный маршрут. Активный маршрут требует отката и согласования. После тайм-аута GET-запросом проверяйте состояние маршрута/плана/отката. `sourceFenceReceipt` — свидетельство оператора, не удалённая аттестация; физический доступ, скомпрометированный systemd и независимые привилегированные писатели вне его области. Настоящие испытания PG, Minecraft, Gravit/systemd и прокси остаются обязательными для выпуска.
