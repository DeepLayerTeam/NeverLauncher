# 0.44.7 — репетиция настоящей миграции Minecraft (MIG10)

Оператор запускает `nl migrate gravit rehearse` **на изолированном одноразовом тестовом хосте**, где уже работают полный клиент Never и Java-сервер Minecraft. CLI проверяет действительный клиентский процесс переднего плана и новое подключение игрока, наблюдаемое тестовым сервером через аутентифицированный RCON по loopback. **Не** запускаются загруженные JAR Gravit, не выдаются промышленные разрешения и не переключаются каналы релизов.

## Настройка и запуск

1. Подготовьте изолированную среду с `.migration-stage.json`, `source-snapshot.json`, `target-snapshot.json` и семью **настоящими тестовыми** исполняемыми пробами (`probes/{launch,login,join,skins,loader,optional,admin}`) в существующем формате MIG10. Снимки источника и назначения должны поступать из реальных изолированных экспортов мира, инвентаря, прав, экономики, текстур и необязательных пресетов; выдуманные дайджесты недопустимы. Используйте **тестовый** Minecraft-аккаунт. Одно успешное подключение не доказывает лицензию, действительность сеанса, рендеринг, права или сохранность мира — нужны самостоятельные пробы.
2. Локально запустите перенесённый **тестовый** Java-сервер с RCON на `127.0.0.1`, `enable-rcon=true`, `broadcast-rcon-to-ops=false`, уникальным надёжным паролем и версией RCON с `/list uuids`. Не открывайте порт RCON публично, не перенаправляйте в промышленной среде и не используйте промышленные секреты. Игрок должен быть **не в сети** до начала репетиции.
3. Разместите в среде созданный оператором исполняемый файл запуска клиента **переднего плана**, например `bin/start-client` с правами `0700`. Он должен запустить настоящий Never Desktop/Runtime → процесс Minecraft Java и **продолжать работать** до завершения. Скрипт, который сразу выходит после запуска потомка, считается ошибкой. CLI запускает его напрямую, без подстановки оболочки, и проверяет активность. Нельзя подменять его скриптом, возвращающим успех.
4. Сохраните пароль RCON в локальном файле, например `rcon-password` (`0600`), и создайте `live-session.json` (`0600`):

```json
{
  "clientPath": "bin/start-client",
  "clientArgs": [],
  "playerName": "StagingPlayer",
  "playerUuid": "12345678-1234-1234-1234-123456789abc",
  "rconAddress": "127.0.0.1:25575",
  "rconPasswordFile": "rcon-password",
  "timeoutSeconds": 300
}
```

`playerUuid` должен присутствовать в `source-snapshot.json` и импортированной карте UUID MIG04; `playerName` — соответствовать настоящему имени игрока. Не помещайте access-токены в аргументы и конфигурацию: используйте защищённое хранилище платформы. Отдельный тестовый сервер или SSH-туннель с завершением **на loopback** допустим только в изоляции от production; публичное имя RCON запрещено.

```bash
nl migrate gravit rehearse \
  --run '<migration-run-id>' \
  --stage '/srv/isolated-migration-stage' \
  --inventory-sha256 '<MIG03-inventory-manifest-sha256>' \
  --backend 'https://test-never-backend.example' \
  --token '<short-lived-operator-token>' \
  --output '/srv/operator-private/rehearsal-result.json'
```

**Реально измеряемые наблюдения:** перед запуском CLI авторизуется на локальном сервере, проверяет отсутствие имени/UUID в списке, запускает клиент переднего плана и опрашивает `list uuids` до появления пары. После выдержки времени повторяет проверку при работающем клиенте. Затем проверяет её после независимых проб и чтения итогового снимка. Ошибка авторизации, преждевременное завершение клиента, чужой UUID, тайм-аут, недоступный RCON, удалённый адрес RCON или уже находящийся в игре игрок приводят к отказу. Сырые журналы, пароли RCON и аргументы не сохраняются; отправляются только хеши и время подключения. Это **наблюдение оператора тестового стенда**, а не криптографически защищённое доказательство: злонамеренный оператор или подменённый сервер могут его сфальсифицировать.

**Поведение Backend:** сервер независимо проверяет дайджесты `liveSession`, согласованность UUID источника и цели, временную шкалу подключения, успешные пробы входа/подключения, сравнение миров/инвентаря/прав/экономики/скинов, квитанции БД MIG03–MIG08 и идемпотентность отчёта перед установкой `ready=true`. Старые синтетические отчёты семи проб без `liveSession` теперь имеют `ready=false`. Успешная репетиция **никогда** не задаёт `cutoverAllowed`; MIG11 остаётся отдельным шагом.

**Границы покрытия:** наблюдение использует Java Edition `/list uuids` и локальный RCON-сервер на хосте, умеющем запустить тестовый клиент. Для macOS/Windows и серверов без RCON нужна отдельно проверенная операторская среда; успех нельзя предполагать. В исходниках нет Minecraft-бинарника и настоящих учётных данных, а локальная разработка не включает проверенную игровую сессию. Для приёмки миграции реального проекта запустите репетицию в настоящем изолированном развёртывании с тестовыми аккаунтами, ассетами, загрузчиком и Bridge-адаптерами. Пробы обязаны независимо проверять скины, необязательные выборы, вход, права администратора и сохранение состояния. Запись поддельного `passed:true` — недействительное подтверждение.
