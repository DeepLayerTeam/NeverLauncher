# Launcher 0.50.0 — GA миграции Gravit и функционального соответствия модулей

## Определение приёмки

Значение `VERSION=0.50.0` не является сертификатом. **Допуск GA заблокирован до появления независимых внешних подтверждений для трёх разных настоящих проектов Gravit, всех 36 проверок миграции, всех 19 проверок модулей, подписанных устанавливаемых пакетов 0.50.0 и фактических репетиций отката.** Успешный `go test`, подписанная схема, имитация, регистрация модуля или тестовая JSON-фикстура не заменяют эти доказательства.

Исполняемые проверки используют существующие настоящие реализации, а не альтернативный бэкенд миграции:

1. `tools/gravit-port/rehearse_cohort_04910.py` выполняет импорт с закреплением исходников и реальный запуск Minecraft до обновления с авторизацией и подключением, транзакционное обновление подписанного клиента, второй реальный запуск и подключение, а также сравнение постоянного UUID и снимков миров/игроков. Результат — `cohort-04910.json` с неизменяемыми исходными `pre-update-live.json`, `post-update-live.json`, `signed-update.json` для каждой категории исходных проектов.
2. `tools/migration-ga` выполняет 10 проверок FileAuth, 14 проверок SQL/модов и 12 проверок прокси/сети, сертификацию подписью Ed25519, сравнение снимков миров, игроков и плагинов, сохранение реальных результатов и проверку переключения **действующих** Backend/PostgreSQL. Три разные исходные архивные установки, идентификаторы проектов и запусков должны совпадать с группой испытаний 0.49.10. `verify-cohort-live` отклоняет изменённое, отозванное или откатившееся состояние. Поддерживаются точно версии Gravit 5.7.0–5.7.12; нельзя незаметно сертифицировать 5.7.13.
3. `tools/gravit-port/ga_acceptance_0500.py` проверяет оригинальные ZIP, подключения до и после подписанных обновлений и запускает **19 отдельных исполняемых тестов поведения модулей с закреплёнными хешами** для реально перенесённых эталонных проектов. Каждый должен показать минимум два наблюдаемых действия и создать новый исходный файл подтверждения с совпадающим SHA-256. Обязательны все M01–M19, включая безопасную административную альтернативу M17 вместо исполнения произвольного недоверенного кода. Средство сохраняет исходные подтверждения в закрытом каталоге и повторно считывает состояние действующего бэкенда после завершения модулей. Матрица `module-parity-04211.json` не доказывает фактическое поведение и не позволяет объявить непроверенный модуль поддерживаемым.
4. Независимый проверяющий лично изучает исполняемый код тестов, исходные журналы, подписанные пакеты, промышленное переключение 0.49.11, учения по восстановлению/откату 0.49.12, границы полномочий, удостоверения, Minecraft, плагины, миры и отрицательные сценарии. Одобрение подписывается **вне процесса сборки и тестирования** отдельным ключом Ed25519 и охватывает хеши каждого файла каталога подтверждений релиза, включая 19 файлов модулей и шесть подписанных пакетов. Проверяющий должен отличаться от всех проверяющих Migration GA. Сам код не создаёт такое внешнее одобрение.
5. `scripts/release/ga_gate_0500.py` проверяет отдельную независимую подпись, дайджест каждого файла, независимость исходных рецензентов, полный устанавливаемый релиз для шести целей через существующий проверяющий модуль поставки и повторяет проверку **действующих** трёх проектов в Backend после одобрения. Подтверждения старше 72 часов, отзыв доверия, несовпадение пакетов либо отсутствие доказательства модуля блокируют выпуск.

## Выполнение оператором

Необходим защищённый изолированный реальный Linux-исполнитель с работающими Backend/PostgreSQL, тремя настоящими исходными проектами Gravit и игровыми узлами, подтверждённым аккаунтом Microsoft там, где он требуется, HAProxy/systemd, Desktop-исполнителями трёх ОС, настоящими сервисами тестируемых модулей и опубликованными подписанными пакетами:

```bash
# Сначала выполните существующие процедуры репетиции трёх проектов и сертификации migration-ga,
# описанные в gravit-cohort-rehearsal.md и
# gravit-migration-ga.md. Исходные результаты без скрытия данных храните закрыто.
# Соберите настоящий проверяющий Go с закреплённой версией инструментов:
go -C tools/migration-ga build -o /srv/gravit-ga/migration-ga .

# Создайте /srv/gravit-ga/config-0500.json с правами 0600. Обязательные поля перечислены ниже.
# Создайте ПУСТОЙ каталог с правами 0700; не используйте прошлую операцию приёмки.
install -d -m 700 /srv/gravit-ga/acceptance-0500
export LAUNCHER_MIGRATION_GA_TOKEN='<short-lived-admin-token>'
python3 tools/gravit-port/ga_acceptance_0500.py \
  --config /srv/gravit-ga/config-0500.json \
  --evidence-dir /srv/gravit-ga/acceptance-0500
```

Средство не принимает 19 простых деклараций статуса. Для каждого M01–M19 оно **запускает настоящий закреплённый самостоятельный тестовый процесс** и ожидает JSON в стандартном выводе с `moduleId`, `runId`, `projectId`, `sourceSha256`, `passed: true`, `observations: ["...", "..."]`, абсолютным `evidenceFile` и `evidenceSha256`. Файл должен быть создан именно при этом вызове. Тестовые исполняемые файлы обязаны проверять настоящий провайдер, Runtime, клиент, интеграцию Discord/Sentry/mDNS/systemd, сервер/JVM-хост или явно разрешённую доверенную замену и фиксировать наблюдаемые эффекты до/после. Регистрация, статический анализ JAR и имитации в тестовом режиме не подходят. Проверки модулей не наследуют bearer-токен Migration GA, ключи подписи или DSN базы; используйте отдельные ограниченные тестовые удостоверения на изолированном исполнителе.

В закрытом объекте конфигурации задаются `format: "launcher/gravit-acceptance-0500/v1"`, абсолютные `rehearsalRoot`/`rehearsalReport`, `checker` (скомпилированный бинарный файл) и `checkerSha256`, `trustedPublicKey` (PEM-ключ Ed25519 Migration GA), `references` по категориям `fileauth-single`, `sql-modded`, `proxy-network` (для каждой абсолютные `plan`, `certificate`, `evidenceDir`) и `modules` для M01–M19 (в каждой `referenceClass`, `executable`, `executableSha256`, строковый список `args`, `timeoutSeconds`). Средство блокирует выпуск при отсутствии поля или обязательного результата, несовпадении исходных хешей, устаревших подписанных E2E-данных, изменении JVM или бинарного файла модуля, отсутствии реального обновления игровой программы или отзыве активного релиза. Оно **не** создаёт подписанные пакеты и не выдаёт независимое одобрение.

Скопируйте исходный каталог `signed/` с фактическими `RELEASE_MANIFEST.json`, `DELIVERY_VERIFIED_0462.json` и шестью окончательными подписанными установщиками 0.50.0 в корень полученных подтверждений приёмки, не заменяя свидетельства. Независимый рецензент, отличный от оператора миграции, должен подписать внешний JSON с полями `schema: "launcher.gravit.ga0500.independent.v1"`, `version: "0.50.0"`, `reviewer`, `commitSha`, `targetReleaseSha256` и `files` (карта относительных POSIX-путей **каждого** файла внутри каталога подтверждений и его SHA-256). Отдельная подпись Ed25519 подписывает точные байты JSON после ASCII-префикса домена `launcher.gravit.ga0500.independent.v1\0`. Одобрение, исходная 64-байтная подпись и доверенный 32-байтный открытый ключ хранятся **вне** каталога подтверждений в закрытом месте. Рецензент самостоятельно проверяет исходные квитанции и принимает решение о выпуске; средство не может установить, действительно ли наблюдения отражают ожидаемую работу Gravit.

```bash
python3 scripts/release/ga_gate_0500.py \
  --config /srv/gravit-ga/config-0500.json \
  --evidence-root /srv/gravit-ga/acceptance-0500 \
  --approval /srv/gravit-ga/external-review.json \
  --signature /srv/gravit-ga/external-review.sig \
  --trusted-reviewer-key /srv/gravit-ga/external-review.pub
```

Либо дважды используйте защищённый процесс CI `.github/workflows/gravit-ga-0500.yml`: режим `witness` выполняет настоящие проверки, затем после **отдельной независимой проверки и подписи** режим `promote` повторно проверяет те же окончательные байты. Переменные `GA0500_CONFIG`, `GA0500_EVIDENCE_ROOT`, `GA0500_REVIEW_APPROVAL`, `GA0500_REVIEW_SIGNATURE`, `GA0500_REVIEW_TRUSTED_KEY` — **абсолютные пути к отдельно подготовленным закрытым файлам**, а не к результатам сборки; токен администратора должен храниться как защищённый секрет. Исходные подтверждения не загружаются в артефакты CI. Отсутствие внешней системы, рецензента или исполнителя даёт **BLOCKED**.

## Границы и оставшиеся работы

Средство восстановления файлов 0.49.12 возвращает лишь проверенные локальные файлы миров, игроков и настроек, **но не PostgreSQL, базы плагинов или S3**. Прежде чем объявлять переключение или возврат с Gravit завершённым, независимые операторы должны подтвердить блокировку прежних писателей, маршруты HAProxy после перезагрузки и перезапуска (изменения runtime-сокета не сохраняются автоматически), реальное восстановление базы и плагинов, UUID и игроков после возврата, все области подписи/доверия и нативные пакеты. Проверки `operational-rollback-drill` и `negative-rollback` из 36 сценариев должны задействовать настоящие процедуры; подготовленный JSON с «успехом» недействителен. Безопасная альтернатива произвольному выполнению `UnsafeCommandPack` аудируется отдельно и не означает двоичной совместимости с небезопасным модулем.

Успех **локальных** тестов двух новых средств проверяет лишь работу контроля допуска и обработку ошибок. Без реальных исходных установок, серверов, подписанных артефактов, исполнителей на ОС и независимого рецензента **промышленная сертификация GA 0.50.0 невозможна**.
