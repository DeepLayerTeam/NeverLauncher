# NeverLauncher 0.49.11 — промышленное переключение входящего трафика Gravit

**Промышленная реализация в исходниках, но не независимая сертификация GA.** Это **настоящее двухэтапное средство оператора** для одной уже подготовленной миграции Gravit `runId/profileId/channel`, работающее с **выделенным Unix-сокетом управления HAProxy v2/v3** для обоих публичных Backend — авторизации и игрового TCP. Оно вызывает существующую активацию маршрута NeverLauncher в PostgreSQL, проверяет настоящий вход на целевом HTTPS, открывает новые серверы HAProxy и требует реальный локальный запуск Minecraft и подключение, наблюдаемое через RCON, по настроенному публичному игровому адресу. Средство не создаёт аккаунт Minecraft, подписанный выпуск, сертифицированный этап MIG10, исходную резервную копию или Linux-хост.

Ни одна распределённая транзакция не может атомарно изменить PostgreSQL, два независимых Backend HAProxy, внешнее состояние авторизации Gravit, DNS и файловое хранилище миров Minecraft. Поэтому при ошибках действует **строгий отказ**: серверы остаются в `MAINT`, требуется ручная сверка оператора. Средство никогда незаметно не открывает старый источник и не отбрасывает новые записи в мире.

## Необходимые условия (реальные, а не созданные тестовыми фикстурами)

- Уже завершённые настоящая независимая проверка источника/репетиция 0.49.10, подготовленный выпуск Never и проверенная подписанная цель с работающим на PostgreSQL Backend и разрешением стабильного Runtime при необходимости. Backend должен предоставлять `/api/v1/admin/migration-runs/RUN/cutovers`; CLI должен действительно работать на машине оператора.
- Выделенный **единственный процесс HAProxy** с раздельными Backend `auth` и `game`. Каждый содержит ровно старый и новый сервер, либо все прочие серверы уже в `MAINT`. Healthcheck HAProxy должен работать: `UP` означает исправность. Административный сокет — настоящий локальный Unix-сокет под контролем root или оператора. Конфигурация и состояние Runtime HAProxy должны контролироваться тем же доверенным оператором.
- До подготовки старые серверы авторизации/игры находятся в `UP`, новые — в `MAINT`, клиентам сообщено об окне обслуживания. Инвентаризируйте и остановите исходную систему авторизации Gravit, всех писателей миров, альтернативные прокси/ingress, кэши, очереди и планировщики. Квитанция **одного** `systemd`-юнита не доказывает остановку всех писателей.
- Независимые проверенные резервные копии миров Gravit и Never, игроков/UUID, авторизации, состояния модулей, БД и подписанных пакетов. Проверьте восстановление на отдельном хосте. Для записей после последнего исходного снимка используйте документ сверки и отката.
- Выделенный тестовый аккаунт Minecraft, разрешённый для проверки входа на **целевой** и **публичный** HTTPS-маршруты авторизации. Тело POST должно храниться в закрытом файле; ответ обязан содержать точный канонический UUID Minecraft в `uuid`, `playerUuid` или `id`. Нужен настоящий API входа, а не healthcheck с постоянным UUID. Обязательна проверка TLS-хоста; перенаправления считаются ошибкой.
- Этап после переключения для `nl migrate gravit rehearse-local` с реальным клиентским исполняемым файлом, проверками и настоящим игровым сервером с RCON на loopback. В `clientArgs` файла `live-session.json` должен быть выбранный **публичный адрес Minecraft** (`host:port`), а не прямой частный адрес сервера. Тестовый вход и наблюдаемый RCON вход Minecraft должны относиться к одному UUID. **Оператор обязан независимо проверить, что фактические аргументы лаунчера действительно направляют соединение через публичный HAProxy.** Наличие подстроки в аргументах — только статическая защита от случайных проверок прямой цели.

## Конфигурация

Создайте `/srv/never-cutover/config.json` с правами `0600`, каталог `/srv/never-cutover/journal` — с правами `0700` на устойчивом хранилище. **Не** помещайте токены доступа или пароли в конфигурацию или аргументы. Замените примеры проверенными промышленными значениями.

```json
{
  "format": "never/gravit-production-cutover/v1",
  "runId": "run_12345678",
  "profileId": "main",
  "channel": "stable",
  "stageId": "stage_12345678",
  "releaseId": "release-abc",
  "expectedRevision": 1,
  "baselineRevision": 7,
  "targetDigest": "<64-символьный SHA-256 подписанного манифеста Never>",
  "sourceSnapshotSha256": "<64-символьный SHA-256 типизированного снимка источника из MIG10>",
  "inventorySha256": "<64-символьный SHA-256 описи миграции>",
  "backend": "https://backend.example.org",
  "launcher": "/opt/never/launcher-cli",
  "launcherSha256": "<64-символьный SHA-256 исполняемого файла>",
  "proxySocket": "/run/haproxy/admin.sock",
  "routes": {
    "auth": {"backend": "auth-backend", "source": "gravit-auth", "target": "never-auth"},
    "game": {"backend": "game-backend", "source": "gravit-game", "target": "never-game"}
  },
  "drainSeconds": 240,
  "fenceReceipt": "/srv/never-cutover/fresh-fence-receipt.json",
  "gamePublicAddress": "play.example.org:25565",
  "postSwitchStage": "/srv/never-cutover/minecraft-canary-stage",
  "authCanary": {
    "url": "https://target-auth.example.org/login",
    "frontendUrl": "https://login.example.org/login",
    "method": "POST",
    "requestBodyFile": "/srv/never-cutover/auth-canary-request.json",
    "requestSha256": "<64-character SHA-256 of auth-canary-request.json>",
    "expectedPlayerUuid": "12345678-1234-1234-1234-123456789abc",
    "uuidJSONField": "uuid"
  }
}
```

`targetDigest` — дайджест подписанного манифеста маршрута, не ZIP и не исходного снимка. `baselineRevision` — старая ревизия Never `channel_heads.revision`, а не `expectedRevision` строки переключения. Поля проверяются независимо. Журнал привязывается к полным **байтам** конфигурации; нельзя менять файл и незаметно возобновлять процесс. Путь `fenceReceipt` задаётся **до** этапа 1, но сама квитанция формируется **после** освобождения и закрытия трафика. Это должна быть **свежая** проверенная квитанция с тем же запуском, профилем, каналом, этапом и типизированным дайджестом снимка источника.

## Двухэтапное выполнение

На машине оператора задайте `LAUNCHER_TOKEN` в защищённом окружении процесса (никогда не записывайте его в историю shell). Не изменяйте `config.json` в ходе этапов.

**Этап 1 — запрет новых подключений и завершение существующих:**

```sh
python3 tools/gravit-port/production_cutover_04911.py prepare \
  --config /srv/never-cutover/config.json \
  --journal-dir /srv/never-cutover/journal --confirm run_12345678
```

Средство требует всё ещё подготовленный совпадающий маршрут PostgreSQL, проверяет точные работающие Backend HAProxy и состояние цели, выполняет настоящие `set server BACKEND/SOURCE state drain`, ожидает нуля активных сеансов (`scur`) у обоих источников, затем переводит **все четыре сервера** источника/цели в `MAINT`. Устойчиво записываются `traffic_fenced` и PID HAProxy. Если сеансы не завершаются, предпринимается принудительный `MAINT` для обоих ingress Backend — это **может прервать** действующих игроков. При недоступном HAProxy оператор должен независимо закрыть firewall/прокси ingress и проверить все frontend-маршруты.

**Между этапами — остановка Gravit, новый исходный снимок, проверка ограждения:**

На настоящем исходном хосте Gravit выполните `nl migrate gravit fence-source`, экспортируйте новый *согласованный* снимок после остановки писателей и запустите `nl migrate gravit verify-source-fence` по [инструкции переключения и отката](gravit-cutover-rollback.md). Поместите квитанцию по точному пути `fenceReceipt` уже неизменяемой конфигурации. Завершите действия до истечения срока квитанции (10 минут; событие остановки — 15 минут). Все остальные независимые писатели источника проверяются внешними средствами; квитанция подтверждает только указанный systemd-юнит и снимок. Не делайте долгую паузу между этапами.

**Этап 2 — активация настоящего маршрута PostgreSQL, вход на цель и трафик Minecraft:**

```sh
python3 tools/gravit-port/production_cutover_04911.py activate \
  --config /srv/never-cutover/config.json \
  --journal-dir /srv/never-cutover/journal --confirm run_12345678
```

Средство требует прежнюю идентичность процесса HAProxy и состояние `MAINT` обоих публичных Backend; проверяет тот же подготовленный маршрут, квитанцию ограждения источника и прямой целевой вход с ожидаемым UUID; вызывает `nl migrate gravit cutover-activate` (Backend проверяет свежий MFA, подписанный выпуск, транзакцию PostgreSQL, требования MIG10 и ограждение источника); **повторно читает** маршрут после ответа; включает лишь два целевых сервера HAProxy; убеждается, что они `UP`, а исходные остаются `MAINT`; проверяет настоящий вход **через публичный HTTPS ingress**; запускает Minecraft через `rehearse-local` после переключения и проверяет наблюдаемый RCON вход, семь обязательных проб и UUID; затем снова сверяет маршрут Backend, состояние HAProxy и PID. `complete` — локальная эксплуатационная запись, **не** независимая аттестация GA.

Прочитайте локальный статус, ничего не переключая:

```sh
python3 tools/gravit-port/production_cutover_04911.py status \
  --config /srv/never-cutover/config.json --journal-dir /srv/never-cutover/journal
```

**При частичной ошибке:** сохраните закрытый журнал и все выводы CLI; остановите весь публичный ingress, напрямую проверьте `cutover-list` и PostgreSQL `channel_heads`, затем установите, была ли зафиксирована активация БД. Неудачная активация могла зафиксироваться даже при тайм-ауте клиента; автоматический повтор запрещён. Нельзя возобновить `blocked`, ещё раз вызвав `activate`. После успешной активации PostgreSQL не размаскируйте Gravit и не воспроизводите старые миры без **нового плана сверки и отката**; см. [инструкцию переключения и отката](gravit-cutover-rollback.md).

**Ограничение перезагрузки HAProxy:** состояния сокета Runtime **не являются** устойчивой конфигурацией HAProxy. Во время переключения запрещены reload HAProxy, замена worker, развёртывание и автоперезапуск; средство отслеживает смены PID между этапами. До завершения обслуживания оператор обязан закрепить *новую маршрутизацию только на цель* (удалив старые серверы) собственным промышленным управлением конфигурацией HAProxy и проверить reload отдельным E2E ingress. Перезагрузка после завершения скрипта **не защищена автоматически**; без постоянного обновления конфигурации старый трафик может снова открыться. Альтернативные frontend, DNS и балансировщики также требуют отдельной приёмки. Это обязательное препятствие для заявления об успешном промышленном переключении.

## Подтверждения и ограничения

В каталоге аудита хранятся JSON маршрута до активации, предварительной активации, активации, после и окончательного состояния, отчёт Minecraft после переключения, журнал без перезаписи и блокировка. Файлы имеют права `0600`, каталог — `0700`. Bearer-токен, пароль тестового аккаунта и ответ авторизации не записываются в свидетельства. Повторная `prepare` в том же каталоге отклоняется. Средство не меняет файлы миров Minecraft, не переносит писателей БД и инвентарь игроков, не меняет DNS, не подписывает выпуски и не сертифицирует устойчивость HAProxy. Не используйте его на настоящем проекте до доказанной репетиции, внешнего fencing и проверенных процедур восстановления.

**Локальная регрессия:** `python3 -m unittest discover -s tools/gravit-port -p 'test_production_cutover_04911.py' -v`. В ней используются настоящий Unix-сокет и реальные вызовы дочернего CLI с тестовыми заменителями HAProxy/Backend, а не промышленная инфраструктура. Для приёмки всё ещё нужны реальные HAProxy, PostgreSQL, Minecraft, подписанный выпуск, аккаунт Microsoft и независимый оператор.
