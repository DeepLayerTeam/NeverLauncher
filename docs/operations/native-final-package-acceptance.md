# NeverLauncher 0.52.2 — приёмка окончательного нативного установщика

## Что действительно запускается

`native_packages_0522.py run` **не** компилирует подменный исполняемый файл, не вызывает фиктивную функцию `main` и не принимает кросс-компиляцию как доказательство. На каждом **нативном** одноразовом исполнителе скачиваются внешний независимо закреплённый неизменяемый индекс и настоящий **окончательный** пакет. До запуска проверяются длина скачивания и SHA-256 по независимо утверждённому индексу источников. Нужны ровно шесть целей: Windows, Linux и macOS на x64 и ARM64. Отсутствие хотя бы одной проваливает весь шлюз.

| ОС | Обязательная проверка платформы | Реальное выполнение установщика |
| --- | --- | --- |
| Windows x64/ARM64 | Authenticode `Get-AuthenticodeSignature`: правильная цепочка сертификатов и **независимо закреплённый отпечаток сертификата** | Запуск скачанного `.exe verify`, `.exe install --root <isolated> --no-start`, `verify-installed`, `uninstall` |
| Linux x64/ARM64 | Отдельная подпись `gpgv`, SHA-256 закреплённого хранилища ключей и отпечаток подписанта; проект/версия/нативная архитектура `.deb` | `sudo dpkg -i` на **временном** исполнителе; вызов **установленного в систему** `/usr/lib/launcher/bundle/neverinstaller`: `verify`/`install`/`verify-installed`/`uninstall` |
| macOS x64/ARM64 | Цепочка сертификатов Apple Installer и закреплённый Team ID; проверка `spctl`; приложенная нотариальная отметка; codesign/Gatekeeper/Team ID установленного приложения | `sudo installer -pkg ... -target /` на **временном** исполнителе; запуск **установленного** `Launcher.app/Contents/MacOS/Launcher` с теми же настоящими действиями |

Операция `install` считается успешной, только если существующий Go-установщик `neverinstaller` устанавливает подписанный Prestarter, содержимое и управляемую Java и фиксирует активное поколение. Сборка замен из исходников, подстановка символических ссылок, вручную установленное `PASS`, неподписанные/разработческие пакеты и пропуск подготовки не засчитываются.

**Это установка пакета и первоначальная подготовка, а не сквозная проверка игрового процесса Minecraft.** Запуск игры, официальный вход, подключение к подписанному миру, работа защиты от читов и полная матрица совместимости относятся к последующим этапам 0.52.3–0.52.11 и остаются BLOCKED, пока не будут реально засвидетельствованы. Тест использует закрытые одноразовые проектные аккаунты. Ни один исполнитель не ставит пакет поверх уже существующего приложения macOS. Сам исполняемый файл не способен доказать физическую независимость хоста; для GA нужна отдельная эксплуатационная проверка планирования доверенных нативных исполнителей и оборудования. Успешное самозаявленное выполнение CI не является независимым утверждением выпуска 0.53.0.

## Подготовка и независимое закрепление окончательных файлов

1. Запустите защищённое промышленное задание `native-installers.yml` из **точного коммита выпуска**. Windows подписывает Authenticode, Linux — отдельную `.asc`, macOS — Developer ID, отправляет окончательный `.pkg` в Apple notarytool, проверяет **Accepted** и прикладывает билет. Неподписанная тестовая сборка недопустима.
2. Опубликуйте **те же окончательные байты** (`.exe`, `.deb`, `.deb.asc`, `.pkg`) по неизменяемому HTTPS-адресу выпуска или промежуточного размещения. После утверждения пересборка запрещена.
3. Разместите все шесть пакетов и обе отдельные подписи Linux в одном каталоге выпуска и сформируйте индекс с дайджестами:

```sh
python3 scripts/acceptance/native_packages_0522.py index \
  --packages /absolute/release/final-files \
  --base-url 'https://download.example.net/releases/v0.52.2/' \
  --version 0.52.2 --commit <40-hex-release-commit> \
  --project <signed-project-id> \
  --output /absolute/release/native-final-sources-0522.json
```

4. Утвердите `indexSha256` и `indexSize` **через независимый канал** (защищённая среда, подписанная заявка на изменение). Хеш внутри скачанного индекса сам по себе не является независимым закреплением. Опубликуйте `native-final-sources-0522.json` без изменений. Каждый артефакт должен быть доступен по HTTPS под точным ожидаемым именем и с ожидаемым размером.
5. Ограничьте защищённую среду `production-acceptance` утверждёнными ссылками выпуска (`main` и доверенные теги `v*`), потребуйте разрешения оператора и установите `NL_NATIVE_ACCEPTANCE_INDEX_SHA256` в независимо утверждённый хеш индекса, а `LAUNCHER_BRANDED_PROJECT_ID` — в реальный подписанный проект. Workflow отклоняет входные данные выпуска, не совпадающие с защищёнными значениями. В среде отдельно задайте доверенные переменные `NL_NATIVE_ACCEPTANCE_WINDOWS_SIGNER_SHA1`, `NL_NATIVE_ACCEPTANCE_LINUX_GPG_FINGERPRINT`, `NL_NATIVE_ACCEPTANCE_LINUX_KEYRING_SHA256`, `NL_NATIVE_ACCEPTANCE_APPLE_TEAM_ID`, а `NL_NATIVE_ACCEPTANCE_GPG_KEYRING_BASE64` задайте секретом с закреплённым минимальным доверенным двоичным хранилищем ключей GPG. Никогда не извлекайте доверенные идентичности из релизного пакета, индекса, вывода CI или самого HTTPS-ответа.
6. Запустите `.github/workflows/native-final-packages-0522.yml` из точного коммита выпуска с независимо утверждёнными `manifest_url`, `manifest_sha256`, `manifest_size` и подписанным `project`.

Рабочий процесс параллельно выполняет шесть *нативных* заданий с `fail-fast: false`. Затем `six-native-gate` повторно скачивает тот же независимо закреплённый индекс, сверяет идентичность пакетов, проверяет SHA-256 всех обязательных журналов команд, требует код завершения 0 каждого процесса и сверяет точный коммит Git, запуск и попытку. Механизмов `always-pass`, `continue-on-error`, `optional platform` и обхода отсутствующих хостов нет. При сбое проверки или установки CLI возвращает код 2.

Каждый успешный нативный исполнитель публикует `receipt.json` и ограниченные по размеру **очищенные от секретов** журналы каждой команды. Неудачные запуски публикуют `blocked.json` с очищенной диагностикой, но никогда не квитанцию PASS. Исходные байты пакета, подписанная начальная конфигурация, полный неочищенный вывод процессов, доверенный материал GPG и параметры запросов к URL выпуска не загружаются в артефакты CI. Сторонние программы могут непредсказуемо выводить секреты: считайте любые скачанные журналы CI ограниченными в доступе до проверки оператором. Целостность квитанций CI защищает от случайной путаницы, отсутствующих журналов и простой подмены, **но не** от полностью злонамеренного исполнителя CI. Используйте только новые выделенные одноразовые исполнители GitHub. Установленный пакет Linux или приложение macOS остаётся для удаления вместе с таким исполнителем; запуск на компьютере сотрудника или постоянном собственном исполнителе **запрещён**.

## Независимая проверка после CI с криптографическим закреплением

Сводка CI **не является** доверенной аттестацией человека или физического оборудования. Независимый оператор должен отдельно проверить журналы шести исполнителей и байты выпуска. Для защиты от изменений после проверки оператор может дополнительно подписать точно **пересчитанную** сводку по шести целям. Инструмент отказывает при отсутствии цели, изменённом журнале, неверном запуске или повторном использовании исходного индекса.

```sh
python3 scripts/acceptance/native_packages_0522.py sign-review \
  --results /absolute/receipt-folders --source-index /absolute/native-final-sources-0522.json \
  --manifest-sha256 <approved-index-hash> --version 0.52.2 \
  --commit <40-hex-commit> --project <signed-project-id> \
  --run-id <run-id> --attempt <run-attempt> \
  --reviewer <independent-operator> --private-key /secure/reviewer-private.pem \
  --public-key /secure/reviewer-public.pem \
  --public-key-sha256 <independently-pinned-SPKI-DER-SHA256> \
  --output /secure/unused/native-package-review.json

python3 scripts/acceptance/native_packages_0522.py verify-review \
  --results /absolute/receipt-folders --source-index /absolute/native-final-sources-0522.json \
  --manifest-sha256 <approved-index-hash> --version 0.52.2 \
  --commit <40-hex-commit> --project <signed-project-id> \
  --run-id <run-id> --attempt <run-attempt> \
  --reviewer <independent-operator> --public-key /secure/reviewer-public.pem \
  --public-key-sha256 <independently-pinned-SPKI-DER-SHA256> \
  --receipt /secure/native-package-review.json
```

Используйте закрытый PEM-ключ Ed25519 с правами `0600` **вне рабочего каталога исходников**. `public-key-sha256` — это SHA-256 DER SubjectPublicKeyInfo, передаваемый независимо. Квитанция создаётся только если файла ещё нет и подписывается по шести исходным дайджестам квитанций с привязкой пакета к источнику. Успешная проверка возвращает `CI_OBSERVED_SIGNED_REVIEW_NOT_GA`; она не превращает CI в GA.

## Что означает PASS и чего он не подтверждает

- Полная матрица кандидата даёт `CI_OBSERVED_REVIEW_REQUIRED`, а не `GA_PASS`. Она связывает шесть нативных пакетов с закреплёнными SHA-256, проверку подписи ОС и Gatekeeper/GPG/Authenticode, настоящую системную установку (Linux/macOS), реальное исполнение установщика, подтверждённую зафиксированную установку Prestarter и чистое удаление изолированных данных приложения.
- Отсутствующая или изменённая квитанция/журнал, устаревший коммит, другая попытка, неверная версия продукта или подписант, пакет не по HTTPS, отсутствие билета Apple, эмулируемый или чужой исполнитель либо нарушение настоящей подготовки оставляет кандидата **BLOCKED**. Для независимого GA повторите проверку поставленных байтов и подпишите её с реальными свидетелями — людьми и оборудованием. Одного CI со сборкой исходников недостаточно.
- Установка Windows `.exe` выполняется настоящим установщиком для текущего пользователя; распространение Windows MSI/Store не проверяется и не входит в эту категорию пакетов. Linux/macOS проверяют нативные системные менеджеры пакетов и установленное приложение Go. GUI Desktop и игровой процесс проверяются отдельно.

Локальная команда регрессии (только тесты безопасности, **не** свидетельство реальной платформы):

```sh
python3 -m unittest scripts/acceptance/test_native_packages_0522.py -v
python3 scripts/version/manage.py check
```
