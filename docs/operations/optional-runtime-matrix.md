# 0.34.8 — фактическая матрица подготовленного опционального Runtime

Для каждой обязательной цели создаются отдельный nonce от Backend, ограниченное разрешение на подготовленный выпуск, непривилегированный исполнитель OCI, новая установка, выбранный набор компонентов, меню Minecraft, настоящее подключение к соответствующему серверу, наблюдение игрового процесса, проверка реальной аутентификации и независимо подписанный `ValidationEvidence`. Запуск с набором по умолчанию никогда не засчитывается за другой набор. Публикация stable остаётся запрещённой до V11.

## Расчёт и поведение с запретом при ошибке

Backend отклоняет неисполняемые варианты старого каталога (манифест до схемы 3.0 или каталог схемы 1.0). Он формирует обязательные ID выбора из **подписанного неизменяемого каталога компонентов выпуска**: все именованные публикуемые наборы (либо `default`, если их нет), самостоятельный положительный выбор для условно доступных необязательных компонентов, отсутствующих в именованных наборах, а затем до 12 детерминированных совместимых пар в лексикографическом порядке. Для пар используется нативная подписанная форма `@custom:v1:<base>:+id,+id`; подмена, неподписанный путь к моду или локальный граф компонентов запрещены. Несовместимые пары исключаются после проверки резолвером. Для объявленных каталогом условных ветвей ОС/архитектуры требуются соответствующие цели; неверные графы наборов, зависимостей или конфликтов блокируют принятие целевой политики. Условия Java/загрузчика проверяются настоящим нативным резолвером на выбранной цели.

Каждый достижимый условный компонент вне именованных наборов требует обязательного выбора; слишком большая обязательная матрица отклоняется, а не обрезается. Максимум 12 дополнительных пар и 512 оцениваемых пар-кандидатов **не образуют исчерпывающего перебора**. Ответ API о покрытии аттестации содержит `requiredComponentSelections`, `targetCoverage`/`targetBlockers` для целей и `unverifiedCandidateCombinations` для совместимых, но не выбранных или ещё не проверенных сочетаний. Никогда не объявляйте непроверенные сочетания успешно испытанными.

Администраторы должны закрепить отдельную запись обязательной цели для **каждого** выведенного выбора в `ValidationRequiredTargetsJSON0346`. Каждая запись также закрепляет дайджесты манифеста и артефактов, Java, загрузчик, ServerBridge, подписанный план Runtime, адаптер, Guard, официальный или пользовательский режим аутентификации и платформу. Backend отвергает матрицу с отсутствующим обязательным выбором и при выдаче разрешения, и при принятии доказательств. Не подставляйте вымышленные дайджесты: сначала создайте и проверьте значения на целевом исполнителе, затем закрепите их в политике.

## Границы доверия

Независимый аттестатор `execute_matrix()` получает свежее разрешение для каждой цели, запускает одобренный OCI-образ по неизменяемому дайджесту с `--preset` и проверяет настоящие файлы компонентов относительно подписанного каталога, результаты нативных транзакционных офлайн-операций Runtime `adopt-staged` и `verify`, а также вновь привязанный дайджест разрешённого плана. Оставшиеся в каталоге клиента необязательные файлы модов, которые не были выбраны, отклоняются. Аттестатор подписывает только успешные запуски; неудачный, заблокированный или неопределённый из-за провайдера запуск не считается сертифицированным, и матрица остаётся неполной. Закрытый ключ аттестации не монтируется в исполнитель.

Запустите существующий аттестатор Podman без root с `--package-id` для однократного полного прогона матрицы либо отправьте ID пакета в существующую конечную точку mTLS `/v1/attest`. Для узла требуются реальные официальные/пользовательские тестовые учётные записи и закреплённый соответствующий набор сервера. Сейчас реализован только визуальный исполнитель Linux/X11; другие ОС остаются **непроверенными**, а не ложно успешными. Для укрепления узла и изоляции учётных данных следуйте инструкциям по аттестации 0.34.5 и 0.34.7.

До приёмки GA запустите тесты Go/Python V08, соберите обновлённый OCI-образ на доверенном узле, закрепите его новый дайджест и выполните полную матрицу на настоящем подписанном подготовленном пакете. Тесты не заменяют этот прогон.

Процесс подготовки сначала выполняет обычные Go-команды установки/проверки клиента в изолированном каталоге поставки. Затем Runtime импортирует только подписанные выбранные файлы в отдельный действующий каталог клиента через устойчивую офлайн-транзакцию выпуска. При этом сетевых загрузок нет, а несовпадающие исходные байты отклоняются. Аттестатор проверяет запись об импорте до подписания доказательств.
