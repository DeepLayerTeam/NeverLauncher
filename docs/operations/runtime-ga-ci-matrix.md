|---|---|---|---|

| `TestGAStableSnapshotImmutablePostgres0350`, V11, V12 и атакующие тесты Go | `runtime-acceptance-0350.yml` PostgreSQL 17 | Тестовая БД | Да, предотвращают обход SQL |

| Windows/Linux/macOS в безголовом режиме и GUI на заявленных архитектурах | `native-runtime-v10-03410.yml` | Наблюдение до независимой аттестации | Для всех заявленных конфигураций |
| Неизменяемый запуск подготовленного пакета в закреплённом rootless-образе OCI с независимой подписью | Внешняя служба аттестации | Доверенная область аттестации | Один независимый результат **на конфигурацию** |

| Обновление, повреждённый кеш, восстановление, прерывание, замена Java, откат | Рабочие предыдущий и текущий релизы | Доверенная только после независимой аттестации | Для всех обязательных сценариев жизненного цикла |
| Обязательный охват действующего Backend / SHA исходников / хеш матрицы | `runtime-acceptance-0350.yml` | Предварительная проверка только для чтения | Да, повторить при подписании |
| Долговременная стабильная публикация и SQL-защита указателя канала | Backend / PostgreSQL 17 | Последний авторитетный контроль допуска | Обязательно до открытия стабильного канала |

Список целевых конфигураций формируется по фактическому подписанному каталогу компонентов и явной политике обязательных конфигураций. Должны быть представлены каждый опубликованный пресет и каждая достижимая ветвь условий; дополнительные совместимые сочетания проверяются ограниченной выборкой, а все непроверенные комбинации явно помечаются как неподтверждённые. Безголовый запуск не заменяет графический игровой процесс. Пропущенная, недоступная, неуспешная или неопределённая обязательная конфигурация блокирует стабильный канал.

Настройте защищённое окружение GitHub `runtime-validation-ga` с `NL_GA_BACKEND_URL` (переменная, HTTPS-адрес) и `NL_GA_OPERATOR_TOKEN` (секретный токен API только для чтения). Окружение промышленного выпуска также должно предоставлять эти значения и `NL_GA_PACKAGE_ID` из входных данных dispatch. `runtime-acceptance-0350.yml` сопоставляет все подтверждения ровно с `github.sha`, а `scripts/release/build-release.sh` повторно проверяет их при подписании. Отсутствие окружения/секрета намеренно блокирует операцию и никогда не приводит к подстановке имитированных данных CI.
