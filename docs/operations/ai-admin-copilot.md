# AI Admin Copilot (1.2.4)

Copilot доступен в Admin Panel после входа и выбора проекта с `project:read`. AI Gateway должен быть включён, глобальная роль пользователя должна быть разрешена в `LAUNCHER_AI_ALLOWED_ROLES`. Действуют прежние бюджеты, учёт токенов, ограничения запросов и параллелизма. API-ключ OpenAI остаётся в Backend. Требуется корневой HTTPS URL Backend; для отдельного домена Admin настройте существующий список CORS origins, не расширяйте его до `*`.

## Использование

1. Откройте «AI Admin Copilot» и выберите проект. Введите вопрос. Не включайте секреты, логи с персональными данными и учётные данные. Подтвердите отправку текста и идентификатора проекта в OpenAI. Автоматическое чтение файлов, базы, журналов и секретов отсутствует.
2. Ответ поступает через SSE. Только полностью завершённый ответ с подтверждённым сервером учётом может содержать структурированное предложение. Невалидный ответ остаётся текстом, без кнопки действия. Никакого исполнения кода модели, HTML, произвольных URL или shell.
3. Поддерживаются две операции существующего устойчивого конвейера: `package-publish` (ID проверенного пакета) и `channel-rollback` (профиль, канал, опубликованная целевая версия). У пользователя должно быть `release:publish` на выбранный ресурс. Уточняйте точные ID; AI не является источником истины о пакетах.
4. Нажмите «Проверить на Backend». Проверка выполняет настоящие проверки подписи, совместимости, канонических файлов, готовности пакета и политики ресурса согласно выбранному типу операции. В предпросмотре видны реальная цель, версия, канал и текущая ревизия head. Это не гарантия исполнения: воркер повторно проверяет права и состояние.
5. Проверьте план, отметьте согласие и подтвердите постановку задачи. Для критических операций требуется свежая MFA (до 5 минут), применяются действующие проверки риска. Если требуется step-up, пройдите его в существующем интерфейсе авторизации и запросите новый план. Истёкший или изменившийся план необходимо проверить заново.
6. После 202 задача принята, но ещё не завершена. Откройте монитор задач, проверяйте статус и аудит. Copilot записывает `copilot:confirmed:package-publish` или `copilot:confirmed:channel-rollback` при создании задачи; идентификатор задачи связывает события и исполнение. Аудит использует имеющийся механизм репозитория, не записывает prompt, ответ, токены или подпись подтверждения.

## Серверный протокол

Существующие `/api/v1/operations/validate` и `/api/v1/operations/execute` дополнены опциональным режимом Copilot. Обычные клиенты не меняются.

- В validate передаётся обычный intent и `idempotencyKey: copilot:<UUID>` в JSON. Header Idempotency-Key для режима Copilot не допускается. Сервер после RBAC и проверки возвращает `copilotConfirmation` и `expiresInSeconds: 120`.
- Execute получает тот же intent и `copilotConfirmation`. Сначала проверяются действительная сессия, свежая MFA, AI-role allowlist, проектные права. Подтверждение HMAC-SHA256 разделено доменом и привязано к субъекту, ID сессии, типу операции, проекту, ресурсу, ключу и полному проверенному payload (включая дайджесты и ожидаемую ревизию head). После истечения срока или смены состояния повторная проверка обязательна. Все экземпляры Backend должны использовать одинаковый защищённый `LAUNCHER_AUTH_TOKEN_SECRET`.
- Модель не получает токен, ключ идемпотентности и подтверждение, не имеет доступа к API управления. Отдельный ключ Copilot не нужен. Подтверждение не заменяет RBAC, MFA или проверку задания воркером. Старые административные маршруты сохраняют собственные правила доступа.
- Журнал идемпотентности гарантирует одну задачу на тот же подтверждённый ключ. После потери ответа UI сохраняет только intent (без подписи и учётных данных) локально в области Backend/пользователь/проект и выполняет GET `/api/v1/operations/recover`. Нет автоматического повтора платного запроса или мутации. При отсутствии записи результат может оставаться неизвестным; проверьте монитор и аудит прежде чем закрывать запись восстановления. Закрытие записи не отменяет задачу.

## Проверки

`apps/admin`: `npm ci && npm test && npm run build`. Backend: `go test -race ./internal/copilotproof` и `go test -race ./internal/httpapi -run 'TestCopilot|TestRecoverOriginalOperation0388|TestRollbackOperationIdempotency0217'`. Workflow `ai-admin-copilot.yml` запускает регрессии и сборки. HTTP-тест использует реальную авторизацию, проверенный релиз и журнал в memory-репозитории, без обращения к платному AI. Для production-приёмки дополнительно проверьте реальный OpenAI, PostgreSQL/SQLite, две роли и два проекта, браузер и выполнение воркером в тестовом канале. Ни одна операция не должна выполняться по одному ответу AI.
