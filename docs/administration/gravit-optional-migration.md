# Перенос Gravit OptionalFile / OptionalView в Launcher 0.24.11

Миграция — **работающий сценарий Admin**, а не прямой импорт кода Gravit или непроверенных путей файлов. Распознанные элементы `ClientProfile.updateOptional` преобразуются в каталог v5; далее применяется обычная последовательность Backend: предпросмотр → атомарное сохранение черновика → подпись Ed25519.

## Рабочий процесс администратора

1. Создайте **неподписанный пакет Manifest v3** в Release Workspace соответствующего проекта/профиля. Все необязательные JAR предварительно загрузите в пакет с владением `optional`; пути обязаны совпадать с исходными путями действия Gravit `file`, без переименования. Backend хеширует настоящие байты и контролирует перечень файлов пакета.
2. Откройте **Редактор графа компонентов → Gravit OptionalFile / OptionalView**. Загрузите строгий JSON ClientProfile (массив `updateOptional`) либо исходный массив OptionalFile. Данные из Gravit не загружаются, код не выполняется.
3. Нажмите **Проверить перенос Gravit**, проверьте и экспортируйте поэлементный отчёт. При наличии `blocked` или `manual` автоматическая конверсия **неприменима**. Исправьте исходник/владение либо вручную перенесите неподдерживаемое поведение в подписываемом редакторе графа с независимой проверкой.
4. Если отчёт совместим и предпросмотр графа Backend успешен, нажмите **Перенести в редактор**: меняется только локальное состояние редактора. Снова выполните штатную проверку Backend и сохраните. При сохранении под блокировкой пакета проверяются CAS ревизии, весь каталог и пересчитывается дайджест.
5. Подпишите, подготовьте и опубликуйте обычным процессом. Клиент использует штатный проверенный нативный резолвер. Данные Gravit не могут изменить подписанный снимок или внедрить команды JVM.

## Поддерживаемые преобразования

| Gravit | Подписанный каталог Never v5 |
| --- | --- |
| `name` | Устойчивый ID компонента `gravit-<slug>-<hash>` из точного имени |
| `info` | Описание |
| `mark`, `visible`, `limited:false` | Выбор по умолчанию и видимость |
| `category` | Категория с устойчивым ID из имени |
| `dependenciesFile[].name`, `conflictFile[].name` | Поиск точного имени → устойчивый ID |
| `actions: [{type:'file',files:{'mods/a.jar':''}}]` или `{'mods/a.jar':'mods/a.jar'}` | Подписанное действие `File` только для фактически загруженных путей `optional` |
| `actions: [{type:'classpath',args:['mods/a.jar']}]` | Подписанное действие `ClassPath`, если файл принадлежит пакету и `useAltClasspath:false` |
| `actions: [{type:'jvmArgs'|'clientArgs',args:[]}]` | Только разрешённые подписанные аргументы Never |
| `triggersList` обязательный, не инвертированный `os` | Условие ОС (`MUSTDIE`→`windows`, `MACOSX`→`macos`) |
| `triggersList` обязательный, не инвертированный `arch` | Условие поддерживаемой архитектуры |
| `triggersList` обязательный, не инвертированный `java` | Диапазон основной версии Java (999 без верхнего ограничения) |

Версия компонента `1.0.0` — явно отмеченная **заглушка для миграции**: OptionalFile Gravit не имеет надёжного эквивалента SemVer. Проверьте и замените её перед ограничениями версий зависимостей. Неизменённый SHA-256 источника включён в отчёт для идентификации проверенного ввода.

## Намеренные условия блокировки

- Отсутствующие, изменённые, неуправляемые или уже принадлежащие другому компоненту файлы подготовленного пакета.
- Переименование источник→назначение, перемещение каталогов и неявное копирование каталога.
- `groupFile` с выборами, `isPreset:true`, визуальная вложенность `subTreeLevel>1`: семантика Gravit отличается и требует проверки вручную.
- Динамические/автоматические триггеры (`required:false`), инвертированные триггеры, произвольные требования JavaFX и неизвестные поля.
- `limited:true` или ненулевые битовые маски прав Gravit: Never не может вывести проверенные серверные разрешения из целочисленных масок.
- Системный/альтернативный classpath, неподдерживаемые действия, неизвестные поля, небезопасные JVM-параметры и переопределения запуска/авторизации.
- Неизвестные имена целей зависимостей, дубли JSON-полей/имён, циклы, конфликты файлов, недопустимая топология подписанного каталога.
- Необязательные компоненты только с действиями без файлов (каталогу Never требуется владение файлом).

**Это не перенос пользовательского состояния выбора `OptionalView.enabled` во время исполнения Gravit.** Маршрут принимает определения компонентов из `updateOptional` ClientProfile или сам массив определений. Пользовательский выбор переносится отдельным процессом Never с подписанными ID компонентов.

## API

`POST /api/v1/packages/{packageId}/component-catalog/gravit-preview`

Требуется разрешение `release:prepare` на пакет, как для предпросмотра/сохранения каталога. JSON: `{ "expectedRevision": 1, "source": "<исходный JSON Gravit без изменений>" }`. Поле `source` может быть также JSON-объектом или массивом. JSON-**строка** сохраняет исходные байты для SHA-256 и поиска вложенных дублирующих ключей. Успех возвращает `migration`, `preview`, `canApply` и диагностику, **не записывая** данные в репозиторий.

Фиксация намеренно происходит через существующий `PUT /api/v1/packages/{packageId}/component-catalog` с проверенным кандидатом и исходной ожидаемой ревизией. Backend повторно вычисляет дайджест.

## Проверка

Go: `cd services/api && go test ./internal/model -run TestGravitOptional`. Admin: `cd apps/admin && npm test`. HTTP: `cd services/api && go test ./internal/httpapi -run TestGravitOptional`. Последней команде нужны внешние зависимости Go проекта. Полный сквозной процесс подписания релиза, загрузки Desktop и запуска Minecraft также должен проходить в промышленном CI до объявления сертификации всего выпуска.

## 0.44.5 — согласование импорта содержимого исходников

Импортёр содержимого Migration Center теперь распознаёт оба допустимых варианта пути действия Gravit `file`: пустое назначение и назначение, совпадающее с источником. Прежний преобразователь принимал оба, но выбор файлов из ZIP источника загружал только вариант с пустым назначением. Каждый выбранный файл теперь проверяется по SHA-256 и получает владение `optional`, а не становится молча обязательным. `updateOptional: null` рассматривается как пустая коллекция и не блокирует корректный базовый профиль. Неподдерживаемые перемещения между путями **по-прежнему блокируют** миграцию; непроверенные или неуправляемые пути в workspace не добавляются. Обычная цепочка проверки черновика, CAS и подписи не меняется.
