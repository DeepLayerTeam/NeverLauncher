# Launcher Admin 0.21.6 — рабочее место администратора

## Запуск

Из корня репозитория:

```bash
cd apps/admin
npm ci
npm run build
```

Собранный `dist/` разворачивается существующим Dockerfile / Nginx. Backend должен быть доступен по URL, указанному в Admin (либо через текущий origin). Адрес Backend сохраняется локально; при его изменении текущие токены удаляются из состояния клиента для предотвращения отправки токена чужому серверу.

## Навигация

Разделы доступны по hash-маршрутам: `#/dashboard`, `#/projects`, `#/profiles`, `#/channels`, `#/packages`, `#/releases`, `#/users`, `#/roles`, `#/devices`, `#/audit`, `#/server-bridge`, `#/extension-registry`. Маршруты работают после перезагрузки браузера и при использовании кнопок «Назад»/«Вперёд». Подключение новых Nginx rewrite rules не требуется.

После входа Admin вызывает `GET /api/v1/admin/me` (полномочия глобальной роли и `projectPermissions`) и защищённый `GET /api/v1/admin/overview` (только доступные проекты). Выбранный проект хранится в sessionStorage. Проектный контекст применяется для профилей, каналов и релизов и сбрасывает ранее выбранные профили/версии при смене проекта. Просмотр чужого проекта не появляется в навигации и таблице.

Видимость действий — *только* клиентский UX. Backend обязан продолжать выполнять все `requirePermission` / `requireProjectPermission` / step-up проверки. В частности, операции с пользователями/устройствами и расширениями требуют глобальной роли; проектные полномочия не разрешают работу с чужим проектом.

## Работа с объектами

В таблицах предусмотрены поиск по видимым полям, фильтрация по категориальным значениям, сортировка по столбцам, пагинация 10/25/50 строк, выбор записи и карточка с полными полями. Пустой список и пустая выборка фильтров отображаются отдельно. Текущий API возвращает списки целиком; пагинация в версии 0.21.6 выполняется на клиенте, а не SQL-запросом. Для крупных журналов потребуются серверные курсоры в следующих версиях.

Открытие проекта, профиля, канала, пользователя или релиза заполняет форму соответствующего раздела. Кнопки скрываются или отключаются по действующим полномочиям. После операции Admin обновляет данные и показывает ответ Backend. Выпуск релиза по-прежнему требует актуального серверного MFA/step-up, если это предусмотрено API. Проверка пакета использует `POST /api/v1/packages/{packageId}/validate` вместо запроса списка версий.

## Проверки

```bash
cd apps/admin
npm test
npm ci
npm run build
```

Тесты Node проверяют реальные трансформации сортировки/поиска/пагинации и контракт Admin API. Браузерное E2E, публикация реального пакета и матрица ролевых доступов на запущенном Backend требуют отдельного integration/CI окружения; отсутствие этих прогонов не является сертификацией GA.

## Границы версии

0.21.6 предоставляет Admin Foundation. Она не вводит единый реестр операций, durable jobs для всех действий, сохраняемый Release Wizard, контролируемый config editor или полный ServerBridge control — это задачи следующих этапов 0.22.0. Встроенная серверная авторизация, подписи и протокол ServerBridge при обновлении панели не меняются.
