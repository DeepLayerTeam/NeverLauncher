# Пользователи, роли и сессии

Launcher содержит административные операции для аккаунтов, ролей, сессий, отзыва доступов и политик паролей. Актуальные параметры запросов, обязательность прав и модели DTO определяются [OpenAPI](../../schemas/openapi.yaml) и обработчиками `services/api/internal/httpapi/`.

## Типовой процесс

1. Инициализируйте первого администратора **после** установки backend согласно разделу `install`.
2. Создавайте учётные записи и роли по принципу минимальных привилегий.
3. Настройте MFA/WebAuthn там, где это поддерживает deployment и фактический домен RP.
4. Проводите регулярный аудит активных сессий, доступов ServerBridge и расширений.
5. При компрометации отменяйте сессии/refresh tokens и ротируйте секреты, не полагаясь только на смену пароля.

CLI содержит `nl auth accounts|roles|sessions|revoke|logout-all|session-policy|password-policy`, а также `nl admin users|roles|audit|create-user`. Для закрытых операций требуется соответствующий токен и права.

## Важное

Не используйте фиксированные демонстрационные пароли в production. Никогда не помещайте access/refresh токены в issue, screenshots или артефакты CI. Для интеграции внешних провайдеров см. [../authentication/providers.md](../authentication/providers.md).
