# Launcher 0.21.10 — повседневный жизненный цикл

Admin 0.21.10 связывает существующие действия Backend с интерактивными сценариями работы. Эта версия не изменяет ServerBridge v3 и не ослабляет серверную авторизацию.

## Задания

- `/api/v1/operations/jobs?projectId=...&limit=25&offset=0&status=...` возвращает задания проекта только после новой проверки разрешения `project:read`. Пользователь с одной лишь глобальной аутентификацией не может просматривать задания других проектов.
- Состояния и история попыток берутся из сохранённых устойчивых заданий. За запрос выдаётся не более 100 записей (`offset` максимум 10 000); токен аренды исполнителя, исходные данные задания и ключ идемпотентности не раскрываются.
- Отмена доступна только для заданий `pending`. Повторный запуск доступен только для `failed`, `dead` или `revoked` и требует серверной авторизации и MFA. Работающие и успешно завершённые задания повторить из этого представления нельзя.
- Ссылки на задания сохраняются в виде `#/job-monitor?job=<ID>`. Перезапуск браузера не отменяет серверное задание. Ссылки на аудит выполняют поиск по идентификатору корреляции или задания.

## Резервное копирование и восстановление

- `GET /api/v1/operations/backup/status` перечисляет архивы. `POST /api/v1/operations/backups` создаёт настоящую резервную копию PostgreSQL и настроенного хранилища.
- `GET /api/v1/operations/backups/{id}` возвращает неизменяемые метаданные архива. `POST /api/v1/operations/backups/{id}/restore-dry-run` проверяет хеш и входные данные восстановления.
- Для восстановления в интерфейсе одновременно требуются разрешения `storage:manage` и `settings:manage`, новое устойчивое к фишингу дополнительное подтверждение на сервере, успешный пробный прогон в том же сценарии интерфейса, явный выбор компонентов, точный ввод идентификатора резервной копии и подтверждение. Backend предварительно создаёт страховочную резервную копию.
- **Важно:** действующий маршрут API восстановления синхронный, а не устойчивое задание. При обрыве соединения с браузером не повторяйте восстановление автоматически. Проверьте аудит и фактическое состояние хранилища и БД. Если ошибка произошла после создания страховочного архива, сохраните его идентификатор для восстановления. Браузер не может гарантировать атомарный откат одновременно PostgreSQL и локального хранилища.

## Сеансы и устройства

- Каждый авторизованный пользователь может просматривать, переименовывать и отзывать **свои** сеансы. Отзыв текущего сеанса завершает работу в Admin.
- Пользователи с `users:manage` дополнительно видят записи доверенных устройств. Отзыв устройства необратим, требует непустого обоснования, явного подтверждения и устойчивой к фишингу дополнительной проверки Backend. Сервер аннулирует связанные сеансы и запросы подтверждения, а интерфейс показывает фактические счётчики из ответа.
- Backend проверяет права чтения при каждом запросе. Скрытие действия в интерфейсе не является защитной границей.

## Расширения

- Подписание реестра, установка, управление жизненным циклом хоста, включение/отключение, обновление, откат и удаление используют существующие рабочие маршруты Backend.
- Изменяющие операции показывают точное расширение, версию и область действия, а также требуют подтверждения. Ответы операций сохраняются в интерфейсе; обновлённый менеджер отображает фактическое состояние. При ошибке выводятся сведения о необходимости повторной аутентификации, разрешениях, перезагрузке и ссылка на аудит. Ошибка транспорта не доказывает, что побочных эффектов не было.
- Существующий изолированный интерфейс расширений и средства контроля разрешений RPC не изменяются.

## Требования испытаний для утверждения промышленного выпуска

Запустите полный набор тестов Go с установленными зависимостями, `npm ci && npm run build` в `apps/admin`, затем авторизованные браузерные E2E-тесты с PostgreSQL. Проверьте отказ пользователю без владения проектом при чтении чужих заданий, ошибку пробного восстановления архива, истечение времени дополнительного подтверждения, потерю HTTP-ответа во время восстановления, отзыв сеанса, откат обновления расширения, повторные и отменённые устойчивые задания.
