# Launcher 0.52.6 — модпаки, текстуры и публикация игры

## Рабочие сценарии

1. Endpoint Backend `/api/v1/packages/{id}/validate` до возврата `valid` проверяет хеши загруженного содержимого **и** полный кандидатный манифест вместе с подписанной топологией компонентов. `/sign` выполняет те же проверки кандидата. Некорректные связи необязательных компонентов отклоняются до подготовки и публикации.
2. Команды нативного Runtime `verify`, `sync` и `sync-local` требуют правильного содержимого **всех файлов, выбранных пресетом**, включая необязательные файлы схемы v2. Компоненты, исключённые подписанным каталогом, пропускаются; пользовательский `options.txt` остаётся неизменным. `sync-local` восстанавливает удалённый выбранный JAR по его подписанному адресу загрузки.
3. Исполняемый операторский скрипт с изменением данных `scripts/acceptance/modpacks_textures_publication_0526.py` выполняет настоящие проверку черновика, подписание, подготовку, контроль целостности и публикацию, проверяет общедоступный подписанный манифест, загружает и читает обратно скины и плащи, запускает нативные синхронизацию и проверку для двух пресетов, удаляет и восстанавливает настоящий JAR мода, затем проверяет фактическое подключение JVM-клиента к соответствующему серверу Minecraft. Серверный журнал, список игроков RCON и игровые такты должны согласовываться. Проверяются настоящее `save-all flush` мира, остановка сервера и код завершения.

## Обязательная выделенная среда реальных испытаний

Подготовьте одноразовые проект, профиль и канал, загруженный черновик **манифеста v3 с каталогом компонентов v5**, настоящий необязательный JAR и два детерминированных пресета каталога, один из которых включает, а другой исключает компонент. Существующие требования к подтверждениям работы Runtime могут блокировать публикацию; исполнитель **не подделывает и не обходит** такие проверки. Требуются Bearer-токен администратора с недавним подтверждением MFA в закрытом файле `0600`, отдельные данные локального игрока Minecraft в JSON-файле `0600` (`origin`, `playerEmail`, `playerPassword`), настоящие PNG скина и плаща, закреплённые исполняемые файлы и хеши релизного Runtime/CLI, корректно установленная Java и независимо закреплённый открытый ключ Ed25519 для манифеста. Для модифицированных серверов предоставьте утверждённый оператором полный серверный архив и SHA-256 вместе с точкой входа; запуск произвольного непроверенного JAR запрещён. Используйте изолированный Linux-исполнитель с графическими возможностями или поддержкой headless-игры и выделенный мир. Скрипт изменяет проект, публикует его и подключается к нему.

Настройте защищённое окружение GitHub `modpacks-textures-physical-acceptance` и переменные `NL_0526_*` из `.github/workflows/modpacks-textures-publication-0526.yml` для всех обязательных внешних данных. Запускайте вручную из основной ветки. Файлы секретов нужно заранее разместить на физическом исполнителе (не добавлять в Git). Примечание: вывод скрипта содержит только статус, хеши файлов и несекретные идентификаторы; подтверждение с режимом `0600` всё равно храните закрыто, поскольку оно идентифицирует окружение.

## Условия допуска и ограничения

Отсутствующий закреплённый исполняемый файл, повреждённый PNG, отсутствующий мод, неверный хеш, несогласованный подписанный манифест, ошибка контрольного чтения хранилища, незавершённая публикация, неизвестный внешний сервер, неудачное настоящее подключение к Minecraft либо неверный RCON/код завершения **блокируют PASS**. Успешные локальные тесты Python/Go/Rust доказывают только заявленные инварианты и не являются внешним GA. Проверка соответствующего loopback-сервера в автономном режиме не подтверждает права Microsoft/Minecraft; загрузка и чтение изображения сами по себе не доказывают его отображения в игре. Для полной независимой приёмки по-прежнему нужны настоящий скриншот/наблюдение игрового скина и плаща, а также авторизованное подключение в сетевом режиме. Отчёт оператора сохраняет `gaCertified:false`, даже если этот локальный сценарий прошёл.
