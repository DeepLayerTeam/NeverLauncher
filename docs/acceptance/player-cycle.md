# 0.39.8 — реальная игровая регрессия и подтверждение результатов

Этот этап **не подменяет** исполнение Minecraft-клиента Python-проверкой протокола. Производственный сценарий запускается через `e2e/scripts/run-minecraft-e2e.sh` в `full` и, кроме существующих запуска JVM, ServerBridge, обновления/отката, проверяет 7 дополнительных **реальных** отказов при проверке подписанного запроса узла в живом Backend/PostgreSQL:

- неверный UUID, невалидный UUID;
- чужой проект, профиль, канал, сервер;
- игрок, которому не был выдан билет.

Каждый запрос подписывается тестовым ключом зарегистрированного Paper-узла, исполняется на реальном Backend и требует `HTTP 403` с конкретной причиной. После всех отказов тот же действительный билет должен успешно погаситься, его повторное погашение — получить отказ. В базовом E2E также остаются запуск действительного Minecraft Java-клиента, вход на Paper, отказ после отзыва сессии и реальное обновление и откат с двумя независимыми входами JVM. Для официального online-mode дополнительно запрещено подтверждение соединения без наблюдаемого UUID; локальная проверка перед входом и доверенная передача сеанса через прокси сохраняют свои отдельные правила.

Результаты проверяются **после запуска**, не на основании написанного вручную `status=passed`:

```bash
bash e2e/scripts/run-minecraft-e2e.sh
python3 scripts/ga/verify_player_cycle.py \
  --e2e-dir e2e/runtime --version "$(cat VERSION)" \
  --source-commit "$(git rev-parse HEAD)"
```

В CI валидатор является обязательной ступенью `production-e2e`; кандидат промышленного релиза повторяет проверку скачанных артефактов от того же SHA исходного кода, идентификатора запуска и номера попытки. Валидатор сверяет настоящие запросы/ответы, HTTP-коды, UUID и целостность данных, и вызывает независимый `verify_game_cycle.py`, проверяющий бинарники, подписи манифестов, счетчики входов и реальные игровые логи. Отсутствующие или искажённые результаты завершаются с кодом выхода 2. Модульные тесты Python проверяют **только** отказоустойчивость валидатора и не являются доказательством успешного игрового запуска.

CI отдельно запускает существующие регрессии Desktop на компоненты, официальную авторизацию, текстуры, выбор аккаунта, серверный UUID, смену сборки и режимы запуска. Это тесты логики, не доказательство работы Microsoft Services или фактического отображения текстур.

**Граница подтверждения:** локальный игровой E2E подтверждает Yggdrasil/ServerBridge/Paper и жизненный цикл сборки. Официальный вход Microsoft/Xbox/Minecraft, `hasJoined` на online-mode сервере, текстуры и произвольные наборы модов требуют самостоятельной сквозной проверки на реальном оборудованном стенде и не могут быть признаны пройденными по данному локальному результату. Действующий отдельный проверка готовности официального входа к общедоступному выпуску не отключается и не заменяется этим отчётом. До получения этих результатов полный игровой цикл и готовность к общедоступному выпуску остаётся непроверенным.
