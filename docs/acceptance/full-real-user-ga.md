# Launcher 0.53.0 — полная приёмка GA с участием реальных пользователей

В этом выпуске изменён **действующий** механизм допуска релиза. Это не означает, что внешние испытания уже завершены. Пока защищённый процесс не выполнен на фактическом подписанном релизе, решение о выпуске 0.53.0 GA остаётся **ЗАБЛОКИРОВАННЫМ**.

## Обязательная независимая приёмка

Существующий `defect_rehearsal_05212.py` теперь привязан к текущей версии. Для 0.53.0 он фиксирует точное чистое состояние исходников Git и шесть окончательных установщиков, проверяет отдельно закреплённый индекс дистрибутива и отделённые подписи Linux, повторно выполняет регрессионные проверки, принимает только независимо подписанную полную выгрузку закрытых дефектов P0/P1 и воспроизводит все **исходные** подтверждения: 280 обязательных комбинаций Minecraft/JVM/загрузчика с реальным подключением, шесть установок конечных нативных пакетов, шесть нативных запусков игры, пять часовых игровых испытаний Minecraft, часовой журнал HTTP-нагрузки и две отдельно подписанные независимые сборки без подписи для шести платформ. Отсутствие исходных данных или любая ошибка означает блокировку; проверку нельзя пропускать автоматически.

`full_real_acceptance_0530.py` **дополнительно запускает** эти реальные наборы испытаний в независимой физической и игровой QA-лаборатории. Он не запускает произвольные пользовательские программы или `sh -c`, не принимает `--help` за успешную проверку и не считает отчёт `status: passed` подтверждением выполнения без завершённого дочернего процесса и хешированных журналов. Все результаты и ограниченные по размеру исходные журналы процессов сохраняются закрыто. Независимая проверка подтверждает исходники, конечные пакеты, полномочия реестра дефектов, полный набор испытаний, исходные журналы и строго определённые условия успеха для каждого сценария.

## Безопасная передача в лабораторию и происхождение доказательств

Защищённый процесс `.github/workflows/full-real-ga-0530.yml` использует три независимые роли машин и отдельную обычную задачу регрессионных проверок. Машина фиксации релиза получает шесть исходных конечных установщиков и независимо утверждённый хеш индекса. Фиксировать разрешено только чистую рабочую копию Git с точно утверждённым коммитом. Выгрузка дефектов поступает из действующей системы отслеживания задач и подписывается **другим** доверенным ключом Ed25519. Пустые или сфабрикованные выгрузки не подтверждают закрытие дефектов: организация должна ограничить право подписи проверяемой полной выгрузкой из авторитетного реестра.

На независимой QA-машине подготовьте:

- `packages/` и `source-index.json` из настоящего дистрибутива, а не собранные заново на QA; `issues.json`/`issues.sig`, `full-sweep-paths.json` (как в инструкции 0.52.12) и закрытый `live-plan.json` во входящем каталоге QA.
- `live-plan.json` — закрытый JSON с режимом `0600`, содержащий **ровно** поля `version`, `sourceCommit`, `sourceIndexSha256` и `scenarios`. Объект `scenarios` содержит 14 строго определённых ключей: `minimal`, `standard`, `auth`, `modpacks`, `install`, `java`, `guard`, `sdk`, `ha-host`, `ha-partition`, `ha-postgresql`, `ha-redis`, `ha-s3`, `ha-world`. Значение каждого — массив строк аргументов настоящей вызываемой программы **без** имени самой программы и без `--report`/`--output` (каталоги результатов создаёт исполнитель GA). Для `auth` первым аргументом укажите `run`, для `java`/`guard` — `live`; для HA используйте режим, предписанный исполнителем. Проверяйте действительные аргументы оператора через `--help` соответствующего исполняемого файла. Подставлять отчёты-заглушки или имитируемые конечные точки нельзя.
- Физические цели HA должны быть выделенными одноразовыми узлами с отдельным управлением BMC, рабочим маршрутом восстановления, действующей доставкой Alertmanager и настоящим изолированным миром Minecraft. Оператор явно разрешает периоды недоступности. Незавершённое восстановление или отсутствие реального игрока Minecraft блокирует GA.
- Подтверждение авторизации официального OIDC истекает через 600 секунд. Создавайте его на настоящем поставщике непосредственно перед фактическим вызовом `auth`; нельзя обходить срок действия или заранее создавать фиктивный успешный результат. На этапе проверки допустим защищённый интерактивный процесс оператора.
- Исполнитель SDK требует закреплённый действующий HTTPS Backend с закрытым Bearer-токеном в файле с режимом `0600`, конечные точки JSON, простого текста и двоичных данных (PNG или ZIP), а также **независимо полученный** SHA-256 двоичного ответа. Он запускает промышленные Go/TS/Java-клиенты; одних локальных модульных тестов SDK на имитациях недостаточно.

Закрытые исходные журналы, резервные копии миров, учётные данные, нативные подтверждения и план лаборатории передавайте **независимому аудитору** по защищённому внешнему каналу. Никогда не включайте закрытые ключи, токены Microsoft, коды авторизации OIDC, учётные данные RCON, секреты игровых идентичностей и данные миров в публичные артефакты GitHub. В публичных артефактах оставляйте лишь не содержащие секретов подписанные решения. QA и аудитор должны использовать разные ключи Ed25519; ни один из них не должен совпадать с ключом релиза или выгрузки дефектов. Закреплённые доверенные ключи задаются независимо от проверяемых файлов.

## Решение о выпуске и публикация

Команда `full_real_acceptance_0530.py review` запускает реальные наборы испытаний и подписывает `qa.json`/`qa.sig` ключом QA. Независимый аудитор вызывает `approve` для **исходных переданных доказательств**, повторно выполняет все закреплённые регрессионные проверки и проверки исходных данных по 280 комбинациям, нативным пакетам, длительным испытаниям и сборкам, проверяет неизменность журналов и результатов каждого сценария и подписывает `approval.json`/`approval.sig`. Только итоговый независимый отчёт может содержать `status: PASS`; один лишь результат QA **не означает GA**. Команда `release-gate` повторно проверяет обоих подписантов и исходные данные, прежде чем завершиться с кодом 0.

Существующий промышленный издатель (`scripts/release/publish_0370.py`) теперь **отказывается публиковать версию 0.53.0**, если в защищённом окружении нет независимо подписанного одобрения и шести исходных утверждённых пакетов. `publication_ga_0530.py` проверяет отдельно закреплённый ключ аудитора, исходный коммит, все 18 групп, независимый хеш индекса и то, что **фактический архив выпуска** содержит побайтно идентичные утверждённым установщики. Любая ошибка останавливает процесс **до** сетевой записи в GitHub. Сохраняются требования к подписанному `SHA256SUMS`, `RELEASE_MANIFEST.json` и остальные ранее действовавшие условия публикации. **Если текущий сборщик подписанного релизного архива не включает шесть точно определённых файлов, публикация 0.53.0 остаётся заблокированной:** нельзя пересобирать или подменять артефакты и ослаблять проверку ради успешного CI.

Исходный ZIP не содержит истории Git или внешних подтверждений. Проверки исходников не заменяют физическую приёмку и не разрешают настоящий выпуск GA.
