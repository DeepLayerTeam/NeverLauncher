# Launcher 0.52.8 — приёмка Java, SDK и миграции

## Рабочий код и локальная проверка

Запускайте на Linux с JDK 21, Go 1.23+, Node 22 и `tsc` 5.8.3:

```sh
umask 077
python3 scripts/acceptance/java_sdk_migration_0528.py local \
  --report /absolute/private-dir/0528-local.json
```

Исполняемый локальный набор собирает настоящий JAR с пятью перенесёнными расширениями Gravit и доверенный агент JVM, запускает отдельный JVM Host и преобразование игрового класса, проверяет отказ при несовпадении хеша агента, затем тестирует HTTP SDK для Go, Java и TypeScript на настоящих локальных HTTP-серверах. Также выполняются существующие отрицательные регрессионные тесты миграции и проверки трёх проектов Gravit и новые отрицательные проверки 0.52.8. Существующий локальный тест Java Host использует имитацию Go Broker и синтетический класс `net.minecraft`: **успех локального теста не подтверждает работу установленной промышленной системы**.

Новые методы Java REST SDK `requestStream`/`callStream` передают большие двоичные данные непосредственно в переданный оператором `OutputStream` (жёсткий предел 1 ГиБ, ограничения каждого вызова, запрет перенаправлений и ограниченный размер тела ошибки). При ошибке вызывающая сторона обязана удалить частично записанный результат. Методы Go `CallStream` и TypeScript `responseType: 'stream'` также тестируются без выделения памяти размером с ответ.

Настоящая репетиция Gravit усиливает контроль SHA-256 чтения исходных ZIP, сопоставлений, плана пробного прогона, изменяемых подготовленных подтверждений и исполняемых проб, защищая от подмены файлов и ссылок. Это работающая защита исходных данных на пути миграции трёх проектов, а не ещё один манифест или метка совместимости.

## Установленный Java Host и настоящие подтверждения Minecraft

Используйте выделенный изолированный проект с настоящим HTTPS Backend 0.52.8, развёрнутыми хостом Java-расширений и брокером Go, краткоживущим токеном администратора проекта, тестовым игроком и ранее загруженными миграционными идентичностями/библиотеками. Подготовьте закрытую конфигурацию `0600` (`launcher.java-host-live-0528/v1`) с ключами:

- `format`, `isolatedProject: true`, `sourceCommit` (40 строчных шестнадцатеричных символов), `backendUrl`, `hostUrl`, `projectId`, `profileId`, `loaderVersion`, `testIdentifier`, `testUuid`.
- `libraryFile`, `librarySha256`, `libraryPath` (реальный файл в `libraries/`, `mods/` или `optional/`, сохранённый и доступный Broker, в пределах лимита актива Java Host SPI 512 КиБ), `extensionJar`, `extensionJarSha256`.
- `agentArtifact`, `agentSha256`, `gameCompatibilityResult` (абсолютный путь к существующему `compatibility-result.json` настоящего нативного запуска Minecraft 0.52.4), `gameTargetId`, `ciRunId`, `ciRunAttempt`.

Передавайте секреты **только через переменные окружения** `NL0528_JAVA_HOST_TOKEN`, `NL0528_OWNER_TOKEN`, `NL0528_TEST_PASSWORD`. Исполняемый сценарий проверяет настоящий пароль и UUID, находит и подготавливает действительную библиотеку содержимого, пытается прочитать запрещённый файл другого проекта, выполняет обратный вызов JVM `profile.before-save` со сценариями разрешения/запрета, затем отправляет реальный PATCH профиля Admin в Go Backend. Он проверяет успешную запись и то, что запрещённая запись не изменила состояние. К изолированному проекту применяется действительный обратный вызов установленного расширения `state.migrate`. Это разрушающая приёмка на тестовом стенде: **никогда не применяйте её к промышленному миру владельца**.

На игровом этапе `inventory_0521.verify_compatibility` повторно анализирует исходный результат совместимости и журналы подключения к серверу, RCON и JVM, сверяя SHA-256. Обычное подключение лаунчера не доказывает работу агента: точное значение `trustedAgentSha256` должно присутствовать в ранее проверенном (сверенном по хешу) `*-certification.json` и совпадать с установленным доверенным агентом. Если нативный клиентский процесс не предоставляет такое независимое наблюдение, этап остаётся **BLOCKED**; произвольное поле `agentHash` в новом отчёте не может давать PASS. Подписанная политика Guard и список разрешённых Java-агентов по-прежнему требуют отдельной приёмки 0.52.9.

## Три разных реально работающих проекта Gravit

Используйте существующий `tools/gravit-port/ga_acceptance_0500.py`, который обязан повторно запрашивать работающий Backend с PostgreSQL и подтверждать 36 отдельно подписанных реальных проверок трёх разных проектов: `fileauth-single`, `sql-modded`, `proxy-network`. Он также выполняет 19 поведенческих проверок модулей с закреплёнными хешами и повторно проверяет настоящее доверие после этих испытаний; каждое подтверждение, исходный ZIP, подписанное обновление и наблюдение Minecraft должны соответствовать точному запуску и проекту. Настройте исходную закрытую конфигурацию `launcher/gravit-acceptance-0500/v1` и **пустой независимый каталог `0700`** для доказательств. Новый исполнитель 0.52.8 вызывает инструмент напрямую; подтверждения всё равно требуют независимого рассмотрения, а `productionGA` остаётся false.

## Миграции исторических версий Launcher

Запускайте `legacy_upgrade_real_0528.py capture` для каждого **действительно работающего исходного** развёртывания 0.36.0 и 0.46.0 до остановки записывающих процессов. Закрытый JSON `0600` имеет вид:

```json
{
  "format": "launcher.legacy-live-upgrade-0528/v1",
  "sourceVersion": "0.36.0",
  "baseUrl": "https://original-isolated-host.example",
  "ownerCredentials": "/absolute/private/owner.json",
  "projectId": "real-project", "profileId": "real-profile", "channelId": "stable",
  "sourceFiles": {"core_db": "/absolute/original/source.sqlite"},
  "storageRoot": "/absolute/original/objects",
  "targetStorageRoot": "/absolute/new/objects"
}
```

Сбор данных выполняет **настоящую HTTP-авторизацию владельца**, считывает исходные проект, профиль, канал и канонический UUID владельца, вычисляет хеши дисковых исходников и игрового хранилища. Пароли и Bearer-токены не сохраняются. Остановите конкурирующие процессы записи и используйте действительно поддерживаемую процедуру миграции/переключения. Скрипт **не притворяется инструментом переноса данных**. После запуска мигрированного Backend 0.52.8 вызовите `verify` с исходной неизменяемой записью: скрипт повторно входит и сравнивает владельца, проект, профиль, канал, дисковые исходники, первоначальные неизменяемые данные и хеши нового хранилища. Любое расхождение, отсутствие старого API, неподдерживаемый исторический исходный формат либо конкурирующий писатель означает **BLOCKED**. Поддержка исторического пути 0.36.0 не объявляется автоматически лишь потому, что скрипт может его запросить: путь должен работать на настоящей исторической установке.

Для обоих путей:

```sh
python3 scripts/acceptance/legacy_upgrade_real_0528.py capture \
  --config /absolute/private/legacy-original.json --output /absolute/private/original-capture.json
# Оператор останавливает запись, выполняет реальное переключение и обновляет baseUrl в ЗАКРЫТОЙ конфигурации на мигрированный сервер
python3 scripts/acceptance/legacy_upgrade_real_0528.py verify \
  --config /absolute/private/legacy-migrated.json \
  --source-capture /absolute/private/original-capture.json \
  --output /absolute/private/live-verify.json
```

## Сводная внешняя приёмка

Защищённый процесс `.github/workflows/java-sdk-migration-real-0528.yml` содержит обычную локальную задачу регрессий CI и ручную задачу реальных испытаний в изолированном окружении. Для последней нужен **закрытый файл конфигурации `0600`** `launcher.java-sdk-migration-0528/v1`:

```json
{
  "format": "launcher.java-sdk-migration-0528/v1",
  "sourceCommit": "0123456789abcdef0123456789abcdef01234567",
  "java": {"config": "/absolute/private/java.json", "output": "/absolute/private/java-result.json"},
  "gravit": {"config": "/absolute/private/gravit.json", "evidenceDir": "/absolute/private/empty-0700"},
  "legacy": [
    {"sourceVersion":"0.36.0", "config":"/absolute/private/legacy-036.json", "capture":"/absolute/private/legacy-036-capture.json", "output":"/absolute/private/legacy-036-verify.json"},
    {"sourceVersion":"0.46.0", "config":"/absolute/private/legacy-046.json", "capture":"/absolute/private/legacy-046-capture.json", "output":"/absolute/private/legacy-046-verify.json"}
  ]
}
```

Запустите `python3 scripts/acceptance/java_sdk_migration_0528.py live --config /absolute/private/composite.json --report /absolute/private/final-0528.json`. Инструмент завершится ошибкой, если **любой** путь Java, Gravit или исторической миграции не имеет реальных доказательств, если изменился исполняемый файл инструмента или исходный файл, если проекты используют один исходник либо если коммиты Git различаются. Закрытый результат записывается только после успешного исполнения; статус — `LIVE_CHECKS_PASSED_REVIEW_REQUIRED`, а не `GA`. Для 0.53.0 по-прежнему требуются независимая проверка конечных подписанных пакетов, выполнение на Windows/macOS, откаты PostgreSQL и проверка аккаунтов/Minecraft.
