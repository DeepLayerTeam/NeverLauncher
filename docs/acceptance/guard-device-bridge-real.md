# Launcher 0.52.9 — Guard / доверие к устройству / ServerBridge

## Фактически выполняемые проверки

`guard_shadow_05012.go` в API теперь записывает действительную `Server.Version` запущенного сервера вместо устаревшей `0.50.12`. Настоящий журнал, создаваемый Go и связанный цепочкой HMAC, читается скриптом `adversarial_pilot_05012.py`: изменение или повторное воспроизведение делают его недействительным. Имена игроков и токены сеансов не записываются. Одна некорректная версия либо повторно использованный журнал от другого выпуска приводят к отказу. Существующие проверки подписанной и отозванной привязки Guard не обходятся.

Промышленный sidecar Vanilla теперь **обязан получить один успешный подписанный сигнал активности Backend до публикации `server.ready`**. `scripts/acceptance/vanilla_sidecar_live_0529.py` активно подключается к **работающему** выделенному серверу Minecraft 1.21.1 по локальному статусному сокету и RCON, проверяет настоящий PID JVM sidecar и точный хеш JAR, анализирует исходные журналы Vanilla и измеряет продвижение игровых тактов. Пароль RCON читается **только** из `LAUNCHER_VANILLA_RCON_PASSWORD` и никогда не попадает в результат. Запускайте на узле Linux с `/proc`, предварительно развёрнутым подписанным промышленным sidecar и закрытым портом RCON. Автономный Java-симулятор не принимается за реальный сервер.

У 14 идентификаторов целевых платформ разные заявленные возможности:

- **10 сквозных проверок среды выполнения:** Velocity, BungeeCord, Waterfall, Spigot, Paper, Purpur, Folia, Fabric, Forge, NeoForge. `serverbridge/live_matrix_04113.py` повторно проверяет оригинальный процесс Docker каждого сервера, точный развёрнутый JAR, подписанный сигнал активности, действительное разрешение и последующий отзыв сетевого доступа, серверные журналы и подключение клиента Paper.
- **Три цели совместимости сборки:** Bukkit, Quilt, Sponge. Производственные JAR проверяет `serverbridge/certify_release.py` (набор из 14 JAR и исполняемый механизм проверки возможностей адаптеров). **Это не означает сертификацию реального исполнения этих трёх целей.** Для заявления «14/14 работают вживую» нужны нативные сквозные свидетельства работы исходных проектов Bukkit/Quilt/Sponge; этот этап не утверждает, что они получены.
- **Один вспомогательный процесс с RCON и E2E:** Vanilla с настоящим статусным сокетом, авторизованным RCON, процессом Java, стартовым рукопожатием и работающим сервером с игровыми тактами.

Для Device Trust аудитор использует и повторно проверяет **все семь исходных результатов по целевым платформам** из существующей матрицы, а также вычисляет хеши настоящих файлов доказательств. JSON со статусом PASS без исходных журналов не проходит. Нативный или headless CI не доказывает аппаратную защищённость хранилища. Guard дополнительно требует исходные пакеты и исполняемые файлы всех трёх целей CI, шесть отдельных записей нативных атакующих испытаний JVM, защищённые теневые серверные журналы HMAC, независимо рассмотренные отзывы, доказательства настоящего авторизованного подключения к Minecraft и фактически сопоставленные измерения длительности кадров. Ложное срабатывание, неопределённый или нерассмотренный отзыв блокирует реальную приёмку. Предлагаемая выборка теневого наблюдения в 10 000 часов игры добросовестных игроков требует **независимой проверки**, а не одних временных меток в журнале.

## Локальный запуск

```bash
python3 -m unittest discover -s scripts/acceptance -p 'test_guard_device_bridge_real_0529.py' -v
python3 -m unittest discover -s scripts/acceptance -p 'test_guard_shadow_crosslang_0529.py' -v
bash e2e/scripts/run-serverbridge-adapter-capabilities-0286.sh
python3 scripts/guard_ci/test_adversarial_pilot_05012.py
python3 scripts/acceptance/guard_device_bridge_real_0529.py local \
  --only-suite loader-transformations --output /absolute/private/0529-loader-only.json
```

Режим `local` с `--only-suite` намеренно возвращает `LOCAL_PARTIAL_JVM_REGRESSIONS_NOT_GA`. Для всех четырёх локально выполняемых наборов проверок процессов Guard запускайте без `--only-suite` на подходящем нативном узле Linux с JDK 21. Это реальные тесты дочерних Java-процессов, **а не официальный игровой процесс Minecraft или сертификация физических платформ и подписей**. Регрессии с имитируемыми RCON-серверами проверяют только враждебные входные данные.

## Внешние реальные испытания

Запустите существующие физические процессы CI и кандидатов с нативными подписями. Сохраните **исходные** семь результатов Device Trust с журналами, три результата Guard CI **вместе с исполняемыми файлами и пакетами**, шесть нативных отчётов испытаний JVM с журналами, данные игровых сеансов и исходное дерево runtime ServerBridge с десятью реальными процессами Docker. Соберите 14 настоящих промышленных JAR ServerBridge через релизный конвейер проекта и проверьте каждый SHA-256. Подготовьте реально запущенный Vanilla-сервер и подписанный sidecar, как описано выше. Настройте закрытый серверный теневой журнал **до** игровых сеансов, храните его ключ HMAC с правами `0600` вне результатов, получите независимые заключения по инцидентам, сопоставленные измерения длительности кадров и данные о реальных разрешённых подключениях игроков.

На выделенной машине создайте JSON с режимом `0600` по пути `/etc/launcher/acceptance/guard-device-bridge-0529.json`. Он должен содержать ровно поля `sourceCommit`, `runId`, `repository`, `deviceResults`, `guardResults`, `guardJvmResults`, `guardShadowDir`, `guardShadowKeyFile`, `guardIncidentReviews`, `frameBaseline`, `frameGuard`, `gameRuntime`, `gameServerLog`, `player`, `serverbridgeRuntime` и `vanilla`. Все пути должны быть абсолютными. Объект `vanilla` содержит ровно `sidecarPid`, `sidecarJar`, `sidecarSha256`, `sidecarLog`, `serverLog`, `serverDir`, `minecraftPort`, `rconPort`, `minecraftVersion`. Пароли и токены доступа в JSON не включаются.

```bash
export LAUNCHER_VANILLA_RCON_PASSWORD="$(cat /secure/rcon-password)"
umask 077
python3 scripts/acceptance/guard_device_bridge_real_0529.py live \
  --config /etc/launcher/acceptance/guard-device-bridge-0529.json \
  --output /absolute/new-private/guard-device-bridge-result.json
```

Скрипт не имитирует отсутствующие машины, не придумывает отчёты о статусе и не ослабляет ни одной обязательной проверки. Он выдаёт `LIVE_CHECKS_PASSED_REVIEW_REQUIRED` **только после успешной проверки исходных доказательств и активного Vanilla-сервера**. Это ещё не промышленный GA: проверка шести подписанных конечных пакетов, независимые доказательства настоящего аппаратного защищённого хранения, независимое рассмотрение часов игры/ложных срабатываний и обязательные реальные запуски исходных проектов Bukkit/Quilt/Sponge остаются отдельными условиями. Никогда не публикуйте пароли RCON, неочищенные данные игроков, теневые ключи HMAC и исходные журналы как публичные артефакты CI.

## Ограничения текущей среды разработки

Здесь можно выполнить локальные тесты журнала на стандартной библиотеке Go и проверку аутентифицированной цепочки Go → Python, Java-механизм проверки возможностей и отрицательные проверки сокетов. Это не доказывает аппаратные возможности Guard, частоту ложных срабатываний в игре, совместимость с реально запущенными Minecraft-адаптерами, аппаратную защиту ключей Device Trust, подписание или нативную установку на шести платформах. Любые недостающие внешние предварительные условия получают статус `BLOCKED`, а не `PASS`.
