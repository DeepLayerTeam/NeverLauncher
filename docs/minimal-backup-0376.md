# NeverLauncher 0.37.6 — минимальное развёртывание: согласованный backup/restore

Это рабочий офлайн-инструмент резервного копирования Linux single-node, **не онлайн-backup**. Для общей точки согласованности SQLite, конфигурации и файлов требуется остановить API и все процессы, которые могут изменять `storage`, `extensions` или `factory` (включая внешние расширения и задачи). API и SQLite должны находиться на локальной файловой системе, поддерживающей flock. Нельзя использовать это средство как механизм горячего резервирования или HA.

## Резервирование

```bash
# 1. Остановить службу API и зависимые процессы (systemctl stop ...).
python3 scripts/install/minimal-install.py backup --root /var/lib/neverlauncher
# При необходимости сохранить сразу в отдельном приватном каталоге:
python3 scripts/install/minimal-install.py backup --root /var/lib/neverlauncher \
  --destination /private/offsite/minimal-2026-10-29
```

Операция требует закрытых SQLite-хранилищ: под неблокирующими flock API/HTTP/coordinator производится SQLite backup API двух основных баз и всех дополнительных локальных SQLite-файлов, включая зафиксированные WAL-транзакции, затем файловый снимок. Создаётся приватный каталог `backups/minimal-.../` с `payload/` и `manifest.json`. Не копируются исходные WAL/SHM/journal, lock-файлы и сам каталог backups. Все остальные объекты под корнем установки перечисляются без молчаливого пропуска; символические ссылки, hardlink-файлы, небезопасные пути и необычные типы объектов запрещены.

Файлы синхронизируются с диском, сверяются SHA-256, а обе БД проходят `PRAGMA integrity_check` и `PRAGMA foreign_key_check`. Неполный снимок остаётся скрытым во временном каталоге и удаляется при ошибке. **Сторонние writers, игнорирующие блокировки и работающие после остановки API, могут нарушить согласованность**; перед backup необходимо остановить и их. Рекомендуется выполнить резервную копию на выделенном обслуживаемом хосте.

## Проверка и восстановление

```bash
python3 scripts/install/minimal-install.py backup-verify \
  --bundle /var/lib/neverlauncher/backups/minimal-YYYYMMDDTHHMMSSZ-XXXXXXXXXXXX

# Копию предварительно разместить за пределами повреждённой установки.
# Восстановление доступно только в отсутствующий каталог — действующие данные не затираются.
python3 scripts/install/minimal-install.py restore \
  --bundle /private/offsite/minimal-2026-10-29 \
  --target-root /var/lib/neverlauncher
```

Проверка проверяет точное совпадение файлов и каталогов с индексом, хеши и целостность SQLite до первой записи целевого каталога. Восстановление создаётся в закрытой временной папке, переписывает только известные абсолютные пути установки в `backend.env`, синхронизирует файлы и атомарно переименовывает каталог. **Уже существующая установка не перезаписывается.** При пересоздании хоста должны быть заново установлены и проверены бинарники API/CLI, системная служба, обратный HTTPS-прокси и внешние файлы/ключи, не лежавшие в корне minimal; восстановление директорий не означает автоматического восстановления инфраструктуры хоста.

Копия содержит учётные данные, ключи подписи, данные пользователей и прочие секреты **в открытом виде**. Доступ к архиву должен ограничиваться владельцем, перенос выполняться по защищённому каналу и с шифрованием при хранении вне сервера. SHA-256 проверяет целостность, **не** удостоверяет источник: атакующий, способный переписать bundle и manifest, может пересчитать хеши. Доверять можно только копиям из защищённого доверенного хранилища.

## Проверки разработчика

```bash
python3 -m unittest discover -s scripts/install -p 'test_minimal_backup.py' -v
python3 -m unittest discover -s scripts/install -p 'test_minimal_install.py' -v
```

Положительные проверки: обе WAL-БД, файлы, перемещение установки и сохранение секретов. Отрицательные: приложение удерживает flock; повреждён файл или БД; вложенная symlink; существующая целевая установка. Реальный приёмочный сценарий на хосте с собранным Go API и полноценной проектной конфигурацией остаётся отдельной обязательной проверкой.
