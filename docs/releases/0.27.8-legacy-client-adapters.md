# NeverLauncher 0.27.8 — Legacy Client Adapters

This release adds executable Java 8 legacy launch handling to the working 0.27.7 Client Factory. It does not replace the existing Mojang/Forge materializers or claim to have run a graphical Minecraft game in CI.

## Working targets

- Vanilla old-style Minecraft profiles (release versions up to 1.12.2): resolve `minecraftArguments`, parent version JSON, exact downloaded libraries and per-target natives. Later Java 8 Vanilla versions using modern `arguments.game` remain with the modern launcher path and are **not** reclassified as LaunchWrapper clients.
- Forge 1.7.10: `net.minecraft.launchwrapper.Launch`, `cpw.mods.fml.common.launcher.FMLTweaker`, Java 8, old universal JAR and Forge libraries.
- Forge 1.12.2: `net.minecraft.launchwrapper.Launch`, `net.minecraftforge.fml.common.launcher.FMLTweaker`, Java 8, V1/V2 legacy installer output and Forge libraries.

The adapters are invoked automatically by `runtime client-factory build` on those versions. The normal installed Minecraft client, assets, libraries, and native archives come from upstream-verified Vanilla/Forge installation steps; the new legacy launch file is written only **after** the materializers complete. NeverLauncher then checks all required classpath JARs, computes each SHA-256, merges Forge/Vanilla library revisions with child precedence and includes this recipe in the immutable InstallPlan digest. A missing, renamed or modified required JAR fails the build or verification.

## Build and inspect

```sh
neverlauncher runtime client-factory build --loader vanilla --minecraft 1.12.2 \
  --client-dir ./clients/vanilla1122 --target linux/x86_64
neverlauncher runtime client-factory build --loader forge --minecraft 1.7.10 \
  --loader-version 10.13.4.1614-1.7.10 --client-dir ./clients/forge1710 \
  --target linux/x86_64 --java /path/to/java8
neverlauncher runtime client-factory verify --client-dir ./clients/forge1710
neverlauncher runtime client-factory legacy-inspect --client-dir ./clients/forge1710
```

Use the host's target when planning an executable client. Cross-building an incompatible architecture does not certify it for host execution. A new `.neverlauncher/legacy-launch.json` is linked to the InstallPlan lock; it is checked on verification/rebuild. To preserve previously pinned reproducibility identities, existing 0.27.7 legacy receipts are left unchanged on replay; build a fresh directory to opt into the new launch recipe.

## Launching a locally materialized Java 8 legacy client

```sh
export NEVERLAUNCHER_MINECRAFT_ACCESS_TOKEN='<official session token if available>'
neverlauncher runtime client-factory legacy-run \
  --client-dir ./clients/forge1710 --java /path/to/java8 \
  --username example --uuid '<Minecraft UUID>'
```

The command executes Java, not a launcher JSON simulation. It checks the installed lock, hashes all outputs, validates the exact classpath/profile, compares OS/arch, requires native materialization for the target and checks Java 8 via `java -version`. Arguments are passed as individual argv tokens without invoking a shell. `--timeout 10m` can bound the process; `--uuid` is required when a token is present. The session token is *not* added to install-plan.json or printed by `legacy-inspect`. Java itself receives the token on the command line as required by old Minecraft arguments, so treat the machine as trusted and restrict process inspection. With no token, availability of offline play depends on the game/server and account configuration. Do not use unofficial sessions as a replacement for Mojang authentication.

CLI process execution is not a runtime security sandbox. The command only accepts locally verified client content; a Java client is capable of filesystem and network operations.

## Bridge constraints

Cleanroom and lwjgl3ify replace classloaders, LWJGL, early classpath artifacts and JVM flags; plain Forge Java 8 cannot safely be relabeled as a Cleanroom or Java 17+ build. This release **does not silently attempt** those conversions. Upstream projects require release-specific packages and dependencies, e.g.:

- lwjgl3ify for 1.7.10: https://github.com/GTNewHorizons/lwjgl3ify
- Cleanroom for 1.12.2: https://github.com/CleanroomMC/Cleanroom

Only the installed, verified Java 8 legacy targets are supported here. A future bridge importer must consume trusted, pinned upstream patches, revalidate full classpath/JVM flags/Java, and provide separate client runtime certification for each bridge profile.

## Verification and known limits

Run `cd cli && go test ./cmd/neverlauncher -run 'TestLegacyAdapters0278|TestClientFactory0271|TestForgeLegacy' -count=1`, then `go vet ./cmd/neverlauncher`. The tests use actual local HTTP download/materialization, Forge V1 ZIP extraction, InstallPlan replay, SHA-256 tamper rejection, and an actual child process for Java argv behavior. Fake Java and fixture JAR content **do not prove** the graphical Minecraft client starts. Real sessions on Windows/Linux/macOS, Cleanroom and lwjgl3ify certification, Forge mod compatibility and full `go test ./...` remain unverified by this release.
