# NeverLauncher 0.25.0 — Optional Components GA

## Scope

Production release hardening for O01–O10: signed Manifest v3/Catalog v5,
component/preset selection, dependency/conflict resolution, constrained signed
actions, resolved download/ownership, migration and ServerBridge plan policy.
This release does **not** reinterpret signed catalog formats, change existing
component identifiers or invalidate prior Manifest v1/v2 signatures.

### Upgrade and runtime behavior

1. Upgrade the full 0.24.13 source tree to 0.25.0. Apply the patch preserving
   paths. Verify `python3 scripts/version/manage.py check`.
2. Back up the currently installed release record, manifest, cached artifacts
   and selection. Never copy local selection into the signed manifest.
3. Run `nl components validate` with the independently pinned release key;
   `resolve` for all shipped presets and representative environment boundaries.
4. Verify staging, repair, missing SHA-256 file, conflicting user-owned path,
   interrupted transaction, resume, migration and rollback. The active release
   record is authoritative; unknown player files must remain untouched.
5. Keep signing trust and policy enforcement in place. ServerBridge policy with
   verified plan evidence is fail-closed. A user-provided list of mods is NOT
   evidence of the modules actually loaded into the Java VM.
6. For imports, unsupported Gravit triggers, permissions and filesystem moves
   remain explicit incompatibilities. Do not silently convert them.

**Known limitation inherited from O04:** entitlement issuance and independent
server verification of user permissions remain incomplete. A restricted
component without a verifiable entitlement must remain blocked. Hardware
identity plus a file-plan digest alone also does not prove classloader state.

## Mandatory 0.25.0 GA conditions

The `scripts/release/build-release.sh` entrypoint now verifies an independently
signed six-platform evidence cohort *before deleting output or starting a build*.
The former general-purpose release candidate workflow cannot generate an
ephemeral CI release root to represent a production release.

Required destinations (one directory per target):

- `windows-amd64`, `windows-arm64`
- `linux-amd64`, `linux-arm64`
- `darwin-amd64`, `darwin-arm64`

Each target must contain ordinary `attestation.json` and `attestation.sig`
files, and every evidence file referenced by `attestation.json` must be stored
in the same directory. Never follow links to arbitrary file paths. Exactly
these objects are required in `objects`, each with `file` and `sha256`:

`installer`, `osSignature`, `cleanMachine`, `certification`, `benchmark`,
`components`, `nativeRun`, `minecraftRun`, `guardRun`, `bridgeRun`.

The Ed25519 signature covers
`NeverLauncher-GA-0.25.0-optional-components-v1\n` followed by **exact bytes**
of `attestation.json`, using an approved *independent* GA key. The trusted
public key is passed to verification from a separately configured protected
organization variable; the proof's own claimed key is never trusted.

The signed document uses `schemaVersion: neverlauncher.ga.optional-components.v1`,
`productVersion: 0.25.0`, `status: passed`, exact `commit`, `gitTreeClean: true`,
`platform`, `architecture`, required `checks`, and the above file objects.
Required checks include the standard clean-machine GA gates plus
`component-graph`, `signed-actions`, `migration`, `serverbridge-plan-evidence`
and `minecraft-component-launch`.

The `components` object is a JSON proof with
`schemaVersion: neverlauncher.components.certification.v1`, status `passed`,
exact installer SHA-256, `target` and `commit`, a verified Manifest `3.0`
and Catalog `5.0`, plus all the component execution checks defined in
`scripts/ga/release_gate.py` as `COMPONENT_GA_CHECKS`. It must contain
`nativeEvidenceSha256` and target-bound `minecraftEvidence`, `guardEvidence`,
`bridgeEvidence` hashes which **must equal the separately attached raw objects**.

Actual `nativeRun` evidence requires a nonzero HTTP request count, verified
signed schema, real process execution, exact target, commit and version.
`minecraftRun` requires a real Mojang Java client launch. `guardRun` must
come from live NeverGuard integration; `bridgeRun` must prove a real
ServerBridge join and replay denial. All reported live proof objects must be
bound to this exact commit and target. Fixtures and mocked/test certificates
are forbidden in release evidence.

Every signed attestation is additionally bound to the exact approved OS-signed
installer bytes; changing or repackaging an installer invalidates certification.
Run on six separate clean machines (or independently provisioned runners),
with all required Minecraft/loader and adversarial/fault conditions. A skipped
platform, failed suite, unsigned receipt or unverified signer blocks GA.

## Operator commands

Verify an independently signed evidence cohort:

```bash
python3 scripts/ga/release_gate.py \
  --version 0.25.0 \
  --attestations /secure/ga-0250 \
  --trusted-attestation-public-key "$NEVERLAUNCHER_COMPONENT_GA_PUBLIC_KEY" \
  --commit "$GIT_COMMIT" \
  --output dist/ga-0250-verification.json
```

Sign an independently collected and validated target attestation only inside
an approved signing environment with its protected Ed25519 private key:

```bash
python3 scripts/ga/sign_optional_components_0250.py \
  --folder /secure/ga-0250/linux-amd64 \
  --private-key /secure/keys/approved-ga-ed25519.pem \
  --trusted-ga-public-key "$NEVERLAUNCHER_COMPONENT_GA_PUBLIC_KEY" \
  --commit "$GIT_COMMIT"
```

The signer **does not generate test successes** and refuses to overwrite an
existing signature. Do not publish the private key or include it in the patch.

Approved release signing then requires (in addition to the existing release
identity, trust policy, clean source and other production certificates):

```bash
export NEVERLAUNCHER_COMPONENT_GA_ATTESTATIONS_DIR=/secure/ga-0250
export NEVERLAUNCHER_COMPONENT_GA_PUBLIC_KEY=<independently-approved-32-byte-hex-public-key>
export NEVERLAUNCHER_SOURCE_COMMIT="$GIT_COMMIT"
bash scripts/release/build-release.sh
```

CI entrypoints: `.github/workflows/ga-0250.yml` verifies approved six-target
signed evidence; `production-release-candidate.yml` downloads that exact
cohort, uses protected production release signing keys and invokes the GA
preflight again. Final release signing and verification remain the existing
CLI operations, not simulated by this patch.

## Evidence vs execution status

Local unit tests and synthetic Ed25519 fixtures prove the verifier rejects
invalid evidence; they do not prove installers, real Minecraft, NeverGuard,
ServerBridge or OS support. **0.25.0 is not production-certified or signed
until the six real target attestations and their actual signed installers
exist and the production release gate passes.**

Recommended local checks:

```bash
python3 scripts/version/manage.py check
python3 -m unittest discover -s scripts/ga -p 'test_*.py' -v
python3 -m unittest discover -s scripts/certification -p 'test_*.py' -v
(cd services/api && go test ./internal/model ./internal/planpolicy02412)
(cd cli && go test ./cmd/neverlauncher -run 'Test.*Components.*0249|TestComponent.*02310')
# Required on actual native CI:
cargo test --manifest-path runtime/neverruntime/Cargo.toml --lib
```

Report each failed or unavailable check honestly. Do not mark it successful
from adjacent passing tests or from a signed manifest alone.
