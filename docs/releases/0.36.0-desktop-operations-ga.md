# NeverLauncher 0.36.0 — Desktop & Operations GA release procedure

This version **does not inherit GA certification from 0.35.14**. Local executable tests do not prove Windows/macOS/Linux, real Minecraft, live Backend, security, DR or real-world performance. The source can carry VERSION=0.36.0 while a production release remains **BLOCKED**.

## Actual release enforcement

`build-release.sh` runs the protected Backend runtime preflight (all versions >=0.35.0), compiles/packages the release, and **before Ed25519 release signing** runs `scripts/ga/verified_targets_0360.py`. Unlike a source contract, this tool hashes the actual, fully staged Desktop executable and platform delivery package, verifies all 54 per-target execution records, and verifies their operator-signed authorization using an independently pinned Ed25519 key. An expired/mismatched signature, missing OS/architecture, changed installation package, missing Minecraft E2E, simulated/failed check or changed commit blocks signing. The results are inserted into the release before its manifest/SHA256SUMS are generated and signed. No GA flag can be set by checking in a JSON file alone.

Current build-release produces all six targets as one product release. Until a genuinely selective release builder is certified, **all six must pass**, otherwise the entire release is refused; an unapproved target cannot be shipped as part of a nominally approved bundle.

### Operator-controlled input

Prepare a protected evidence directory with `approval.json`, `approval.sig`, and `targets/<target>/<check>.json` files. Target IDs are `windows-x64`, `windows-arm64`, `linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`. Checks per target: `nativeInstall`, `desktopLaunch`, `minecraftLaunch`, `serverJoin`, `releaseRollback`, `security`, `performance`, `operations`, `osSignature`. These must come from actual installed binary + real game/owner/operations executions. The protected operator must verify them *before signing*. Each execution record binds `version`, `commit`, `target`, `kind`, `status=passed`, `actualExecution=true`, `simulated=false`, `artifactSha256` (hash of shipped Desktop executable), and a unique `executionId`. The approval binds each record's SHA-256, the exact released Desktop binary SHA-256, and package SHA-256. Approval timestamps must be UTC and valid for at most seven days.

The operator signs raw bytes using Ed25519 over `b'neverlauncher.ga036.targets.v1\0' + approval.json`; `approval.sig` contains its 64-byte signature as hexadecimal. The trusted independent **public** key is a separate file of 64 hex characters, outside the repository and distinct from production release signing credentials. Never put a private approval key in the release or repository.

The trusted `production-release` GitHub environment supplies `NL_GA036_OPERATOR_PUBLIC_KEY_HEX`. Workflow dispatch supplies `ga036_operator_approval_run_id`, pointing to a protected artifact named `neverlauncher-ga036-signed-<source SHA>`, containing the complete signed evidence directory. This is an external **actual acceptance** dependency; an artifact name or CI status alone does not grant release authorization.

**Build prerequisite:** operator approval must bind the *exact* already-built distribution files. Produce candidate distribution bytes and their hashes on the intended release stand, then approve those bytes. If any subsequent build changes hashes, the approval must be renewed; do not edit the candidate hashes by hand or disable the gate. A one-pass rebuild is only acceptable when binary and package bytes reproduce exactly.

Direct staging verification:

```bash
python3 scripts/ga/verified_targets_0360.py \
  --bundle dist/release-0.36.0 \
  --evidence /protected/ga036-evidence \
  --trusted-key /protected/ga036-operator.pub \
  --version 0.36.0 --commit "$RELEASE_COMMIT" \
  --output dist/release-0.36.0/GA_VERIFIED_TARGETS_0360.json
```

`build-release.sh` also **requires all three** Compatibility, Device Trust and Guard CI publish certifications for 0.36.0 and executes the existing `release publish-check`; it no longer accepts a signed-but-nonpublishable bundle as completed GA.

## Evidence acceptance and residual risks

* RC native fixture tests validate real signed HTTP install/repair but do not demonstrate real Minecraft; only actual Minecraft and protected ServerBridge traces can satisfy the operator approval.
* Real external Microsoft authentication/entitlement, offline policy, Linux/Windows/macOS screen reader and native HiDPI verification, installer Authenticode/notarization, and owner publish/rollback must be performed on the exact shipped binaries.
* Operator must independently record reproducible 10k-file, 1/10 GiB, CPU/RAM, cold/warm Desktop and API p50/p95/p99 measurements. No fabricated comparative speed claims.
* Verify PostgreSQL/Redis outage and recovery, local/S3 restore, full disaster recovery, off-host backups, queue overload and meaningful RPO/RTO. A successful Redis connection does not imply HA.
* No automatic diagnostics upload without player consent; no raw tokens/logs in player/operator bundles.

Until evidence is available, keep `0.36.0` **release blocked**. No auto-publish action is added; release signing, verification and publish-check retain their pre-existing protected controls.
