# NeverLauncher 0.29.2 — Auth SDK v2 & Conformance

This release enhances the existing federation and `pkg/authconnector` rather than introducing another token, provider or user system.

## Operational changes

- All providers registered through `federation.Core.RegisterWithPolicy` pass the same `authconnector.ValidateConnector` capability gate. A missing implementation **or** an undeclared sensitive operation is rejected before the provider becomes available.
- The common authentication validation runs on provider password login, browser code completion, provider-token refresh and authenticated linking. Subject, issuer, token size, methods, and identity fields are validated before canonical identity writes. The issuer-aware resolution and Minecraft UUID protections introduced in 0.29.1 remain in place.
- `federation.Core.ResolveProviderIdentity` / `ResolveProviderProfile` execute the actual configured connector operations. They reject mismatched subjects instead of accepting provider-supplied reassignment.
- `conformance.Run` is explicitly **structural** and non-destructive, preserving startup safety. `conformance.RunBehavioral` is a separate test-account-only execution mode: correct and incorrect password, browser authorization callback, lookup, profile, refresh with subject/issuer continuity, and explicit revocation/invalidation where supported.
- Behavioral fixture failures do not include upstream error strings, passwords, tokens, names or emails in the report. Destructive revoke is opt-in; the test account's rotated credentials may be invalidated. There is no automatic failover to another provider.
- Configured provider JSON uses the existing unversioned array (v1) or versioned envelopes (`schemaVersion: 1` with `configs` and `schemaVersion: 2` with `providers`). This is an in-memory, backward-compatible migration in all four SQL, HTTP, OIDC and Microsoft loaders; no credentials are rewritten, configuration files are not changed and unknown/future schemas fail closed. Individual provider `Normalize` and transport/security validation still run after decoding.

## Behavioral conformance status

| Connector | Executed checks | Limits |
| --- | --- | --- |
| HTTP | Signed TLS request authentication, invalid password, lookup, refresh, revoke, identity/issuer | Test service returns `revoked`, but does not invalidate token; strict post-revoke behavior tested separately in the SDK stateful fixture |
| OIDC | Signed JWT from TLS test IdP, browser PKCE, subject/issuer, refresh | Live third-party issuer not certified |
| Microsoft | Signed JWT from multitenant test IdP, PKCE, issuer/subject and refresh | Microsoft cloud account not used in offline tests |
| SQL | Static capability and config mapping paths; existing connector fixture tests | Real PostgreSQL/MySQL/MariaDB run needs online modules and/or test services |
| Local | Federation conformance, issuer and linking tests | End-to-end Minecraft launch is a later milestone |

The release adds GitHub Actions workflow `.github/workflows/auth-sdk-conformance-0292.yml` for these gates.

## Boundaries

The linking trust boundary remains the existing `federation.Core.LinkPasswordIdentity` or the browser proof handler; the SDK's older subject-only `IdentityLinker` is **not** proof of ownership and is not invoked for account linking. Global revocation of Minecraft sessions, device protection and broad legacy Gravit migrations belong to future 0.29.x milestones. This is not independent GA certification for real Microsoft login or live multi-provider database deployment.
