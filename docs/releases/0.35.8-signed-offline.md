# NeverLauncher 0.35.8 — Policy-Driven Signed Offline

## Player journey

1. Owner creates a real Minecraft profile and explicitly signs a v2/v3 game Manifest with `runtime.launch.offlineMode: true`. A signed bootstrap binds the Desktop to that owner, project, profile, channel and pinned Ed25519 key. The flag **does not grant a Minecraft entitlement**.
2. While online, the player installs the full release, verifies the files, completes the signed first-run workflow, and saves a signed Manifest to the local game directory cache. Online profiles with `offlineMode=false` cannot populate an offline cache.
3. When the Backend is unavailable, open **Settings → Load offline cache** or select **Offline** in the Minecraft mode selector. Tauri invokes `prepare_offline_launch_0358`, which re-verifies the owner-signed bootstrap, pinned game signature and full profile/channel identity, ensures the exact installed transactional release and component preset are active, and SHA-256-verifies every required managed file. No Backend, Microsoft or ServerBridge request is made by that native command.
4. Only after successful native verification does Desktop switch the identity to offline. It clears ServerBridge auto-enter and direct server host for this launch, including when owner-signed online auto-enter options are locked. Existing online preferences are not lost.
5. `launch_minecraft` performs the same binding and cached-release check independently of the renderer; NeverRuntime validates the installed release and hashes files under a launch lease before spawning Java. `offline` has no official/Yggdrasil credentials, no Microsoft entitlement and no ServerBridge join ticket. Runtime refuses server auto-join options embedded in signed game arguments.
6. A missing, altered or switched release returns an error and a concrete user recovery recommendation (reinstall signed bundle, restore original release/channel, save cache while online, or run **Repair**).

## Security boundaries

- The signed owner bundle, profile manifest and pinned key are not writable policy via localStorage. No arbitrary user-provided public key can authorize a different profile in Desktop offline flow.
- A cached signed Manifest is necessary but insufficient: first-run completion, currently active installation, component preset and managed file SHA-256 checks are all required. Changing the UI, cache file, selection or install pointer does not satisfy these checks.
- Offline does not create/refresh a Minecraft entitlement, or turn an offline UUID into an official Microsoft account. Online-mode and ServerBridge-protected servers must still enforce their own server-side authentication. A locally authenticated operator/OS owner can change or replace program binaries; this is outside an application's client-side trust boundary.
- The owner may revoke permission by distributing a new signed profile/installer. Without network connectivity a client cannot learn about newly issued remote revocations. Native delegated trust-policy expiry is still enforced and may require re-provisioning before another offline session.
- Optional player-owned files are retained under their existing ownership policy. Offline integrity confirms the signed managed release, not all third-party files the player can manually place in the game directory.

## Acceptance

- `cd apps/desktop && npm run test:offline && npm run test:launch-modes`.
- `cargo test --manifest-path runtime/neverruntime/Cargo.toml offline_policy_0358` — signed arguments cannot auto-enter a network server.
- `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml offline_policy_0358 --no-default-features` — scope, digest/first-run, policy and release mismatch rejection.
- Real-world E2E: provision signed bundle, install online, disconnect network, load cache, start single-player Minecraft; then repeat with bad signature, wrong owner/channel/profile, altered JAR, incomplete release, wrong component preset, disabled offline policy, expired trust policy, and a protected online server. The last case must be denied by the **server** as well as not auto-joined by the launcher.

Do not declare release/GA certification complete from unit tests or CI configuration without a real packaged Tauri binary on Windows/Linux/macOS and an actual offline Minecraft run.
