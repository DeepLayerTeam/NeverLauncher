# NeverLauncher 0.28.4 — RemoteControl Agent & Security

## Scope and trust boundaries

`nl server-bridge host remote` is a real, independently running HTTPS service in the **Host Process Control** trust domain. It invokes the existing 0.28.2/0.28.3 `start`, `stop`, `restart` and process identity checks; it is not a second JVM execution engine.

Supported remote operations, and **only** those operations:

| Action | HTTP endpoint | Exact token scope |
|---|---|---|
| Read verified host status | `GET /v1/host/status` | `host.status` |
| Start existing configured server | `POST /v1/host/commands {"action":"start"}` | `host.start` |
| Gracefully stop supervised server | `POST /v1/host/commands {"action":"stop"}` | `host.stop` |
| Restart supervised server | `POST /v1/host/commands {"action":"restart"}` | `host.restart` |

No shell execution, arbitrary binaries, config mutation, JVM flags, project auth, player broadcast, Backend restart, logs streaming, or token issuance via network. They are **not** implied by any of the above permissions. Game Server Control remains in the existing Backend/ServerBridge protocol, separately authorized by 0.28.1. This host agent has no generic access to Backend or player sessions. The Backend operations/control plane is a later release.

The service token is HMAC-SHA256 signed, bound to a randomly generated local node ID, a subject, exact scopes, a caller network CIDR set, `iat`, unique `jti`, and `exp` <=15 minutes after issue. Key material is stored in the private server-root state directory and is not returned to callers. The operating-system service account, **not a game administrator**, must protect this directory. The agent loads current identity on every request, so key rotation revokes old tokens without restarting the listener; explicit revocations are checked against disk on each request.

## Preparation

First configure Host as in 0.28.3 (`nl server-bridge host configure --server-root /srv/minecraft/lobby ...`). Run the following local operator-only commands as the dedicated host account:

```bash
nl server-bridge host remote init --server-root /srv/minecraft/lobby

# Install a valid TLS certificate for host01.example.net and an owner-only private key.
# The network listener requires TLS >=1.3; remote CLI verifies the chain and DNS name.
chmod 600 /etc/neverlauncher/host01.key

nl server-bridge host remote serve \
  --server-root /srv/minecraft/lobby \
  --listen 10.10.0.20:9443 \
  --allow-source 10.10.1.0/24 \
  --tls-cert /etc/neverlauncher/host01.crt \
  --tls-key /etc/neverlauncher/host01.key
```

Optional `--client-ca /etc/neverlauncher/clients-ca.pem` requires and verifies mutual-TLS client certificates. The agent trusts **only** the TCP peer address, never `X-Forwarded-For`. Default listen address is `127.0.0.1:9443` and the default allowed CIDRs are local loopback. External bind requires an explicit `--allow-source` to authorize an external caller.

**Issue a short-lived token locally** (never in a command argument, URL or terminal output):

```bash
nl server-bridge host remote issue \
  --server-root /srv/minecraft/lobby \
  --subject operations-controller \
  --scope host.status --scope host.stop --scope host.start \
  --source 10.10.1.15/32 --ttl-seconds 300 \
  --token-file /run/user/1001/lobby-remote.token

# From the operations controller (trust the exact server TLS certificate chain):
nl server-bridge host remote call \
  --url https://host01.example.net:9443 \
  --ca-file /etc/ssl/certs/neverlauncher-ca.pem \
  --token-file /run/user/1001/lobby-remote.token \
  --action status

nl server-bridge host remote call \
  --url https://host01.example.net:9443 \
  --ca-file /etc/ssl/certs/neverlauncher-ca.pem \
  --token-file /run/user/1001/lobby-remote.token \
  --action stop --idempotency-key incident-20261024-lobby-stop-1
```

The client token file must be a regular, owner-private (0600) file. The HTTPS client supports optional `--client-cert` and `--client-key` when mTLS is required; it forbids insecure certificate verification, URLs containing credentials/query/fragment, and HTTP redirects. Do not persist bearer credentials in logs or command history.

To revoke that specific token immediately:

```bash
nl server-bridge host remote revoke --server-root /srv/minecraft/lobby \
  --token-file /run/user/1001/lobby-remote.token
```

To invalidate **all** service tokens, rotate the local signing key:

```bash
nl server-bridge host remote rotate-key --server-root /srv/minecraft/lobby
```

Protect `host/remote/identity.json` (HMAC key), `host/remote/revoked.json`, `host/remote/commands/*.json`, `host/remote/audit.jsonl` and `host/remote/agent.lock`; the agent rejects insecure permissions and symlinks for state/secret files it reads. Run under a dedicated host account. Use firewall ingress controls in addition to `--allow-source`.

## Command delivery, replay, crash, fencing

Every HTTP mutation requires `Idempotency-Key` with 16–128 restricted characters. The command key is hashed to a journal filename under `remote/commands/`. Its binding covers the node, operator subject and action. The durable journal is written **before** Host operations start and later updated after they finish. Concurrent requests in one agent are serialized and the agent uses a private, OS-process-identity-checked lease to prevent multiple live agents for the same server root. Disk journal replay after an agent restart returns the saved receipt without re-executing.

- `succeeded`: the existing Host Supervisor call returned and the journal update was persisted; retried delivery returns this result (HTTP 200).
- `indeterminate`: the external call failed, the service crashed, or the result cannot be proved. A repeated request returns the prior uncertain record (HTTP 409) **without** silently executing again. An operator must inspect the verified Host runtime and reconcile manually using a **new** idempotency key only after confirming the intended effect.
- Conflicting reuse of the key (different action/subject) returns HTTP 409, and never runs the new operation.

The agent writes a restricted append-only JSONL audit with caller address, subject, `jti`, scope, event/outcome and a hashed command key. Bearer values are never written to the audit. Audit or journal persistence failure blocks dispatch. The existing Host Supervisor still validates process/session identity before stopping; RemoteControl never signals a PID read from disk directly.

## Limits and follow-up

- The agent is **not** an HA coordinator distributed across multiple independent hosts. PostgreSQL/Redis command leasing, fencing and cross-Backend journal integration are planned for 0.28.5. Never run two agents on the same server root; a local process-identity lease prevents it on supported platforms.
- The agent needs a trustworthy host OS identity and private local filesystem. Multi-host shared filesystems, hostile local privileged users, a compromised service account and manual mutation of state files are outside its guarantee.
- Service installation, autostart and systemd watchdog belong to 0.28.11. Rollout, enrollment and adapter maintenance belong to 0.28.12.
- Production deployment must use verifiable server certificates, restrictive firewall rules and a dedicated unprivileged host account. A passing fake Java test does not certify real Minecraft or player-routing E2E.
