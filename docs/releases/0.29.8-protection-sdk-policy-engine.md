# NeverLauncher 0.29.8 — Protection SDK & Policy Engine

The implementation extends existing MFA, risk, device trust, issuer, RBAC, Minecraft and ServerBridge checks; it does not create a second authentication provider or claim that hardware IDs prove identity.

## Enforcement and operator workflow

- `pkg/protection.Engine` executes prioritized handlers for `before-auth`, `after-auth`, `before-launch`, and `before-join`. Mandatory failures and unknown decisions deny. A denial cannot be overwritten by an `allow` handler. Modules may be registered at runtime via `Server.Protection` before constructing the HTTP handler. Hooks receive scoped identifiers, not secrets.
- The built-in account-ban handler always reads the authoritative repository and enforces bans in Never login, refresh, access token validation, Minecraft session issuance and joins, and ServerBridge gameplay trust. Backend store failures deny authorization rather than treating a missing lookup as "not banned".
- POST `/api/v1/admin/protection/users/{userId}/ban` with `{ "reason":"confirmed credential abuse", "expiresAt":"2026-11-01T00:00:00Z" }` (expiry optional) applies a ban. POST `.../unban` lifts it, but does **not** resurrect previously revoked sessions or modify separately disabled users. GET `/api/v1/admin/protection/bans` lists the last 500 bans with their reasons and revocation metadata. Listing needs `users:manage`, changes additionally require fresh phishing-resistant step-up. An administrator cannot ban their own active identity.
- PostgreSQL migration `0083` stores active/revoked bans independently from user status. A database trigger revokes all Never sessions for the user, cascading through refresh, Minecraft, ServerBridge and jobs from migration `0082` across all API replicas. User-row locking serializes a concurrent newly issued session with a ban. Memory mode explicitly revokes the same user's in-process sessions.
- `protection:ban`, `protection:unban`, and `protection:denied` audit records are recorded without passwords, token material or device fingerprints. Reasons are limited to 512 characters.

## Operational limits and rollout

Apply the sealed `0083` migration in both Backend and CLI before enabling 0.29.8 instances. Bans fail closed if the table is unavailable. This version offers code-registered Protection SDK handlers and persistent account-wide bans, not an interpreted/remote rule language; existing role and device policies stay authoritative within their own checks. Temporary bans expire when the timestamp passes; expired records are retained for audit. Custom handlers must respect `context.Context` cancellation and cannot be used as a trusted sandbox for unreviewed code. Manual or multi-replica PostgreSQL/ServerBridge tests and live Minecraft join/kick remain necessary before production certification.
