# NeverLauncher 0.38.8 — восстановление операций Admin

## Изменения

- Намерения публикации и отката записываются **до** запроса в `localStorage`, в разделе, привязанном к URL Backend, идентификатору аутентифицированного пользователя и проекту. Доступ к API всё равно определяется Backend; секреты/токены в записи не сохраняются.
- После перезагрузки страницы и перевыпуска сессии Admin в первую очередь выполняет **только чтение** исходного durable job по `GET /api/v1/operations/recover`. Сервер выбирает запись по виду операции, текущему пользователю и исходному ключу, а также повторно проверяет право чтения проекта.
- Если Backend ещё не содержит запись, Admin **не создаёт новый job автоматически**. Для повторения точно сохранённого намерения требуется явное подтверждение и действующее MFA. Backend повторно применяет актуальную политику публикации и проверки целостности.
- После получения ID выполнение отслеживается по durable job и фактическому `channel head` без объявления HTTP 202 успехом публикации.
- В Unified Operations восстановление не даёт скрыто сменить idempotency key. Снять блокировку новой операции можно только после наблюдения терминального job и явного подтверждения проверки его истории.
- ServerBridge сохраняет ключи незавершённых команд между обновлениями сессии внутри вкладки. Командные payload хранятся только в `sessionStorage` и удаляются при выходе.
- Проверка незавершённой операции перед отправкой не позволяет другой вкладке без проверки затереть сохранённое намерение в том же пользовательском контексте.

## Границы гарантий

- Восстановление из журнала возможно, только если исходная операция была durably committed. Если запрос не дошёл до Backend, повтор с тем же ключом остаётся явным действием пользователя.
- Нельзя приравнивать найденный `succeeded` job к подтверждённой публикации без проверки `channel head`.
- Текущий Backend обязан иметь доступ к тому же durable repository после перезапуска. Полноценная эксплуатационная проверка PostgreSQL/SQLite с kill/restart и сетевыми отказами должна проводиться в реальном окружении.
- Сохранённое намерение не даёт прав на обход актуальной авторизации/MFA и не содержит токенов.
