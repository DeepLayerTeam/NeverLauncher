# NeverLauncher 0.31.12 — macOS Signed Sandbox Helper

H11 implementation patch on top of 0.31.11.

- Built-in Darwin backend/CLI routing uses a separate Developer ID-signed
  App Sandbox helper. The helper entitlement whitelist is verified at runtime.
- Only a single native self-contained Mach-O backend or CLI executable is
  accepted. Unsupported package types fail closed.
- Image SHA-256 is verified inside the helper before private-container staging
  and `posix_spawn`; the resulting executable inherits the macOS App Sandbox.
- Unix socketpair FD4 carries Host Protocol to a one-instance server on the
  host. There is no TCP/network entitlement or direct host filesystem mount.
- Both Go extension SDKs connect using the inherited FD on Darwin.
- Running status is marked isolated only after helper readiness and PID
  confirmation. Server rejects IPC from a different extension instance.
- Launch/release paths and signing requirements: see
  `docs/security/macos-signed-extension-sandbox-03112.md`.

## Non-negotiable release caveat

The macOS helper has not been compiled/signed or exercised in a macOS App
Sandbox by a Linux-hosted workflow. The Swift source can only be syntax-parsed
there. Aggregate descendant process memory, CPU, PID counts and breakaway
resistance still require the next H12 step. **Do not claim full production
certification or H12 compliance until hardware macOS tests pass.**
