# NeverLauncher 0.26.12 — Integration & Compatibility Certification

## What is implemented / what is NOT certified

The 0.26.12 release adds executable **live** Microsoft → Xbox Live → XSTS → Minecraft Services → Java profile → Mojang **sessionserver join/hasJoined** verification, plus a modern-server encryption-handshake probe and an evidence checker for actual vanilla/modded player joins. No tokens are recorded in evidence JSON, log messages or UI. The existing Native Identity Manager and game launching paths are not replaced with a simulated provider.

**Provider access, Minecraft online login and native OS-vault behavior have NOT been verified in this source-only build environment.** A successful local `go test`, CI build, fake HTTP fixture, `online-mode=true` in a config file, or `join/hasJoined` without an actual running game client **alone** cannot certify end-to-end game login. Provider approval must be confirmed independently by its owner.

## 1. Prerequisites

- Your OWN Microsoft Entra public desktop client ID (personal Microsoft account; `consumers` authority), registered `http://localhost/minecraft-poc/callback`, `XboxLive.signin offline_access`, and actual Microsoft/Xbox/Minecraft Services permission.
- A personal Microsoft account with a valid Minecraft Java profile and multiplayer permitted by its Xbox/Family settings. Never provide Microsoft passwords, access tokens or refresh tokens to CI, issues, support tickets or build artifacts.
- A native Windows, macOS or Linux machine with an accessible OS credential store, NeverLauncher Desktop, a vanilla `online-mode=true` dedicated server and authorized Fabric/Forge/NeoForge test instances appropriate to your published client profiles.
- A matching Java protocol version for the optional server probe. For example, **767 corresponds to Java 1.21.0–1.21.1**; choose the correct value for your version, do not guess.

## 2. Run REAL provider + Mojang sessionserver E2E

On the local test machine, from repository root:

```sh
cd services/api
go run ./cmd/official-provider-poc \
  --client-id 'YOUR-OWN-MICROSOFT-APPLICATION-ID' \
  --flow browser --online-session=true \
  --report './official-browser-live.json'
```

The OAuth browser flow uses the system browser with PKCE S256. Use `--flow device` for an independent fallback test and a **new** report path, and confirm expiry, cancellation, `slow_down`, denial and refresh flows. The default `--online-session=true` creates an ephemeral 2048-bit RSA challenge, derives the signed Java server hash, calls the **real** Mojang `POST /session/minecraft/join` (expects 204) and `GET /session/minecraft/hasJoined` (expects 200), and compares both username and UUID to the official profile. Real Minecraft tokens must be used. A non-success status blocks the entire test. Respect Mojang join rate limits; do not continuously poll the endpoint.

To additionally probe the online-mode Encryption Request of a test server you control (example only):

```sh
go run ./cmd/official-provider-poc \
  --client-id 'YOUR-OWN-MICROSOFT-APPLICATION-ID' \
  --flow browser --online-session=true \
  --probe-server '127.0.0.1:25565' --protocol 767 \
  --report './official-vanilla-probe.json'
```

The probe opens a regular Minecraft login TCP handshake with a synthetic username; it validates the presence of the standard RSA encryption request, **without sending a bearer or completing the login**. It currently supports Java 1.20.2+ standard login packets. Firewalls, proxies, mod-loader networking and non-standard auth may prevent the probe from being applicable. Do **not** interpret a passing probe as a successful game join. Without the `--probe-server` flag, the probe remains `not_tested` in the report. The CLI is live-only at runtime: fixtures exist only in Go unit tests. `--online-session=false` is a diagnostic-only option and its report does **not** certify this release.

## 3. Verify actual vanilla / modded **client game joins**

1. Start a dedicated server owned by the test operator with its authentic server `server.properties` containing `online-mode=true`. Avoid authentication proxies or mods that alter this guarantee for the test. Keep the live console/server log from that run.
2. Launch NeverLauncher Desktop using the **official** account, NOT project Yggdrasil or offline, using the exact intended game version and native credentials. Join the actual game server and wait until a successful player login is recorded.
3. Keep the actual server's `logs/latest.log`, matching `server.properties` and successful provider report from the **same subject**. Do not replace them with example or simulated output.
4. Check a vanilla join:

```sh
python scripts/certification/official-game-join-02612.py \
  --provider-report ./official-browser-live.json \
  --server-properties /path/to/vanilla/server.properties \
  --server-log /path/to/vanilla/logs/latest.log \
  --kind vanilla \
  --evidence ./official-vanilla-login-evidence.json
```

5. Repeat with the actual modded server/launcher profile (`--kind fabric`, `--kind forge` or `--kind neoforge`), each with a fresh privately stored provider report and evidence file. The checker requires loader startup markers for those modes, an exact UUID digest match and subsequent login record from the log. It rejects offline mode, wrong subjects, failed/partial provider reports, missing actual login and missing loader markers.
6. Review the exact server log and client's on-screen game state manually, including world entry and disconnect/reconnect. The checker establishes consistency of the supplied files, **not their authenticity**; it cannot prove the log is genuine, that modded client assets are correct, or that the credentials were never extracted elsewhere.

## 4. OS compatibility & native credential vault

Run `.github/workflows/official-compatibility-02612.yml` on hosted Windows, macOS and Linux for genuine Go builds/tests and native Tauri/Rust compilation/tests plus Desktop renderer build; do not mark a failing or skipped platform as passed. Perform the following **interactive** runs on physical or VM test stations with functional native credential storage:

| Check | Windows | macOS | Linux |
|---|---|---|---|
| Microsoft browser OAuth / Device Code, including cancel | required | required | required |
| Keyring persists multiple accounts after restart | required | required | required |
| Refresh / expired refresh / revoked account / logout | required | required | required |
| UUID remains stable after refresh, nick change | required | required | required |
| Official vanilla online-mode world entry | required | required | required |
| Modded online-mode world entry where supported | required | required | required |
| Disallow offline/Yggdrasil substitution; tokens excluded from logs/renderer | required | required | required |

A job showing Rust compilation and tests is a **preflight**, not a test of physical OS keychains or the Microsoft account. Real-world failures must block publication and be fixed before 0.27.0 GA.

## 5. Tests and release gate

```sh
cd services/api
go test -race -count=1 ./internal/officialminecraft ./cmd/official-provider-poc
go vet ./internal/officialminecraft ./cmd/official-provider-poc
go build ./cmd/official-provider-poc
cd ../..
python -m unittest discover -s scripts/certification -p 'test_official_game_join_02612.py'
```

Additional CI runs Rust/Tauri native compilation, launch isolation and renderer tests on each target OS. **Never publish 0.26.12 as certified** unless all required runtime tests, the provider registration permission, the live sessionserver reports, real vanilla/modded joins and interactive platform/vault checks have actually passed. Local simulated tests must never be included as real provider approval evidence.

Operator evidence should be retained privately with controlled access and short retention. Reports contain the public Client ID, a hashed Minecraft UUID, safe stage/error codes and platform labels, not raw credentials; game logs can contain personally identifying names/IPs and should be restricted or sanitized before sharing.
