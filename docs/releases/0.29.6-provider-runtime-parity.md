# NeverLauncher 0.29.6 — Provider Runtime Parity

## Implemented runtime changes

The existing Federation Core remains the **only** identity boundary. This release changes live Admin/Desktop/OIDC/Minecraft authorization behavior rather than introducing another session system or abstract connector interface.

1. **Provider MFA isolation.** `SafeUpstreamAuthMethods` preserves reported methods from HTTP/OIDC/Microsoft as `upstream:*` provenance. Authentication methods sent by an IdP, even signed or contained in a validated ID token, do **not** claim that NeverLauncher verified a passkey, TOTP or recovery code. Only successful local Never MFA verification upgrades `authStrength`; the same `evaluateLoginMFA117` runs for Admin, Desktop, browser login and Yggdrasil password login. Untrusted provider MFA claims cannot satisfy Never `required` or `phishing-resistant` policies.
2. **Admin password login parity.** Provider routing is validated before login throttling, and the throttle key includes the selected provider. A successful external password login persists the upstream refresh credential in the existing AES-GCM identity-bound repository, as Desktop does; failure revokes the newly created Never session. Never access/refresh tokens are never provider tokens.
3. **Browser provider lifecycle.** OIDC/Microsoft browser login no longer persists upstream credentials *before* local MFA succeeds. Successful login creates a Never session and stores an encrypted provider refresh credential if supplied. A persistence failure revokes the issued Never session and denies login. Browser responses and audit records include the canonical issuer, matching password login.
4. **Passkey continuation.** If Never policy requires WebAuthn after password/OIDC/Microsoft authentication, the upstream token is sealed with the existing credential AEAD and bound to the exact identity, provider and subject within the short-lived, single-use MFA challenge. Only successful Never WebAuthn verification and session creation can commit the credential. Challenge metadata never stores plaintext; a failed commit revokes the Never session.
5. **Canonical identity and permissions.** The existing `(provider, issuer, subject)` identity, Never-owned RBAC, session registry, token rotation and Minecraft session adapter remain authoritative. Provider roles are not directly granted Never administrative permissions. SQL providers remain read-only; the official Microsoft Minecraft Java license/profile proof remains **separate** from Azure/OIDC identity federation.

## Supported modes and certification boundaries

| Provider | Real runtime proof | Never session | External refresh | Minecraft entitlement |
|---|---|---|---|---|
| Local | local password + known legacy verifier | yes | not applicable | never profile; no official entitlement implied |
| SQL: PostgreSQL, MySQL, MariaDB | configured read-only mapping and password verifier | yes | not advertised | not implied |
| HTTP | signed request/response protocol and password proof | yes | encrypted token, refresh/revoke supported | not implied |
| OIDC | discovery, PKCE, state/nonce, signed ID token, subject/issuer | yes | encrypted token; refresh supported | not implied |
| Microsoft OIDC | verified tenant/issuer, `tid+oid`, policies | yes | encrypted token; refresh supported | **not implied**; official Minecraft profile verification is a separate flow |

The CI workflow exercises local SDK/conformance, signed test IdPs, Admin/Desktop/browser/Minecraft integration paths and real SQL engines, with race checks. It **cannot** certify live Azure tenants/Minecraft licenses without configured protected external test accounts. CI outcomes are not assumed until a workflow has actually run.

### Upgrade

Upgrade the standard project files and deploy the new Backend. No schema migration or new environment variables are required by these changes. Any sessions that previously received Never `authStrength=mfa` from upstream `amr` alone must be treated as lower assurance on the next login; administrators should revoke existing overstated sessions when enabling the new code. Existing locally verified passkey logins and TOTP/recovery flows are unaffected.

### Manual acceptance

- Require MFA for a Never account; return `amr=[mfa,webAuthn]` in an otherwise valid signed HTTP/ID-token response. Login **must not** succeed without Never second-factor verification.
- Disable that Never MFA requirement and log in via each supported provider. Auth strength remains single-factor until Never verifies a local factor, while upstream provenance is preserved.
- Force failure of provider credential encryption/storage. Admin/OIDC login must fail without leaving an active Never session.
- For passkey-required logins, verify that pending provider refresh tokens are AEAD-sealed in challenge metadata and not persisted before the WebAuthn proof; after successful WebAuthn verification, only the matching identity may receive the credential.
- For OIDC/Microsoft: after successful Never MFA, provider refresh credentials are stored per identity/issuer; the response exposes no provider token.
- Validate linked Minecraft and Never session revocation behavior with the existing game bridge tests; this does not replace the cross-service revocation project in 0.29.7.
