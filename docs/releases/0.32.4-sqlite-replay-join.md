# NeverLauncher 0.32.4 — Durable SQLite Replay Nonces & Join Tickets (DEP01/02)

## Functional scope

This release adds real SQLite persistence and transactionally safe one-time ServerBridge join tickets to the same on-disk WAL database as the 0.32.3 identity and authentication records.

- Native Ed25519 trusted-node enrollment/rotation/disable, with operator role enforcement, durable identity epochs and atomically invalidated outstanding tickets.
- Every signed node request uses an explicit protocol domain, verb, node ID, current identity epoch, Unix timestamp, base64url 192-bit nonce, and SHA-256 payload digest; the stored public key is consulted for every verification. Time skew is limited to 30 seconds and signatures are verified before the nonce is inserted.
- Unique durable nonce ledger per node/identity epoch. A repeated signed nonce is rejected, including after process restart. Expired nonces may be removed after the signed request's replay window is past. No Redis dependency or memory fallback.
- Ticket issuance validates active NeverLauncher access and Minecraft sessions **in the same `BEGIN IMMEDIATE` transaction**, verifies matching user, Minecraft UUID and current auth epoch, checks node scope and project role, and atomically replaces an older outstanding ticket for that node/player. Secrets have 256 bits of OS entropy; only SHA-256 hashes persist.
- Redemption validates node signature, nonce, current node identity and epoch, ticket expiry, original access token state, session and Minecraft token state and auth epoch; nonce insertion + `active → consumed` CAS + audit commit in the **same durable SQLite transaction**. An authenticated but invalid ticket still burns the nonce in a committed transaction. Consumed tickets cannot be updated or deleted by the normal schema.
- Issuance TTL is at most 120 seconds and never extends beyond the access, NeverLauncher or Minecraft session expiry. Unknown, revoked, replaced and expired tickets fail closed. Node key rotation invalidates pending tickets.
- Schema migration **323 → 324**; upgrades from **322** are still supported. No changes to previously encrypted MFA AAD or stored authentication secrets.

## Operational CLI

Only a trusted local service administrator who can access the private 0700 SQLite directory should run these commands. The `join-sign` operation is for an authenticated ServerBridge node that holds its own private key; never copy node private keys to the public launcher or Admin frontend. JSON secrets are read from mode 0600 regular files.

```sh
neverlauncher-sqlite core-init --db /secure/never.sqlite
neverlauncher-sqlite join-keygen --key-file /secure/node/node.key > /secure/node/public.json
neverlauncher-sqlite join-node --db /secure/never.sqlite --input /secure/node/enroll.json
neverlauncher-sqlite join-issue --db /secure/never.sqlite --key-file /secure/mfa.key --input /secure/issue.json
neverlauncher-sqlite join-sign --key-file /secure/node/node.key --input /secure/node/sign.json > /secure/node/proof.json
neverlauncher-sqlite join-redeem --db /secure/never.sqlite --input /secure/node/redeem.json
neverlauncher-sqlite join-status --db /secure/never.sqlite --input /secure/inspect.json
neverlauncher-sqlite join-disable --db /secure/never.sqlite --input /secure/disable.json
neverlauncher-sqlite join-prune --db /secure/never.sqlite
```

Sample JSON (each in its own private file):

- `enroll.json`: `{"ID":"node1","ProjectID":"my-project","ProfileID":"vanilla","Channel":"stable","PublicKeyHex":"<64 hex digits from public.json>","Actor":"owner"}`. The actor must be a stored active owner/admin or have the appropriate project owner/admin binding.
- `issue.json`: `{"accessToken":"nla_...","minecraftToken":"nlm_...","nodeId":"node1"}`. The user needs project owner/admin/player authorization (or global owner/admin) and both tokens must be current.
- `sign.json`: `{"nodeId":"node1","identityEpoch":1,"action":"redeem","ticket":"nlj_..."}`. The node signs over `SHA-256(ticket)` and emits a `NodeProof` structure. For a generic signed ping, use `"action":"ping","data":"payload"` instead.
- `redeem.json`: `{"ticket":"nlj_...","proof":{...contents of proof.json...},"remoteIp":"127.0.0.1"}`.
- `inspect.json`: `{"ticket":"nlj_..."}`.
- `disable.json`: `{"nodeId":"node1","actor":"owner"}`.

Private key generation writes 64-byte Ed25519 key material with exclusive-create mode 0600; public key material is safe to use for node enrollment. Do not print private credential input files in build logs.

## Deployment gate and limitations

**This is operational SQLite Core code and local CLI, not yet a drop-in HTTP/ServerBridge replacement.** Production HTTP API continues using PostgreSQL, and SQLite cannot be enabled as the entire API repository until remaining durable state, auth/authorization parity, trusted-device binding, node runtime attestation, coordination and deployment requirements are fulfilled. The SQLite ticket path currently requires the project's canonical Minecraft identity and authenticated session, but does not implement Guard/trusted-device admission or HTTP-facing ServerBridge runtime attestation; those checks must not be silently bypassed. A stale database-backup restore requires an explicit trust/ticket reset before traffic is re-enabled; restoring an old live state alone cannot guarantee that a previously issued ticket stays consumed.

The generator environment does not have Go 1.27.3 or the pinned real SQLite driver available and uses intentionally rejected overlayfs. Local checks cover isolated Go package compilation with temporary test substitutes, `go vet`, schema execution and SQL invariants; none of those are a real native-driver integration test. Release certification requires the accompanying GitHub Actions job with `go test -race`, process/restart tests on supported ext4/XFS/Btrfs, signed-request end-to-end test, and deployment smoke test before production rollout. Never package or deploy temporary validation substitutes.
