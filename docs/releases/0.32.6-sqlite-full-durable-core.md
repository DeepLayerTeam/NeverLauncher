# NeverLauncher 0.32.6 — DEP01/02 SQLite durable ServerBridge, packages, extensions

This patch adds working SQLite Core operations; it **does not** assert full HTTP Backend parity or certification as production-ready. The main API still selects PostgreSQL. Do not enable SQLite as the principal API repository yet.

## Migration and integrity
- Core schema `user_version=326` (upgrade from 322–325 is atomic using the existing single-writer `BEGIN IMMEDIATE` store and WAL `synchronous=FULL`). Unknown/future versions fail closed.
- Real embedded package bytes, max 16 MiB each, SHA-256-verified on read and startup, immutable rows (no outside blob dependency for these artifacts).
- Trusted Ed25519 extension publishers, immutable identity and signature-verified package ID/version/digest, persisted publish decisions; revoking a publisher disables currently enabled installs in the **same** transaction.
- Global/project-scoped install CAS generation + append-only history; JSON extension state CAS + append-only hash history; audit in every state transition. Extension secrets do **not** go into JSON state.
- ServerBridge runtime heartbeat verified against enrolled node key with timestamp, identity epoch, signed message and durable nonce. Dispatch and acknowledgement **also require** signed Ed25519 proofs and new nonces. Typed commands only, no shell/argv dispatch. No automatic re-delivery following uncertain network failure: expired leased commands become `indeterminate` and require manual reconciliation. Node key rotation or disable invalidates pending/leased commands atomically.
- Startup integrity verifies package bytes and Ed25519 extension package signatures, command request hashes, extension history and active trust, KV hashes, WAL DB integrity, foreign keys and previous security invariants.

## Operator CLI (local management only)

Run `neverlauncher-sqlite core-init --db /secure/local/state.db` on supported local ext4/XFS/Btrfs storage. Other commands accept `--db` and `--input` pointing to a 0600 JSON input file (`readPrivateJSON` refuses input above 1 MiB, symlinks and permissive permissions). `package-import` additionally uses `--package` pointing to a local private regular file <=16 MiB.

Commands: `bridge-runtime`, `bridge-command-enqueue`, `bridge-command-lease`, `bridge-command-ack`, `bridge-command-get`, `package-import`, `package-verify`, `extension-publisher`, `extension-revoke`, `extension-publish`, `extension-install`, `extension-install-get`, `extension-state-put`, `extension-state-get`.

Sign a runtime heartbeat using `CanonicalNodeRequest("runtime", proof, SHA256(bridgeRuntimePayload))`. Sign dispatch/ACK using `control-lease` / `control-ack`, binding **every** request parameter to the signed body. Operations require previously enrolled Ed25519 node identities and appropriate operator authorization. Preserve stdout mode 0600 when capturing lease tokens. Never log lease tokens or encrypted/plaintext secrets.

An extension publisher signs `NeverLauncher/extension-package/0.32.6\n<extensionId>\n<version>\n<sha256>\n`. The SHA-256 covers persisted bytes; signature and trusted publisher key are checked during publication and verification. Installation records are **control-plane selection** and do not independently execute the extension. Package installs need downstream runtime integration before activation.

## Verification and release gate

Included `full_state_326_test.go` tests signed package validation, CAS concurrency, restart persistence, revoked publisher disabling, signed heartbeat replay prevention, single-delivery commands, lost ACK/indeterminate safety, and tampering. CI `sqlite-full-state-0326.yml` runs the complete pinned Go/SQLite driver with race tests and CLI smoke checks on a native filesystem. A static Go compile with temporary stand-ins and SQLite DDL checks are **not** substitutes for this CI gate.

**Remaining before declaring DEP01 complete:** wire all SQLite operations into the live HTTP/ServerBridge and extension host paths, migrate authoritative package registries, bridge telemetry/topology/events and all required security/extension secrets and device state, prove API authorization parity and full crash/power-loss restore, and run measured native FS load and failover/fencing tests. Do not silently fall back to in-memory state or change the live deployment mode in this patch.
