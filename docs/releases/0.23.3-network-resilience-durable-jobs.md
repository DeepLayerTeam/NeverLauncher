# NeverLauncher 0.23.3 — Network Resilience & Durable Jobs

## Исполняемый путь

- `neverruntime::download_missing_files_with_progress` и `repair_client_with_progress` используют `durable_downloads::start`, который **до сетевой активности** записывает исходный подписанный manifest и закреплённый публичный ключ в журнал задания.
- `download_scheduler` использует `http_resume::download_verified_controlled`, ограничивает параллельность, повторяет временные ошибки, суммирует фактически переданные байты и продолжает независимые файлы, если один файл исчерпал повторы.
- `http_resume` сохраняет/проверяет strong ETag, Range/If-Range и полную сумму SHA-256, добавляет таймауты на HTTP-запросы и получение тела. При pause/cancel частичный файл синхронизируется перед выходом.
- `network_resilience` задаёт лимиты: 12 с connect, 30 с send, 20 с ожидание очередного фрагмента, максимум 7 попыток, exponential full jitter до 20 с, Retry-After до 120 с, поддерживает секунды и RFC 9110 IMF-fixdate.
- `durable_downloads` хранит две чередующиеся версии журнала в `.neverlauncher/download-job-{0,1}.json`. Восстановление повторно проверяет цифровую подпись через **текущий pinned key из настроек Desktop**, а не доверяет собственному ключу из журнала. При завершении всё перепроверяется стандартной SHA-256 логикой. Для прерванного/неуспешного задания журнал остаётся, для полностью успешного — удаляется.
- Tauri commands: `pending_download_job`, `resume_download_job`, `control_download_job` и события `neverlauncher-download-progress`. Desktop поднимает прерванное, но не вручную приостановленное задание, при запуске и отображает кнопки паузы, продолжения и отмены.

## Семантика

- **Pause:** прекращает сетевые операции и задержки между повторами, сохраняет доступные проверяемые части и статус «paused» на диске; возобновление производится новым вызовом Resume, в том числе после перезапуска.
- **Cancel:** прерывает операцию и удаляет журнал. Частичные объекты остаются во внутреннем хранилище, но никогда не используются без совпадения подписанного SHA-256/размера, URL и сильного ETag. Повторное явное скачивание может повторно использовать подходящую часть.
- **Failed:** ошибки конкретного файла не мешают завершению других; журнал сохраняется как `pending`, чтобы при следующем запуске повторить только недостающие/непроверенные файлы.
- **Crash:** целевые файлы, прошедшие полную SHA-256 в прошлой попытке, будут пропущены; `.part` применяется только с безопасным Range. Две версии журнала предотвращают потерю всей операции при прерывании записи.

## Проверки

```sh
cargo test --manifest-path runtime/neverruntime/Cargo.toml network_resilience
cargo test --manifest-path runtime/neverruntime/Cargo.toml download_scheduler
cargo test --manifest-path runtime/neverruntime/Cargo.toml durable_downloads
cargo test --manifest-path runtime/neverruntime/Cargo.toml http_resume
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
cd apps/desktop && npm ci && npm run build
```

Тестовые сценарии: 503 → кратковременный разрыв body → 206 Range/If-Range в одном запуске; пауза/переоткрытие сохранённого подписанного задания и загрузка только неполученной части; отказ при несовпадении закреплённого ключа; bounded backoff с jitter и Retry-After HTTP-date; остановка ожидания по pause/cancel. Rust-сборку и Tauri E2E необходимо подтвердить на целевой платформе; наличие теста само по себе не свидетельствует о его прохождении.
