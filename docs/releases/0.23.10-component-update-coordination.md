# NeverLauncher 0.23.10 — Component Update Coordination

## Исполняемый путь

Набор **Desktop + Guard + Runtime + sensor (Windows) + updater helper** устанавливается единой транзакцией. Desktop передаёт pinned SHA-256 пакета отдельному Go updater, предварительно скопированному в приватный каталог пользователя: обновляемый `neverlauncher-cli` больше не является собственным запущенным образом (Windows sharing violations). Существующий `transactionalUpdater0156` подготавливает **все** проверенные SHA-256 файлы и состояние в staging, сохраняет резервные копии и durable journal до начала переключения. При любой ошибке commit запускается rollback. `update recover` идемпотентно восстанавливает повреждённый набор.

При прямом старте Desktop **до запуска Guard/Tauri** внешний updater делает `update status`; при незавершённом журнале Desktop запускает приватную копию updater для `update recover --wait-pid <desktop-pid> --restart-desktop <executable>`, после чего завершается. Helper дожидается освобождения Desktop и только затем выполняет recovery. Перед автоматическим рестартом дополнительно сверяются SHA-256 всех компонентов с установленным state, включая новый updater. Для macOS при сбое между подписанным переключением `.app` и записью внешнего state состояние можно повторно получить только из проверенного Ed25519 manifest в целостном sealed `.app`.

## Подписанный набор

`COMPONENT_UPDATE_MANIFEST.json` включает `componentSet` (matrix v1) с явными `provides` и `requires` и обязательным `supportFiles[component=updater]`. `COMPONENT_SET_SIGNATURE.json` содержит Ed25519-подпись **точных байтов** manifest и его SHA-256. Production updater использует **только публичный ключ, встроенный в бинарник в доверенной сборочной среде** (`main.componentSetTrustedKey02310`). Внешний пакет не может подменить этот корень доверия.

Проверяются: платформа и архитектура, хеши/размеры файлов, подпись manifest, состав набора, матрица протоколов (NeverGuard IPC 4, Windows sensor IPC 3, component updater 2), обязательные зависимости и платформенные подписи бинарников (Authenticode/ELF/Mach-O/codesign). Проверка выполняется **перед** установкой и **после** переноса пакета в staging, до первого изменения live-файлов.

На переходе с 0.23.9 используется совместимый `schemaVersion: "1.0"` с новыми полями и sidecar-подписью: установленный updater 0.23.9 уже проверяет pinned package hash и способен принять этот контейнер. **Важно:** старый 0.23.9 updater не умеет самостоятельно проверять Ed25519 sidecar. Обязательная signature validation начинает действовать после установки нового updater 0.23.10. Это ограничение переходной совместимости, не гарантия защиты старого приложения от атак на источник закреплённого package hash.

## Release signing

1. Сгенерировать Ed25519 signing seed в защищённом ключевом хранилище. Не сохранять seed в репозитории.
2. Настроить секрет `NEVERLAUNCHER_COMPONENT_SET_ED25519_SEED` (ровно 32 байта hex) и соответствующий **проверенный** `NEVERLAUNCHER_COMPONENT_SET_ED25519_PUBLIC_KEY` (32 байта hex).
3. Передать публичный ключ в доверенную Go release-сборку через `-ldflags '-X main.componentSetTrustedKey02310=…'`. Частные данные в исполняемый бинарник **не встраиваются**.
4. `scripts/release/component_set_sign.py` связывает неизменяемый manifest, протоколы и Ed25519-подпись; при отсутствующем секрете или несовпадении публичного ключа production-сборка прекращается.
5. Linux tar.gz, Windows zip и macOS `.app`/zip включают подписанный manifest и `COMPONENT_SET_SIGNATURE.json`. Для сборок CI без публикации допускается только явно указанный `--development`, а CI Linux использует одноразовую тестовую пару Ed25519 для испытания production-пути.

Release-подписи Windows/macOS, реальный smoke-тест Windows file locks, подпись macOS, notarization и проверка на чистой машине остаются **обязательными внешними gate** перед публикацией production.

## Проверка

```bash
python3 scripts/version/manage.py check
python3 -m unittest discover -s scripts/release -p test_component_set_sign.py -v
(cd cli && go test ./cmd/neverlauncher -run 'TestSignedComponentSet02310|TestCoordinatedPackageCommitAndFailure02310|TestComponentSetInterruptedSwitchRecovery02310' -count=1)
(cd cli && go vet ./cmd/neverlauncher)
(cd cli && go build -ldflags '-X main.version=0.23.10' -o /tmp/nl ./cmd/neverlauncher)
/tmp/nl update component-self-test
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

Интеграционные Go-тесты покрывают подмену manifest/ключа, несовместимый протокол, отсутствие updater, испорченный файл пакета до commit, успешную транзакцию всех четырёх ролей (Linux) и crash recovery после переключения только первого файла. Сценарий требует тестирования на Windows x64/ARM64, Linux x64/ARM64, macOS x64/ARM64 на настоящих подписанных пакетах.
