# NeverLauncher 0.27.10 — Visual Client Factory Builder

## What actually runs

The visual Client Factory appears in **Release Workspace → Build Workspace** after the operator creates a workspace. The browser never installs arbitrary binaries itself. The API spawns the existing `neverlauncher runtime client-factory` executable in a private, per-job directory and verifies its outputs through `runtime client-factory verify`. This is an executable end-to-end build path, not a mock UI. An operator must have `release:prepare` for the owned workspace; session ownership is checked again on every job, export, diff and cancellation request. A workspace that is already built cannot start a new job.

Inputs: pinned Minecraft/loader family, exact loader version (when creating from version), OS/arch. Modrinth `.mrpack` and CurseForge ZIP uploads are supported for local installation; the imported pack is checked against the workspace's pinned Minecraft and loader after verification. Import failures show the CLI's missing-artifact report. Existing directory import, stage, scan, diff, validate and Build Workspace packaging remain available below the wizard.

The UI presents input preview, asynchronous job status, processor logs, cancellation, persisted job history, exact InstallPlan details (Java, outputs, sources, processors and reproducibility digest), SHA-256 diff against a prior job in the same workspace, a ZIP of locally verified outputs and job deletion.

## Configure the worker

Provide an **absolute executable** and **private absolute root**. This is mandatory; if either is unavailable the API returns HTTP 503 rather than pretending a build succeeded:

```bash
export NEVERLAUNCHER_FACTORY_CLI=/usr/local/bin/neverlauncher
export NEVERLAUNCHER_FACTORY_ROOT=/var/lib/neverlauncher/factory
# Optional Java for Forge/NeoForge (exact path to binary):
export NEVERLAUNCHER_FACTORY_JAVA=/usr/bin/java
# For untrusted Forge processors on a prepared Linux bwrap host:
export NEVERLAUNCHER_FACTORY_SANDBOX=required
```

The production API Dockerfile now also builds the CLI and installs OpenJDK 21; the compose file adds a private persistent named volume for factory artifacts. Existing source materializers require outgoing TLS access to allowed vendor distribution endpoints. Java 8 legacy installs need a separate compatible Java runtime; do not imply they are certified by the included Java 21 runtime.

`NEVERLAUNCHER_FACTORY_SANDBOX=required` fails closed where the 0.27.3 bubblewrap sandbox cannot start. Default execution retains the previous `process` isolation mode; **this is not a security boundary against malicious third-party installer code**. For untrusted processors, dedicate a secured worker host/container with a verified sandbox and tight network policy. The bridge bounds concurrent builds to two processes, CPU-related work to six downloader workers per build, limits logs to 2 MiB and enforces a 75-minute wall clock timeout. Jobs are stored with 0700 directories, progress survives browser refresh and completed jobs can be deleted. Twenty retained jobs per workspace are allowed.

## API endpoints (all authenticated and owner-scoped)

- `POST /api/v1/build-workspaces/{workspaceId}/factory/jobs` — launch exact-version build, JSON `{minecraft,loader,loaderVersion,target}`.
- `POST /api/v1/build-workspaces/{workspaceId}/factory/modpack-jobs` — multipart upload `file` and `target` (max 128 MiB request).
- `GET /api/v1/build-workspaces/{workspaceId}/factory/jobs` — persistent workspace history.
- `GET /api/v1/build-workspaces/{workspaceId}/factory/jobs/{jobId}` — state, limited logs, verified plan and optional import report.
- `POST /api/v1/build-workspaces/{workspaceId}/factory/jobs/{jobId}/cancel` — cancel active/queued worker.
- `GET /api/v1/build-workspaces/{workspaceId}/factory/jobs/{jobId}/diff?baseJob=...` — output-by-output SHA-256 diff.
- `GET /api/v1/build-workspaces/{workspaceId}/factory/jobs/{jobId}/export` — reverify and stream local-use ZIP with InstallPlan.
- `DELETE /api/v1/build-workspaces/{workspaceId}/factory/jobs/{jobId}` — delete completed/failed/cancelled job and reclaim disk.

All CLI arguments are formed from strict enums/exact versions, never arbitrary URLs, paths, scripts or command lines. A cancellation, timeout, missing file or failed integrity verification never creates a completed job.

## Publishing and limits

**Export is for local build transfer / inspection, not an authorization to redistribute third-party Minecraft files.** It never signs or publishes a release. To publish, import appropriate verified files into Build Workspace, stage, validate, sign and publish via the existing release workflow. The prior 0.27.6 redistribution permission gates still need to be applied to any files being distributed. Direct one-click promotion from a Client Factory job to a release package is intentionally **not** implemented: it would bypass permission checks and package validation.

The preview before the build shows source/target/steps; the exact upstream-resolved dependency graph and lockfile are available only after materialization. Diff is between two successfully completed jobs in the same workspace. No claim is made about actual Minecraft game launch, host isolation under `process`, third-party license grants or all OS/arch runtime E2E.
