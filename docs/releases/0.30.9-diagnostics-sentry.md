# NeverLauncher 0.30.9 — Diagnostics & Sentry

Implemented optional **actual Sentry event ingestion** using the envelope HTTP API:

- Backend: `services/api/internal/sentrydiag` wraps the real API handler. Panic and HTTP 5xx events are sent asynchronously through a bounded queue with a 3-second HTTP timeout; URLs, headers, bodies, tokens and user identities are not sent. Off by default.
- Desktop/Tauri: native Rust reporter handles consented native panics and strictly filtered JS frames. User-facing opt-in checkbox is disabled by default. Native process independently enforces consent; JavaScript cannot bypass it via `invoke`. Cannot read session or credential stores.
- JVM: Java 17+ uncaught exception handler for Java Extension Host, with safe class/method/filename/line frames. Never serializes raw exception messages, environment, system properties or Java arguments. Requires administrator opt-in. Does not change exception termination semantics.
- JS: Vite produces hidden source maps; CI/release upload script sends maps before deleting them from the distributable directory.
- Native debug symbols: release upload script supports PDB/dSYM/unstripped ELF artifacts from the *same* build. Does not synthesize symbols from a stripped executable.
- JVM ProGuard/R8 mapping: uploaded only when an actual mapping file and matching embedded UUID are provided. Normal Java SDK builds are not obfuscated, so mapping upload must be skipped.

## Deployment

Backend:

```sh
NEVERLAUNCHER_SENTRY_BACKEND_ENABLED=true
NEVERLAUNCHER_SENTRY_BACKEND_DSN=https://PUBLIC_KEY@sentry.example.org/PROJECT_ID
```

Desktop: configure public `NEVERLAUNCHER_SENTRY_DESKTOP_DSN` at compile time or in the native process environment and let users enable **Отправлять обезличенные отчёты о сбоях** in Settings. Without an explicit opt-in nothing is transmitted; desktop runs normally if Sentry is unavailable. DSN is never read from remote API config.

JVM extension host (operator-managed):

```sh
NEVERLAUNCHER_SENTRY_JVM_ENABLED=true
NEVERLAUNCHER_SENTRY_JVM_DSN=https://PUBLIC_KEY@sentry.example.org/PROJECT_ID
NEVERLAUNCHER_SENTRY_RELEASE=neverlauncher@0.30.9+YOUR_GIT_SHA
```

For symbolication all targets should use the same `neverlauncher@VERSION+GIT_SHA` release identity. For Rust use compile-time `NEVERLAUNCHER_RELEASE_ID`, and for backend inject Go `version` and `commit` via ldflags. JVM requires `NEVERLAUNCHER_SENTRY_RELEASE`.

The Sentry public DSN key is *not* the Sentry API auth token. `SENTRY_AUTH_TOKEN` must be available **only in CI** and never packaged with the launcher.

### Release artifacts

After `NEVERLAUNCHER_SENTRY_RELEASE_BUILD=1 npm run build`, with fresh Desktop `dist/` (hidden `.js.map` included) and the **matching** native symbols:

```sh
SENTRY_AUTH_TOKEN=... SENTRY_ORG=... SENTRY_PROJECT=... \
python3 scripts/diagnostics/upload_release_0309.py \
  --version 0.30.9 --commit YOUR_GIT_SHA \
  --js-dist apps/desktop/dist --native-symbols /private/build/symbols
```

If obfuscation was used, add `--jvm-mapping /private/build/mapping.txt --jvm-jar /private/build/host.jar --mapping-uuid UUID_FROM_BUILT_JVM`. Never guess a mapping UUID; a release ID alone does not link obfuscation maps.

**Release gate:** only package the desktop assets after successful map upload; the script deletes uploaded `.map` files *only on success*. Failed upload leaves maps untouched for retry and must block release. Do not publish symbols or mapping files as client assets.

### Verified and unverified

Unit tests cover real HTTP ingest, privacy checks and errors. Production/Sentry SaaS, native Windows/macOS binaries, Rust/Tauri integration and cross-platform symbolication still require CI and release-gate execution. Optional diagnostics never block Minecraft launch or ordinary API requests.
