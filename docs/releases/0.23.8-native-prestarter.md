# NeverLauncher 0.23.8 — Native Prestarter

## Implementation

`prestarter/cmd/neverprestarter` is a stand-alone Go 1.22+ native executable. It has **no JVM dependency**, no backend account credentials, and no `cargo` dependency at run time. The first-run path executes real NeverRuntime CLI binaries, **never fake endpoint requests**:

1. Read an Ed25519-signed configuration envelope from `bootstrap.signed.json` next to the binary (or `--config`). The signed bytes are Base64 in the envelope, with an Ed25519 signature over **exact raw payload bytes**. Verify against a root public key embedded via `-ldflags` at build time. No unsigned network-config or trust-on-first-use. Local operator builds can pass `--operator-root-public-key`; it cannot override an embedded root.
2. Restrict target to an exact `windows|linux|darwin / amd64|arm64` match; sanitize project/profile/channel IDs and validate HTTPS artifact source, signed size and SHA-256 for `neverruntime`, `desktop`, `neverguard` and both manifests.
3. Acquire the process-wide installation lock. Verify existing content cache or offline bundle first. Otherwise stream HTTPS downloads with size caps, ETag/If-Range and HTTP 206 Content-Range validation. Hash each artifact in full before caching, again before copying into versioned staging and again before activating.
4. Install a complete immutable component release under `launcher/releases/<signed-payload-hash>-<platform>/`; use durable, alternating `active-{0,1}.json` records as last-known-good. Interrupted `.incomplete-*` staging is discarded on recovery. For a failing new bootstrap, restore the previous verified release as a new pointer generation.
5. Retrieve the signed profile manifest and verify it using `neverruntime verify --manifest ... --pinned-public-key ...`, the existing Ed25519 verifier. Project/profile/channel identity must match the signed Prestarter payload.
6. Resolve the Java **major and distribution from that verified Minecraft profile**. Require a pinned Managed JRE distribution manifest, call `neverruntime java ensure --major ... --manifest ... --manifest-sha256 ...`. The existing Managed Java installer performs staging, integrity inventory, OS/arch/major checks and JVM self-test. Online manifest archives resolve at the original HTTPS URL; offline archives are resolved relative to `offline/managed-jre/manifest.json`.
7. Install/repair client release via the added `neverruntime sync-local --manifest <previously verified path> --root ... --pinned-public-key ...`. This invokes the existing scheduler, content-addressed cache, managed-only transactional client release and recovery. It does **not** re-fetch a mutable manifest URL after verification.
8. Provision the existing Desktop config only on the first run, preserving subsequent user settings. Launch the verified native `neverlauncher-desktop` with `NEVERLAUNCHER_CONFIG_DIR`, pinned Java manifest, and project/profile paths. Optional `--launch-profile --username Player123` launches the Minecraft process via `neverruntime launch`; only signed `offlineMode` profiles are eligible and, to preserve NeverGuard's authenticated supervisor enforcement, this direct option is disabled on Windows. Windows and online/Microsoft profiles are launched through Desktop.

This is an executable Go path with unit/integration tests. It does **not** replace the earlier Rust Download Scheduler, file transactions, Java installer or signature verifier. Those are invoked as actual installed binaries.

## Production configuration and signing

The signed payload is JSON with this shape (each `<...>` is an operator-supplied release value):

```json
{
  "schemaVersion": "1.0", "projectId": "demo", "profileId": "vanilla",
  "channel": "stable", "backendUrl": "https://api.example.org",
  "profilePublicKey": "<64-hex-ed25519-profile-public-key>",
  "manifest": {"url":"https://cdn.example.org/manifest.json", "sha256":"<64-hex-sha256>", "size":1234},
  "javaManifest": {"url":"https://cdn.example.org/jre/distribution.json", "sha256":"<64-hex-sha256>", "size":1234},
  "targets": [
    {"os":"linux", "arch":"amd64", "components":[
      {"name":"neverruntime", "url":"https://cdn.example.org/neverruntime", "sha256":"<64-hex-sha256>", "size":1234},
      {"name":"desktop", "url":"https://cdn.example.org/desktop", "sha256":"<64-hex-sha256>", "size":1234},
      {"name":"neverguard", "url":"https://cdn.example.org/neverguard", "sha256":"<64-hex-sha256>", "size":1234}
    ]}
  ]
}
```

Only released verified SHA-256 and sizes may be used. Each supported OS/architecture must have its own target. `profilePublicKey` is authorized by the **separately pinned bootstrap root** and used to verify Minecraft manifest; it is never copied from an unverified remote response. Never distribute the signing seed.

```sh
# Private seed is stored in a restricted 0600 file, not in environment or shell arguments.
cd prestarter
go run ./cmd/sign-config --payload ../bootstrap.payload.json \
  --private-key-file /secure/root-ed25519-seed.hex --out ../bootstrap.signed.json
cd ..
NEVERLAUNCHER_PRESTARTER_ROOT_PUBLIC_KEY='<your-public-key-hex>' \
  scripts/release/build-prestarter.sh
```

Production release binaries **must** be built with the project's true pre-provisioned root key. A missing key fails the build; test-only embedded keys from CI must never be published.

To run the downloaded Java-free native binary, place `bootstrap.signed.json` next to it and execute it. The default data root is `%LOCALAPPDATA%/NeverLauncher` (Windows), `~/Library/Application Support/NeverLauncher` (macOS), or `${XDG_DATA_HOME:-~/.local/share}/NeverLauncher` (Linux). Optional flags: `--config`, `--root`, `--offline`, `--offline-dir`, `--launch-profile`, `--username`, `--no-desktop`. The config file contains only trusted signed URLs/hashes; account secrets are never embedded.

An offline bundle can be supplied as:

```
offline/
  components/neverruntime[.exe]
  components/neverlauncher-desktop[.exe]
  components/neverguard[.exe]
  profile-manifest.json
  managed-jre/manifest.json
  managed-jre/<archives declared by the pinned Managed JRE manifest>
```

Every source file is verified against its pinned digest before use; the signed profile is verified again by NeverRuntime. Alternatively cache objects can be supplied as `offline/objects/<sha256>`.

## Tests and known validation boundaries

```sh
cd prestarter && GOPROXY=off go test -count=1 ./...
# With a provisioned root key, build 6 native OS/architecture executables:
NEVERLAUNCHER_PRESTARTER_ROOT_PUBLIC_KEY="$ROOT_PUBLIC_KEY" scripts/release/build-prestarter.sh
# Real Rust side: (requires cargo and dependencies)
cargo test --manifest-path runtime/neverruntime/Cargo.toml
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

Integration tests cover signed config rejection, partial HTTP recovery with Range/If-Range, invalid 206 rejection, offline installation without system Java, verified binary recovery, dual-slot activation, interruption cleanup, last-known-good rollback after a post-switch error, user saves preservation and launching Desktop with a signed first-run configuration. The end-to-end Go fixture replaces the external NeverRuntime/Java process with a deterministic process to test hand-off. **Real** clean-machine Minecraft launch, Rust compilation, OS code signatures, macOS notarization, Windows locks and architecture-specific JRE archives require platform testing; they are **not** certified by these Go tests. Native OS installers/branded bundle signing is separately planned for 0.23.9.
