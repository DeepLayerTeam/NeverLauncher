# NeverLauncher 0.24.0 — General Availability release procedure

## Code delivered

- Native installer commit safety: installer now **provisions Prestarter and Managed Java first**, and only then persists the new active release pointer. Interrupted/failed provision keeps the preceding valid generation; regression tests exercise canceled first installation and reinstall.
- `scripts/ga/verify_os_signature.py`: native verification against a **pinned** Authenticode signer, Apple Developer ID Installer Team ID or an isolated GPG signing keyring. It rejects unsigned installers; no test-signing bypass.
- `scripts/ga/clean_machine_e2e.py`: executable clean-OS VM runner. Installs real native package, invokes actual Prestarter and NeverRuntime, checks signed profile, Managed Java, verified file sync and process log from a real Minecraft launch. Requires real signed bundle, launchable Minecraft profile and a graphical VM; no fake Minecraft or Java.
- `scripts/ga/release_gate.py`: checks Ed25519-signed evidence for **all six** OS/architectures and hashes of actual installer, signature evidence, clean-machine test, certification and benchmark. Exactly one clean git commit across reports; no partial matrix, unsigned JSON, simulated test or mismatched artifact accepted.
- `.github/workflows/ga-0240.yml`: guarded manual verification of an externally produced release; fails if approved signing credentials or six evidence packages are absent.
- Updated 0.23.13 integration/benchmark runners to target NeverRuntime **0.24.0** while keeping 0.23.0 as the true sequential baseline; **do not** replace this with an artificial sequential client.

## Required real release sequence

1. Create an exact Git commit for all 0.24.0 sources, use that SHA in every tool and attestation. A source ZIP is **not** a Git commit.
2. Build Desktop/Guard/Runtime/sensor/updater/Prestarter and installable OS packages on Windows, Linux and macOS for each declared architecture. Verify every native OS signature with `verify_os_signature.py` using signer IDs from a protected release environment. The release must carry its actual detached `.asc` on Linux.
3. Boot disposable clean VMs (Windows x64/ARM64, Linux x64/ARM64, macOS x64/ARM64). Use signed bundles and a real Minecraft profile. Execute `clean_machine_e2e.py` with the corresponding installer and profile in an empty install root on Linux/macOS. **Windows game launch requires a separate real Desktop/NeverGuard GUI E2E**, not direct CLI launch; the script explicitly rejects the latter. Run repair and rollback tests and fault/power-loss scenarios in the VM. Record executed commands, image identifiers, real exit statuses and redacted process evidence.
4. Run `scripts/certification/certify.py --mode full` with a genuine compiled **0.23.0** baseline, a compiled 0.24.0 NeverRuntime and real Java, power-loss, Windows lock and signed installer evidence. Publish `benchmark.json` containing individual elapsed times, actual transferred bytes, compiler/OS metadata and SHA-256 of both binaries. The GravitLauncher comparison is a separate report and cannot substitute for this benchmark.
5. Assemble each platform's external evidence folder (`windows-amd64`, `windows-arm64`, `linux-amd64`, `linux-arm64`, `darwin-amd64`, `darwin-arm64`). Each must contain actual installer and its SHA-256, OS signature verification, real VM clean install, full certification and baseline benchmark results. Do not redact identity fields, result status or source SHA. Ed25519-sign the **exact raw bytes** of each `attestation.json` with the production GA attestation key, domain `NeverLauncher-GA-0.24.0-attestation-v1\n`; save lowercase hex signature to `attestation.sig`. Keep the signing key outside the repository.
6. Run `python3 scripts/ga/release_gate.py --attestations dist/ga-attestations --trusted-attestation-public-key <protected-public-key> --commit <exact-sha> --output dist/ga-0240-verification.json`. Exit code zero is **necessary**, not sufficient without examining the chain of custody of the attestation signer and the underlying CI/VM logs.
7. **Publish only after all six platform attestations verify** and the final benchmark and OS packages are made available to users. Publish build hashes and security bulletin alongside signed packages. Do not set a GA release tag when the gate is incomplete.

## Recovery and rollback

- When interrupted before activation, rerun installer `repair --root <install-root>` with its retained verified offline bundle. Do not remove `.neverlauncher-installer` or `.neverlauncher-prestarter` before recovery.
- If the currently active component set is incompatible, use the separate signed component updater and its transaction journal, not manual DLL/EXE replacement.
- For Minecraft game content, restore a previous release only through a **new signed game release generation**, referencing the old content hashes; don't replay a prior signed manifest or lower the component security generation.
- Preserve user-owned directories (`profiles/**/saves`, screenshots, mods and user config) during repair/uninstall; consult the managed-file registry for deletion boundaries.
- If an external process holds a Windows executable open, defer replacement until the file lock is gone and recover via the updater; never force-delete the running binary.

## Current certification status

The 0.23.13 snapshot shipped without `.git`, Rust toolchain, platform code-signing certificates, Apple notarization credentials, production Minecraft profile, disposable VM farm or a measured 0.23.0 baseline. **No production GA signature, clean-machine run, full Rust E2E, power-loss run or published benchmark is claimed from this environment.** The new release gate remains **incomplete**, unless independently executed evidence is supplied. Version 0.24.0 in source code does not imply approved GA publication.
