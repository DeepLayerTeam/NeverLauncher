# NeverLauncher 0.35.1 — User Journey Audit & Executable Acceptance

## Functional change

0.35.1 does **not** rename previous module/unit tests to E2E tests. The 35 `G` requirements and 19 `M` modules have been converted into 54 explicit owner/player/operator **user journeys** in [`compatibility/gravit/user-journeys-0351.json`](../../compatibility/gravit/user-journeys-0351.json). Each has an entry surface, production action, observable outcome, negative case, operator step classification, existing implementation/test references, historical status and explicit unverified state. The historical G/M baselines remain untouched. M17 intentionally forbids unsafe arbitrary code/credential access; do not "fix" that gap by reimplementing it.

Executable integration has two independent levels:

1. `scripts/acceptance/ux_0351.py audit` checks all 54 IDs against the frozen G/M inventory; confirms actual existing implementation/test files; refuses missing scenario fields, path traversal, catalog `verified` claims, and missing UX01–UX12 links. This is **not** execution evidence.
2. `scripts/acceptance/ux_0351.py run --ids M04,M07,G31 --report /tmp/0351-local.json` executes existing real Node test modules, deduplicates Go tests by package, captures exit code and output SHA-256 (never stores potentially sensitive stdout), and writes an atomic mode-0600 JSON result. For Go requirements the runner executes the corresponding actual Go package with `go test` and a timeout; `_test.go` is never treated as standalone code. Shell Minecraft E2E scripts are deliberately NOT auto-executed with the wrong credentials/environment. An unknown or missing executable is `blocked`, not passed.
3. `scripts/acceptance/run_owner_player_0351.sh /tmp/0351-owner-player.json` compiles and runs the **real Go Backend** in a disposable local memory-only instance, authenticates both admin and player, creates a project/profile/channel through actual guarded handlers, reads them back through public player routes, verifies denied anonymous write/audit, verifies unpublished files stay private, rotates refresh tokens and checks revocation. It never uses production PostgreSQL, live channels or an attestor. The helper accepts **only** localhost and requires `--isolated-test-instance`. Do not run it on a production host that has inherited privileged environment or different service configuration.

The included `.github/workflows/user-acceptance-0351.yml` runs the inventory/unit regressions plus native Backend lifecycle separately and uploads sanitized test summaries. A GitHub workflow existing in the source tree does not itself establish a passing CI run.

## Verification levels (must not be conflated)

| Level | Meaning | Can publish stable? |
|---|---|---|
| Catalog `not-run` | Requirement is fully specified with code/test refs but no new acceptance run | No |
| `local-regression-passed` | Real existing Node/Go test command exited 0 | No |
| `local-loopback-passed` | Real disposable Backend performed owner/player HTTP lifecycle | No |
| Real native/GUI acceptance | Real installer, Desktop, Minecraft and ServerBridge used on the specified target | Not by itself |
| Protected GA | Signed ValidationEvidence, all target stages + independent policy and PostgreSQL stable commit | Only through the existing Backend release gate |

Current 0.35.1 catalog: **54 mapped, 0 target-verified**. Forty-nine other compatibility or release decisions are not inferred from the few local checks. No real Minecraft E2E, native installer, protected PostgreSQL or runtime GA certification is claimed by this document.

## Practical acceptance workflow

Run `python3 scripts/acceptance/ux_0351.py audit` on each code change affecting G/M parity. Run `python3 scripts/acceptance/test_ux_0351.py -q` and the scoped CLI tests. Run the real loopback Backend journey with Go 1.27.3 or newer (matching the Go module) and a clean CI machine. Before calling **any** G/M journey verified, manually execute its `entry`, `action`, `success`, and `negative` on the target device/server and attach an independent evidence receipt; a passing unit test alone is not sufficient. Never promote the catalog's static `not-run` field to `verified` in source control, and never call a local result GA evidence.

### UX01–UX12 dependency tracking

The runner embeds a nonempty mapping from each planned UX item to concrete G/M IDs and verifies referential integrity; see `UX` in `scripts/acceptance/ux_0351.py`. Planned later releases must replace remaining `advanced` operator operations with supported UI workflows when appropriate. Do not conflate necessary deployment secrets, native OS permissions, live provider accounts or release signing with avoidable manual player setup. `M17` always remains `prohibited` and is accepted only through an enforceable negative test.

### Known blockers to 0.36

- `0.35.0` GA readiness is **NOT VERIFIED**. This patch does not bypass its Backend/PostgreSQL stable guard.
- Real owner release with staging, independent validation, publication, observation and rollback through Admin still needs complete target E2E acceptance. CRUD alone cannot establish that outcome.
- Player onboarding, real signed installer, Java/loader, optional mod installation and Minecraft join need the provisioned test matrix planned for 0.35.2 onward.
- Current catalog classifies required operator work explicitly; it does not assert all 54 features have full upstream functional parity.
- Unit tests that require Go 1.27.3 cannot be run on an older Go installation. A missing toolchain must remain `blocked` in acceptance output.
