# NeverLauncher 0.28.3 — JVM Launch Profiles

The existing `nl server-bridge host` supervisor **executes** supported Java launch profiles. No separate script-only or shell-based launch engine has been introduced. The already shipped start/stop/restart, supervision, crash-limit, stop request, logs, and host identity checks remain in force.

## Supported launch modes

| Launch mode | Java invocation | Required inputs |
| --- | --- | --- |
| `java-jar` | `java [approved JVM args] -jar <jar> [server args]` | `--server-jar`, or safe platform JAR autodetection |
| `java-args-file` | `java [approved JVM args] [validated user JVM args] @<vendor file> [server args]` | `--java-args-file` or Forge/NeoForge autodetection |
| `java-main-class` | `java [approved JVM args] -cp <classpath> <mainClass> [server args]` | `--main-class` and `--classpath-entry` or `--classpath` |
| `java-module` | `java [approved JVM args] --module-path <modulepath> --module <module>[/<mainClass>] [server args]` | `--module`, `--modulepath-entry` or `--modulepath`; Java >= 9 |

`--main-class` and `--module` also infer the correct mode when `--launch-mode` is omitted. Entry-point names follow Java identifier rules; main-class and module modes cannot mix a configured server JAR or vendor args file. Module mode is deliberately separate from classpath mode to avoid silent classloader ambiguity.

## Production examples

```sh
# Standard Paper JAR: no shell command string, binary resolved as Java.
nl server-bridge host configure --server-root /srv/mc/paper --platform paper \
  --java /usr/lib/jvm/java-21-openjdk/bin/java --launch-mode java-jar \
  --server-jar paper.jar --jvm-arg -Xms1G --jvm-arg -Xmx4G \
  --server-arg nogui --restart-policy on-failure

# Boot via a Java main class with classpath jars from the project tree.
nl server-bridge host configure --server-root /srv/mc/custom --platform paper \
  --java /usr/bin/java --launch-mode java-main-class \
  --main-class org.example.minecraft.Main \
  --classpath-entry classes --classpath-entry 'libraries/*' \
  --jvm-arg -Xmx2G --server-arg nogui

# Named JPMS module, optionally selecting its main class.
nl server-bridge host configure --server-root /srv/mc/modular --platform paper \
  --java /usr/bin/java --launch-mode java-module \
  --module org.example.server --modulepath-entry modules \
  --main-class org.example.Main --jvm-arg=-Xmx2G

# Forge/NeoForge generated launch arguments still work.
nl server-bridge host configure --server-root /srv/mc/neoforge --platform neoforge \
  --java /usr/bin/java --launch-mode java-args-file \
  --java-args-file libraries/net/neoforged/neoforge/21.1.0/unix_args.txt

nl server-bridge host start --server-root /srv/mc/custom
nl server-bridge host status --server-root /srv/mc/custom
nl server-bridge host logs --server-root /srv/mc/custom --stream stdout --follow
nl server-bridge host stop --server-root /srv/mc/custom
```

Use `--dry-run` on `configure` and `start` to inspect a validated profile without starting the child. On Windows use `java.exe`, platform-appropriate `;` path-list separation, and `win_args.txt` for Forge. `--classpath` and `--modulepath` accept an OS-native path-list; the equivalent `--classpath-entry` / `--modulepath-entry` may be repeated.

## Effective constraints

- Only a Java entry point is launched. Before Java's `-version` is executed, the executable name must be `java` (`java.exe` on Windows). A custom executable path is an **explicit trusted-host opt-in** using `--allow-custom-java-executable` during local configuration; this is *not* a remotely delegable RBAC permission. The host's OS account and `host.json` permissions remain the security boundary; it must not be exposed to game operator roles.
- Classpath entries must be existing directories or `.jar` files inside the resolved server root. Classpath wildcard support is limited to `directory/*`; modulepath entries must be existing directory or `.jar`, no wildcard. Entries are checked again before every start; symlinks that escape the server root are rejected. The limit is 128 entries in each path list.
- Explicit JVM flags have an allowlist for bounded `-Xms`, `-Xmx`, `-Xss` settings (up to 1 TiB heap, 64 MiB thread stack), selected GC/tuning flags and narrowly scoped JVM properties. Free-form `-javaagent`, `-agentlib`, `-Xbootclasspath`, `@response-file`, arbitrary `-Djava.*` and command-execution hooks are rejected. App/server arguments are passed as argv, never shell-interpolated; empty, control-character and `@response-file` game tokens are rejected.
- In Forge/NeoForge `java-args-file` mode, the optional `user_jvm_args.txt` is read into memory, checked against the same approved flags, and its checked values are passed directly as argv, preventing a separate second read of that user-supplied file at JVM startup. The vendor-provided Forge/NeoForge args file remains **operator-approved external launch input**. It can contain loader-required module/classpath directives that do not fit the JVM tuning allowlist. Its provenance and signature must be verified by trusted provisioning; strict package signing/verification is part of 0.28.12, not claimed here.
- The host is a JVM supervisor, not a generic executable installer or a sandbox against a malicious Minecraft JAR, plugin, or Java module. An approved Java main class can execute arbitrary Java code at the privilege level of the host's OS identity. Use a least-privileged OS account; service-level confinement is planned for 0.28.11.
- Profile paths are checked immediately before creating argv, but mutable jars/classes/vendor argfiles are not hash-pinned in this release. An operator changing files in place between validation and JVM reading them can change executed code. For higher-trust environments use immutable, privately owned artifact trees and a trusted artifact rollout procedure.

## Verification performed

Go tests exercise the existing 0.28.2 Host lifecycle and new 0.28.3 positive/negative profiles. Includes actual `javac` compilation and Java execution for both `-cp` and JPMS `--module`, fake-Java argv inspection, custom executable authorization, response-file and Java-agent rejection, directory traversal and symlink replacement, and the Forge optional user JVM argument file. The full repository suite, cross-platform runtime E2E and live Minecraft server integration are separate release checks; this implementation does **not** claim to have completed them.
