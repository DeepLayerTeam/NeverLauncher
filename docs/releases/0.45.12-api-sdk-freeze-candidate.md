# NeverLauncher 0.45.12 — API/SDK Freeze Candidate

## Проверяемое назначение

Общий публичный REST API **v1 (OpenAPI 3.1.1)** остаётся отдельным от версии продукта и протоколов расширений. Backend добавляет ответный заголовок `X-Launcher-API-Contract: 1.0.0` для каждого запроса, включая ошибки. Спецификация остаётся в `schemas/openapi.yaml`; выполняемый маршрутизатор проверяется через `scripts/contracts/validate-openapi.py`.

**Go:** `sdk/api/go` — независимый модуль на Go 1.22+, `New`, `Call`, `Request`, `CheckCompatibility`; поддерживает contexts, токен, query, параметры, JSON, идемпотентность и APIError.

**TypeScript:** `sdk/api/typescript` — браузерный и Node 22+ ESM SDK. `npm test` компилирует `dist` и выполняет HTTP-тесты. `NeverLauncherAPI.call` использует сгенерированные имена операций; `request` поддерживает FormData/Blob для multipart.

**Java:** `sdk/java/http-client` — Java 17+ HTTP клиент, использует настоящий JSON encoder/decoder из уже существующего Java Core SDK. `sh sdk/java/http-client/build.sh test` собирает обе библиотеки и проверяет HTTP-запросы. Для распространения Java API JAR требуется также JAR `sdk/java/core/build/launcher-java-sdk-core.jar` на classpath.

Все три клиента имеют полный список из **452 конкретных операций** из текущей OpenAPI, не симулируют ответы и отправляют реальные HTTP-запросы. Реализация вызовов бинарных/мультимедийных операций отличается: TS использует rawBody, Java — `requestBytes` с byte[]/contentType, Go — `CallRaw` с bytes и MIME типом для файлов. Ответы Java SDK ограничены 1 MiB политикой существующего Java Core JSON decoder (Go и TS — 8 MiB). Не каждое тело/ответ всех 452 операций имеет сгенерированный строгий тип — это **не заявляется**.

## Совместимость N−1/N

- N−1 — работающий backend 0.45.11; отсутствие нового HTTP-заголовка компенсируется проверкой `/ready` и версии 0.45.11.
- N — backend 0.45.12; проверяется заголовок 1.0.0.
- Состояние OpenAPI 0.45.11 зафиксировано в `scripts/contracts/baselines/openapi-04511.json` из предоставленного архива. `compatibility_04512.py` сравнивает прежние операции, имена, параметры, request/response-схемы и публичные компоненты. Изменение несовместимого контракта блокируется до отдельной миграции. Проверки дополнены негативными unit-тестами.
- Это **проверка обратной совместимости схем и поведения HTTP SDK**; настоящий live E2E с двумя backend-бинарниками, работающими на PostgreSQL/SQLite, должен быть дополнительно выполнен на production-подобном стенде.

## Пример Go

```go
c, err := neverapi.New("https://launcher.example.org", accessToken)
if err != nil { return err }
if err := c.CheckCompatibility(ctx); err != nil { return err }
var projects map[string]any
err = c.Call(ctx, "get_projects", nil, nil, nil, &projects, "")
```

## Пример TypeScript

```ts
import { NeverLauncherAPI } from '@neverlauncher/api-sdk';
const api = new NeverLauncherAPI('https://launcher.example.org', token);
await api.checkCompatibility();
const projects = await api.call('get_projects');
```

## Пример Java

```java
var api = new NeverLauncherAPI("https://launcher.example.org", token);
api.checkCompatibility();
Object projects = api.call("get_projects", Map.of(), Map.of(), null, "");
```

Не сохраняйте Bearer-токены в браузерном коде расширений или публичных ресурсах. Для Admin/Desktop используйте предусмотренный Host bridge; REST SDK предназначен для доверенных клиентов и интеграций. По умолчанию не включены повторы изменяющих запросов; для них следует явно использовать idempotency key, если операция его поддерживает.

## Команды приёмки

```bash
python3 scripts/contracts/validate-openapi.py
python3 scripts/contracts/compatibility_04512.py
python3 -m unittest discover -s scripts/contracts -p 'test_compatibility_04512.py'
python3 scripts/sdk/generate-http-operations.py --check
(cd sdk/api/go && go test -race ./...)
(cd sdk/api/typescript && npm test)
sh sdk/java/http-client/build.sh test
```

Отдельная приёмка: два живых экземпляра API 0.45.11 и 0.45.12 с одной и той же сохранённой конфигурацией, рабочий login, список проектов, запрет неавторизованного доступа и изменение состояния разрешённой тестовой операции; выполнение на всех заявленных топологиях нельзя подменять mock HTTP-тестом.
