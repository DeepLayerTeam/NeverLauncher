# NeverLauncher 0.28.7 — Authlib / ServerBridge Integration

## Рабочий путь аутентификации

1. Launcher должен получить реальную Never/Minecraft-сессию и создать одноразовый ServerBridge join ticket уже существующим `POST /api/v1/session/join` (см. текущие routes). ServerBridge на прокси проверяет ticket подписанным Ed25519 запросом, привязанным к узлу и runtime identity. Для direct backend работает тот же ticket без прокси.
2. До завершения Minecraft аутентификации прокси видит username, **но ещё не знает подтверждённый UUID**. Backend в `validate-join` возвращает **UUID из действительного ticket**, а не из недоверенного `req.uuid`; Java-клиент проверяет структурированный ответ, `authorization`, имя/узел и непрозрачный `sessionCorrelationId`.
3. После шифрованного Minecraft login/online-authlib проверки, на `LoginEvent` Velocity/BungeeCord/Waterfall полученный платформой UUID сравнивается с UUID ticket. Несовпадение или отсутствие подтверждённого UUID отклоняет вход до `ServerPreConnect`. `player.quit` очищает оба реестра; reload/shutdown также сбрасывают ожидающие и подтверждённые identity.
4. Handoff возможен только после подтверждённой identity игрока. Прокси передаёт UUID-ассоциированный player-session correlation в существующий `POST /api/v1/server-bridge/handoff`; ответ проверяется по source/target/name/correlation/handoff ID/expiry. При прямом входе backend тоже сверяет reported UUID с UUID ticket до его атомарного погашения.
5. Потеря подтверждения одноразового join/handoff **не запускает повторное выполнение на другом Backend**: одноразовые операции отправляются ровно одной выбранной реплике. При потере ответа вход блокируется. Для обычных heartbeat/telemetry/control используются ранее действовавшие правила failover.

## Требования эксплуатации

- **Официальный online mode**: игра и прокси должны успешно проверять фактический профиль через Mojang/Minecraft sessionserver; UUID в билете NeverLauncher должен совпадать с официальным UUID. Сам по себе положительный результат Bridge ticket НЕ заменяет Mojang authentication.
- **Project authlib mode**: game authentication должна происходить через действующую Yggdrasil/authlib-injector цепочку NeverLauncher; UUID, сообщаемый платформой после аутентификации, обязан совпадать с profile UUID билета. Offline-mode proxy, который произвольно назначает username/UUID и не проверяет криптографическую сессию клиента, не является доверенным режимом.
- При использовании Velocity/Bungee/Waterfall **обязательно** включить и проверить безопасное backend forwarding согласно конкретной платформе, использовать секреты forwarding, ограничить доступ игроков к backend-узлам только через прокси. Подписанный ServerBridge API не является firewall для игрового порта.
- Старое `security.failMode: open` не открывает вход без подтверждённого ServerBridge ticket. Это преднамеренное security-несовместимое изменение: при отсутствии Backend игрок получает отказ.
- Если `serverbridge_player_uuid_mismatch`, `join_player_uuid_mismatch` или `proxy_authenticated_uuid_mismatch`: проверить согласованность official/project identity, authlib configuration, forwarding и online mode. **Не отключать** UUID-проверку в продакшене.
- Если перезапуск или потеря ответа случились после расходования ticket, игрок должен запросить **новый** сеанс/билет через Launcher; старый нельзя повторно использовать.

## Совместимость / границы

Wire protocol ServerBridge v3, структура SQL и PostgreSQL fencing не менялись. Новая версия изменяет условия разрешения соединения; все прокси-адаптеры и Backend следует обновлять согласованно. Bukkit/Fabric/Forge и другие прямые адаптеры, передающие UUID до допуска, получают серверную сверку UUID; если их ранний login-hook ещё не может получить UUID, они не должны выдавать такой UUID за подтверждённый. Для интеграции с неподтверждёнными платформенными версиями требуется отдельный runtime E2E.

Тестирование: `bash e2e/scripts/run-serverbridge-auth-integration-0287.sh` компилирует рабочий bridge-common и proxy-family-common, запускает негативные/позитивные тесты ответов API и unit-тесты нормализации UUID на Go. Это **не** реальный Minecraft E2E. Полный API/Gradle build требует разрешённых зависимостей; реальная сертификация login/proxy forwarding требует действующих серверов Mojang/Yggdrasil и тестовых игроков.
