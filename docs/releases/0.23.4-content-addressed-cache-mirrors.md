# NeverLauncher 0.23.4 — Content-addressed Cache & Mirrors (D04)

## Real execution path

`durable_downloads::perform` → `download_scheduler::run` → `fetch_one` →
`content_cache::CacheStore::lock` → cached restore OR `http_resume::download_verified_controlled`
with source fallback → `CacheLease::publish`.
The Desktop download and Repair buttons already use this execution path; there is
no separate dummy downloader. Every cache hit goes through SHA-256 and exact-size
validation and is staged as an independent copy (no hardlinks). Existing file
ownership rules and the signed manifest verification remain unchanged.

## Shared storage

- Linux: `$XDG_CACHE_HOME/NeverLauncher/content-v1`, or `$HOME/.cache/NeverLauncher/content-v1`.
- macOS: `$HOME/Library/Caches/NeverLauncher/content-v1`.
- Windows: `%LOCALAPPDATA%/NeverLauncher/content-v1`.
- Object names: `sha256/<first-two-hex>/<full-lowercase-sha256>`.
- Interprocess locks: `locks/<first-two-hex>/<full-lowercase-sha256>.lock`.
- Only the object bytes are cached; metadata, target names and source URLs are
  taken from the independently verified signed manifest on every installation.
- Verified data are copied (never hardlinked) into the target and atomically
  switched using the existing NeverRuntime replacement logic.
- On bad type, wrong size or digest, the cached object is removed under lock.
- Disk-full or unwritable cache does not invalidate an otherwise successfully
  installed signed file. A failed cache restore still propagates an error.
- Cache has no garbage collection / quota enforcement in D04; defer to D06.

## Mirrors

The signed `files[]` object may optionally include `mirrors: string[]`:

```json
{
  "path": "libraries/shared.jar",
  "url": "https://cdn.example.org/shared.jar",
  "mirrors": ["https://mirror.example.org/shared.jar"],
  "sha256": "<64-hex-digit SHA-256>",
  "size": 123456,
  "required": true
}
```

`mirrors` is omitted from legacy manifests and their signing canonicalization,
so valid old manifest signatures are preserved. The operator must publish a
new **signed** manifest to add mirrors. Each URL is validated. Workers first
try the primary, then fall back in order; errors including incorrect size or
SHA-256 cannot activate the object and permit safe failover. A mirror must not
be allowed to change the expected SHA-256 or the signer/trust root. The current
HTTP resume module binds partial state to the **exact URL**, so switching
mirrors discards prior server-specific partials rather than concatenating
bytes from distinct HTTP entities. Per-host throttling follows the new host;
previous host permits are released first. Automatic redirects remain disabled.

## Observability

Download results add `cacheHits` and `bytesReused`; progress events include
these fields and `cache-hit`, `mirror-fallback`, and `cache-write-failed` phases.
`bytesDownloaded` / `bytesTransferred` remain **actual HTTP body bytes**,
including rejected primary responses. Cache reuse is never counted as traffic.
Desktop surfaces this breakdown. Download and Repair can reinstall into a
second profile with `bytesDownloaded == 0` if all needed objects are cached.

```sh
cargo test --manifest-path runtime/neverruntime/Cargo.toml content_cache
cargo test --manifest-path runtime/neverruntime/Cargo.toml content_cache_mirror_integration_tests
cargo test --manifest-path runtime/neverruntime/Cargo.toml download_scheduler

(cd services/api && go test ./internal/model ./internal/repository ./internal/httpapi)
(cd apps/desktop && npm ci && npm run build)
```

- Integration fixture 1: poisoned primary CDN delivers incorrect bytes of
  correct size; a separate mirror provides the signed digest; neither partial
  nor corrupted primary bytes are activated.
- Integration fixture 2: following success, both HTTP servers are killed;
  a fresh profile installs using cache only (`bytesDownloaded == 0`).
- Unit fixture: cached object corruption is detected and evicted.
- Unit fixture: 8 concurrent callers serialize a single cache publish.
- Existing test fixtures: bounded global/per-host concurrency, HTTP resume,
  transient network errors, durable pause/resume/restart.
