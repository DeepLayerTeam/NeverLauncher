# NeverLauncher 0.26.10 — Desktop Authentication Experience

This release updates the actual authenticated Desktop screen, not just API declarations.

## Behavior

- Restores native-vault accounts on screen initialization. NeverLauncher and Minecraft identities remain separate.
- Shows the account directory (UUID, player name, active selection) without credentials.
- Starts native system-browser Authorization Code + PKCE or native Device Code with automatic polling, expiry countdown and cancellation.
- Serializes account mutations. Cancellation fences late UI results and prevents a new OAuth attempt from starting after a concurrent cancellation during preliminary native cleanup.
- Displays real selection and revalidation results; the Minecraft profile must match the currently active UUID in the native account directory before the UI marks an account as ready.
- Supports account switch, per-account local logout, session refresh, re-login, and Never linkage/unlinkage with explicit confirmation.
- Maintains skin and cape management; clears a selected file when the active Minecraft UUID changes.
- Distinguishes an unavailable Never linking service from Minecraft login failure, so a link-service outage does not incorrectly clear an otherwise valid game profile.
- Maps untrusted native errors to fixed user-facing messages rather than displaying raw exceptions, tokens or OAuth query strings.
- Any unsuccessful explicit refresh or profile revalidation clears the official launch-ready profile in React. Rust remains authoritative for validation at launch.

## Manual native acceptance matrix (required before production certification)

1. Windows Credential Manager, macOS Keychain, Linux Secret Service: restore, select and delete account A without affecting B; confirm no plaintext fallback.
2. Browser PKCE: success, user denial, cancellation during preliminary native setup and immediately before callback, expired session, repeated login with same Minecraft UUID.
3. Device Code: automatic polling, `slow_down`, expiry, network retry, cancellation before and after user code appears, application exit mid-flow.
4. Restart Desktop: active UUID, current profile and available accounts are restored. Old Never session credentials must not appear in a different Never session.
5. Refresh token revoked: account remains in local directory but official launch readiness is revoked; re-login replaces that UUID's native credentials.
6. Switch A → B and modify a skin/cape; only B is affected. Offline and Yggdrasil remain separate launch identities.
7. Never linking unavailable: show warning but do not revoke Minecraft gameplay access. Linking/unlinking requires explicit confirmation.
8. Confirm the real Microsoft → Xbox Live → XSTS → Minecraft profile chain and vanilla/modded `online-mode=true` join with an approved Microsoft app registration.

## Local tests

From `apps/desktop`:

```bash
npm ci
npm run test:auth-experience
npm run test:official
npm run test:textures
npm run test:launch-modes
npm run test:components
npm run build
```

`test:auth-experience` is native-command-fixture based and verifies state transitions, cancellation races and renderer credential isolation; it does **not** prove a successful Microsoft/Minecraft provider login. Real provider login and native OS keyring tests are still external release gates.
