# NeverLauncher 0.28.6 — Adapter Capabilities & Certification

## Реальные изменения

- Backend проверяет `adapter.*` только после проверки подписи Ed25519 runtime identity; неизвестная платформа, неподдерживаемая capability и гибридное ядро отклоняются. Проверка не подменяет runtime E2E.
- `POST /api/v1/server-bridge/servers/{serverId}/control` дополнительно проверяет *актуальные* подписанные возможности узла (последнее runtime-состояние <=90 секунд), его runtime identity и RBAC/MFA. Отсутствующее/устаревшее capability — HTTP 409, без постановки новой команды.
- Перед подписыванием выдачи из очереди Backend повторно проверяет capability. Если она отозвана после постановки команды, опасное действие **не отправляется**. При истечении lease состояние остаётся `indeterminate`, а не выдаётся другому исполнителю автоматически (поведение 0.28.5).
- Java `NeverLauncherApiClient` проверяет capability после проверки подписи удалённой команды и **до** исполнения через platform executor; результат unsupported записывается в существующий durable control journal и подтверждается ACK. Устройство логирования и v3 wire protocol не меняются.
- Sponge больше не объявляет операции whitelist/ban/save/console, которые его обработчик не поддерживает надёжно. Vanilla sidecar объявляет RCON/log-tail, но не `adapter.auth.login-gate`. Proxy не объявляет сохранение мира; платформенные capability профили проверяются как исполняемый Java-код.
- Admin показывает свежесть runtime capability и источник (node-signed identity), скрывает недоступные команды независимо от RBAC. Это только подсказка: Backend выполняет собственную авторизацию.

## Сертификация: что подтверждено и что нет

* `e2e/scripts/run-serverbridge-adapter-capabilities-0286.sh`: компилирует настоящий `plugins/bridge-common` Java 17, проверяет 14 фактических профилей, негативные capability assertions и сопоставление команд. **Не запускает Minecraft**.
* `e2e/scripts/run-serverbridge-security-certification-01912-e2e.sh`: 14 x 10 криптографических adversarial harness cases. Название E2E историческое; это **Java protocol harness**, не runtime E2E Minecraft.
* `serverbridge/certify_release.py --artifacts artifacts/plugins`: проверяет реальные JAR, SHA-256, содержимое, allowlist, исполняет adapter capability policy. Его output явно содержит `certificationScope=artifact-integrity-and-java-capability-policy`, `runtimeE2eVerifiedByThisReport=false`, и отдельную `requiredCoverage` для каждого target. **Не приравнивать успешную сборку к runtime E2E**.
* CI `.github/workflows/serverbridge-adapter-capabilities-0286.yml` исполняет Java/Go/Admin проверки. Для полноценной сертификации каждого адаптера требуются реальные серверные процессы/клиенты, версии Minecraft и plugin в целевом окружении.

### Runtime acceptance gate (обязательно до production-certified)

Для каждого target, кроме явно отмеченных build-compatibility, требуется реальный runtime на закреплённой версии Minecraft, загрузка модификации с проверенным JAR SHA-256 и живое подтверждение: успешный heartbeat, подписанная runtime identity, работающие login-hook allow/deny (кроме Vanilla), проверка просроченного/одноразового join, успешные и запрещённые управляющие команды, crash/reconnect и неизменяемые результаты ACK. Для Vanilla допустим только `sidecar-rcon-e2e` с проверкой отказа pre-login gate. Bukkit, Quilt, Sponge с `build-compatibility` **не должны** получать статус runtime-certified после успешной компиляции.

Не выпускать утверждения о реальном runtime E2E без выводов реальных Minecraft-процессов, версий плагинов, строгой привязки артефакт-хешей и результатов всех отрицательных сценариев. Этот архив не содержит таких результатов. Go API тесты требуют внешних Go-модулей, PostgreSQL integration также требует test DSN.

## Раскатывание и совместимость

Все реплики Backend и java adapters должны быть обновлены одновременно (протокол ServerBridge v3 не меняется). Для legacy nodes без свежих подписанных `adapter.control.*` новое управление командами **запрещено**; сначала обновить их плагины и дождаться heartbeat. Уже запланированные команды могут стать `indeterminate` после отзыва capability, их нельзя автоматически переисполнять. Перед обновлением проверить `apps/admin` видимость и сохранить предыдущую версию плагина для rollback.
