# NeverLauncher 0.29.10 — Admin Auth Provider Wizard

## Implemented runtime behavior

- The Admin `Auth Provider Wizard` section is gated by global `settings:manage`. Saving drafts requires a recent MFA authentication; activation, rollback and disable require recent phishing-resistant MFA.
- Supports **real**, existing SQL (PostgreSQL/MySQL/MariaDB), signed HTTP, OIDC and Microsoft connector constructors. No second authorization system was introduced: active connectors are reconciled into `federation.Core`, which continues issuing Never sessions and enforcing issuer-aware identity, RBAC and MFA.
- Test connection opens the actual source with bounded timeouts, validates real SQL table/column mapping using a read-only query, validates provider credentials by accessing environment references within the Backend only, invokes health and SDK conformance, returns metadata/column types, and closes the test connector. It **does not authenticate a user's password** or certify Minecraft entitlement.
- Provider configs are strictly schema-validated before database persistence. Plaintext DB DSNs, passwords, inline client secrets, TLS private key file paths and arbitrary unknown fields are blocked. Supported credential references are provided through `dsnEnv`, `hmac.secretEnv`, `clientSecretEnv`. Environment variables must be present consistently on **all** Backend replicas. The database stores only reference names and non-secret settings.
- Drafts are durable PostgreSQL revisions (`0085`) with actor, timestamp, and reason. `activate` checks a live connector again and moves the pointer transactionally with compare-and-swap, audit recording and no unverified fallback. Previous revisions may be reactivated as rollbacks after the **same live test**; target revision `0` disables the managed provider. Static/bootstrap configurations, and `local`, cannot be overridden.
- Each auth request, including Yggdrasil `/authserver/` and Minecraft/ServerBridge entry points, refreshes the set of **active** revisions from PostgreSQL. On replica sync or source health failure, auth fails closed (`503`), instead of using a weaker provider. No Backend restart is required. In-flight connector handles remain valid while older generations are retired until service shutdown.

## Deployment and migration

1. Apply `0085_auth_provider_wizard_02910.sql` through the regular Backend or CLI migration path, before running the new binary. Both embedded migration catalogues include the same SQL.
2. Set secret environment variables such as `AUTH_SQL_DSN` and `AUTH_OIDC_CLIENT_SECRET` on **every** API replica. Use privilege-limited SQL credentials and the existing connector allowlist/TLS settings; never put actual secrets in wizard JSON or audit reasons.
3. In Admin → Auth Provider Wizard select kind and ID. Edit the typed connector configuration JSON, run **Test connection**, inspect SQL mapping preview, save the tested draft, then activate with fresh passkey authentication. Logins can then explicitly select its provider ID.
4. On error, activate a previously healthy revision, or disable the managed provider (`revision: 0`). If an active external source becomes unavailable, existing unauthenticated requests are blocked; recovery remains available through Admin using a local administrative account.
5. Existing `NEVERLAUNCHER_AUTH_*_PROVIDERS_JSON/FILE` configurations are not modified. Their IDs remain owned by bootstrap configuration; moving a provider to Admin management requires operator-controlled removal of the conflicting bootstrapped definition.

## Verification and known limits

- Local tests: repository and federation Go test/race checks, CLI/Backend migration checks, Go vet on locally buildable packages, TypeScript syntax parse, Admin Node tests. Actual HTTP/API build, PostgreSQL E2E, full Admin compile and browser login verification must be run in an environment with Go/Node dependencies and a real PostgreSQL database; `.github/workflows/auth-provider-wizard-02910.yml` supplies the corresponding CI gates. Their successful completion has **not** been established locally.
- This release supports **staged validation, transactional activation and rollback**, but does **not** implement progressive percentage-based canary traffic allocation. Live credentials checks verify the configured provider connection; they do not validate arbitrary end-user passwords. The Microsoft connector does not prove Mojang/Minecraft Java ownership.
- Admin management is not a secrets vault. Use platform secret injection/rotation. Retired connector instances remain open until shutdown to protect in-flight operations; operators should avoid continuously cycling provider configurations on long-lived processes.
