# NeverLauncher 0.30.10 — DevTools & Test Isolation

This release adds **working, standalone, opt-in development utilities** to the existing Go CLI. None of these handlers is mounted on the production HTTP API or modifies the credentials, sessions, or permissions of a real Minecraft user.

## Bytecode analysis and transformation

```bash
nl devtools jar analyze --input /tmp/component.jar
nl devtools jar strip-debug --input /tmp/component.jar --output /tmp/component-stripped.jar
java -jar /tmp/component-stripped.jar
```

The analyzer decompresses the JAR with path traversal, symlink, duplicate-entry, expansion and resource limits. It parses JVM classfile constant pools and attributes, reports referenced process execution, reflection, classloader, native, network and filesystem APIs with class/evidence, and prints SHA-256 and JVM classfile version. The transformer rewrites actual bytecode classfile containers (including nested `Code` attributes) removing `SourceFile`, `SourceDebugExtension`, `LineNumberTable`, `LocalVariableTable` and `LocalVariableTypeTable` without rewriting JVM instructions. It rejects an existing output, corrupted classfiles and signed JARs instead of invalidating their signatures; only the newly generated JAR is modified.

**Heuristic findings are not proof that a JAR is harmful or harmless.** Reflection, invokedynamic, native code, encrypted payloads and runtime class loading can evade static detection. The transformer is not an obfuscator, malware remover or safe-to-run certificate. Any altered artifact must be re-signed by the trusted release publisher before distribution.

## Executable test components

```bash
# Default: Linux bubblewrap container; no network and no access to host HOME
nl devtools component test --jar ./untrusted.jar --timeout 20s --heap-mb 128 -- args-to-main

# TRUSTED fixture only; no OS sandbox, no production secret environment variables
nl devtools component test --jar ./test.jar --isolation process --ack-unconfined -- arg1
```

The test component runs as a separate JVM, in a temporary working directory, with a sanitized environment, closed stdin, bounded stdout/stderr, JVM heap constraint, a wall-clock timeout, and parent-controlled termination. Linux sandbox mode requires working unprivileged user namespaces and `bubblewrap`: it creates separate PID, mount, network, user and IPC namespaces, read-only Java runtime mounts, and only ephemeral writable `/tmp`/`/work`. If the sandbox is unavailable the default command **fails closed**. Process isolation mode is explicitly opt-in and is **not a security sandbox**: same-user host files remain readable and child processes have OS-user privileges. It must never run an untrusted component. JVM `-Xmx` is not a bound on total native RSS. On Windows/macOS the OS-sandbox mode is not offered in this version; use a separately managed VM/container for untrusted tests. Java exits with nonzero status are reported as errors, and timeouts terminate the process group where supported.

## Auth fixtures and debug identities

Enable the separate debug policy and start a **loopback-only** server with randomly generated test credentials. There is no external listener and no integration with the real authorization API:

```bash
NEVERLAUNCHER_DEVTOOLS_TEST_MODE=1 nl devtools auth serve --ack-test-only \
  --listen 127.0.0.1:0 --duration 5m --user debug-player
```

The command prints its loopback `baseUrl`, ephemeral `username`, `password`, and `controlToken` to stdout for local test automation. Protect CI logs; don't print this startup JSON in public pipelines. Test-only tokens use the `nltest.v1.` prefix and HMAC over a separately generated, in-memory secret; they are not production NeverLauncher JWTs or sessions and cannot be promoted to them. Token TTL is limited to 15 minutes, fixture server lifetime to 30 minutes; server startup requires both a process environment gate and explicit CLI opt-in.

Available, **live** fixture operations:

| HTTP method and route | Behavior |
|---|---|
| `POST /fixture/v1/login` | Temporary username/password login; publishes success/failure auth events |
| `POST /fixture/v1/issue` | Control-token-only issuance of scoped debug identities |
| `POST /fixture/v1/introspect` | Verifies debug signature, issuer, expiry and revocation |
| `POST /fixture/v1/revoke` | Control-token-only revocation |
| `GET /fixture/v1/events?after=N` | Control-token-only ordered auth fixture events (last 256) |
| `GET /fixture/v1/health` | Test-only server health |

All POSTs use bounded strict JSON, rate of use should be controlled by the caller, and no production admin token is read. The fixture uses HTTP on **loopback only**; local processes may access the listener, so use on an isolated development host. Tokens have no authority outside this fixture instance. Don't proxy fixture paths to production or route real login requests to it.

## Verification

`go test -race ./internal/devtools` covers Java compilation, bytecode rewrite and real Java execution, detection of risky references, hostile JAR paths, signed JAR handling, sanitized subprocess environment, timeouts, real HTTP auth login, failure, issue, introspection, revocation, event polling and TTL expiry. `scripts/devtools/smoke_03010.py` exercises the built CLI using javac, a transformed JAR, two JVM launches and a real loopback HTTP server. CI targets Linux/macOS/Windows plus a separate Linux bubblewrap network-isolation smoke gate.

**Certification boundary:** local test evidence does not certify OS sandbox portability, complete malware detection or security of arbitrary JVM agents. Explicit external sandbox testing is required before enabling untrusted component execution in production workflows.
