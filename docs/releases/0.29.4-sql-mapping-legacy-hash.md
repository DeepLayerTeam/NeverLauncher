# NeverLauncher 0.29.4 — SQL Mapping & Legacy Hash

## Changes running in production paths

- Existing `sqlconnector.New` invokes `InspectMapping` against the live, configured PostgreSQL/MySQL/MariaDB database before preparing authentication statements. It selects **zero rows**, validates actual column presence and database type, and aborts activation when the mapping is inconsistent. No password hashes or row data are read during schema inspection.
- `AuthenticatePassword` calls the existing verifier dispatcher, now extended with `digest`, `doubleDigest`, and PHPass. The selected format must be configured and opted into; it never guesses algorithm, salt, encoding or cost from a hash. It keeps existing Argon2id, bcrypt and PBKDF2 paths unchanged.
- Gravit digest and doubleDigest support MD5/SHA-1/SHA-256/SHA-512, strict HEX or canonical padded Base64 storage, and explicit binary/hex double-digest mode. Gravit AdditionalHash portable PHPass `$P$`/`$H$` supports embedded eight-character salt and bounded iteration count; a bcrypt hash is not automatically reinterpreted as PHPass.
- Configurations are normalized at activation and unsupported/ambiguous configurations fail startup. An unknown stored hash yields `ErrMisconfigured`; a wrong password yields `ErrInvalidCredentials`. External SQL data are never modified during login, and no automatic provider fallback occurs.
- Existing SQL identity mappings (subject, username, email, status, roles/groups, Minecraft UUID) remain in the live authentication result. No database schema migration or table creation on external providers is performed.

## Security boundaries

`allowLegacyHashes: true` is mandatory for unsalted digests and PHPass. Avoid legacy digest verifiers for new accounts. PHPass count log2 must be 7–17. Configure the exact algorithm, encoding and `doubleDigestHex` mode used in the source CMS. No arbitrary salts, custom Gravit hash modules, digest auto-detection, or binary hash conversion are supported. Unsupported formats require explicit migration analysis, not a password reset or insecure fallback. New SQL verifiers are **read-only**; Argon2id rehash after successful proof on Never-owned records is explicitly deferred to 0.29.5.

## Testing and limitations

`go test ./internal/sqlconnector -count=1` on an environment with Go modules runs digest, PHPass, negative vector, SQL fixture, and schema tests. Real PostgreSQL/MySQL/MariaDB tests are implemented in `TestLiveSQLLegacyAuthentication0294` and are wired to a dedicated CI workflow provisioning all three engines, exercising provider activation, correctly verified login, wrong password rejection, absent columns, and invalid stored hashes. CI success has not been independently observed in this development sandbox. Local unit tests with an offline dependency-free file selection are not a substitute for complete Backend build or live server integration.

## Upgrade

Change `VERSION` and app/release metadata to `0.29.4`; preserve all current auth identity/issuer and GameProfile UUID records. Existing supported SQL connector configurations remain valid. SQL credentials now require sufficient read-only column access for zero-row schema validation at startup. Enabling new legacy verifiers must be a deliberate configuration rollout, with known example hashes independently tested before changing production routing. No automatic provider selection changes or fallbacks are introduced.
