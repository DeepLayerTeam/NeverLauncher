# Launcher 0.42.11 — перенос исходных Gravit-модулей

## Что выполняется, а что не обещается

Версия 0.42.11 содержит работающий исходный перенос **совместимого подмножества** Gravit Java API. Это не загрузчик неизменённых Gravit JAR, не переписывание закрытого Java-кода и не исполнение чужих модулей в безопасной OS sandbox. Java Extension Host является отдельным **доверенным процессом**. Не устанавливайте исходники или пакеты от неизвестного издателя.

`tools/gravit-port/port.py` физически компилирует Java 17 исходники через штатные Java Core и Gravit Compat SDK, не принимает classpath от исходного Gravit, создаёт исполняемый JAR с проверенными entrypoint-классами, копирует одобренный манифест. При передаче ключей он передаёт каталог штатному `nl extension pack` и **обязательно** вызывает `nl extension verify`. Java annotation processors отключены. Неизвестные Gravit API не заменяются фиктивными функциями: компиляция не проходит.

Проверяйте источник вручную: обычная Java-компиляция и подписанный пакет не доказывают безопасность поведения кода, выполняемого в отдельном процессе с его OS-привилегиями.

## Перенос

1. Получить **исходный код** модуля, установить, какие `LaunchServer`/JavaFX/контексты/хуки несовместимы, и переписать их через документированные Never `ExtensionContext`/Runtime API. Предварительно определить подписанные `permissions`, `targets`, `cli.commands` и зависимости. Привязать команды к именам в подписанном манифесте.
2. Разместить `.java` в собственной исходной директории. Класс entrypoint должен напрямую наследовать поддерживаемый `pro.gravit.launcher.base.modules.LauncherModule`, иметь публичный конструктор без аргументов и собственную реализацию `init(LauncherInitContext)`.
3. Подготовить валидный `schemaVersion: 2.0`, `api: 1.0` манифест с `backend` и/или `cli` targets; для обоих entrypoint равен `backend/gravit-port.jar`.
4. Скомпилировать и получить доверенную подпись из собственных ключей издателя:

```sh
(cd cli && go build -o /secure/bin/nl ./cmd/launcher)
python3 tools/gravit-port/port.py \
  --source path/to/ported/java/src \
  --module-class org.example.MyPortedModule \
  --manifest path/to/launcher-extension.json \
  --output /tmp/my-port-stage \
  --nl /secure/bin/nl \
  --private-key /secure/publisher.key \
  --public-key /secure/publisher.pub \
  --package /tmp/my-port.nlext
```

Без аргументов подписи сборщик выдаёт **только локальный каталог**, а не готовый к установке `.nlext`. Он не генерирует ключи и не меняет доверие к издателю. Безопасный путь установки требует штатной проверки ключа/доверия издателя, разрешений и жизненного цикла Never.

## Проверка реального запуска

```sh
python3 -m unittest discover -s tools/gravit-port -p 'test_port.py' -v
sh examples/extensions/gravit-compat/build.sh
python3 examples/extensions/gravit-compat/test-runner.py
nl module-parity audit --root . --baseline 0.42.11 --report /tmp/gravit-matrix.json
nl module-parity audit --root . --baseline 0.42.11 --module M02 --run-tests --require-tests
```

JVM-пример проверяет live host handshake, durable подписку, доставку события, Storage broker и CLI/RPC через отдельную JVM. Подписание `.nlext` выполняется штатным CLI; модификация байтов после подписи должна отклоняться.

**Границы:** `compatibility/gravit/module-parity-04211.json` охватывает исходные 19 модулей: 18 `partial` с точными ограничениями, M17 `blocked`. Наличие исходника/теста, локальный E2E и действительная подпись *не равны* полной функциональной эквивалентности Gravit. Отдельная сертификация требует реальных Discord/Sentry/mDNS, Minecraft/JVM, официального входа и целевых ОС; они не подтверждаются этим выпуском. Исторические матрицы оставлены неизменными и могут требовать отдельного восстановления устаревших файлов для самостоятельного воспроизведения старых версий.
