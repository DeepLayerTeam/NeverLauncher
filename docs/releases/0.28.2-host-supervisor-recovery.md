# NeverLauncher 0.28.2 — Host Supervisor 2.0 & Recovery

## What is implemented

The existing `nl server-bridge host` Java supervisor remains the execution engine. This release changes the actual child process lifecycle instead of adding a parallel or declarative service.

- `configure`: `--working-directory` must resolve inside the canonical server root; `--env-allow NAME` permits explicitly inherited environment keys and `--env NAME=VALUE` sets an allowlisted key. The default inherited environment is limited to OS basics (PATH, HOME, USER, LANG, LC_ALL, TZ and temporary-directory/Windows system keys). Child processes no longer inherit arbitrary parent secrets or JVM injection variables.
- `run/start`: exclusive session lock, OS-backed process identity (Linux boot ID + `/proc/PID/stat` start ticks; Windows creation time), and recognition of stale previous-session runtime records. A real orphan is **never adopted** and a different process reusing the same PID is **never killed** merely because the old runtime JSON references that PID.
- `stop`: session/PID-bound request in the protected host directory. Only the owning supervisor drives termination. It sends Minecraft's `stop` on stdin, waits `--stop-timeout-seconds`, then sends a process-group termination signal on Unix, then a final kill. On Windows, the existing platform termination operation is used after console stop times out. No direct signal is dispatched by the CLI from historical PID metadata.
- `restart`: supervised stop followed by a fresh supervisor. `recover` is an explicit alias for safe `start` and reports `recoveredFrom` when restarting after stale runtime metadata. The host process must be restarted by an external service manager after a **machine reboot**; the actual systemd service installer/watchdog belongs to 0.28.11, and is **not** claimed for this release.
- `run`: bounded exponential restart delay (up to 60 s), restart-count window (`--crash-window-seconds`) and reset after a stable run (`--stable-run-seconds`). Runtime JSON records cumulative restart/crash count, last exit status and the termination method.
- Log streams `stdout.log`, `stderr.log`, `server.log` are append-only, permission-restricted rolling logs with `--log-max-bytes` and `--log-backups`. `logs --follow` reopens rotated files rather than remaining on an old inode.
- `status`: distinguishes stale runtime, orphaned process and observed running/stopped state. It does not treat a historical PID alone as proof of health. Explicit environment values are redacted in user-facing configure, dry-run and status JSON.

## Operator commands

```shell
nl server-bridge host configure --server-root /srv/minecraft/lobby --platform paper \
  --server-jar paper.jar --java /usr/lib/jvm/java-21-openjdk/bin/java \
  --working-directory . --restart-policy on-failure --max-restarts 3 \
  --restart-backoff-ms 2000 --crash-window-seconds 300 --stable-run-seconds 120 \
  --stop-timeout-seconds 30 --log-max-bytes 20971520 --log-backups 4 \
  --env-allow MY_GAME_REGION --env MY_GAME_REGION=eu
nl server-bridge host start --server-root /srv/minecraft/lobby
nl server-bridge host status --server-root /srv/minecraft/lobby
nl server-bridge host stop --server-root /srv/minecraft/lobby
nl server-bridge host recover --server-root /srv/minecraft/lobby
nl server-bridge host logs --server-root /srv/minecraft/lobby --stream all --follow
```

`host.json` contains explicitly configured environment **values** and is written with owner-only permissions. Treat its directory as sensitive and prefer a dedicated unprivileged service account. Inherited credentials are not copied by default. Never send the whole config to unrelated application logs.

## Failure and safety boundaries

1. **After an unclean shutdown:** if the previous child is proven dead, a new session can start without killing an unrelated reused PID. If its identity is still alive but the supervisor is gone, operation refuses an unsafe double start and requires operator reconciliation; the process is not silently adopted.
2. **Old state:** legacy `host.lock` or `runtime.json` entries without identity stamps are handled conservatively if their PID is alive. To restore service, the operator must first confirm the true process state. `recover` does not forcibly kill legacy PIDs.
3. **Stop timeout:** `stop` is sent to Minecraft stdin first so normal world-save shutdown can run. After the timeout, Unix SIGTERM and then SIGKILL are last-resort fallbacks and **cannot guarantee world consistency**. Use a separate verified world-backup/snapshot workflow (planned 0.28.10).
4. **Service ownership:** OS-wide process groups are not a full Linux cgroup/Windows Job Object. A forked/daemonized process whose parent exits might survive a host crash. System service supervision, watchdog and process-tree containment are separate 0.28.11 work; do not certify “no process orphans after host death” from this release alone.
5. **Platform identity:** kernel-backed process identity is implemented for Linux and Windows. The supervisor refuses unverified control on other OSes rather than sending signals based on PID reuse guesses. This is intentional fail-closed behavior.
6. **Control plane:** this release does not expose arbitrary host shell commands, does not grant new API/RBAC privileges, and does not implement RemoteControl or service enrollment (0.28.4). The CLI remains local to the host user account.
7. **Host process startup after reboot:** arrange an existing trusted boot/service mechanism to call `nl server-bridge host recover`; automatic installer, systemd notify/watchdog and service sandbox are planned for 0.28.11.

## Verification

New Go integration tests launch a real local test executable (POSIX shell standing in for Java in offline tests) to check stdin shutdown, stale session-request rejection, stop before timeout, env non-inheritance, working-directory containment, recovery after stale PID identity, refusal to adopt live child, crash-loop limits and rolling logs. They are **not** a claim of Paper server gameplay E2E, real world-save validation, machine-reboot simulation, or systemd/Windows-service E2E.
