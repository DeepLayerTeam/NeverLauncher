# NeverLauncher 0.40.0 — окончательная приёмка игрового цикла

Версия 0.40.0 требует **фактического запуска конечных установочных пакетов**. Номер версии и пройденные unit-тесты не являются подтверждением GA. Защищённый релиз остаётся заблокированным, пока независимый оператор не выполнит полный цикл на всех шести целях: Windows/Linux/macOS, x64/ARM64.

## Приёмка и журнал исполнения

Сохраняются девять исторических проверок для каждого целевого пакета плюс шесть новых:

| Проверка | Что необходимо реально наблюдать |
| --- | --- |
| `componentPresetInstall` | Игрок устанавливает именованный пресет, разрешаются зависимости, несовместимые моды не допускаются |
| `skinCapeGameRender` | Скин, плащ и модель проверены **в запущенном Minecraft**, не только в HTTP-профиле |
| `localYggdrasilJoin` | Игровой сервер проверяет UUID и сессию через проектный Yggdrasil и принимает подключение |
| `officialOnlineModeJoin` | Действующий лицензированный Microsoft/Minecraft-профиль проходит `online-mode`, UUID подтверждён сервером |
| `identityNegativeAndReplay` | Сервер отклоняет неверный UUID, чужой проект, чужой режим и повторное использование билета |
| `playerUpdateRollback` | После обновления и возврата клиент запускается и заходит на сервер; пользовательские файлы сохранились |

**Не заменять наблюдение игрового сервера ответом API.** Каждый этап запускается против установленного из утверждённого пакета клиента и фактического сервера; проверяются журналы процесса и игровые события. Official и local — разные цепочки, каждая выполняется самостоятельно. Непройденный/невозможный этап — BLOCKED, а не PASS.

Для каждой платформы `scripts/ga/verified_targets.py` требует подпись оператора над точными SHA-256 Desktop-бинарника и установщика. Каждый новый `targets/<target>/<check>.json` должен содержать базовые поля текущей подписанной проверки и `packageSha256`, `playerCycleId`, `evidenceSha256`. Для каждого этапа хранить:

- `targets/<target>/player-0400/<check>.json` — отдельный отчёт, его SHA-256 соответствует `evidenceSha256` подписанной проверки;
- `targets/<target>/player-0400/<check>.log` — оригинальный журнал реального исполнения; SHA-256 связан с отчётом.

Отчёт имеет `schemaVersion: neverlauncher.player.final.0400.v1`, `version`, `commit`, `target`, `kind`, `status`, `playerCycleId`, `binarySha256`, `packageSha256`, `observed`, `runtimeLogSha256`. Поле `observed` содержит все требуемые для данного этапа факты из `PLAYER_OBSERVATIONS_0400` со значением `true`, только **после фактической проверки**. Все этапы одного целевого пакета имеют одинаковый `playerCycleId`. Противоречие, отсутствующий журнал, подмена файла, чужой SHA, несовпадение релиза или неполная независимая подпись блокируют выпуск.

В журналах и отчётах запрещены Microsoft refresh/access tokens, Minecraft access tokens, Never session tokens, приватные ключи, персональные идентификаторы устройств и другие секреты. Полные UUID тестовых Minecraft-аккаунтов разрешено хранить только в защищённых источниках оператора; публичные журналы очищать, не уничтожая проверяемые SHA и факты результата.

## Проверки для разработчика

```bash
python3 scripts/version/manage.py check
python3 -m unittest discover -s scripts/ga -p 'test_player_final_0400.py' -v
python3 -m unittest discover -s scripts/ga -p 'test_verified_targets*.py' -v
python3 -m unittest discover -s scripts/release -p 'test_rehearsal_0365.py' -v
python3 -m unittest discover -s scripts/release -p 'test_publish_0370.py' -v
```

Unit-тесты создают **синтетические подписанные данные только для испытания отказов**. Они не создают сертификатов GA и не заменяют реальный Minecraft E2E. Никакие примеры или результаты этих тестов нельзя использовать как GA-подтверждение.

На защищённом runner выполнить существующий `e2e/scripts/run-minecraft-e2e.sh` и `scripts/ga/verify_player_cycle_0398.py`; затем провести **отдельные** live-прогоны точных установщиков, включая официальный Microsoft login. После полного независимого подписания шести целей запустить `scripts/release/build-release.sh`. Он проверяет подписи, содержимое пакетов, независимую приёмку, выпускает подписанные артефакты и выполняет публикационную репетицию; `publish_0370.py` повторно проверяет соответствие перед публикацией. Ключи оператора и релизного подписанта должны оставаться вне исходников.

Если отсутствуют подписанные и актуальные реальные результаты хоть одной обязательной платформы или официального входа, **0.40.0 не имеет подтверждённого статуса production/GA**.
