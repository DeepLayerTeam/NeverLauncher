# NeverLauncher 0.26.11 — Official Provider Management

## Deployment

1. Back up PostgreSQL and apply migration `0076_official_provider_management_02611.sql` using NeverLauncher's existing migration runner **before deploying the new Backend**.
2. Deploy Backend and Admin together; register your own Microsoft public desktop app supporting personal accounts. Configure the native loopback redirect according to Microsoft registration rules. No client secret is needed or accepted in Admin.
3. An existing `NEVERLAUNCHER_MINECRAFT_MICROSOFT_CLIENT_ID` continues to work as the default until the first saved Admin revision. Once saved, PostgreSQL is authoritative for every API instance; environmental values are no longer silently merged.
4. Authenticate to Admin with global `settings:manage` and recent MFA, open **Minecraft Provider**, specify your own UUID Client ID and choose allowed browser PKCE/Device Code flows. Save a revision with a reason. The Admin read permission does not bypass Backend RBAC/MFA.
5. Diagnostics perform real, bounded network requests to fixed Microsoft OIDC, Xbox Live, and Minecraft Services endpoints. HTTP 401/403/405 may mean the endpoint is reachable, **not that Microsoft or Mojang approved this app**.
6. Run the **0.26.1 official-provider-poc** using the same Client ID and a real Java Edition account. Confirm actual Minecraft access and a verified online-mode server join before declaring provider approval/GA.

## Operational behavior

- Policies are read from the authoritative repository for each new flow or credential validation. Database failures fail closed.
- Only `consumers` issuer is supported. No arbitrary issuer, client secret, scope override, redirect host, or provider URLs can be entered from Admin.
- Browser PKCE and Device Code fallback can be independently disabled; disabling the entire provider prevents native official session validation and legacy Backend official operations, but does not revoke Microsoft sessions at the provider.
- Changing the Client ID invalidates existing **native** official sessions for use until users reauthenticate. There is no automatic migration of OAuth credentials between Microsoft registrations.
- Each policy update is compare-and-swap against a revision, committed together with its immutable PostgreSQL history entry. Separate Never audit events record changes and diagnostic invocations without tokens.
- Diagnostics do not redeem OAuth codes, request third-party user secrets, or assert external approval.

## Routes

- `GET /api/v1/admin/official-provider` — global `settings:manage`.
- `PUT /api/v1/admin/official-provider` — global `settings:manage` **plus fresh MFA**, body `{ "expectedRevision": 0, "settings": { "clientId":"...", "enabled":true, "browserEnabled":true, "deviceEnabled":true, "issuer":"consumers" }, "reason":"..." }`.
- `GET /api/v1/admin/official-provider/history` — previous settings, revision, actor, timestamp and reason.
- `POST /api/v1/admin/official-provider/diagnostics` — fixed-target real network probes; does not prove entitlement or application approval.
