# 0.35.2 — Owner-signed first run

The **same signed** `bootstrap.signed.json` verified by Prestarter is installed
into its private `desktop-config` directory. For delegated v2 envelopes,
`trust-policy.signed.json` is copied only after root verification and policy
anti-rollback acceptance. The Tauri process verifies the exact signed payload
**again** using an Ed25519 root pinned into the Desktop binary at build time;
there is no renderer-provided root, no TOFU, and no trust in `config.json` for
project routing. Missing compiled root with a signed bundle stops the UI.

## Owner workflow

1. Create a valid Prestarter bootstrap `Config` and sign it using the existing
   `prestarter/cmd/sign-config` tool or client-factory signing workflow. Set
   `backendUrl` (HTTPS), `projectId`, `profileId`, `channel`,
   `profilePublicKey`, and the pinned game `manifest` artifact. Optionally set
   signed `serverId`, `serverHost`, `serverPort`, and `autoEnter: true` to
   allow direct connection without the player entering a game server address.
   The server must be accessible in the verified profile's server catalog.
2. Compile the branded native Desktop with the bootstrap trust root using
   `scripts/desktop/build_signed_0352.sh /absolute/path/root-public.hex`.
   **Only a public key is used**; keep all signing private keys off build agents.
   This root must match the Prestarter binary's pinned root. Each owner requires
   its own correctly built Desktop artifact; a generic Desktop without this
   key cannot silently accept owner bundles.
3. Include the generated Desktop artifact in the **signed Prestarter target**
   and distribute the already-supported signed installer/prestarter bundle.
   Prestarter verifies all target hashes before execution. On first launch it
   copies the verified signed bootstrap and starts Desktop with the private
   configuration directory. A raw Desktop executable without this step is not
   an equivalent preconfigured installer.
4. The player logs in through NeverLauncher authentication. The first-run
   screen checks API health, project/profile authorization, actual native
   signed Manifest, runtime requirements and Java; displays available mod
   presets and profile servers; executes the transactional file installer;
   and finally requires another **native** complete-file verification before
   enabling the Play step. Installation errors do not mark onboarding complete.

Native `load_desktop_config` and `save_desktop_config` both impose signed
project identity, backend URL, channel, pinned public key and manifest URL;
trusted server routing is also imposed for signed auto-enter. User-selected
RAM, display and other harmless preferences are preserved across updates.
The signed identity cannot be reset via untrusted Desktop UI. Existing
non-bundled operator installs retain advanced manual binding.

## Reproduction and limitations

- `cd prestarter && go test -run 'TestOwnerSignedFirstRun0352|TestBootstrapServerPolicy0352' -count=1 .`
- `cd apps/desktop && npm ci --ignore-scripts && npm run build`
- `cd apps/desktop/src-tauri && cargo test signed_first_run_0352 -- --nocapture`
- Full native sign-in → production Backend → download → Minecraft/ServerBridge
  acceptance requires signed owner binaries, a reachable live Backend and
  real Java/Minecraft; it is **not** established by unit tests alone.
- Owner-defined custom component selection remains available on the existing
  profile screen; a preconfigured bundle's default preset is initially used.
- Offline access remains under the signed Manifest policy and never creates
  a server entitlement or a bypass of login/ServerBridge checks.
