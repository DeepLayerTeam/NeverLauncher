# NeverLauncher 0.28.5 — Durable Commands & HA Fencing

## Changes shipped

The existing ServerBridge **Game Server Control** is changed at the **actual execution/dispatch boundary**, not by adding another queue or declarative API:

- `SQLRepository.LeaseServerBridgeControlCommand`: PostgreSQL row lock and durable command journal continue to elect exactly one channel; after a delivery lease is lost, the row is **indeterminate**, never eligible for automatic delivery again. The same channel can resume the same still-live lease with its original token/sequence.
- The in-memory implementation follows the identical policy. The control journal retains the original delivery sequence, lease owner, lease token, command digest, audit context and attempt count for later investigation.
- SQL reads and Admin overview reconcile expired/unowned delivered work even if the game server **never reconnects**. `pending` commands that expired without a delivery are `expired`, not `indeterminate`. A late ACK cannot change a terminal uncertain outcome.
- Signed ServerBridge Protocol v3 control envelopes use the **minimum** of command expiry and active lease expiry. A cached, delayed signed poll response cannot authorize execution beyond the lease. This preserves the frozen Protocol v3 field and signature scheme.
- The new PostgreSQL migration `0078_control_ha_fencing_0285.sql` repairs existing uncertain deliveries and installs a database trigger to fence **old Backend replicas** that might attempt to re-lease a delivered command in a rolling deployment. Old binaries that try to reschedule after lease expiry will fail closed at the database level. Both the CLI and API migration catalogs have the identical migration.
- The existing Redis coordinator remains the transient second lease guard. Redis outages fail closed and PostgreSQL remains the durable authority; Redis does **not** prove an external action was not executed.
- For the existing Host RemoteControl HTTPS agent, the **local, operator-only** `remote inspect` action reads the real durable Host command receipt and independently observed supervisor status without reissuing a process operation. It never claims process status proves the original command's success.

## Operations

Install/apply all migrations on the shared PostgreSQL database **before** rolling Backend processes. Both API migration runner and CLI migration tooling include `0078`.

Query a Game Server command in Admin (`ServerBridge Workspace`) or with the existing authorized command lookup. An uncertain command is displayed as `indeterminate`. A different idempotency key is **not** a safe retry until an operator verifies the actual Minecraft-side effect.

For a Host command, inspect the original journal and observed process:

```bash
nl server-bridge host remote inspect \
  --server-root /srv/minecraft/lobby \
  --idempotency-key incident-20261024-lobby-stop-1 \
  --output /tmp/lobby-inspection.json
```

This requires local access to the protected Host state. `verifiedExternalEffect=false` means the Host's PID/health alone is not proof of the command result. An unresolved command is not automatically repeated; compare Minecraft server state, game logs and application data before using a new idempotency key. Do not delete/edit journal files to force automatic re-execution.

## Failure and concurrency semantics

| Scenario | Durable result | Automatic retry |
|---|---|---|
| Command never dispatched; request TTL expired | `expired` | No |
| Client reconnects to a different Backend with the **same** channel while lease live | Same signed command ID/lease token | Bridge local journal deduplicates external execution |
| Bridge died after starting effect, ACK lost, lease expired | `indeterminate` | **Never** |
| Redis unavailable after PostgreSQL claim | `indeterminate` once lease expires | **Never** |
| Signed poll HTTP response arrives after delivery lease | Rejected by Bridge timestamp verification | No |
| Old replica tries to replace an existing lease | PostgreSQL trigger rejects mutation | No |
| Late ACK after expiry or after manual/operator reconciliation | Conflicting/terminal command | No |

## Verification and boundaries

Targeted Go CLI Host tests, 0.28.4 security regression tests and migration catalog tests can run without external infrastructure. PostgreSQL integration tests for multi-replica and lost ACK run when `NEVERLAUNCHER_SERVERBRIDGE_HA_DSN` points to an isolated real PostgreSQL database with migrations. Unit-only tests cannot prove the SQL trigger works on a live database. Validate Redis fail-closed behavior separately with a real Redis, and test the Java Bridge's signed expiry handling in a live server before declaring Minecraft E2E certification.

**Host/Backend distributed execution is not yet fully HA:** Host RemoteControl continues to use a durable private **local filesystem** journal and process-identity lease. This release does **not** claim a shared PostgreSQL Host command journal, cross-machine fencing of arbitrary host processes, or a new Backend control executor. Those require explicit Host enrollment/identity and orchestration in future work. These limitations are not hidden by the Game Server SQL/Redis guarantees. Never point multiple independent Hosts at a single logical game process without host-level fencing.
