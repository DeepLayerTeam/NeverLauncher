# NeverLauncher 0.35.3 — Player Desktop Workspace

This release changes the **running Desktop renderer**, not the API schema or a manifest-only projection.

## Working player scenarios

1. **Accounts**: the existing project login, account and device management and native Microsoft account workflows are accessible from one account route. Session/refresh tokens remain with existing auth/native handling.
2. **Builds**: fetch authorized projects and profiles from Backend v1, select project/profile, fetch a manifest through native `load_manifest` (Ed25519 verification), ensure project/profile/channel match, prepare isolated game directory through native `prepare_profile_directory`, persist config through native `save_desktop_config`, and open verified release. An unsuccessful operation does not report the build as active. Signed owner project/profile constraints are kept.
3. **Servers**: fetch active nodes through the profile-scoped ServerBridge API, reject removed/foreign IDs, show status/health and persist selection using native config. A ServerBridge ID is NOT inferred to be a public Minecraft hostname; the existing server address setting remains explicit or owner-signed.
4. **Optional mods**: a dedicated player route invokes the existing native verified component preview / transactional install / migration and portability tools. No unverified component plan is installed.
5. **Textures**: retain the existing 0.25.8 working project/official skins and capes UI (upload, revision/ownership checks and gallery), now a first-class nav destination.
6. **Downloads**: existing native download/update/repair/pause/resume/rollback workflow is retained as a first-class route. Download-speed/ETA is deferred to 0.35.4.
7. **History**: load persisted native runtime history on entering the route; show local timestamp, profile, version, success/error, exit code, log path and message with exact filters. Live runtime stop remains backed by native `stop_runtime_process`.
8. **Navigation**: current screen is restored only after the Desktop binding has been verified natively; an incomplete signed first-run cannot restore protected destinations. Keyboard focus and disabled states are visible, with desktop-width and narrow layouts.

## Verification

- `cd apps/desktop && npm ci && npm run build` — full production React compile. This step requires registry dependencies and is included in CI.
- `cd apps/desktop && npm run test:workspace` — live-render-function event/callback tests and navigation domain tests.
- `cd apps/desktop && npm run test:components && npm run test:launch-modes && npm run test:auth-experience && npm run test:textures && npm run test:sentry` — existing regression tests.
- `.github/workflows/signed-first-run-0352.yml` continues to enforce native signed-bootstrap verification in its own job.

An end-to-end Minecraft/ServerBridge test with an actual signed owner bundle, Windows/macOS native packaging and an operator production deployment is still required before calling the complete desktop stack GA-ready.
