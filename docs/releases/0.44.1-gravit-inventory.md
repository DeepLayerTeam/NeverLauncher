# NeverLauncher 0.44.1 — Gravit inventory and compatibility

The following actions are implemented by the Backend, not a simulated import.

1. Create a migration run in Admin → Migration Center and advance to `source_assessment`.
2. Upload the **same source ZIP** via `POST /api/v1/admin/migration-runs/{runId}/compatibility` and `POST /api/v1/admin/migration-runs/{runId}/inventory` with `Content-Type: application/zip`. The compatibility scanner additionally accepts `X-Gravit-Version` as an **untrusted hint**.
3. Both endpoints accept a 1..512 MiB ZIP and validate the original bytes. The compatibility report contains SHA-256 of the original ZIP, SHA-256 of a canonical list of member hashes, SHA-256 of `LaunchServer.jar` when present, source sizes, counts by category and explicit findings without exporting credentials.
4. The inventory returns per-member digests and a manifest digest. Export requires **reuploading exactly the same source ZIP** and a previously saved inventory; mismatches are rejected. Export includes secrets: protect it as a backup.

## Failure policy

- Bounded extraction: max 2 GiB expanded, 30,000 entries, expansion ratio bounded per entry, 2 MiB for inspected JSON configurations and 256 MiB for `LaunchServer.jar` manifest inspection. Encrypted ZIP entries, special files, case-folded path collisions, ZIP slip and CRC failures are rejected. These are explicit current limits, **not a promise to accept any modpack**.
- Missing client content, shared assets/libraries, account exports and texture files are surfaced for operator review, not silently interpreted as successful migration. External data must be inventoried separately. Unknown auth and optional action semantics remain blockers.
- Recognizing the `5.7.0`–`5.7.13` version string is **not evidence** that arbitrary server JARs or any specific Gravit 5.7.13 installation have been verified. Check `serverJarSha256` against an approved upstream artifact and run actual project-specific migration acceptance. An altered JAR manifest can misrepresent the binary.
- `cutoverAllowed` is always `false` in the compatibility report. This release does not perform player migration, module replacement, the real server switch or rollback. Those are scheduled for the subsequent migration stages.

## Validation

Unit and regression checks are in `services/api/internal/gravitinventory` and `services/api/internal/gravitdetector`. Actual Postgres-backed HTTP integration, signed release artifacts, canonical Go 1.27.3 build, GUI verification and live Minecraft source migrations require their configured runners/credentials. Do not call unit tests a production migration certification.
