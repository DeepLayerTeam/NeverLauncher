# NeverLauncher 0.30.8 — Discord & LAN Discovery

## Implemented runtime (not only API declarations)

- Native Desktop Discord IPC client: opcode 0 handshake, wait for READY, opcode 1
  `SET_ACTIVITY` with correlated nonces and ACK, bounded framing, 4-second I/O
  deadlines, connection replacement on failures, reconnect by periodic refresh.
- Explicit Desktop opt-in, App ID and optional HTTPS activity button. Live states:
  login, project/profile selection, Minecraft startup, game running. Discord
  absence is never a launch/Guard/Auth blocking condition. Button links are
  validated; no OAuth tokens, game credentials, user names or peer/lobby data
  are sent. IPC is local and existing Discord installation is required.
- Go CLI Discord IPC process (`nl discord presence`) supports initial presence,
  optional action buttons and stdin-driven JSON activity transitions while
  keeping the local IPC session alive. No unsupported Discord Game SDK peer API.
- Real multicast DNS-SD IPv4 publisher/resolver via UDP 5353, service
  `_neverlauncher._tcp.local.`, PTR/SRV/TXT/A, TTL 120, announcements, queries,
  query replies, goodbye (TTL=0), compressed-label parsing bounds and limits.
- `nl lan publish` requires an already listening **local HTTPS IPv4 backend**
  and verifies its certificate against the specified fingerprint before
  publishing. `nl lan discover` yields UNTRUSTED advertisements only.
- `nl lan verify` performs a TLS 1.2+ handshake, comparing SHA-256 of the DER
  leaf certificate to a pin given **independently of mDNS** in constant time.
  The pin must come from an out-of-band administrator or existing verified
  configuration, NEVER from the discovery TXT record alone. No trust anchors
  are modified and no connection is established automatically.

## Commands

The backend must already be listening with HTTPS on the specifically advertised LAN interface.
Obtain the SHA-256 fingerprint from the backend administrator/certificate.

```sh
nl lan publish --instance ExampleBackend --url https://192.168.10.2:8443 --fingerprint 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
nl lan discover --timeout 5s
nl lan verify --url https://192.168.10.2:8443 --pin "${TRUSTED_CERT_FINGERPRINT_FROM_ADMIN}"
```

Do not set `--pin` by copying `fingerprint` from the discovery result.
Discovery may be blocked by LAN multicast isolation, host firewalls, Docker
networks, or systems with active mDNS daemons; these are explicit I/O failures
or empty discovery results, not an excuse to trust unverified endpoints.
IPv6 discovery and conflict resolution are not yet supported.

Standalone Discord session with two optional action buttons:

```sh
nl discord presence --application-id 123456789012345678 --state 'Выбор сервера' --details 'NeverLauncher' --buttons-json '[{"label":"Проект","url":"https://example.org"}]'
# Dynamic updates: stdin newline-delimited JSON when --interactive is supplied.
```

For desktop: open Settings, turn on Discord Rich Presence, set Discord
Application ID from Developer Portal and optionally an HTTPS action URL.
When disabled, the activity is cleared; on process termination Discord
removes the IPC-owned activity. Discord optional failure is silent to game
operations.

## Verification status

Local Go package tests exercise DNS serialization, corruption handling, TLS
pin acceptance/rejection, malformed URLs, invalid buttons, real Unix socket
Discord handshake and acknowledged SET_ACTIVITY, and Go CLI build. A local
Linux multicast publish/discover test also exchanged real packets. All of
these tests must continue in CI. Rust native Tauri/TypeScript builds are gated
in `.github/workflows/discord-lan-0308.yml` and were NOT verified locally
where Rust toolchain and frontend dependencies were unavailable. Production
release must be blocked if CI does not pass. Live Discord desktop and real
Minecraft runtime on Windows/macOS were not tested in this environment.
