# NeverLauncher 0.26.0 — Textures & Personalization GA

The source tree contains the operational texture feature set introduced in
0.25.1–0.25.12: canonical local UUIDs, PNG upload/normalization and SHA-256
objects, S3/local storage, quotas, owner-controlled gallery, protected URL
imports, RSA-signed Yggdrasil profile textures, separate official Minecraft
Services, Desktop 2D/3D previews, Admin policy and Gravit TextureProvider
migration.

**Important:** `VERSION=0.26.0` identifies the source snapshot. It is not a
certificate of live Minecraft compatibility, nor evidence that a production
release was signed/published. GA publication MUST be blocked until the
externally signed platform evidence and CI prerequisites below succeed.

## Additional 0.26.0 executable hardening

- Texture maintenance `--command verify` now checks actual *canonical*, fully
  decoded Minecraft PNG geometry as well as SHA-256 and byte count. Arbitrary
  bytes with a valid SHA-256 filename do not constitute a usable texture.
- Restore refuses partial snapshots (the snapshot must match the entire pinned
  PostgreSQL `verified` inventory) and duplicate inventory entries; reports
  missing/mismatching objects rather than silently restoring a subset.
- Restore limits untrusted backup-manifest reads to 16 MiB and refuses symlinked
  or nonregular manifests. Existing full-file SHA-256 preflight remains required
  before any restore writes. Every restored PNG is read back and hash-checked.
- Existing 0.25.12 fenced GC, backup pins, rollback logic and real MinIO/
  PostgreSQL integration tests remain in use. **Do not run older GC workers
  concurrently with the 0.26.0 maintenance tool.**

Use the existing migrations through `0074_texture_lifecycle_recovery_02511.sql`.
There is **no new schema migration** in 0.26.0. Backup a matching PostgreSQL
snapshot and local/S3 object inventory before upgrading. Stop old maintenance
workers, run schema migration checks, deploy matched API/Admin/Desktop releases
and resume maintenance only after storage integrity verification.

## Executable tests and maintenance

From the project root:

```bash
python3 scripts/version/manage.py check
python3 scripts/contracts/validate-openapi.py
python3 -m unittest discover -s scripts/textures -p 'test_*.py' -v
(cd services/api && go test -count=1 ./internal/storage ./internal/texturepng \
    ./internal/yggdrasiltexture ./internal/texturefetch ./internal/dbmigrate)
(cd apps/desktop && npm ci && npm run test:textures && npm run build)
(cd apps/admin && npm ci && npm test && npm run build)
```

The maintenance executable is built with the normal Go dependencies:

```bash
(cd services/api && go build -trimpath -o /tmp/texture-maintenance \
    ./cmd/texture-maintenance-0253)
```

For a consistent snapshot, set `NEVERLAUNCHER_DATABASE_DSN`, the configured
`NEVERLAUNCHER_STORAGE_DRIVER` and its local or S3 configuration, then run:

```bash
/tmp/texture-maintenance --command verify --report /secure/texture-verify.json
/tmp/texture-maintenance --command backup --backup /secure/texture-snapshot-YYYYMMDD
# Restore ONLY against the matching PostgreSQL inventory after exercising dry-run
# and recovery validation on a disposable environment:
/tmp/texture-maintenance --command restore --backup /secure/texture-snapshot-YYYYMMDD
```

Use only an empty, protected directory for new snapshots, use restrictive
filesystem permissions and keep the exact corresponding PostgreSQL snapshot.
The tool refuses an incomplete inventory match, preventing a "successful" but
partial restoration. For a staged recovery, restore the matching PostgreSQL
snapshot first, then the objects; run `verify` after recovery. An error while
replacing an S3 object requires intervention and another integrity scan.

The release CI invokes `.github/workflows/texture-certification-02512.yml`
with real PostgreSQL 17, MinIO, Go race tests, live protocol CLI compilation,
Desktop/Admin test/build jobs. The manually protected 0.26.0 GA workflow
`.github/workflows/textures-ga-0260.yml` requires that entire suite to pass.

## Independently signed release evidence

An *external* release run must upload **six separately signed** artifact
bundles as `textures-ga-0260-{os}-{arch}` for Windows, Linux and macOS on amd64
and arm64. Each bundle must contain its actual native release installer plus:

- `attestation.json` with `schemaVersion=neverlauncher.textures.ga.v1`,
  `productVersion=0.26.0`, the exact 40-hex-character git commit, target name,
  `status=passed`, `actualExecution=true`, `sourceTreeClean=true`, and UTC
  `recordedAt` within the verifier's freshness window;
- `attestation.sig`, a lowercase hex Ed25519 signature over the raw
  `NeverLauncher-Textures-GA-0.26.0-v1\n` domain prefix and the EXACT bytes of
  `attestation.json`, signed by an **independent authorized release evidence
  signer**. The signing private key must not be added to this repository;
- `reports`, exactly five entries (`gameplay`, `official`, `backend`, `desktop`,
  `installer`), each a `{ "file": "direct-name.json", "sha256": "..." }`
  reference to a hashed JSON report. Every report must contain its report type
  schema (`neverlauncher.textures.ga.{type}.v1`), exact version/commit/target,
  `status=passed`, `actualExecution=true`, `mocked=false`, `simulated=false`,
  and the mandatory type-specific positive observations enumerated in
  `scripts/textures/ga_gate_0260.py`;
- `releaseArtifact` with the exact real installer filename and SHA-256. The
  verifier streams the installer while hashing; evidence claims of OS signature
  validation are checked against the trusted independent signer.

The real gameplay report requires real vanilla, Fabric and NeoForge launches,
remote observer confirmation of classic/slim/cape, cache invalidation. The
backend report requires actual PostgreSQL 17, live S3, tested backup/restore,
GC races, Gravit migration, RSA signed texture profile, SSRF and foreign UUID
rejections. The official report requires a real owned Microsoft/Minecraft
account, live ownership-verified profile/skin/cape operations without local UUID
mixing. The native Desktop report requires real 2D/3D/cape rendering,
upload/cancel/progress and error paths. The installer report confirms actual
signed installation and rollback with a verified trusted OS signer.

The authorized verifier, not the source tree, makes the final decision:

```bash
python3 scripts/textures/ga_gate_0260.py \
  --evidence /secure/six-platform-evidence \
  --trusted-public-key "$NEVERLAUNCHER_TEXTURE_GA_TRUSTED_ED25519_PUBLIC_KEY" \
  --commit "$EXACT_RELEASE_GIT_SHA" \
  --output /secure/texture-ga-verdict.json
```

A missing target, invalid signature, differing installer hash, skipped/false
observation, simulated report, symlinked proof, duplicate JSON key or wrong
commit is a **hard failure** (`status=incomplete`, nonzero exit). The source
repository cannot issue its own proof by adding tests or creating fake JSON.
The GitHub workflow additionally requires production-release environment
approval and `NEVERLAUNCHER_TEXTURE_GA_PUBLIC_KEY` configured as the approved
independent trust root in repository/environment variables.

Do not upload live access tokens, private keys, full usernames, account email
addresses or personal profile data in evidence artifacts. Store redacted
proofs and hashes only. Even a passed verdict authorizes release review; the
workflow intentionally does not upload or publish installers on its own.

## Deployment and rollback

- Apply existing migrations, deploy the matching release components, and
  configure a permanent RSA Yggdrasil signing key (not the Ed25519 release
  attestation key). Restrict texture domains and the safe URL fetcher.
- Keep official Microsoft/Xbox/XSTS tokens and UUIDs isolated from locally
  signed Yggdrasil identities. Never treat local skins/capes as Microsoft-owned.
- Confirm S3 preconditions and ETags with the **target** provider, not just
  MinIO. Record live 2D/3D Desktop tests and game renders.
- Test a clean restore of the exact matching database/blob snapshot. If
  rolling back application code, stop maintenance GC and verify backward
  compatibility before starting older components; newer schema migrations
  should not be reversed destructively on production data.
- Until every required independent evidence file is validated, this version
  remains an **uncertified source build**, not a released GA installer.
