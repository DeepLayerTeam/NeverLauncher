# NeverLauncher 0.35.4 — verified downloads and recovery

This release changes executable Desktop/Native NeverRuntime paths, not only manifests or API contracts.

## Player workflow

Open **Downloads** → **Download missing** or **Repair**. Progress frames come from NeverRuntime's active worker pool and are emitted during streaming. The UI shows actual network bytes, an observed five-second-window transfer rate, an approximate ETA, and the number of signed SHA-256-verified bytes. A failed HTTP mirror or retry can increase wire bytes without increasing verified bytes: the UI deliberately does not equate them. ETA is unknown when traffic is stalled, while the commit/verification phase has no ETA.

The stages are `starting`, `downloading`, `retrying`, `mirror-fallback`, `staged`, `verifying`, `publishing`, `completed`, `paused`, `cancelled`, and `failed`. **Staged is not installed**: `completed` is emitted only after the native transactional publication/rollback boundary. Cancellation and pause use the existing durable native watch channel and signed job journal; resuming reads the saved manifest against the Desktop's independent pinned key and reuses verified HTTP Range partials. **Do not cancel during `publishing`**: that button is disabled while NeverRuntime performs the protected switch.

If the native operation returns a partial failure or a persistent `pending` job, the UI presents one recommended recovery action. Disk and transport failures suggest retry, hash mismatch suggests repair, and invalid signatures/pinned keys prohibit unsafe retry or bypass. After successful native download, the Desktop checks installed files again and rejects unverified results. The repair flow also requires a `ready` native result and no invalid required file.

## Verification

- `cd apps/desktop && npm run test:downloads` — parser/formatting and verified-vs-wire progress, error and security behavior.
- `cargo test --manifest-path runtime/neverruntime/Cargo.toml download_scheduler` — local TCP HTTP workers, failed mirror integrity, throughput/ETA and bounded concurrency.
- `cargo test --manifest-path runtime/neverruntime/Cargo.toml durable_downloads` — real partial pause/resume and signed recovery.
- `.github/workflows/download-reliability-0354.yml` — desktop production build and runtime regressions in CI.

## Limitations of this workstation

The Desktop dependency cache lacks Vite 8.0.14 and there is no local Rust toolchain, so native compile/test, React production build, and actual Minecraft/server E2E could **not** be certified here. The new TypeScript tests and existing standalone desktop regression scripts pass. CI configuration is a runnable check, not evidence of success until its workflow completes. The supplied archive was named 0.35.3 but contained `VERSION=0.35.2`; the canonical version manager was used to set and check all supported release metadata at 0.35.4.
