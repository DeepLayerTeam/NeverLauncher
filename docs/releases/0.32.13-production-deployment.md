# NeverLauncher 0.32.13 — DEP09 production deployment

**Scope:** executable deployment commands, Standard Compose, Network/HA overlay,
native Linux systemd install using the existing signed Ed25519 bundle, safe removal.
**Not claimed:** a SQLite-only HTTP Repository, live SQLite → PostgreSQL cutover,
or independently certified multi-host failover. PostgreSQL is still mandatory.

## Docker Compose: Standard

Requirements: Docker Engine with Compose v2, HTTPS terminating reverse proxy,
validated Guard/Bridge release policies, local filesystem appropriate for SQLite
WAL in Docker's named volume, and independent off-host backups. The supplied
Compose continues using PostgreSQL 16. Do **not** change this major version
against an existing volume without a PostgreSQL upgrade procedure.

```sh
cp deploy/production/env.production.example deploy/production/.env
chmod 600 deploy/production/.env
# Edit .env. Replace every placeholder, use cryptographic random secrets,
# supply signed Guard/ServerBridge allowlists and the correct HTTPS origin.
python3 scripts/install/production-deploy.py compose check --mode standard
python3 scripts/install/production-deploy.py compose up --mode standard
python3 scripts/install/production-deploy.py compose status --mode standard
```

Default Standard starts PostgreSQL, API, Admin, Nginx and a one-shot
volume initializer. **Redis is not started.** API uses a persisted SQLite WAL
coordinator in the `neverlauncher_coordinator` named volume for leases/rate
limiting, with exactly one Backend replica. PostgreSQL remains the primary
repository. Named volumes hold PostgreSQL, storage, backups, factory and the
coordinator. HTTPS must be provided by an external proxy/load balancer; the
bundled Nginx listens on HTTP only. Do not expose that port publicly without TLS.

For an upgrade, perform and verify independent backups of PostgreSQL, local
blobs and configuration first; then change `NEVERLAUNCHER_IMAGE_TAG` and invoke:

```sh
python3 scripts/install/production-deploy.py compose up --mode standard --backup-confirmed
```

The command runs `docker compose config --quiet`, then `docker compose up -d
--wait`, failing if Compose health checks do not pass. No CI simulation
substitutes for real readiness and recovery tests. Automatic database migration
in Standard requires a tested backup/rollback plan.

## Docker Compose: Network/HA

Supply actual S3 endpoint/bucket/credentials, Redis password, unique stable
`NEVERLAUNCHER_REPLICA_ID` and production release policies in the `.env` file.
Set `NEVERLAUNCHER_DEPLOYMENT_MODE=network-ha` in `.env`. Do not use the same
replica ID for two Backend instances. Redis is started with its `network-ha`
profile; API switches to S3 and PostgreSQL + Redis; SQLite coordinator is
disabled. DB automatic migrations are disabled in this mode: migrate separately
and validate the schema and application versions before traffic.

```sh
python3 scripts/install/production-deploy.py compose check --mode network-ha
python3 scripts/install/production-deploy.py compose up --mode network-ha
```

This is a **single Compose host with HA-required infrastructure checks**, not
a certified multi-host HA architecture. Additional hosts need independent
configuration and validated failure/fencing behavior. To switch modes, stop and
uninstall the current Compose application **without purging volumes**, then
reconfigure and deploy the new mode after completing the appropriate state/
blob migration. Switching `.env` alone is refused.

## Native Linux systemd

Requires root, active systemd, PostgreSQL already provisioned, verified native
ext4/XFS/Btrfs SQLite coordinator storage, and a trusted pinned Ed25519 public
key obtained **independently** of the release bundle. Build the previously
implemented signing-aware installer:

```sh
cd installer && go build -o /tmp/neverlauncher-install ./cmd/neverlauncher-install
# Independently install/review binary as root-owned /usr/local/bin/neverlauncher-install.
# Provision /etc/neverlauncher/backend.env using neverlauncher-install init,
# then supply the approved Guard/Bridge policies (permissions 0600).
```

A signed release bundle must contain executable
`bin/neverlauncher-api`. DEP09 accepts version **0.32.13 or later** (monotonic upgrades) and verifies all
manifest entries before writing `/opt/neverlauncher/releases/0.32.13`.
It creates the dedicated `neverlauncher` OS user, app state directories,
a root-owned systemd unit, and an atomic `current` release pointer.

```sh
sudo python3 scripts/install/production-deploy.py native install \
  --bundle /secure/neverlauncher-0.32.13.bundle.zip \
  --trusted-key /secure/release-publisher.pub \
  --env /etc/neverlauncher/backend.env
```

Existing installs require `--upgrade --backup-confirmed` and a fresh release
version; an already-existing signed release directory is never overwritten.
The old release is retained. On failure to start or pass local `/ready`, the
unit and pointer are rolled back and the old service is restarted where
possible. Database changes are **not** automatically reversed: do not run an
unbacked migration during an upgrade.

The native command provisions only the API service; external PostgreSQL,
TLS proxy and static full Admin hosting remain independently administered.
The minimal embedded Admin setup page is available through the API.

## Safe uninstall

```sh
# Stop Compose and preserve every named volume:
python3 scripts/install/production-deploy.py compose down --mode standard
# Remove Compose resources, still keep PostgreSQL/data/backup volumes:
python3 scripts/install/production-deploy.py compose uninstall --mode standard

# Native: remove only the DEP09-owned systemd unit and signed releases.
sudo python3 scripts/install/production-deploy.py native uninstall
```

Data and credentials are retained by default. **Data destruction is separate**:

```sh
python3 scripts/install/production-deploy.py compose uninstall --mode standard \
  --purge-data --confirm PURGE-NEVERLAUNCHER-VOLUMES
sudo python3 scripts/install/production-deploy.py native uninstall \
  --purge-data --confirm PURGE-NEVERLAUNCHER-NATIVE-DATA
```

Compose purge deletes the **NeverLauncher Compose project named volumes**,
including PostgreSQL data. Native purge deletes **only DEP09-marked local
`/var/lib/neverlauncher`** after checking that no symlink or mount is inside;
it never deletes the external database, `/etc/neverlauncher`, or unrelated
operator paths. Preserve off-host backups before any destructive action.
Do not remove secrets `.env` before uninstall; preflight intentionally requires
valid configuration to identify the intended deployment.
