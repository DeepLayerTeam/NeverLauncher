# NeverLauncher 0.35.10 — Player/Operator Diagnostics & Support

## Player

1. Open **Diagnostics**. Select **Сформировать предпросмотр**.
2. Review the complete native-generated report. The bundle stores **only** release/platform/stage identifiers and aggregate category counts. No raw logs, user identifiers, paths, URLs, tokens or credentials are collected. It is not possible to enable raw-logs upload with this version.
3. **Сохранить пакет локально** writes the exact reviewed report to the application-owned diagnostics directory with private permissions and a cryptographically random filename. The review token is single-use, expires after 10 minutes and is not part of the file.
4. **Отправить в поддержку** is separately enabled only after selecting the explicit consent checkbox and signing in. Desktop sends the reviewed report to `POST /api/v1/diagnostics/reports` with the current account bearer session; the bearer token is never included in report content. A generated support ID confirms server acceptance.
5. To prevent duplicate reports, if the network fails *after* submission, contact support before retrying; a network exception is not proof that the operation was rejected.

The existing setting **Send diagnostic reports (opt-in)** is separate: it governs minimal Sentry error categories, never bulk support bundles. Manual support uploads are never scheduled or automatic.

## Operator

Admin → **Диагностика** displays current allowlisted Backend health and up to 100 newest anonymized player reports. `diagnostics:read` is required. Operators can download exact JSON locally for a support case. Reports are never returned to anonymous clients.

Backend support uploads require an authenticated user, `consent=true`, JSON <= 8 KiB and a strict allowlist of event fields/categories; extra keys, free-form logs and invalid fields are rejected. Reports are stored in `BackupRoot/support-reports`, 0700 directory/0600 files, capacity-capped at 1000 reports. Operational retention/deletion after incident closure remains the deployment operator's responsibility; do not place this directory on an unaudited or publicly served volume.

Operator bundle no longer includes storage/database paths, S3 endpoints, public URLs or raw storage/DB error messages. Counts and categorical health results remain available.

## Verification boundary

New Node and Go negative tests plus native Rust tests and 3-platform CI are included. Neither CI outcomes nor packaged native Minecraft E2E are asserted without a real run; verify with production staging before deployment.
