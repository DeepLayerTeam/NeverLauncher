# NeverLauncher 0.29.5 — Local Auth, FileAuth & Rehash

## What changed in production code

* `internal/fileauth` consumes the upstream GravitLauncher FileAuthSystem **Database.json**: `Map<UUID, UserEntity>` with `username`, `uuid`, `password`. Additional fields such as Gravit permissions are deliberately not mapped to Never RBAC. **Sessions.json is never imported.**
* The importer is an offline PostgreSQL transaction, not a set of independent user/profile inserts. Each entry creates an unprivileged Never `player` user with deterministic `gravit-fileauth-<uuid>` internal ID, Never local auth identity, and immutable game profile preserving **the original Gravit UUID and case-sensitive player name**. Its login email is `lowercase(username)@fileauth.invalid` (an internal namespace, not a deliverable address). Existing names/UUIDs/emails/IDs abort the entire import; automatic linking is forbidden.
* The local provider accepts the original case-sensitive Gravit username for these **imported IDs only** (or the account's synthetic email). It never switches providers when verification fails. Unknown/custom formats cannot be imported and wrong passwords cannot cause a hash reset.
* After a successful known legacy password proof, a new **Argon2id/PHC** hash is generated and committed using `UPDATE ... WHERE password_hash = priorHash AND status='active'`, so concurrent password changes cannot be overwritten. This updates only the Never-owned `users` row; external SQL/HTTP/OIDC/Microsoft credential stores are not modified. Existing Argon2id hashes are verified but not unnecessarily rewritten.
* Ordinary local account management is a CLI wrapper around the **live Admin API**. It uses the existing auth, permissions, audit, session revocation, and elevated-auth policies, rather than writing passwords directly to PostgreSQL while the Backend is running. `list` / `export` explicitly allowlist public account fields: **no password hashes, credentials, refresh tokens, or sessions**.

## Supported import formats (mandatory choice)

`sha256-hex` (typical Gravit FileAuth default), `sha256-base64url` (pre-5.2.3 historical representation), `md5-hex`, `sha1-hex`, `sha512-hex`, `double-sha256-hex`, `double-sha256-binary-hex`, `phpass`, `bcrypt`, `argon2id`. Weak legacy verifiers are accepted **only for explicit local import**, never guessed from hashes; cost/length/encoding are strictly checked. For a custom verifier, implement and test the exact algorithm before importing, otherwise abort. Original plaintext is not known and cannot be pre-emptively rehashed.

## Operator procedure

1. Make a verified backup of the Never PostgreSQL database and the Gravit `Database.json`; stop any Gravit writes before the snapshot. **Do not supply `Sessions.json`.** Apply the existing Never migration catalog first.
2. Use a dedicated PostgreSQL account with migration-appropriate write permissions; keep `NEVERLAUNCHER_DATABASE_DSN` in a protected environment file (do not place credentials on the command line).
3. Dry-run all records without committing:

   ```sh
   cd services/api
   go run ./cmd/local-auth-0295 import --file /secure/gravit/Database.json --format sha256-hex
   ```

4. Review duplicate/UUID-name conflicts, back up the database, then run with `--apply`:

   ```sh
   go run ./cmd/local-auth-0295 import --file /secure/gravit/Database.json --format sha256-hex --apply
   ```

5. Verify login using `providerId=local` and the original Gravit player name, then inspect `minecraft_profiles.uuid`, a protected Minecraft join, and the resulting Argon2id password row. Gravit role/permissions are **not** adopted; assign Never roles only via reviewed RBAC actions.
6. The second import is deliberately rejected on collisions. There is no force overwrite and no automatic account merge. Perform rollback from the validated PostgreSQL backup if required.

## Local account management commands

Provide `NEVERLAUNCHER_API_URL=https://your-backend` and a current `NEVERLAUNCHER_ADMIN_ACCESS_TOKEN` (with `users:manage`). Create, disable, enable and rotate passwords use the server endpoints and their session/audit controls.

```sh
# Password is read only from stdin, never argv or output:
printf '%s\n' "$NEW_PASSWORD" | go run ./cmd/local-auth-0295 create --email user@example.invalid --name NewPlayer --role player
printf '%s\n' "$NEW_PASSWORD" | go run ./cmd/local-auth-0295 password --user-id never-user-id
go run ./cmd/local-auth-0295 disable --user-id never-user-id
go run ./cmd/local-auth-0295 enable --user-id never-user-id
go run ./cmd/local-auth-0295 list
go run ./cmd/local-auth-0295 export > /secure/accounts-only.json
```

**Security:** the password variable example is for local scripting only; prefer a protected interactive stdin source. Keep the Bearer token out of terminal history, do not connect to non-local HTTP, and do not include password hashes in any ordinary export. The `fileauth.invalid` emails are synthetic and cannot receive password-reset emails; owners must configure validated email flows explicitly when needed.

## Certification limits

Offline parser/hash tests can run without network access. The full Backend needs `golang.org/x/crypto` and registered PostgreSQL drivers. Live PostgreSQL import/login/E2E and real Minecraft player join require the protected CI/infrastructure; their results must not be assumed from compiling this patch alone.

**Source reference:** GravitLauncher/LauncherModules FileSystemAuthCoreProvider.java, `Database.json` and `Sessions.json` serialization and UserEntity fields.
