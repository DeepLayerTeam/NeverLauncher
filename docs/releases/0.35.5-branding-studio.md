# NeverLauncher 0.35.5 — Branding Studio, owner-signed bundle and Desktop consumption

## Working owner workflow

1. Log into **Admin**, select the project and open **Branding Studio** (`#/branding-studio`). You need `project:read` to view it, and `release:publish` for the selected project to sign. Without the signing permission the download button remains disabled.
2. Select the **existing owner-signed `bootstrap.signed.json`**, enter the public **Ed25519 trust root that is already provisioned in the target Desktop**, and (for delegated schema 2.0) load its existing **`trust-policy.signed.json`**. Check the original signature before editing. The signed `projectId` must match the currently selected project.
3. Edit display name, publisher, HTTPS website, accent/background/text colours, ru/en branding locale, logo PNG, in-app icon PNG, splash PNG and up to five HTTPS news links. The editor shows a **live Desktop-style preview**. This is a representation of the branding surface, not a running game client.
4. Select a **local Ed25519 32-byte seed hex file** corresponding to the provisioned root signer (v1) or active `bootstrap` delegate from the root-signed policy (v2). Click **Sign and download**. WebCrypto imports the key non-extractably; the seed is never sent through an API request or saved in browser storage. The newly signed envelope is cryptographically re-verified before download. A wrong seed fails closed. The browser must support WebCrypto Ed25519 and a secure origin (HTTPS or localhost).
5. Independently confirm the export with the **actual Prestarter production verifier**:

   ```bash
   cd prestarter
   go run ./cmd/verify-branding --config /path/bootstrap.signed.json --root-key-file /path/root-public-key.hex
   # For an existing delegated v2 trust policy add:
   # --trust-policy /path/trust-policy.signed.json
   ```

6. Place the **newly signed bootstrap** in the owner installer bundle and rebuild the **platform-signed** installer using the existing `scripts/release/build-branded-installers.py` workflow and the same trust root. Do **not** edit a published installer in place: doing so invalidates its platform signature. Existing installer manifest/component SHA-256 pins remain unchanged; no bypass of stable publication gates is introduced. The Admin export is **not** a deployed release or a signed executable.

## Signed format and real enforcement

`branding` remains inside the **exact Ed25519-signed bootstrap payload**; it is not pulled from an unsigned URL, localStorage, a mutable renderer config or an unauthenticated endpoint. New optional fields: `accentColor`, `backgroundColor`, `textColor` (strict `#RRGGBB`), `logoPng`, `iconPng`, `splashPng` (embedded base64 PNG, <=128 KiB each, 1024x1024 standard/2048x1200 splash max), `locale` (`ru` / `en`), `news` (<=5 HTTPS `{title,url}`). `displayName`, `publisher` and `websiteUrl` remain compatible. No HTML, SVG, dynamic code, remote images, custom stylesheet or native capabilities are accepted.

Prestarter validates these fields, the browser signer independently verifies the original and resulting envelope (v1 root / v2 root-signed delegated policy), and **Tauri native Rust** validates the signed payload again before releasing trusted rendering data to React. Existing Desktop CSP already permits embedded PNG `data:` images, while blocking arbitrary scripts; untrusted content never receives Tauri command access. Signed links open in a separate browser context with `noopener noreferrer`.

The `iconPng` controls the **in-app logo**. OS taskbar icons, executable resources, code signing and platform package metadata must still be generated during the normal native build. Changing the signed bootstrap changes its payload SHA-256; the 0.35.2 first-run binder will therefore re-check onboarding on a changed signed bundle.

## Acceptance and limitations

- Executed: all Admin tests, including real WebCrypto v1/v2 signing and independent Go verification of exported files; Prestarter Go tests and negative branding validation; TypeScript source transpilation / pure module strict check; version manager check.
- Native Rust unit tests for verified theme and rejection of unsafe content are included, but cannot execute on this local machine without Rust toolchain.
- Full React/Tauri build requires packages missing from local offline npm cache (notably `vite@8.0.14`). The CI workflow is a runnable check, **not proof of successful remote execution**.
- No actual Windows/Linux/macOS built installer or Minecraft E2E certification was performed in this change set. Do not report the version as platform-certified GA on the basis of source code or CI configuration alone.
