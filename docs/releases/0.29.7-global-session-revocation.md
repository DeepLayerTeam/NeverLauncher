# NeverLauncher 0.29.7 — Global Session Revocation

## Runtime changes

This release adds an authoritative PostgreSQL revocation cascade to the existing Never AuthCore, Minecraft/Yggdrasil and ServerBridge runtime, with no new parallel session service:

- Revoking an active Never session invalidates its refresh token family and tokens, linked Minecraft sessions and pending Yggdrasil joins, active ServerBridge join tickets/handoffs, active player sessions and issued transfers in **the same database transaction**. An `auth_events` entry records the reason.
- Invalidation of an online ServerBridge player session enqueues `player.kick` to the existing durable control plane for its recorded proxy/backend runtimes. Repeated requests cannot duplicate the same command. The command is not evidence of actual disconnection until the connected plugin acknowledges delivery.
- Password-hash, status and global/project-role changes revoke the affected user's active sessions. Changes to role permission definitions and trusted-device status/key/trust cause the same cascade, including changes made directly by a different API replica.
- Compromised/risk-revoked sessions are terminal. Revoked sessions cannot be reactivated, and device binding/creation and game admission lock parent rows so concurrent revocation cannot leave new active credentials behind.
- User-authored pending/running jobs are fenced by revocation when their last active session is lost. Sensitive password, permission and device changes cancel relevant work even if another session is active. Running attempts are revoked and lease tokens cleared so stale worker completions cannot commit.
- HTTP Admin verification checks the current user/global-role against session/token claims. The Admin user-edit path revokes memory-backed sessions when project/global roles change. Memory risk revocation also invalidates refresh tokens.

## Deployment

Apply migration `0082_global_session_revocation_0297.sql` (identical in `services/api` and `cli` migration catalogs) **before** rolling out 0.29.7 API replicas. Take a full PostgreSQL backup and verify the existing sealed migration checksums; do not edit already-applied SQL migrations. The new trigger functions and supporting indexes are created once as a transactional migration. Deploy new ServerBridge runtimes using the supported control-plane protocol; do not assume an offline bridge has disconnected the player.

Changes to existing auth/session/bridge rows and the enqueueing of player-kick commands use the same PostgreSQL commit boundary. Avoid applying during heavy authentication bursts; test lock and statement timeouts in staging. No data or password material is exported.

## Testing and certification

`internal/repository/global_revocation_0297_integration_test.go` requires a disposable `NEVERLAUNCHER_TEST_POSTGRES_DSN` and verifies cross-connection invalidation of refresh, Minecraft, Yggdrasil, connected ServerBridge player sessions/queued kick, jobs, game-admission rejection, terminality, harmless user edits and permission changes. HTTP regression tests exercise role revocation and memory risk/refresh handling. `.github/workflows/global-session-revocation-0297.yml` runs tests with PostgreSQL 16, full API compilation, race tests and `go vet`.

In an offline environment the HTTP/API and PostgreSQL E2E cannot be certified if `pgx`, `x/crypto` and a disposable PostgreSQL instance are absent. Do not treat static SQL review or passing isolated Go tests as production certification. The target is to deny new sensitive API requests and new join/handoff admission immediately after committed revocation; real player disconnection depends on healthy control-plane polling and plugin acknowledgments. SLA targets (30s API / 60s game admission) require measured load/failover E2E before publication.
