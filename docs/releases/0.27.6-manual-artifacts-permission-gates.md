# NeverLauncher 0.27.6 — Manual Artifacts & Permission Gates

This is an executable extension of the 0.27.5 Modpack Import Engine, not a schema-only release. It handles missing artifacts without silently accepting unverified bytes, separates *local installation* from *redistribution*, and provides a restricted, audited artifact-only export.

## Import with actionable manual recovery

```bash
neverlauncher runtime client-factory import-modpack \
  --file ./pack.mrpack \
  --client-dir ./clients/pack \
  --manual-dir ./manually-acquired \
  --report ./missing.json
```

`--manual-dir` accepts the exact relative mod path (e.g. `mods/alpha.jar`) and the compatible flat filename fallback. It rejects symlink components and requires an upstream SHA-1, SHA-512, or SHA-256. SHA verification is mandatory before materialization. A failed source never produces a half-published client. An absent CurseForge API key or unavailable file metadata **cannot** be bypassed with an unverifiable manual filename, because the upstream expected hash is not known. Download permission is not inferred from a guessed CurseForge CDN link. The API `downloadUrl` / official download URL endpoint are used only when the upstream provides them. For Modrinth, only indexed URLs can be used; no third-party mirror is invented.

`--report` persists the complete failure description. The machine-readable `missing[]` fields include `code` (e.g. `api_key_required`, `metadata_unavailable`, `manual_required`, `download_forbidden`, `checksum_mismatch`, `redistribution_not_authorized`), `path`, `source`, `expectedSha1`, `expectedSha512`, `expectedSha256`, `expectedSize`, `canManual`, and `manualAction`. For a successful import, `imported[].acquisition` distinguishes `download` and `manual-verified`; every final SHA-256 is retained in the receipt and locked InstallPlan.

## Separate local installs from redistribution

**Default `--distribution local`:** creates a client for local installation once upstream hashes match. This does not claim any rights to rehost game files or redistribute mods.

**`--distribution redistributable`:** also requires `--permissions-file`. Before executing Minecraft materializers, the engine checks that *every* imported mod and override has a grant pinned to the exact pack SHA-256, relative path and imported SHA-256. Missing / conflicting rights block the build; no destination is published.

Example permission record (an operator declaration, not a generated license):

```json
{
  "schemaVersion": "neverlauncher.artifact-permissions.v1",
  "packSha256": "<64-character sha256 of the original pack.zip>",
  "grants": [
    {
      "path": "mods/example.jar",
      "sha256": "<64-character sha256 of the downloaded or manual JAR>",
      "right": "redistribute",
      "evidenceUrl": "https://example.org/publisher-license",
      "authorizedBy": "Copyright holder / responsible authorized publisher"
    }
  ]
}
```

**The operator is responsible for obtaining genuine rights.** Evidence URL and authorizing party are required declarations; the program validates their shape and exact-file coverage but **cannot independently establish legal validity, site terms, identity of a copyright holder or authenticity of the URL**. A SHA-256 match proves byte identity, not redistribution permission. Always check upstream terms and the rights holder's actual grant. Do not treat `--distribution redistributable` as a legal authorization mechanism.

```bash
neverlauncher runtime client-factory import-modpack \
  --file ./pack.mrpack --client-dir ./clients/pack \
  --distribution redistributable \
  --permissions-file ./permission-grants.json \
  --report ./rights-report.json
```

## Publication check and artifact-only export

Run the check after installation, even for a client initially imported in `local` mode. It re-verifies the entire existing InstallPlan and matches the immutable import receipt against every requested file and SHA-256. If a file changed or has no matching grant, it exits non-zero. Reports have `status: blocked|ready`, `checked`, `authorized`, `missing`, and the locked build digest.

```bash
neverlauncher runtime client-factory verify-publication \
  --client-dir ./clients/pack \
  --permissions-file ./permission-grants.json \
  --output ./rights-report.json

neverlauncher runtime client-factory export-modpack-artifacts \
  --client-dir ./clients/pack \
  --permissions-file ./permission-grants.json \
  --file ./pack-artifacts.zip
```

The export is a **NeverLauncher artifact-only overlay ZIP**, NOT a self-contained Minecraft client and NOT a native `.mrpack`. It contains `files/<relative path>` for the imported mods and overrides, plus `artifact-bundle.json` with exact hashes and declared rights. It excludes Minecraft version JARs, Mojang assets, launcher/loader libraries, Java, other user files and secrets. Every exported file is rehashed while being streamed; ZIP publication is atomic and never overwrites an existing archive. It does not publish to a remote service. Other export/release pipelines are **not automatically protected** by this CLI check: integrate `verify-publication` as a mandatory release gate before using such pipelines.

## Testing

```bash
cd cli
go test ./cmd/neverlauncher -run 'TestManualGates0276|TestModpack0275|TestClientFactory0271|TestMirrorHelper0274' -count=1
```

Tests cover real local HTTP fixtures, Modrinth import, structured missing actions, nested manual files, SHA integrity, import-time blocking, exact-file permission grants, malicious policy rejection, artifact-only ZIP export, no-overwrite behavior, and tampered lock failure. Public CurseForge access, real Minecraft GUI launches, and legal verification of rights are **not** certified by fixture tests.
