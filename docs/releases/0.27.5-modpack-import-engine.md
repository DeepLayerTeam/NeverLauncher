# NeverLauncher 0.27.5 — Modpack Import Engine

**Command implementation:** `cli/cmd/neverlauncher/modpack_import_0275.go`, wired into existing `runtime client-factory` CLI. The resulting instance is built by the actual Vanilla/Fabric/Quilt/Forge/NeoForge materializers and the same checksum-verified InstallPlan/atomic publisher as previous releases; this is not a standalone ZIP unpacker.

## Inspect first (no network or installation)

```bash
neverlauncher runtime client-factory inspect-modpack \
  --file ./my-modpack.mrpack --output ./inspect.json
```

## Import a Modrinth pack

```bash
neverlauncher runtime client-factory import-modpack \
  --file ./my-modpack.mrpack \
  --client-dir ./clients/my-pack-v1 \
  --report ./modpack-import-report.json \
  --output ./installed-report.json
```

The ZIP root must contain `modrinth.index.json` (format version 1). The importer pins Minecraft and the sole exact loader version, verifies both SHA-1 and SHA-512 for downloaded files, follows file `env.client` rules, and layers `client-overrides/` on top of `overrides/`. Server-only files and `server-overrides/` are intentionally excluded. Optional files are skipped unless `--include-optional true`. A missing mandatory file blocks publication.

Only `cdn.modrinth.com`, `github.com`, `raw.githubusercontent.com`, `gitlab.com`, and local loopback URLs (development/testing) can appear as direct Modrinth file sources. Redirects still go through the existing secure HTTP validator. Each file and the original ZIP have separate hashes in provenance.

## Import a CurseForge pack

```bash
export NEVERLAUNCHER_CURSEFORGE_API_KEY='REDACTED'
neverlauncher runtime client-factory import-modpack \
  --file ./curseforge-pack.zip \
  --client-dir ./clients/curseforge-pack-v1 \
  --report ./missing-or-complete.json
```

A CurseForge ZIP must contain the `minecraftModpack` v1 `manifest.json` and optionally the declared overrides directory. The importer resolves each exact `projectID/fileID` from the official CurseForge API, checks metadata identity and SHA-1, and queries the `download-url` endpoint if `downloadUrl` was withheld. It does **not** synthesize restricted download links or bypass file distribution restrictions. No API key, absent trusted hash, denied URL, or unavailable mandatory file results in a blocked report. Keep API keys in the environment rather than command-line arguments.

## Missing/manual files

```bash
neverlauncher runtime client-factory import-modpack \
  --file ./pack.mrpack --manual-dir ./verified-manual-files \
  --client-dir ./clients/pack-v1 --report ./missing.json
```

Manual filenames are taken from trusted metadata or the pinned index and must be regular files with matching publisher checksums. Place the exact filename in `--manual-dir`; mismatches never fall back to accepting unverified content. The `missing` list contains the file, pinned registry identity, failure reason, and required manual action. Failed imports leave no published client. An empty existing directory is *not* a valid destination: choose a path that does not exist to preserve Windows/macOS/Linux atomicity.

## Overrides, provenance and publication

Allowed overrides include instance data such as `config/`, `mods/`, `resourcepacks/`, and `options.txt`. Protected paths `.neverlauncher/`, `versions/`, `libraries/`, `assets/`, `natives/`, and `runtime/` cannot be replaced from an untrusted pack. ZIP symlinks, traversal, Windows reserved device names, oversized entries, and collisions with pinned files fail closed. `modpack-import.json` persists the original ZIP hash, imported exact file hashes and registry identifiers, and is itself included in the InstallPlan sources, alongside the existing mirror actions ledger.

No partially installed release is published: prepare and verify files in an isolated sibling workspace, invoke existing Client Factory build, insert content via its transactional stage, verify InstallPlan, then move into a fresh destination. The import report includes the resulting reproducibility digest, or `blocked` status with missing files. **The report does not establish legal redistribution rights**: hosting or redistributing third-party files requires independent permission. For a local personal install, publisher and platform terms still apply.

## Testing and limitations

```bash
cd cli
go test ./cmd/neverlauncher -run 'TestModpack0275|TestClientFactory0271|TestMirrorHelper0274' -count=1
go vet ./cmd/neverlauncher
go build ./cmd/neverlauncher
```

Tests include HTTP-backed imports for each format, SHA integrity, layering, forbidden ZIP paths, missing-file publication blocking, verified manual fallback, and `inspect-modpack`. A real end-to-end Minecraft client launch, full CurseForge hosted API interoperability, exhaustive cross-platform native testing, and runtime certification have not been established by these fixtures. CurseForge packs with other types of content in file lists (not JAR mods), unknown Modrinth dependency keys, unsupported format versions, and server-side packs are deliberately rejected rather than silently imported incorrectly; support for additional formats belongs in separate verified adapters.
