# NeverLauncher 0.30.11 — executed equivalents and desktop startup optimization

## Actual functionality

- M04 (FxRuntimeOptimizer *functional outcome*, not JavaFX): React screens for extensions, components, portability, official account, textures, device risk are loaded as separate Vite dynamic chunks, not in the initial JS dependency graph. Idle scheduling asynchronously preloads two common screens after startup, deduplicates promises, handles cancellation and evicts failed import promises (a React.lazy screen rejected by the WebView may require a reload). A localized Suspense fallback keeps the navigation shell responsive.
- Desktop production build now runs a real postbuild pass producing `dist/asset-index-03011.json` with SHA-256/size for each content-hashed asset, deterministic ordering and symlink/source-map refusal. `npm run verify:assets` catches missing/stale/tampered content; Sentry builds may generate maps for subsequent authenticated upload, but final verification rejects an unstripped map.
- CLI `module-parity audit` now uses **current** `module-parity-03011.json`. Source digests and Go/Node tests are validated per-module. The frozen 0.30.1 baseline and upstream commit remain independently verified, without rewriting the historical artifact. M02/M13–M15/M17/M18–M19 now reference actually shipping code and runnable tests from 0.30.8–0.30.10.
- Existing working equivalents M01/M03/M05–M12/M16 remain in service and are not replaced by parallel implementations. M17 intentionally remains excluded from unsafe production credentials and classloader mutations.

## Certification honesty and known limits

The current source audit contains **18 partial equivalents and one intentionally blocked unsafe module**. This is *not* equivalent to 19 certified Gravit modules. It is executable evidence of specific available functionality. Gravit binary/JAR compatibility, live Windows/macOS or Discord Cloud acceptance, fully real Minecraft launch, upstream command-by-command comparison and real Sentry Cloud uploads have not been certified by this release. JavaFX CSS-to-BSS conversion remains unnecessary for the native Tauri UI and is not supported.

The Go CLI tests and static audit can be run locally with the available Go toolchain. A real Vite output must pass the production build and integrity gate; a full native Tauri build and real cold-start performance measurements need a Rust + desktop CI environment. The CI workflow performs these additional desktop prebuild checks for Windows, Linux and macOS; successful actual CI execution is not claimed in advance.
