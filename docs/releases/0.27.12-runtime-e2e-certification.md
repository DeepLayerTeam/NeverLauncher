# NeverLauncher 0.27.12 — Runtime E2E & Certification

## Implemented executable path

`runtime client-factory certify-run` validates the existing materialized InstallPlan, current adapter pins and every tracked file, requires a *single* native OS/arch target, and copies the build to a disposable directory. It then runs the existing NeverRuntime `certify-vanilla` implementation (also used for Fabric, Quilt, Forge and NeoForge installed version profiles). This command starts a **real JVM**; it is not a fixture plan or a mock declaration. The CLI pins NeverRuntime by an operator-supplied SHA-256, hashes the actual Java binary, and checks that neither binary changed during the run.

The probe must report the exact installed profile, main class, Java major, nonempty classpath, a successful exit or sustained timeout, and a recognized Minecraft initialization marker **after** the process-output section of the runtime log. A missing marker, early JVM failure, wrong Java, damaged file, wrong OS/arch or unexpected tool exit produces **no signed certificate**. A stalled process without an initialization marker is not considered a working client. Real gameplay, multiplayer connectivity and performance are **not** inferred from process survival alone.

The signed certificate contains the InstallPlan reproducibility SHA-256, loader and exact version, native target, Java/runner binary SHA-256, launch duration, and separately retained probe/log SHA-256. Evidence is stored *outside* the immutable client directory. The Ed25519 private key is never part of the client or its lockfile.

## Commands

```bash
# Generate and safely store a trust root. Never commit private keys.
neverlauncher runtime client-factory certify-keygen \
  --private-key /secure/factory-signing.key \
  --public-key /trusted/factory-signing.pub

# Require a known, pinned real NeverRuntime executable SHA-256.
neverlauncher runtime client-factory certify-run \
  --client-dir ./clients/vanilla-1.21.1 \
  --runtime ./runtime/neverruntime/target/debug/neverruntime \
  --runtime-sha256 "$RUNTIME_BINARY_SHA256" \
  --java /opt/java-21/bin/java \
  --private-key /secure/factory-signing.key \
  --max-runtime-seconds 45 \
  --output ./evidence/vanilla-linux-x64.json

# Verify signature, exact lock, current installed files and probe/log bytes.
neverlauncher runtime client-factory certify-verify \
  --client-dir ./clients/vanilla-1.21.1 \
  --certificate ./evidence/vanilla-linux-x64.json \
  --public-key /trusted/factory-signing.pub
```

Use a graphical session or Linux `xvfb-run` with appropriate OpenGL/Mesa libraries. NeverRuntime is responsible for spawning the Minecraft client; Java must be installed, with a version matching the actual Minecraft target. A locked multi-target build must be materialized as **separate single-target installations** for native certification.

## Mandatory certification matrix

A local matrix file lists **actual client roots and certificates**, not declarations of passed tests:

```json
{
  "schema": "neverlauncher.factory.certification-matrix.v1",
  "targets": [
    {"id": "vanilla-linux", "loader": "vanilla", "minecraft": "1.21.1", "os": "linux", "arch": "x86_64", "clientDir": "../clients/vanilla", "certificate": "vanilla-linux.json"},
    {"id": "fabric-linux", "loader": "fabric", "minecraft": "1.20.1", "os": "linux", "arch": "x86_64", "clientDir": "../clients/fabric", "certificate": "fabric-linux.json"},
    {"id": "quilt-linux", "loader": "quilt", "minecraft": "1.20.1", "os": "linux", "arch": "x86_64", "clientDir": "../clients/quilt", "certificate": "quilt-linux.json"},
    {"id": "forge-linux", "loader": "forge", "minecraft": "1.12.2", "os": "linux", "arch": "x86_64", "clientDir": "../clients/forge", "certificate": "forge-linux.json"},
    {"id": "neoforge-linux", "loader": "neoforge", "minecraft": "1.21.1", "os": "linux", "arch": "x86_64", "clientDir": "../clients/neoforge", "certificate": "neoforge-linux.json"}
  ]
}
```

```bash
neverlauncher runtime client-factory certify-matrix \
  --matrix ./evidence/matrix.json \
  --public-key /trusted/factory-signing.pub \
  --output ./evidence/matrix-result.json
```

Every listed target is **required**: unsigned, missing, tampered, version-mismatched and adapter-outdated entries fail. By default, the matrix must contain all five loader families. To certify a subset for development only, explicitly pass `--require-all-loaders=false`. A passing subset is not 0.27.12 GA parity.

For actual CI runs, dispatch `.github/workflows/runtime-e2e-certification-02712.yml` with `actual_minecraft=true`. It runs live upstream installs and JVM launches on native Linux for Classic Vanilla, Modern Vanilla, Fabric, Quilt, Classic Forge and NeoForge, with real graphics dependencies. A separate mandatory job uses the pre-existing `run-vanilla-matching-e2e.sh` to start an exact-version Mojang server and verify an observed client join; its evidence is separate from the Client Factory client-launch certificate. `e2e/scripts/run-client-factory-certification-02712.sh` can be run outside CI with `NEVERLAUNCHER_CERT_LOADER`, `NEVERLAUNCHER_CERT_MINECRAFT`, `NEVERLAUNCHER_CERT_JAVA`, and `NEVERLAUNCHER_CERT_OUTPUT`. CI keys are ephemeral test trust roots; to approve public production certification, configure a separately protected signing key and audit the resulting evidence.

## Scope and unresolved certification

- Existing Minecraft compatibility E2E scripts include matching-server launch and client join evidence (`run-vanilla-matching-e2e.sh`). The new Client Factory certificate covers **client launch only**, not proof of a joined server; the older server test remains an independent release gate.
- The new Go fixture test executes real HTTP-backed Client Factory materialization, while using a deliberately fake Java/NeverRuntime fixture *solely to test negative verification, signing and integrity*. Fixture results are never labelled as real Minecraft runtime certification.
- Live Mojang/loader downloads, the native GUI launch matrix, Windows/macOS execution, hardware/graphics portability, installer service quotas and true multiplayer joining must pass on external runners before 0.27.12 can be claimed fully runtime-certified.
- `certify-verify` checks the recorded binary SHA-256 values as signed evidence but does not have access to binaries on an unrelated verifier host. Rebuilding release attestations should independently verify the permitted `runtimeSha256` against approved distribution artifacts.

No fixture or compile result is substituted for a successful native Minecraft launch.
