# NeverLauncher 0.32.5 — SQLite Durable Jobs, Leases & Outbox (DEP01/02)

## Shipped behavior

- **Persistent queue**: `Repository.EnqueueDurableJob`, `LeaseDurableJob(s)`, `RenewDurableJob`, `FailDurableJob`, `TerminateDurableJob`, `CompleteOperationJob`, `GetDurableJob` and `ListOperationAttempts`. Data lives in the same WAL DB as authentication/replay/core. No Redis or process-local state is used for these operations.
- **Immutable request identity**: unique `(kind, actor_type, actor_id, idempotency_key)`. Repeating the same operation/payload returns its original job even after restart; changing action, resource or payload returns `ErrDurableIdempotency`. Keys are **not automatically pruned** even if the caller supplies a TTL argument, since TTL reuse could repeat irreversible work. To repeat intentionally, submit a new key. Max JSON payload/result is 1 MiB.
- **Leasing**: `BEGIN IMMEDIATE` serializes claims, persists cryptographic random lease capabilities, increments `lease_fence` on each acquisition, and appends immutable-attempt identity to `durable_job_attempts`. Leases require TTL 1s..1h, are exclusive and can be renewed by the current holder only. Expired jobs may be reclaimed; previous attempt becomes `expired`. Exhausted attempts transition to `dead` permanently (operator must create a new job/key to retry).
- **Retries**: explicit failure returns to `pending` with `available_at`; delays are 0..7 days. Failure at the attempt limit transitions to `dead`. Terminal states are immutable at the SQLite trigger layer. In-flight attempts survive restart; no scheduler is required to mark a worker successful.
- **Independent scope leases**: acquire, renew and release on persistent `durable_scope_leases` rows. The fencing high-water mark is never deleted or decreased, including after release and restart. An expired or replaced scope token is rejected.
- **Transactional completion**: `CompleteJobWithOutbox` atomically commits job result and outbox events; `CommitFencedJob` additionally validates active job lease AND exact scope lease token/fencing epoch before performing a trusted callback's **SQLite-only** mutation. External I/O must happen in a separate worker consuming the outbox, never inside that DB transaction.
- **At-least-once outbox**: `EnqueueOutboxEvent`, `ClaimOutboxEvents`, `RenewOutboxEvent`, `CompleteOutboxEvent`, `FailOutboxEvent` persist event payloads, idempotency keys, TTLs, attempts, lease epochs and delivery state. A restart after sending but before acknowledgement **redelivers** the event. Consumers must de-duplicate externally (use event ID or stable idempotency key); do not claim exactly-once delivery.
- **Schema & integrity**: `PRAGMA user_version=325`, upgrade from versions 322/323/324, `foreign_key_check`, payload SHA-256 verification, immutable tombstones and fencing checks. Migration runs in a single SQLite transaction and preserves all previous core/auth/join records.

## Working local CLI

The operator must have OS-level exclusive access to the private SQLite file/directory. Every command reads a private input JSON file (mode 0600, no secrets in argv); redirect output containing a lease token to a mode-0600 file and avoid CI log exposure.

```bash
neverlauncher-sqlite core-init --db /secure/neverlauncher.db
# 0600 JSON: {"job":{"kind":"release","actorType":"user","actorId":"operator","action":"publish","resourceType":"release","resourceId":"r1","idempotencyKey":"request-1","payload":{"release":"r1"},"maxAttempts":3}}
neverlauncher-sqlite job-enqueue --db /secure/neverlauncher.db --input /secure/job.json
# 0600 JSON: {"kind":"release","worker":"local-worker","limit":1,"ttlSeconds":30}
neverlauncher-sqlite job-claim --db /secure/neverlauncher.db --input /secure/claim.json > /secure/claimed.json
# 0600 JSON: {"id":"job_...","token":"<claim leaseToken>","result":{"ok":true},"outbox":[{"eventType":"release.published","aggregateType":"release","aggregateId":"r1","idempotencyKey":"request-1","payload":{"release":"r1"}}]}
neverlauncher-sqlite job-complete --db /secure/neverlauncher.db --input /secure/complete.json
# 0600 JSON: {"worker":"event-sender","limit":5,"ttlSeconds":30}
neverlauncher-sqlite outbox-claim --db /secure/neverlauncher.db --input /secure/outbox-claim.json > /secure/outbox-claimed.json
# After idempotent external delivery: {"id":"evt_...","token":"<outbox leaseToken>"}
neverlauncher-sqlite outbox-complete --db /secure/neverlauncher.db --input /secure/outbox-ack.json
```

Other commands: `job-get`, `job-renew`, `job-fail`, `job-attempts`, `scope-acquire`, `scope-renew`, `scope-release`, `outbox-enqueue`, `outbox-get`, `outbox-renew`, `outbox-fail`. `job-fail` and `outbox-fail` accept `retrySeconds` and `error`; scope lease commands accept `scope`, `owner` or `token`, and optional `ttlSeconds`.

A native worker must check authorization again at execution time; enqueue-time authority must not be implicitly inherited. `CommitFencedJob` is an internal Go API for completing same-database operations, not an operator CLI endpoint. External consumers must respect fencing epochs and idempotency keys to guard against effects that happen outside the SQLite transaction.

## Deployment boundary / certification

This delivers **working SQLite Core queue and CLI methods**, not the main HTTP API's database switch. The existing PostgreSQL durable control plane and HTTP routes remain in use; packages, Guard/device admission, extension state, Redis-less runtime coordinator and cross-component dependency gates are still unfinished. The presence of the SQLite queue does **not** make it safe to select SQLite for the entire Backend or Network/HA mode.

SQLite lease expiry trusts the local system wall clock: run a time-synchronization service and do not tolerate large backwards clock jumps. Redis/network-based distributed fencing does not replace the SQLite store's single-process-owner constraint. SQLite FULL/WAL commits protect ordinary restart/crash recovery on a supported local filesystem, **not rollback to an old backup snapshot**; restoring a stale backup requires explicit job/outbox reconciliation and external idempotent delivery safeguards.

The artifact build environment provides Go 1.23.2 and overlayfs, not pinned Go 1.27.3 + `modernc.org/sqlite` on a supported ext4/XFS/Btrfs path. Source compilation with isolated stand-ins, `go vet` and Python SQLite DDL/invariant checks are feasible here; these do not certify runtime correctness. The repository's `sqlite-durable-0325.yml` workflow must pass with the actual pinned SQLite driver, race tests, restart/retry/fencing tests and CLI roundtrip on a supported native filesystem before treating 0.32.5 as production-qualified.
