# 0.47.7 — offline migration failure recovery

This release hardens **real** `scripts/operations/sqlite_pg_cutover_0475.py` and
`sqlite-to-postgres-live` / `sqlite-to-postgres-files`, not a separate mock
migration runner. The operator is deliberately fail-closed because 0.47.4/0.47.5
have **not** implemented a complete PostgreSQL translation of the independent
SQLite HTTP Repository, Coordinator, devices and extension state. Therefore the
current installation cannot pass the production cutover gate.

## Failure handling and operator action

| Failure before starting PG Backend | Implemented behavior | Next action |
|---|---|---|
| Interrupted SQLite online backup | Existing partial backup never reused; SQLite source never overwritten | Inspect private journal/backup; use clean workspace after reconciliation |
| ENOSPC or limited disk availability | Preflight estimates two Core backups, HTTP/Coordinator copies and WAL; storage copy checks target capacity. Actual filesystem errors still fail | Increase free space; re-check backups before restarting |
| PostgreSQL connection lost / ambiguous COMMIT | Import outcome persisted as unknown **before** CLI invocation; retry blocked | Inspect SQLRepository/staging/receipt on PostgreSQL, then manually reconcile; do not delete data blindly |
| Duplicate ID or incompatible foreign key | Importer transaction fails; no verified live receipt, backend cutover not permitted | Repair source/target conflict in an isolated copy; rerun only after authoritative PG inspection |
| MFA key mismatch or corrupt TOTP ciphertext | Authenticated decryption/rewrap fails; importer transaction rolls back | Restore the original private key; never disable MFA to force an import |
| Blob corrupted or changed while copying | SHA-256 verified by Go during source copy and destination readback; Python independently hashes the entire local source before/after copy | Stop writers, repair original blob from a verified snapshot, discard invalid target object only after forensic review |
| Incomplete file-copy receipt | No migration verification accepted unless a nonempty catalog digest exists | Re-run full offline copy and readback verification |
| Interrupted/resumed stage journal | Only ordered durable stage prefixes and matching receipts are accepted | Reconcile the failed stage; no blind stage skip/reimport |
| Failed SQLite rollback before any PG writes | Retains source databases, checks SQLite integrity, restores original env and starts all declared services; failure to restart any unit stops units and does not mark success | Fix original service and retry verified recovery |
| PG backend could have accepted any writes | A fsynced write-boundary marker is saved **before** rewriting service configuration | **Rollback to SQLite is forbidden.** Keep writers stopped and reconcile new PG writes; no automated reverse import is implemented |

### Operator invocation

Use the same command and required arguments documented in
`docs/deployment/sqlite-postgres-cutover-0475.md` with a **private, new**
`--work-dir`; provide the full list of all writer `--writer-unit` services.

- For a safe source recovery while the PG write boundary is not crossed:
  `python3 scripts/operations/sqlite_pg_cutover_0475.py rollback --work-dir ...`
  plus the same source/backup/unit/DSN arguments as the original run.
- Inspect `state.json` and `stages.jsonl` with permissions `0600` in a `0700`
  work directory. Keep them and the frozen backups independent of deployment.
- **Never** reset `writeBoundaryCrossed`, edit an import receipt, change a
  journal status, or overwrite frozen backups to force a retry.

### Verification

Run from the repository root:

```sh
PYTHONPATH=scripts/operations python3 -m unittest \
  scripts.operations.test_sqlite_pg_cutover_0475 \
  scripts.operations.test_sqlite_pg_recovery_0477 -v
```

This executes real on-disk SQLite backup/restore and operator fault injection.
`.github/workflows/sqlite-pg-recovery-0477.yml` also provisions an isolated
PostgreSQL 17 service and runs the existing Go import tests with Go 1.27.3.

**GA caveat:** failure-injection tests and a separate SQLRepository integration
test do not prove that a previously deployed Backend runs on PostgreSQL.
User login, full HTTP/Coordinator/extension migration, real service cutover,
post-cutover new-write preservation and Minecraft E2E remain unverified.
No successful production cutover or reverse migration is claimed by 0.47.7.
