- `cli/cmd/neverlauncher/trusted_jvm_0306.go`: signed `.nlext` verification using existing Ed25519 signing domain, bounded JAR validation, digest checks, atomic activation, external trust anchor, fail-closed launch verification, CLI install/verify/inspect/remove.

## Signing and install

Build with JDK 17+ (emits Java 8 bytecode):

```bash
sh examples/extensions/trusted-jvm/build.sh
(cd cli && go build -o /tmp/nl ./cmd/neverlauncher)
openssl genpkey -algorithm ed25519 -out /secure/private.pem
openssl pkey -in /secure/private.pem -pubout -out /secure/public.pem
/tmp/nl extension pack examples/extensions/trusted-jvm/build/package --output /tmp/trusted.nlext --private-key /secure/private.pem
/tmp/nl extension verify /tmp/trusted.nlext --public-key /secure/public.pem
/tmp/nl runtime client-factory trusted-install --client-dir /games/client --package /tmp/trusted.nlext --public-key /secure/public.pem --approve-full-jvm-access true
/tmp/nl runtime client-factory trusted-verify --client-dir /games/client --public-key /secure/public.pem
```

The Java agent/payload is under `.neverlauncher/trusted-jvm/releases/<signed-package-sha256>/`. An `active.json` record switches the version atomically. Existing signed releases remain available: reinstall a previous signed archive to roll back. `trusted-remove` deactivates without deleting audit artifacts. Installation verifies the real Ed25519 signature and checks JARs before modifying the active selection; launch **rechecks the signature, fingerprints and on-disk JARs**.

Every subsequent Minecraft JVM launch requires an **externally trusted key** (not shipped in the client's writable directory):

```bash
export NEVERLAUNCHER_TRUSTED_JVM_PUBLIC_KEY_FILE=/secure/public.pem
/tmp/nl runtime client-factory legacy-run --client-dir /games/client --java /path/to/java8 --username Example --uuid UUID
```

The **legacy-run adapter** currently provides the automatic Minecraft entrypoint replacement. Other launcher routes must explicitly integrate `trustedPrepare0306` before claiming trusted hooks work there. Do not use an arbitrary `-javaagent` flag or bypass the signed active record. The original Minecraft entrypoint still receives the exact game arguments. Class file hooks cover names under `net.minecraft`, `com.mojang`, Forge, Fabric and Quilt namespaces. `afterMinecraftMain` is called **after the Java `main()` returns/throws**; it is *not* a world-loaded or game-ready callback.

## JVM privileges and limitations

All trusted agents and plugins execute **inside the game JVM, with full game JVM/OS-process privileges**. Signing establishes publisher trust, not sandboxing. A plugin can change bytecode, classloaders, credentials, memory and filesystem access. Never label this as an isolated/permission-scoped extension. The external public key and private publisher key must be protected separately; do not distribute signing private keys. Existing classloader auth compatibility remains a separate feature.

Java 8 compatible agent code is built/tested against JDK 17/21; full official Minecraft 1.8–1.21 and Forge/Fabric/Quilt E2E coverage is **not established** by the synthetic fixture test. JVM `ClassFileTransformer` failures can be ignored by the JVM and are logged rather than claimed as guaranteed fail-closed bytecode instrumentation. Go verifies signed artifacts at preparation time; an attacker with concurrent write access to trusted package files can race file opens. Production deployments must protect install directories with filesystem ACLs and keep the external trust anchor read-only.
