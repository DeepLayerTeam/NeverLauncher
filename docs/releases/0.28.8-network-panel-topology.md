# NeverLauncher 0.28.8: Network Panel & Topology

## Operator flow

1. Apply the API/CLI migration `0079_serverbridge_network_admission_0288.sql` (same bytes in both catalogs). Deploy new API nodes before using the panel. Do not roll back to an older API once capacity policy is in use: an older writer does not enforce it.
2. Sign in to Admin with a project-scoped `project:read` permission. The ServerBridge Workspace now shows live PostgreSQL topology (proxy -> backend), signed routing snapshots, heartbeat/routing age, online players, reserved handoff slots, health and status. Read-only members see the network but cannot change admission.
3. With `gameserver:traffic` and a fresh MFA session, choose an **active backend** and set `operator capacity`: empty field clears the ceiling, `0` denies all new admission, `N` limits backend admission to N simultaneous online/reserved slots. A second operator changing the policy results in HTTP 409, never last-writer-wins. Runtime replacement invalidates a stale edit.
4. The Backend changes the effective admission decision at the PostgreSQL source of truth. It does **not** modify `server.properties/max-players` or disconnect existing players; existing online players can temporarily exceed a newly lowered ceiling. Outstanding handoffs are invalidated transactionally. Direct new join tickets and proxy handoff redemption also enforce this ceiling.
5. Use **Prepare drain/maintenance** to select existing Game Server Control commands; submit through the existing command form. Confirm the Bridge ACK in the journal, then verify that a fresh node-signed routing state shows draining/maintenance and `routable=false`. The panel never treats 'command queued' as completion.
6. Remove maintenance/drain through the same command flow, then verify signed state is ready, health acceptable, and the operator ceiling allows admission. Existing players and plugin state are retained.

## Enforcement and boundaries

- The standalone operator limit only **reduces** routing admission relative to the node's signed `capacityMax`. `NULL` means no operator limit, signed `capacityMax=0` means unlimited as before. `operator_capacity_max=0` denies all new arrivals.
- PostgreSQL locks serialize capacity changes with handoff minting (target row `FOR UPDATE`). A capacity change invalidates previously unconsumed handoffs. The new ceiling is also checked before handoff redemption. A backend reporting ready can still be denied by the independent operator ceiling.
- Legacy v2 handoff minting is rejected when an operator ceiling is present because v2 cannot provide runtime-bound routing proof. A previously minted v2 handoff cannot bypass the policy at redemption. Frozen ServerBridge v3 has **no new feature flags**.
- The panel gives operator evidence, not independently verified game-session success. Node declarations remain observations from authenticated adapters, not certified live Minecraft pre-login E2E. A stale routing snapshot is **not** shown as routable.
- The network limit does not cover admission paths outside NeverLauncher/ServerBridge (for example, direct unprotected Minecraft server access with no join gate, external proxy plugins bypassing ServerBridge, or unsupported adapters). Such traffic must be blocked through firewall or native platform controls.
- `gameserver:traffic` grants neither host process nor Backend management nor shell execution. The mutation requires fresh MFA and audits the actor/node/revision; project visibility is checked before revealing denial detail.
