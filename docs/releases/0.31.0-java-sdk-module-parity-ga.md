# NeverLauncher 0.31.0 — Java SDK & Module Parity GA release procedure

## Shipped code vs. certification

This release upgrades the **executable Java SDK packaging and release process**, not just contracts. The SDK, JVM-host, typed events/commands/config/storage/secrets, signed Java Extension Manager, trusted Minecraft agent and source-port-only Gravit adapter introduced by 0.30.2–0.30.12 remain in the production codebase. The current Gravit module inventory is `compatibility/gravit/module-parity-0310.json` (19 entries). The old 0.30.1/0.30.11/0.30.12 baselines remain accessible. **None of the 19 modules is asserted fully equivalent to every upstream implementation by this release**: 18 are partial and M17 retains an intentional security restriction. Unsupported upstream Gravit internals/JavaFX classes require explicit ports; never promise that arbitrary upstream JARs work unchanged.

Production GA is **conditional** on signed, identical-commit evidence from the actual external CI and release environment. In particular, local class-fixture tests do not certify all Minecraft/Forge/Fabric launches or native macOS/Windows installation. Publishing unsigned/unreviewed artifacts as GA is prohibited. Running `scripts/ga/java_sdk_ga_0310.py` does not itself publish anything to Maven Central.

## Public Java 17 SDK: actual Maven artifacts

```sh
python3 scripts/ga/java_sdk_ga_0310.py --output /secure/staging/neverlauncher-sdk
# Maven-compatible local repository: /secure/staging/neverlauncher-sdk/maven
```

This invokes real Java 17-compatible source compilation and the 42 Core, 29 runtime and 10 Gravit API tests; emits repeatable JARs, `-sources.jar`, generated `-javadoc.jar`, POMs and SHA-256/SHA-512 sidecars. Then it compiles/runs an independent downstream consumer exclusively against the emitted JARs. Results are published to CI only after checks pass. Java SDK runtime and signed extension packages are **separate artifacts**: a Maven dependency does not grant host permissions or attest to publisher trust.

Gradle consumption after uploading the repository to a controlled Maven mirror:

```kotlin
repositories { maven { url = uri("https://YOUR-CONTROLLED-MIRROR/maven") } }
dependencies {
    implementation("ru.neverlauncher:neverlauncher-java-sdk-core:0.31.0")
    // for explicitly ported Gravit-style modules only:
    implementation("ru.neverlauncher:neverlauncher-gravit-compat:0.31.0")
}
```

The adapter's POM depends on exactly the matching SDK Core version. The source-compatible Gravit subset is documented in `sdk/java/gravit-compat/README.md`. The public Maven artifacts are libraries, **not self-contained runnable host JARs**. A production extension must package the SDK and its own classes into a signed fat JAR and include it as a manifest backend/CLI target.

## Real signed packages: build / verify

```sh
(cd cli && go build -o /secure/build/nl ./cmd/neverlauncher)
python3 scripts/ga/package_java_0310.py \
  --cli /secure/build/nl \
  --private-key /secure/issuer/extension-ed25519-private.pem \
  --public-key /secure/issuer/extension-ed25519-public.pem \
  --output /secure/staging/extension-examples
```

`package_java_0310.py` builds both runnable reference JARs, creates actual signed `.nlext` packages through `nl extension pack`, verifies each with `nl extension verify`, and writes SHA-256 hashes in `index.json`. These **are examples, not certified production packages**: `java-host` deliberately includes a noncooperative `hang` command for supervision tests. Never install that example on a real production server. Do not package private keys into ZIPs or repositories. The package must be trusted by the installed NeverExtensions registry/publisher policy before installation; a valid cryptographic signature alone does not establish code safety.

## Release certification (fail closed)

The `.github/workflows/java-sdk-module-parity-ga-0310.yml` workflow executes the same **real** Java host, ported Gravit adapter, auth fixtures, signed packages, LAN/TLS pinning, Discord IPC, Sentry, module parity and actual JVM integration cases on all specified OS configurations. It additionally builds production Vite assets and performs Tauri `cargo check --locked` on Linux/macOS/Windows. It rejects Go test skips, missing files, duplicate IDs, unrecognized commands, timeouts, wrong API/protocol and version drift. A single Git commit SHA must match all platform reports. The module parity case tests all 19 entries rather than treating the subset as complete.

Run platform reports on separately provisioned runners:

```sh
python3 scripts/certification/run_integration_0310.py \
  --cases java-publication,java-signed-fixtures,java-sdk,jvm-host-e2e,gravit-e2e,java-supervisor-go,java-lifecycle-e2e,java-runtime-e2e,trusted-agent-e2e,devtools-e2e,lan-security,discord-ipc,devtools-security,sentry-backend,asset-integrity,sentry-release,module-parity \
  --cli /absolute/CI/staging/nl --report /absolute/CI/staging/integration-0310.json \
  --revision "$GIT_SHA" --timeout 300
python3 scripts/certification/review_integration_0310.py \
  --evidence /secure/CI-reports --revision "$GIT_SHA" --output /secure/integration-review-0310.json
```

The review binds approval to SHA-256 of **exact report bytes**, the required exact command lists, case counts and same checkout revision. An **independent authorized release operator** must examine the upstream CI run and sign the exact review JSON (raw bytes) using an externally protected Ed25519 key:

```sh
openssl pkeyutl -sign -rawin \
  -inkey /secure/ga-approval-private.pem \
  -in /secure/integration-review-0310.json \
  -out /secure/ga-approval.sig
python3 scripts/ga/verify_java_ga_0310.py \
  --evidence /secure/CI-reports --revision "$GIT_SHA" \
  --public-key /secure/ga-approval-public.pem --signature /secure/ga-approval.sig
```

The existing production signing pipeline `scripts/release/build-release.sh` refuses release `0.31.0` **before it removes or signs any outputs** unless the checkout is clean and the following externally provided inputs validate for its Git HEAD:

- `NEVERLAUNCHER_JAVA_GA_EVIDENCE_DIR` — actual complete multi-platform CI reports
- `NEVERLAUNCHER_JAVA_GA_APPROVAL_PUBLIC_KEY_FILE` — independent pinned approval public key **outside the source tree**
- `NEVERLAUNCHER_JAVA_GA_APPROVAL_SIGNATURE_FILE` — detached Ed25519 signature of the exact reviewed JSON **outside the source tree**

Existing backend/desktop signing, deployment, live Minecraft and other production gates remain in force. Ed25519 approval **does not automatically certify functional identity with upstream Gravit**, complete real Minecraft loader coverage or the absence of vulnerabilities.

## Verified here / still outstanding

Verified locally for this change: SDK Core, Runtime and limited Gravit Java tests; public Maven binary/sources/Javadoc/POM publication and independent Java consumer; deterministic JAR checks; real `nl` pack + Ed25519 verify for both executable example packages; refusal of tampered packages/wrong keys; actual Java Host and Gravit subprocess E2E; Go CLI, module matrix and source-version synchronization; negative approval signature/case/evidence tests.

Not verified locally: complete Go backend supervisor integration (`pgx/v5` missing from offline cache), native Tauri builds on all three OSes, all required M01–M19 module E2E, real official Minecraft + Forge/Fabric on all targets, live production systems and authorization of a 0.31.0 release by a protected operator key. Accordingly the build is a **0.31.0 source candidate, not an already approved production GA deployment**. Never mark those absent proofs as passed.
