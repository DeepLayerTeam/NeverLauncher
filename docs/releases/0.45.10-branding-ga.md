# NeverLauncher 0.45.10 — Branding GA / native installers and verified updates

This release repairs and extends the **existing runnable Prestarter / installer** rather than creating a new manifest-only subsystem. The signed bootstrap remains the authority for project identity, publisher, branding, backend trust and all exact bytes required to boot.

## Prerequisites

- Product sources at VERSION `0.45.10`; Go 1.22+ for Prestarter/installer, Python 3 and `cryptography` for the builder.
- A valid owner-signed `bootstrap.signed.json` with `projectId`, trusted Ed25519 key and `installerTargets` matching each platform's exact **already built Prestarter**. If the signature uses delegated bootstrap v2, supply its root-signed trust policy.
- Actual signed release components/Java manifests and trusted update source; the example below does not invent those assets.
- Native release OS and signing credentials: Windows Authenticode + signtool, macOS Developer ID Application/Installer + codesign/pkgbuild, Linux dpkg-deb + GPG signing key. Signed artifacts require independently provisioned root trust.
- An `iconPng` is optional; when present the Go verifier checks valid embedded PNG. The Windows native EXE icon accepts PNG up to 256×256; macOS/Linux support larger valid signed PNG. For a consistent six-target brand, use 256×256.

## Build and verification (Linux example)

```bash
python3 scripts/release/build-branded-installers.py \
  --platform linux --arch amd64 --project my-project --version 0.45.10 \
  --config /secure/owner/bootstrap.signed.json \
  --prestarter /release/neverprestarter-linux-x64 \
  --root-key-file /secure/root-public-key.hex --output dist/native
```

This command checks the root signature using Python and Go's actual Prestarter validator, pins the Prestarter bytes and architecture, writes a real `.deb`, extracts the **completed** package, executes its real `neverinstaller verify` and checks the bundled Prestarter's signed digest, then detaches/verifies the GPG signature. Failure aborts publication. The `--unsigned-test` option makes test-only artifacts that must **never** be represented as a production signed installer.

The native build on Windows writes the owner's icon resource *before* Authenticode signing and then runs the final `.exe verify`. macOS creates an `icns` in `.app`, signs the `.app` and `.pkg` and executes the installed app's bootstrap verifier. Signed PNG assets become the visible Desktop brand, and installed shortcuts receive verified local icons.

## Installation and branded update

Linux (run `launcher` as the target **desktop user**, not as root):

```bash
sudo dpkg -i dist/native/launcher-0.45.10-my-project-linux-x64.deb
launcher verify
launcher install --no-start
launcher verify-installed
```

For a brand change, the owner produces a **new signed** bootstrap, builds and signs another installer with new exact bytes, installs the package, and updates the existing profile under the same desktop user:

```bash
sudo dpkg -i dist/native/launcher-0.45.10-my-project-linux-x64.deb
launcher update --no-start
launcher verify-installed
```

The `update` command requires a verified current release, a matching signed project, profile, channel and pinned game trust root. The existing file-lock, executable SHA-256 checks and Prestarter lifecycle execute for real. The active release pointer is advanced only after successful provisioning and shortcut generation. A failed update leaves the previous signed active slot intact; use `launcher repair --no-start` with a trusted retained bundle if needed. Changing project identity is a migration, not an upgrade.

For Windows, execute the signed `.exe` with `install`, `update`, `verify` or `verify-installed`; the signed bootstrap is embedded in the single-file package. macOS uses the signed `.pkg` and `Launcher.app/Contents/MacOS/Launcher` with the same commands. GUI-first-run, system warnings and final OS signatures must be tested on actual platforms.

## Required acceptance before declaring GA

1. Produce all six final installers using actual release signing identities; verify native signatures and exact hashes *after* packing/signing.
2. On clean Windows/Linux/macOS x64 and ARM64 machines, install, open the real Desktop, provision Java, enter an actual supported Minecraft server and verify branded icons, title and backend pinning.
3. Sign a **different brand revision** under the same trusted project; upgrade all six clients and confirm the new signed display, resources, preserved accounts, mods and worlds. Verify damaged package, wrong trust root, project mismatch, unavailable update origin and interrupted update all fail closed and retain the previously verified state.
4. Repeat package-level and updater acceptance using the actual final signed bytes. Store hashes, commit, platform signature results, signer identity, logs and operator name. A local fixture .deb test is not this certification.

Do not claim an unverified Windows/macOS target is GA based on a Linux-only test. No root private key or delegated signing seed is written to the produced installers or this repository.
