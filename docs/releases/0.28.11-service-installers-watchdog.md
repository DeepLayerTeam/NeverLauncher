# NeverLauncher 0.28.11 — Host Service Installers & Watchdog

## Runtime (Linux systemd)

`nl server-bridge host service install|uninstall|start|stop|restart|status` is a real systemd installer and controller. It creates an enabled service for the existing Host Supervisor (`run`) or the existing HTTPS RemoteControl agent (`remote serve`). It does not implement an alternate process manager or shell execution API. Service definitions are created with `O_EXCL`; conflicting units are not replaced. On systemctl enable/reload failure installation is rolled back. Uninstall only deletes a NeverLauncher-marked unit, disables and stops it, then reloads systemd.

Build the CLI in a persistent location **outside** the writable Minecraft server directory. Configure and validate Host first. For a normal non-root operator:

```bash
nl server-bridge host configure --server-root /srv/minecraft --platform paper --server-jar /srv/minecraft/paper.jar
nl server-bridge host service install --scope user --name host-survival --server-root /srv/minecraft --now
nl server-bridge host service status --scope user --name host-survival
nl server-bridge host service stop --scope user --name host-survival
nl server-bridge host service start --scope user --name host-survival
nl server-bridge host service uninstall --scope user --name host-survival
```

For boot-time **system** service, run the installer explicitly as root and specify an existing unprivileged service account that owns `--server-root`:

```bash
sudo nl server-bridge host service install --scope system --name host-survival --server-root /srv/minecraft --service-user minecraft --now
sudo nl server-bridge host service status --scope system --name host-survival
sudo nl server-bridge host service uninstall --scope system --name host-survival
```

The system unit uses `User`/`Group` (never root), `NoNewPrivileges`, empty capability sets, protected system/home mounts and write access only to the chosen server root; elevated installer actions remain outside the long-running daemon. The unit is `Type=notify`, `NotifyAccess=main`, `WatchdogSec=30s`, `KillMode=mixed`, and `TimeoutStopSec=configured graceful timeout + 15s`. When systemd sends SIGTERM, the supervisor posts a **session- and process-identity-bound** stop request. The Minecraft child receives console `stop`, then the existing timeout escalates to SIGTERM/SIGKILL; systemd handles the remaining cgroup if the supervisor does not complete.

`READY=1` is sent only after JVM launch succeeds and its runtime record is saved. `WATCHDOG=1` is sent only when the supervisor session and process identity are verified and the child is running, or when the supervisor is in a recorded restart backoff. The watchdog is disabled if systemd has not configured `WATCHDOG_USEC` or the `WATCHDOG_PID` is for another process. `STOPPING=1` is emitted on service-stop signals.

For HTTPS RemoteControl, initialize the agent and provide locally stored TLS paths. Its systemd service uses `Type=simple`, `KillMode=process` (so reloading the agent does not terminate a child JVM supervisor in the agent cgroup), and does **not** claim systemd watchdog support (the watchdog applies to the JVM supervisor only):

```bash
nl server-bridge host remote init --server-root /srv/minecraft
nl server-bridge host service install --scope user --name remote-survival --component remote --server-root /srv/minecraft --listen 127.0.0.1:9443 --tls-cert /secure/tls/cert.pem --tls-key /secure/tls/key.pem --allow-source 127.0.0.0/8 --now
```

The remote service remains governed by its existing TLS 1.3, node identity, token scopes, CIDR, journal and authorization checks. `systemctl` cannot grant Game Server permissions or shell permissions. RemoteControl `serve` does not support sd_notify readiness; no misleading ready-state is emitted.

**Operational boundaries:** user-level services automatically start on user-manager activation; for reboot startup without login, a system administrator must explicitly configure lingering (`loginctl enable-linger`) or choose the system scope. The installer does not change login-manager policies or grant sudo. Windows service installation is not implemented in 0.28.11; the CLI rejects `host service` on non-Linux platforms rather than silently creating an inert service. JVM process-tree isolation beyond systemd's cgroup enforcement and integration of world-backup into RemoteControl/Admin remain outside this version. A RemoteControl `start` currently uses its existing detached Host launch path, not `systemctl start` for a separately installed Host unit; do not combine RemoteControl start/restart with independent systemd Host lifecycle management for the same root. Never deploy two host supervisors against the same root; the existing runtime identity/lock prevents unsafe adoption.

## Verification

Run:

```bash
cd cli && go test -race ./cmd/neverlauncher -run 'TestHostSystemd|TestHostService|TestServerBridgeHost|TestWorldBackup' -count=1
cd .. && python3 scripts/test/host-systemd-e2e-02811.py --cli /path/to/built/nl
```

The Python E2E uses an independent fake JVM process and a live Unix datagram socket to verify READY, WATCHDOG, SIGTERM → `stop`, runtime `stopped`, and persisted simulated world/playerdata/plugin data. This is **not** an actual Minecraft end-to-end test or a running PID 1 systemd integration test; testing on an actual systemd host remains mandatory before claiming production certification.
