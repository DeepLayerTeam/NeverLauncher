# NeverLauncher 0.30.1 — исполняемый аудит Gravit M01–M19 и Java-host API

## Что действительно реализовано

- `nl module-parity audit` — встроенная в Go CLI команда (не Python wrapper, не новый backend endpoint). Проверяет **ровно 19** записей M01–M19, названия модулей и зафиксированный upstream commit, версию продукта и ссылки на существующие исходники/тесты. Не принимает выходящие из репозитория пути, symlink evidence, дубликаты, необоснованное `verified`, отсутствие тестов у `partial` и дрейф host API.
- `--run-tests` запускает реальные top-level функции в привязанных `_test.go` через `go test -count=1 -json`, не засчитывает `skip`, не выдаёт успешный результат при запуске 0 тестов. Тесты нескольких модулей в одном Go-пакете учитываются по именам **каждого** модуля, без взаимного зачёта. Для `.test.mjs` выполняется `node --experimental-strip-types --test` с проверкой ненулевого количества успешно прошедших тестов. Таймаут задаётся отдельно для каждой тестовой группы.
- `--require-tests` возвращает ошибку, если у выбранной `partial` записи тесты не прошли или не запускались. `--require-full-parity` **намеренно возвращает ошибку** до отдельной сертификации всех M01–M19.
- Машинный отчёт содержит SHA-256 фактически прочитанных локальных файлов, `passed/skipped` и точный уровень проверок; SHA-256 — это привязка аудита к содержимому, а **не** подтверждение безопасности или соответствия модулю Gravit.
- `sdk/api/java-extension-api-0301.json` проверяется Go AST и действующим `sdk/api/extension-host-protocol.json`, включая версии `1.0`, типы запросов и реальные backend host routes. Это **дизайн публичного Java API, а не выпущенный Java SDK или Java Extension Host**; полноценная реализация запланирована на 0.30.2–0.30.4. Не создаётся параллельный registry/host и не меняется подписанный manifest v2.

## Пример использования

```sh
cd cli
go test ./internal/moduleparity ./cmd/neverlauncher -run 'TestAudit0301|TestModuleParityCLI0301' -count=1
go build -o nl ./cmd/neverlauncher
cd ..
./cli/nl module-parity audit --report module-parity-report.json
./cli/nl module-parity audit --module M07 --run-tests --require-tests --report desktop-tested.json
./cli/nl module-parity audit --module M11 --run-tests --require-tests --timeout 240s --report prestarter-tested.json
./cli/nl module-parity audit --require-full-parity # ожидаемое завершение с ошибкой
```

Требуются Go 1.22+ для Go-тестов, Node 22+ для desktop `.test.mjs`. Исполняемые тесты могут требовать другие платформы и сервисы: неуспешный тест/таймаут не считается подтверждением. Невозможность испытать Windows/macOS на Linux явно не приравнивается к cross-platform certification.

## Функциональные статусы аудита

- `partial`: найдены реальные исходники и связанные тесты, но полного functional equivalent не доказано (11 записей).
- `planned`: полноценный пользовательский исход ещё не реализован/проверен (7 записей).
- `blocked`: опасное поведение намеренно запрещено и требует безопасной альтернативы (M17).
- `verified`: на 0.30.1 **ни одной** записи. Сертификация должна учитывать реальные сценарии и платформенные ограничения.

Старая `compatibility/gravit/authorization-coverage-0211.json` — исторический снимок версии 0.21.1 и намеренно не изменяется. Источник названий и upstream commit в новой матрице взят из зафиксированного snapshot, **живое сопоставление с HEAD Gravit не выполнялось**.

### Технические ограничения этапа

0.30.1 **не** выпускает Java SDK/JVM host, не добавляет Sentry, Discord, mDNS, не обеспечивает полноценный literal JavaFX API parity и не обещает произвольную совместимость сторонних Gravit JAR. Эти задачи остаются релизами 0.30.2–0.31.0. Запуск юнит-тестов не доказывает совместимость с реально работающим Minecraft клиентом или внешней аутентификацией. Host IPC сейчас остаётся `1.0` и должен сохранять обратную совместимость.
