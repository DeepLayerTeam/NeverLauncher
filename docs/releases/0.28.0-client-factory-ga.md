# NeverLauncher 0.28.0 — Client Factory GA integration

## Shipped executable changes

- `runtime client-factory certify-matrix` is now wired into the actual CLI dispatch; 0.27.12 accidentally exposed it in the command implementation but not in the router.
- `runtime client-factory ga-sign-join` validates actual matching-server JSON and signs its exact SHA-256, a 40-character release commit and version with an operator-controlled Ed25519 root.
- `runtime client-factory certify-ga` is fail-closed: checks the pinned release identity, verifies real runtime certificates for all five loader families through the existing certificate matrix engine, requires an independently trusted and signed server-join observation, and rejects missing/expired/altered evidence.
- Admin API prepares the complete export ZIP *before* sending HTTP headers. Each file is rehashed during a bounded copy, unsafe paths/symlinks are rejected and errors discard the temporary archive. Exports are marked local-only. This does **not** bypass the permission checks or create a public release.
- Production release candidate requires an exact-commit successful protected Client Factory GA Actions run and checks independently trusted runtime and join attestations before it can build the signed release bundle.
- Version metadata are synchronized across the CLI, web application, Rust components, target matrices and deployment samples.

## Protected release process

1. Set up protected GitHub Environment `production-release`. Store two **different** Ed25519 private keys as secrets `NEVERLAUNCHER_FACTORY_RUNTIME_PRIVATE_KEY_B64` and `NEVERLAUNCHER_FACTORY_JOIN_PRIVATE_KEY_B64`. Each secret is the base64 encoding of a file containing the base64 representation of the 64-byte Go Ed25519 private key, created using `runtime client-factory certify-keygen`. Store the matching base64-encoded 32-byte public keys in repository variables `NEVERLAUNCHER_FACTORY_RUNTIME_PUBLIC_KEY` and `NEVERLAUNCHER_FACTORY_JOIN_PUBLIC_KEY`.
2. Dispatch `.github/workflows/client-factory-ga-0280.yml` with `confirm_live=true` and `expected_commit=<exact HEAD SHA>`. The job uses protected keys and real Mojang and loader downloads, five distinct native GUI launches, Go/API/Admin build checks, and a separate real matching-server join.
3. The job creates a five-family signed certification matrix, a signed joining-server observation and a GA report. Missing artifacts, mismatched commits, broken signatures or unsuccessful runs fail the workflow and leave no GA approval.
4. Dispatch `.github/workflows/production-release-candidate.yml` on `main`, providing its `client_factory_ga_evidence_run_id` plus the other independently required release evidence inputs. The workflow checks that the run succeeded on the **same commit**, and verifies the Ed25519 runtime and join evidence against the independently configured trusted public keys, using `scripts/ga/verify_client_factory_0280.py`.
5. The existing signed release, approval and publication checks still apply. Never distribute Mojang-owned files or third-party mods without the separate permission-gate review. Client Factory Admin ZIP download is for **local use only**.

## Manual gate (operator)

```bash
neverlauncher runtime client-factory ga-sign-join \
  --join-evidence e2e/runtime/matching-server.json \
  --private-key /secure/join.key \
  --version 0.28.0 --commit "$RELEASE_COMMIT" \
  --output evidence/join-attestation.json

neverlauncher runtime client-factory certify-ga \
  --matrix evidence/matrix.json \
  --runtime-public-key /trusted/runtime.pub \
  --join-evidence e2e/runtime/matching-server.json \
  --join-attestation evidence/join-attestation.json \
  --join-public-key /trusted/join.pub \
  --version 0.28.0 --commit "$RELEASE_COMMIT" \
  --output evidence/ga-report.json
```

The signer confirms *cryptographic provenance*, not the underlying truth of user-supplied JSON. Only approved independent real-run jobs and protected signing keys provide the operational guarantee. The release workflow verifies the source Actions run before accepting its artifacts.

## QA in this development environment

- The CLI GA adversarial/unit tests, fixture certification tests, targeted Client Factory integration tests, and Python verifier fixture/tamper tests ran successfully.
- An isolated Go harness exercising the **same production API ZIP packing function** passed file-integrity, symlink, traversal and race-detector checks.
- The complete services/api compilation and Admin React build have **not** been verified here: Go modules for PostgreSQL/MySQL/x/crypto and npm dependencies were unavailable in the local environment. The protected GA job explicitly executes both checks.
- The full CLI Go suite was not completed within the local execution limit. `release doctor` continues to fail for inherited repository-policy, migration/template and NeverRuntime/Managed Java consistency issues; those must be fixed before the guarded production job can pass.
- The actual five-family Minecraft GUI matrix, matching-server join, Windows/macOS runtime behavior, Docker image, Authenticode and notarization were **not executed** in this environment. No GA certification or production release is claimed until the protected workflow reports success.

## Deferred beyond 0.28.0 source implementation

Windows/macOS real-world runtime certification, Cleanroom/lwjgl3ify bridges and any target excluded from the actual signed GA matrix remain **not certified**, even where adapters can assemble files. Production release gates must not silently treat CI fixtures as equivalent to a real launch.
