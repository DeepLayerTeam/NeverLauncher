# NeverLauncher 0.32.7 — Redis-Free SQLite Coordinator (DEP03)

This changes the **live HTTP runtime** for the explicitly selected local coordinator; it is not a replacement for the main PostgreSQL repository. The existing PostgreSQL/Redis HA route remains unchanged. **Full SQLite-only backend production mode is not supported in 0.32.7.**

## Configuration

For one Linux API process, set `NEVERLAUNCHER_SINGLE_NODE_COORDINATOR_SQLITE_PATH=/var/lib/neverlauncher/coordinator/state.db`. The parent directory must be owned by the process, mode 0700, on supported local ext4, XFS, or Btrfs; the SQLite file is 0600. The pathname must be absolute in production. Set `NEVERLAUNCHER_SERVERBRIDGE_HA_REQUIRED=false` (default when explicit SQLite coordinator path is selected), `NEVERLAUNCHER_RATE_LIMIT_ENABLED=true` and `NEVERLAUNCHER_RATE_LIMIT_FAIL_CLOSED=true`. Redis is not consulted when the SQLite mode is selected; there is no fallback to process memory on SQLite failure. Other 0.32.6 production dependencies, including PostgreSQL for the main API repository, are unchanged. Never put this database on NFS, SMB, Docker overlay layers, or a multi-node shared volume.

The coordinator must NOT point to the separately-opened SQLite Core repository DB file; both open paths require exclusive ownership of the SQLite file. Use a dedicated coordinator file until the complete single-node repository integration is delivered.

## Executing semantics

- `serverbridgeha.Coordinator` is backed by durable `coord_channels`, `coord_leases`, and `coord_lease_tokens`. `TouchChannel` persists channel ownership and cursors; lower cursors cannot supersede a live higher cursor. `AcquireCommandLease` uses `BEGIN IMMEDIATE` and returns `false` when owned by another active holder. Each new acquisition uses a fresh token and strictly increasing fencing counter; old tokens are tombstoned permanently even after expiry or release. `VerifyCommandLease` compares owner + token digest and TTL. `ReleaseCommandLease` is conditional and cannot release a replacement holder's lease.
- `ratelimit.Limiter` uses persistent SHA-256-indexed per-key counters in `coord_limits`, with an atomic first increment and expiration rollover for fixed windows. Denied attempts are counted; budgets survive API restart. The same database writer is used for the ServerBridge coordinator and request limiter.
- Startup refuses unexpected local filesystem/engine, a second process with the same file, incompatible coordinator schema, or an unhealthy writer. Runtime failures are returned to the callers and, when enabled, HTTP rate limiting fails closed (503). They are never treated as free permits.
- `Prune` removes only expired rate counters and channel-presence entries when invoked. Expired lease rows and token tombstones remain to retain the high-water mark and prevent replay. There is no unbounded TTL pruning loop created in this patch. Plan external scheduled maintenance as usage grows.

## Integration / limits

`RuntimeState.ConfigureProductRuntime` directly selects this implementation when the configured path is nonempty, and `main.go` closes it on clean shutdown. It satisfies the pre-existing ServerBridge HA coordination and request-limiting interfaces, without bypassing existing upstream authorization or PostgreSQL command ownership checks. The single process filesystem owner lock blocks a second process that uses the same DB file; it cannot detect unrelated replicas configured with a different database path. Deployment configuration must enforce single-node topology.

The underlying ServerBridge runtime/controller's legacy in-memory and PostgreSQL paths are not changed. Runtime-level state parity, durable auth and all-Redis-removal from the entire Backend must be completed in later releases before advertising standalone SQLite-only production. This release also does not certify system-wide failover or cross-node coordination.

## Required verification before operating in production

The CI workflow `sqlite-coordinator-0327.yml` runs the pinned driver on a supported real local filesystem, with race/restart/concurrent lease tests and the API build. Failures/skips in that job block release. Test storage-restored copies separately before upgrades. The checked-in code adds tests, but a CI workflow file does **not** prove it has passed; inspect its actual run result before promoting this build.
