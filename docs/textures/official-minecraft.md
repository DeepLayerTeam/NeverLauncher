# Launcher 0.25.7 — интеграция с официальным Minecraft

## Реализовано (не имитация локального Yggdrasil)

Launcher 0.25.7 предоставляет **независимую** интеграцию с Minecraft Java: авторизация Microsoft OAuth 2.0 по коду устройства → Xbox Live → XSTS → токен Minecraft Services → настоящий `/minecraft/profile` Minecraft Services соответствующего аккаунта Microsoft. Адрес `/minecraft/profile` должен вернуть UUID и имя; **одного** входа в Microsoft или Xbox недостаточно для создания профиля Minecraft Java. У аккаунтов Game Pass может быть доступный профиль без обычных записей о покупке, поэтому критерием допуска является проверенный действующий профиль Minecraft.

Официальный сеанс отличается от входа в Launcher. Для входа нужны действующая сессия Launcher и **отдельное подтверждение пользователя у Microsoft**. Локальные UUID Launcher, текстуры, подписи скинов, пользовательские ID профилей, владение ServerBridge и ключи RSA Yggdrasil никогда не используются повторно для официальных аккаунтов. OAuth client ID соответствует зарегистрированному *публичному* приложению Microsoft Identity; реализации не нужен секрет клиента и она его не сохраняет.

### Конфигурация

Задайте `LAUNCHER_MINECRAFT_MICROSOFT_CLIENT_ID` равным ID приложения Azure/Microsoft Identity с поддержкой *личных аккаунтов Microsoft* и публичного клиента/авторизации по коду устройства. Согласие должно включать области `XboxLive.signin` и `offline_access`. Убедитесь, что промышленный `LAUNCHER_AUTH_TOKEN_SECRET` случайный, содержит не менее 24 байтов и **одинаков на всех репликах API** (рекомендован случайный секрет длиной не менее 32 байтов). Используйте HTTPS для Launcher. API содержит фиксированный список разрешённых внешних источников Microsoft/Xbox/Minecraft; URL от вызывающей стороны не принимаются. Перенаправления между API и Microsoft отключены, ответы ограничены 1 МиБ и конечными тайм-аутами.

### Использование API с авторизацией

Все конечные адреса требуют **Launcher** `Authorization: Bearer <access-token>`; локальный Minecraft Bearer-токен Yggdrasil здесь использовать **нельзя**.

| Операция | Метод / путь | Дополнительная авторизация |
|---|---|---|
| Начать вход по коду устройства | POST `/api/v1/minecraft/official/device/start` | Сеанс Launcher |
| Опросить статус входа Microsoft | POST `/api/v1/minecraft/official/device/poll` | `X-Official-Minecraft-Session: <flow>` |
| Получить официальные скины/плащи | GET `/api/v1/minecraft/official/profile` | Зашифрованный привязанный сеанс |
| Загрузить официальный скин | POST `/api/v1/minecraft/official/skin` | Привязанный сеанс; multipart `file` (PNG), `variant` (`classic` или `slim`) |
| Сбросить официальный скин | DELETE `/api/v1/minecraft/official/skin` | Привязанный сеанс |
| Выбрать принадлежащий пользователю плащ | PUT `/api/v1/minecraft/official/cape` | Привязанный сеанс; JSON `{"capeId":"<один из profile.capes[].id>"}` |
| Скрыть активный плащ | DELETE `/api/v1/minecraft/official/cape` | Привязанный сеанс |
| Начать официальную игру Minecraft | POST `/api/v1/minecraft/official/launch-credentials` | Привязанный сеанс; проверка идентичности Minecraft только для чтения |

После `start` покажите игроку полученные от Microsoft `userCode` и `verificationUri`. Пользователь входит напрямую на сайте Microsoft. При опросе отправляйте зашифрованный `flow` в `X-Official-Minecraft-Session`. Пока вход не завершён, API отвечает HTTP 202 с **обновлённым** значением flow и минимальным интервалом опроса; соблюдайте этот интервал и `Retry-After`. При успехе API возвращает аутентифицированный профиль Minecraft, принадлежащий Microsoft-аккаунту, и непрозрачный зашифрованный билет `session`.

Передавайте этот билет в `X-Official-Minecraft-Session` для последующих официальных операций. При обновлении токена Minecraft заменяйте билет на **новое значение заголовка ответа** `X-Official-Minecraft-Session`. Модуль Desktop `official_minecraft_0257.ts` обрабатывает такую ротацию и хранит билет только в памяти (не в localStorage и не в сохранённой конфигурации аккаунта Tauri). Сеанс доступа/обновления Launcher по-прежнему хранится в существующем хранилище учётных данных ОС.

### Семантика скинов и плащей

- Официальные скины загружаются **напрямую** в Minecraft Services токеном аутентифицированного аккаунта Microsoft. PNG предварительно проходит полный парсер и нормализатор 0.25.2; поддерживаются 64×64 (и прежний формат 64×32 classic). Официальный Minecraft может применять более строгие ограничения; ошибки внешней проверки показываются, а не обходятся.
- Активация официального плаща перебирает принадлежащие **аутентифицированному** профилю Minecraft значения `capes[].id` и отклоняет чужие ID. Пользовательский плащ, выданный проектом, нельзя добавить в этот список. Сброс/удаление через официальные Minecraft Services действует только на активный официальный скин/плащ.
- Официальные метаданные и URL скинов/плащей берутся из настоящего профиля Minecraft. Они никогда не копируются в назначения локального Yggdrasil, и Launcher **не подписывает** их локальным ключом Yggdrasil.

### Выбор идентичности в Desktop и запуск игры

Раздел **Авторизация** позволяет игроку завершить вход Microsoft по коду устройства, посмотреть проверенный официальный профиль, загрузить/сбросить скин и выбрать/скрыть свой плащ. По умолчанию режим аккаунта — **локальный**; до запуска его нужно явно переключить на **официальный**. В нативный Runtime передаются `userType=msa`, официальный UUID и настоящий Minecraft Bearer. В режиме `msa` не внедряются локальный URL Yggdrasil или агент authlib-injector. Если подписанный манифест содержит аргументы JVM с authlib-injector, официальный режим завершается отказом. Официальные токены запрещено использовать для входа через локальный ServerBridge; эта версия блокирует официальный режим при выборе локального `serverId` и запрещает его для автономного запуска.

Повторное открытие Desktop или выход сбрасывает официальный билет и требует нового входа Microsoft по коду устройства. Долгоживущий токен обновления Microsoft хранится только внутри аутентифицированно зашифрованных билетов AES-256-GCM; билеты привязаны к пользователю Launcher и ID сеанса Launcher, их срок — не более 30 дней. API не сохраняет токены или ID профилей Microsoft в таблицах локальных текстур или сеансов Minecraft и не выводит официальный Bearer в журнал. Замена `LAUNCHER_AUTH_TOKEN_SECRET` отзывает все ранее выданные официальные билеты.

### Испытания и оставшиеся проверки релиза

Модульные тесты `internal/officialminecraft` охватывают разрешения кода устройства Microsoft, цепочку идентичности Xbox/XSTS, Java-профиль, принадлежащие и чужие плащи, multipart-загрузку/сброс скина, обновление токена, перенаправления и ограничения ответа. Тесты `httpapi/minecraft_official_0257_test.go` проверяют зашифрованные билеты, подделку, истечение срока и ограничение частоты опроса (запускайте с полными зависимостями API). Команда Desktop `npm run test:official` проверяет действующий TypeScript-клиент. Перед промышленным выпуском выполните полную сборку Go/TypeScript/Rust и E2E с реальным личным аккаунтом Minecraft Java, лицензированным или доступным профилем Game Pass, зарегистрированным приложением Microsoft, аутентификатором, действующим выбором текстур и настоящим входом клиента. Поставляемый пакет изменений **не является** сертификатом подписанного выпуска и не утверждает успешность этих проверок.
