# Текстуры 0.25.1 — каноническая идентичность и версии выбора

## Область действия

Выпуск сохраняет **данные идентичности текстур и выбранных вариантов**. Он не включает загрузку PNG, доставку через локальное/S3-хранилище или полноценную реализацию подписей Yggdrasil: эти этапы запланированы отдельно на 0.25.2–0.25.7. Существующие текстуры по URL продолжают определяться, если владение доказано ранее созданным профилем Minecraft. URL без подтверждённого соответствия сохраняются в отчёте карантина и **не выдаются**.

Идентичность Minecraft (`minecraft_profiles.uuid`) назначается один раз и сохраняется. Ни ID аккаунта Never, ни ID профиля лаунчера, ни ID проекта не превращаются в новый UUID профиля Minecraft. Билеты сеанса/подключения используют тот же UUID, что и локальный профиль Yggdrasil. Область `official-minecraft` отделена; в этой версии намеренно нет API для изменения официального назначения текстуры.

## Развёртывание и миграция

1. **До** обновления 0.25.1 создайте резервную копию промышленного PostgreSQL и существующей таблицы `server_bridge_textures_v2`.
2. Разверните API 0.25.1 и выполните штатную команду миграций, атомарно применяющую `0067_texture_identity_0251.sql` через миграционную систему. Не изменяйте контрольные суммы старых миграций. Встроенный `sha256(bytea)` требует PostgreSQL 14+; обычно поддерживается PostgreSQL 17+.
3. Проверьте контрольную сумму миграции и выполните запросы:

   ```sql
   SELECT count(*) FROM texture_legacy_unmatched;
   SELECT legacy_uuid,username,reason FROM texture_legacy_unmatched ORDER BY legacy_uuid;
   SELECT realm,profile_uuid,user_id,kind,revision,source FROM texture_assignments;
   SELECT count(*) FROM texture_assignment_revisions;
   ```

4. Записи, связанные точным UUID или известным историческим алгоритмом `playerUUID910(user_id)`, получают канонический псевдоним и первую ревизию. Неизвестные владельцы остаются в `texture_legacy_unmatched` и нетронутой исходной таблице. При создании профиля Minecraft для существующего аккаунта его детерминированный псевдоним разрешается лениво, в атомарной транзакции; права владения между аккаунтами не передаются.
5. Для отката остановите процесс записи 0.25.1 и **восстановите резервную копию БД** до запуска исполняемых файлов 0.25.0. Автоматической обратной миграции нет; параллельная запись обеих версий не поддерживается. Старая таблица не перезаписывается, но новые ревизии существуют только в новой схеме и при таком откате иначе потеряются.

## Эксплуатационный API

Все перечисленные операции требуют действующего пользовательского токена Never. UUID **локального Minecraft-профиля вызывающего пользователя** определяется сервером, требуется PostgreSQL.

- `GET /api/v1/me/textures` возвращает канонический UUID и все сохранённые назначения (`skin`/`cape`, источник, видимость, ревизия, идентификаторы области и флаг активности). Аккаунт нельзя выбрать параметром запроса или произвольным UUID.
- `PATCH /api/v1/me/textures/skin` и `/cape` изменяет модель, видимость и активность **существующего** назначения с атомарным увеличением ревизии и снимком аудита. Не создаёт внешние URL и не загружает произвольное содержимое. Включение плаща также требует явного разрешения проекта или пользователя; по умолчанию доступ закрыт.
- `GET /api/v1/me/textures/skin/history` и `/cape/history` возвращают до 100 последних ревизий для аутентифицированного владельца.

Пример изменения (ревизия `1` условная: сначала получите настоящую через GET):

```http
PATCH /api/v1/me/textures/skin
Authorization: Bearer <access-token>
Content-Type: application/json

{"expectedRevision":1,"model":"slim","visibility":"private","active":true}
```

`profileUuid` допустим только как утверждение вызывающей стороны; UUID чужого аккаунта возвращает HTTP 403. Сервер **не** принимает переданный UUID как доказательство права. Отсутствие назначения → 404, устаревшая ревизия → 409, неправильная модель/видимость/тело → 400, отсутствие авторизации → 401, недоступность PostgreSQL → 503. Каждое успешно зафиксированное изменение добавляет ревизию и событие аудита. Отложенного сохранения без подтверждения нет.

Публичный `GET /api/v1/textures/{uuid}` и локальный Yggdrasil используют один канонический выбор с псевдонимами только для доказанных исторических идентичностей. Приватные, скрытые из списка и неактивные текстуры не попадают в публичный результат. Исходные URL остаются ссылками `remote-reference` и **не загружаются сервером** в 0.25.1. Перед приёмом новых удалённых или загруженных байтов необходимы будущий загрузчик с SSRF-защитой, проверка PNG и адресуемое по содержимому локальное/S3-хранилище.

## Диагностика и проверка

В исходниках есть тесты репозитория и включаемый отдельно интеграционный тест PostgreSQL `services/api/internal/repository/textures_0251_integration_test.go`. Используйте исключительно изолированную БД разработки/тестирования:

```bash
cd services/api
GOPROXY=off go test ./internal/model ./internal/dbmigrate -count=1
TEST_PG_DSN_0251='postgres://.../testdb?sslmode=disable' go test ./internal/repository -run 'TestTextureIdentityAndRevisionPostgres0251' -v
```

Интеграционный тест создаёт уникальную временную схему и проверяет миграцию старых записей, разрешение псевдонимов, нераспознанных владельцев, отказ чужому пользователю, сокрытие приватных текстур, монотонность ревизий, конфликт устаревшего CAS, неизменяемую историю и идемпотентное ленивое заполнение. Для запуска полного набора Go-тестов также нужны все зависимости `go.mod`, включая `pgx`.

**Не входят в 0.25.1:** multipart-загрузка и декодирование PNG (0.25.2), хранилище объектов (0.25.3), загрузчик URL (0.25.4), полный пользовательский жизненный цикл текстур (0.25.5), совместимость подписей (0.25.6), официальные текстуры (0.25.7), UI Desktop/Admin (0.25.8–9), импорт Gravit (0.25.10), жизненный цикл/резервное копирование (0.25.11) и Minecraft E2E (0.25.12).
