# Launcher 0.25.11 — жизненный цикл текстур и восстановление

Этот выпуск защищает существующий CLI обслуживания текстур от одновременных процессов сборки мусора (GC) и конкурентного резервного копирования/восстановления. Он работает с настоящими строками PostgreSQL и настроенным локальным либо S3-хранилищем текстур, а не с отдельным манифестом или независимой базой данных.

## Инструкция оператора

1. Перед обновлением остановите прежние процессы обслуживания текстур. Сборщики мусора версий 0.25.3–0.25.10 не учитывают закрепления резервных копий и ограниченные аренды: **никогда не запускайте старые и новые процессы одновременно**. Примените миграцию `0074_texture_lifecycle_recovery_02511.sql` штатной командой миграции Launcher **до** запуска обновлённого CLI. Учитывайте `texture_blobs` и снимки хранилища совместно в плане аварийного восстановления; одних PNG недостаточно для восстановления назначений.
2. Задайте `LAUNCHER_DATABASE_DSN` и `LAUNCHER_STORAGE_DRIVER=local|s3` с конфигурацией хранилища, совпадающей с API. Используйте отдельные учётные данные оператора.
3. Проверка объектов: `go run ./cmd/texture-maintenance-0253 --command=verify --report=texture-integrity.json`. Команда потоково читает полные объекты, вычисляет хеши, сверяет длину и SHA-256 с PostgreSQL, создаёт результат для каждого дайджеста и возвращает ненулевой код при недоступном или повреждённом объекте. Файл отчёта создаётся с правами `0600` и не перезаписывает существующий отчёт.
4. Резервное копирование: `go run ./cmd/texture-maintenance-0253 --command=backup --backup=/backups/textures-YYYYMMDD`. Инвентаризация закрепляется транзакцией против GC максимум на 45 минут; CLI ограничен 30 минутами. Снимок публикуется только после проверки и синхронизации на диск (`fsync`) **всех** файлов. Предыдущий снимок не перезаписывается.
5. Восстановление: сначала восстановите соответствующую резервную копию PostgreSQL, затем запустите `go run ./cmd/texture-maintenance-0253 --command=restore --backup=/backups/textures-YYYYMMDD`. Текущая инвентаризация БД определяет разрешённые объекты восстановления. Полный манифест и хеши объектов проверяются до начала исправлений. Локальные исправления выполняются через временный файл с `fsync` и атомарным переименованием. Для исправлений S3 необходим условный PUT с проверкой ETag и последующее контрольное чтение.
6. Сбор мусора: `go run ./cmd/texture-maintenance-0253 --command=gc --limit=50`. Кандидатами являются лишь объекты старше семи дней без назначений, сохранённых элементов, проектных значений по умолчанию, недавних ревизий или активных закреплений снимков. Уникальный токен защищает каждое требование на удаление (срок 45 минут). GC заново проверяет токен и объект хранилища, использует условное удаление S3 `If-Match`, затем атомарно удаляет строку PostgreSQL с полной проверкой ссылок. При неудачном удалении объекта освобождается аренда только текущего процесса; аренду аварийно завершившегося процесса можно перехватить.

## Эксплуатационные ограничения

- Режим `verify` проверяет все объекты со статусом `verified`. Объекты `staging` и в карантине обслуживает GC; они не считаются завершённой резервной копией.
- Защита снимка истекает через 45 минут. Не обходите 30-минутное ограничение CLI обслуживания. Если резервное копирование систематически занимает дольше, до запуска автоматических задач согласованно увеличьте оба ограничения.
- Служба S3 должна поддерживать запросы SigV4 и условный DELETE с надёжным ETag. Иначе GC безопасно отклоняет удаление вместо риска удалить объект другого процесса. Проверьте это на используемом провайдере S3.
- Никогда не запускайте копирование и восстановление из каталога, доступного для записи недоверенным пользователям. Копии содержат частные PNG. Ограничьте доступ и храните дубликаты вне основной площадки.
- GC намеренно отказывается удалять повреждённые объекты S3. Исследуйте проблему и восстановите объект из проверенного снимка до повторного запуска.
- Интеграционные тесты PostgreSQL требуют одноразовый экземпляр PostgreSQL 17+ и `TEST_PG_DSN_02511`. CI запускает настоящий PostgreSQL и тесты с детектором гонок. Полная сертификация игровой совместимости остаётся отдельным этапом 0.25.12.
