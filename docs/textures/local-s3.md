# Launcher 0.25.3 — эксплуатация локального хранилища текстур и S3

Выпуск 0.25.3 добавляет **эксплуатационное хранилище** к конвейеру безопасной загрузки PNG из 0.25.2. Сервис действует только для локальных профилей проекта; он не записывает и не подменяет официальные текстуры Mojang.

## Развёртывание

1. **До обновления** создайте резервную копию PostgreSQL и объектов `texture-blobs/sha256/`.
2. Примените `services/api/internal/dbmigrate/sql/0069_texture_storage.sql` штатным мигратором с контролем сумм (не повторяйте и не редактируйте 0067/0068).
3. Разверните API 0.25.3. При загрузке в S3 используется условный `If-None-Match: *` с подписанными `Content-Type`, заголовками кеша и SHA-256; коллизия проверяется по содержимому, а не перезаписывается. Локальные записи остаются атомарными, через жёсткие ссылки и fsync.
4. Настройте либо `LAUNCHER_STORAGE_DRIVER=local` + `LAUNCHER_STORAGE_LOCAL_PATH`, либо `LAUNCHER_STORAGE_DRIVER=s3` + существующие `LAUNCHER_STORAGE_S3_*`. **Не переключайте драйвер без миграции метаданных БД и байтов объектов.** При восстановлении и резервном копировании используется тот же драйвер, что в снимке.

Общие ограничения проекта: **20 уникальных сохранённых объектов на пользователя** и **10 МиБ суммарных нормализованных байтов**. Объекты 0.25.2, на которые указывают назначения, учитываются по одному разу у владельца во время миграции; общий физический объект с одинаковым дайджестом для двух пользователей даёт два независимых учёта квоты. Политика `texture_project_policies` (`project_id=''`) задаёт `max_blobs_per_player` и `max_bytes_per_player`. Проверки квоты и резервирование владения выполняются в одной транзакции PostgreSQL с advisory lock на пользователя. До записи байтов обработчик создаёт запись `staging` и резерв квоты. При сбое записи в хранилище или финального CAS осиротевшая запись остаётся в PostgreSQL и может быть удалена GC через семь дней; обработчик 0.25.3 не создаёт неучтённых объектов. Неучтённые объекты от старых экземпляров 0.25.2 требуют отдельной сверки инвентаря до обновления; не удаляйте их по предположениям об именах файлов.

## Автономная команда обслуживания

Выполняйте команды из `services/api` с тем же окружением, что и API, и настроенным `LAUNCHER_DATABASE_DSN`. Сборка: `go build -o texture-maintenance ./cmd/texture-maintenance`.

```bash
./texture-maintenance --command backup --backup /var/backups/launcher/textures-2026-10-23
./texture-maintenance --command restore --backup /var/backups/launcher/textures-2026-10-23
./texture-maintenance --command gc --limit 100
```

`backup` читает проверенный перечень объектов PostgreSQL, загружает и сверяет SHA-256 **каждого** объекта локального/S3-хранилища и создаёт каталог только для владельца с JSON-манифестом и файлами, адресуемыми по содержимому. Перед атомарной публикацией синхронизирует файлы и каталоги. Целевой каталог не должен существовать; неуспешная копия никогда не публикуется. Храните копию **вне хоста**, шифруйте данные и держите отдельно от исходного bucket. PostgreSQL резервируйте штатным механизмом восстановления на момент времени. Одна копия текстур **не является полной копией БД**.

`restore` требует соответствующего восстановленного перечня PostgreSQL (дайджест, размер, backend и ключ), проверяет каждый файл перед записью, повторно использует исправные объекты и чинит повреждённые атомарной заменой локального файла либо подписанным S3 `If-Match` ETag CAS с последующим полным чтением для проверки. Такое восстановление доступно **только автономной операторской команде**, а не публичной загрузке. Не восстанавливайте из недоверенного снимка. Команда не восстанавливает аккаунты, назначения и саму БД.

`gc` арендует до 100 устаревших проверенных/карантинных объектов за запуск. К удалению допускается объект возрастом **не менее 7 дней** без текущего назначения, проектного значения по умолчанию и ревизий со ссылкой на него за последние 7 дней. Повторная попытка промежуточной загрузки обновляет время последней загрузки и защищает от гонки с GC. Исполнитель переводит записи в карантин, удаляет физический объект и запись БД вместе с квотами владельца. Неудачное удаление повторяется после освобождения аренды или истечения 15 минут. Не запускайте `backup`/`restore` одновременно с GC. Запускайте GC только после успешной внешней резервной копии и по расписанию оператора, не при старте API. Никогда не обслуживайте объект драйвером, отличным от сохранённого в его метаданных.

`GET /api/v1/textures/blob/{digest}` продолжает возвращать ETag SHA-256, ограниченные проверки целостности и короткое публичное кеширование только для назначенного публичного содержимого. Предпросмотр владельца получает `private, no-store`. Удаление или замена выбора мгновенно отменяет разрешение публичной выдачи, но не может отозвать ранее кешированные внешними клиентами копии.

## Проверка

```bash
cd services/api
go test ./internal/storage ./internal/texturepng ./internal/dbmigrate ./internal/model
# Полный тест Backend требует зависимости модулей Go проекта:
go test ./internal/repository ./internal/httpapi
# Интеграционная проверка PostgreSQL для 0.25.3 (отдельная тестовая БД):
TEST_PG_DSN_0253='postgres://...' go test ./internal/repository -run TestTextureStorageQuota0253 -count=1
```

S3-совместимые реализации необходимо отдельно проверить с целевым провайдером/MinIO: условный PUT и версионирование различаются. Включите внешнее версионирование и репликацию для лучшего аварийного восстановления; резервирование уровня приложения их не заменяет.
