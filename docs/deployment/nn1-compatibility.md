# 0.51.6 — совместимость N/N−1: API, обработчик, ServerBridge, PostgreSQL

Этот выпуск поддерживает **конкретную пару бинарных файлов управляющей плоскости 0.51.5 ↔ 0.51.6** на одной БД PostgreSQL. Совместимость с произвольными более ранними или будущими версиями **не заявляется**.

## Исполняемое поведение и ограничения

- API и обработчик заданий остаются отдельными процессами `network-ha`. Существующие устойчивые задачи PostgreSQL, владение очередью исходящих событий, идемпотентность и защита от устаревших владельцев ServerBridge остаются источником достоверного состояния; в 0.51.6 не добавляется новый писатель или транспорт.
- Обе версии используют **те же 117 неизменяемых миграций PostgreSQL, что и 0.51.5**, с одинаковыми именами файлов и SHA-256. Поэтому строгая проверка миграций 0.51.5 не встречает неизвестных миграций после развёртывания 0.51.6. **Не выполняйте миграции или расширяющие/сужающие DDL во время смешанного режима.** Для следующих версий добавляйте отдельно проверенный маршрут совместимости; неизвестные миграции нельзя автоматически считать совместимыми.
- `dbmigrate.StatusOf` в новой версии работает только на чтение. Отдельная роль миграции по-прежнему удерживает существующую консультативную блокировку PostgreSQL и применяет миграции транзакционно. Отсутствующая таблица учёта, незакреплённая или изменённая контрольная сумма, неизвестная или ожидающая миграция по-прежнему блокируют запуск и готовность.
- Существующие HTTP API v1, ServerBridge v3 (и согласованный v2) и протокол устойчивых задач и очереди исходящих событий PostgreSQL не меняются. Проверка допуска совместимости выполняет **реальные** запросы `/ready` к API и обработчику заданий каждого хоста, затем `/api/v1/status`, `/api/v1/loaders`, `/api/v1/runtime/requirements` и к подписанной точке согласования возможностей ServerBridge. Между работающими версиями сравниваются стабильные отпечатки ответов протокола, включая отпечаток ключа подписи доверия и хеш возможностей Bridge.
- Лаунчер промышленного выпуска для нескольких хостов по-прежнему **отклоняет произвольную смесь образов**. Во время поэтапного развёртывания 0.51.5→0.51.6 специализированный верификатор — единственный поддерживаемый способ допуска нескольких версий. Не используйте `--skip-growth` и не ослабляйте неизменяемость образов ради превращения FAIL в PASS. Фактическое управление развёртыванием и осушением трафика относится к 0.51.7.

## Подготовка

1. На **каждом хосте** разверните обновлённые инструменты `ha_inventory_0511.py`, `multi_host_0512.py` и исходное дерево этой версии до изменения работающих контейнеров. Старые бинарные файлы поддерживаются: скрипт проверяет их реальной HTTP-готовностью и публичными маршрутами, а не по `VERSION`, тегам образов или результату `go build`.
2. Убедитесь, что на каждом Docker-хосте API и обработчик заданий используют один локальный закреплённый OCI-хеш Backend. В этом окне у двух хостов могут быть разные хеши **только** для версий `0.51.5` и `0.51.6`. Остальные образы остаются закреплёнными, а все хосты продолжают использовать одинаковые PostgreSQL, Redis, S3 и публичный адрес источника.
3. Запускайте проверку с доверенного операторского хоста с заранее закреплёнными SSH-ключами хостов и установленным `psql`. Поместите URI **единственного основного** PostgreSQL (`postgresql://user:password@db.example/launcher?sslmode=verify-full`) в приватный файл `0600`. **Не** передавайте DSN в командной строке и не включайте его в отчёты; используйте подходящий корневой TLS CA и сертификат хоста.
4. Убедитесь, что в `schema_migrations` присутствуют все 117 ожидаемых строк с закреплёнными контрольными суммами и что DSN указывает на основной сервер, а не на асинхронную читающую реплику. Верификатор читает реальные данные PostgreSQL внутри транзакции только для чтения; запись и изменение схемы не выполняются.

## Запуск

```sh
python3 scripts/operations/nn1_compat_0516.py \
  --node a=ops@node-a.example --node b=ops@node-b.example \
  --directory /opt/launcher/deploy/production --project launcher \
  --edge-url https://launcher.example \
  --pg-dsn-file /run/secrets/launcher-primary-dsn \
  --require-mixed --output /run/launcher/nn1-mixed-0516.json
```

До и после смешанного периода уберите `--require-mixed`, чтобы разрешить однородный кластер любой из двух поддерживаемых версий. Файл отчёта не должен существовать заранее; создайте приватный каталог отчётов и сохраните результат с фактическими хешами образов и независимыми свидетельствами инцидента. Ненулевой код выхода или отсутствие отчёта блокирует продвижение трафика. Верификатор отклоняет устаревшие по времени или неподдерживаемые версии рабочих процессов, несоответствие действующих HTTP-контрактов, нездоровые зависимости, неожиданные миграции, изменение отпечатка ключа подписи и несоответствие идентичностей хостов.

## Границы приёмки

Исполняемые проверки задают **критерии допуска действующей системы**, а не доказывают завершённое поэтапное развёртывание или нулевой простой. Независимо подтвердите фактическую идемпотентную доставку команд/ACK между старым и новым рабочим процессом и работу Minecraft + ServerBridge под нагрузкой; проверьте fencing пишущего PostgreSQL HA и внешний балансировщик при физическом отказе. Исходный архив не содержит свидетельств нативной проверки игры на трёх ОС или испытаний с отказом двух хостов. Совместимость для несовместимых DDL, миграций снимков миров, обновления состояния расширений и горячей замены JVM-агента не заявляется.
