# Launcher 0.50.3 — проверенный запуск JVM Minecraft под Guard

Возможность реализована **исполняемым кодом** существующей нативной функции запуска Runtime, а не альтернативным имитатором лаунчера. Она использует пакеты `launcher.trusted-jvm.v1`, устанавливаемые действующей командой `trusted-install`, и политики `launcher.guard-compatibility.v1`, устанавливаемые через `guard-policy-install`. Требуются подписанные материалы обоих видов и внешние открытые ключи оператора; нативный мост никогда не принимает хеш или список плагинов, переданный игровым процессом, в качестве авторизации.

## Действия оператора

1. Используйте обычный конвейер подписанных профилей Minecraft/ClientFactory, чтобы установить точные игровые файлы Vanilla/Fabric/Quilt/Forge/NeoForge. Загрузчик, версия и путь классов профиля остаются под контролем подписи выпуска.
2. Установите доверенный пакет расширения командой `launcher runtime client-factory trusted-install --client-dir <CLIENT> --package <SIGNED_NLEXT> --public-key <EXTERNAL_TRUSTED_KEY> --approve-full-jvm-access true`. Это код JVM с **полным доверием**, а не изолированный плагин.
3. На отдельной защищённой рабочей станции оператора подготовьте политику совместимости Guard с точными `projectId`, версией Minecraft, загрузчиком, SHA-256 всех включённых `mods/*.jar`, обязательных нативных библиотек и неизменяемых `.launcher/trusted-jvm/releases/<PACKAGE_SHA256>/agent.jar` и `plugins/*.jar`. Разрешайте только проверенные `transformations: [{"id":"net.minecraft.client.Minecraft", "ownerSha256":"..."}]`. Используйте поставляемый подписыватель Guard и установите подписанную политику. Подробности: `docs/security/guard-compatibility.md`.
4. Задайте **внешние** `LAUNCHER_GUARD_COMPAT_PUBLIC_KEY_FILE` и `LAUNCHER_GUARD_COMPAT_REQUIRED=1` в окружении лаунчера, управляемом оператором. Команды установки/обслуживания Trusted Java дополнительно используют `LAUNCHER_TRUSTED_JVM_PUBLIC_KEY_FILE`, но нативный Runtime опирается на отдельно подписанный список разрешений Guard **при каждом запуске**. Не размещайте открытые якоря доверия внутри изменяемого игрового каталога.
5. Запускайте обычный подписанный выпуск Minecraft через нативный Runtime (или существующий устаревший путь ClientFactory для старых клиентов Java 8). Нативный Runtime повторно проверяет SHA-256 установленного подписанного пакета и байты кода с подписью Guard, создаёт уникальный приватный premain-конфиг `.guard-launch-*.properties`, передаёт точный `-javaagent` для одобренного агента лаунчера и запускает исходный Java main загрузчика через `ru.launcher.trusted.MinecraftMain`. Premain сверяет хеши плагинов и ограничивает преобразования классов. Временная конфигурация удаляется после завершения JVM.

## Отказ при нарушениях

- При наличии установленного доверенного пакета без подписанной политики Guard, неизвестной подписанной области действия, повреждённой/просроченной/отозванной политике, отсутствующем/изменённом JAR, неожиданном моде или нативном компоненте, неразрешённом плагине или преобразовании запуск отклоняется **до старта** JVM.
- Неизвестные `-javaagent`, `-agentpath`, `-agentlib` и отладочные параметры по-прежнему запрещены существующими Runtime/Windows Sensor. Действительная политика не является общим разрешением на посторонние агенты.
- Точка входа подписанного модуля Java не может незаметно заменяться обёрткой пути классов. При установленном пакете Trusted JVM нативный лаунчер отказывает в таком сочетании. Сборки без Trusted JVM используют штатный путь запуска.
- В Windows Guard Sensor по-прежнему требует проверенную DLL запуска, аутентифицированный IPC, ограниченную политику процессов и контроль нативных модулей; одобренный стартовый Java-агент проверяется относительно корня подписанной **установки**, который может отличаться от рабочего каталога JVM игры.

## Приёмка, обязательная до GA

Запустите матрицу CI для шести платформ `guard-compatibility-0502.yml`, включая тесты подписанных политик `guarded_trusted_launch_0503` в нативном Runtime. Независимо скачайте итоговые подписанные пакеты на Windows x64/ARM64, Linux x64/ARM64 и macOS x64/ARM64, установите реальные версии загрузчиков (Vanilla/Fabric/Quilt/Forge/NeoForge в пределах поддержки), запустите точный модифицированный клиент с доверенным хуком, выполните вход и подключитесь к реальному серверу Minecraft, проверьте разрешённый игровой процесс и повторите испытания с изменёнными/дополнительными модами и агентами. Зафиксируйте хеши платформы/JDK/загрузчика/игровой сборки, свидетельства Guard IPC и причины завершения процессов. Настоящая тестовая Java-среда не является E2E-тестом Minecraft, а объявление CI не означает его выполнение. Загруженный проект нельзя объявлять GA до получения независимых подтверждений и прохождения действующих этапов приёмки.

### Границы безопасности

Политика предотвращает несанкционированные *стартовые* артефакты в пределах поддерживаемой границы лаунчера; пользователь, контролирующий ОС, всё ещё способен изменять процессы пользовательского пространства, окружение, поведение в памяти или локальное состояние защиты от отката. Доверенный агент JVM обладает полными привилегиями Instrumentation; список разрешённых обратных вызовов не изолирует вредоносный доверенный код. Непрерывный отзыв разрешений во время выполнения и доказательство, привязанное к серверу, — отдельные задачи 0.50.6/0.50.7, не заявленные для 0.50.3.
