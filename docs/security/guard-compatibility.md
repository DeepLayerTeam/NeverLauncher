# Launcher 0.50.2 — подписанная политика совместимости Guard

Этот релиз содержит **принудительное применение политики при запуске**, а не аттестацию безопасности всех преобразований классов работающего процесса. Политика должна быть подписана ключом, хранящимся за пределами каталога клиента. Ни одна из приведённых команд не требует размещения закрытого ключа подписи на компьютере игрока.

## Разрешение кода для конкретной сборки игры

Точная область действия подписи определяется сочетанием `projectId`, версии Minecraft и загрузчика. Для прежних проектов ClientFactory значение `projectId` берётся из проверенного `reproducibilitySha256` объекта InstallPlan; для Rust Runtime — из `projectId` проверенного игрового манифеста. Политика для одной области не разрешает другую. Значение `epoch` увеличивается при **каждом** обновлении политики или отзыве; срок действия не более 90 дней.

1. На контролируемом оператором узле создайте пару ключей без подключения клиентского устройства, после чего защитите закрытый ключ. Запускайте из каталога `cli/`:

   ```sh
   go run ./cmd/guard-policy-sign -mode keygen -private-key /secure/guard-private.hex -public-key /secure/guard-public.hex
   ```

2. Подготовьте проверенную политику JSON в UTF-8. Укажите настоящие SHA-256 **установленных байтов**, пути относительно корня игры и корректную область проекта. Образцовые значения ниже необходимо заменить — они не являются заранее разрешёнными настройками:

   ```json
   {
     "schemaVersion": "launcher.guard-compatibility.v1",
     "projectId": "INSTALL_PLAN_REPRODUCIBILITY_SHA256_OR_MANIFEST_PROJECT_ID",
     "minecraft": "1.20.1",
     "loader": "fabric",
     "epoch": 1,
     "issuedAt": 1793664000,
     "expiresAt": 1793750400,
     "artifacts": [
       {"kind":"mod", "path":"mods/example.jar", "sha256":"REPLACE_WITH_64_LOWERCASE_HEX"},
       {"kind":"java-agent", "path":".launcher/trusted-jvm/releases/PACKAGE_SHA256/agent.jar", "sha256":"REPLACE_WITH_64_LOWERCASE_HEX"},
       {"kind":"java-plugin", "path":".launcher/trusted-jvm/releases/PACKAGE_SHA256/plugins/example.jar", "sha256":"REPLACE_WITH_64_LOWERCASE_HEX"},
       {"kind":"native-library", "path":"natives/linux/libexample.so", "sha256":"REPLACE_WITH_64_LOWERCASE_HEX"}
     ],
     "transformations": [
       {"id":"net.minecraft.client.Minecraft", "ownerSha256":"REPLACE_WITH_APPROVED_JAVA_PLUGIN_SHA256"}
     ],
     "revokedDigests": [],
     "revokedTransformations": []
   }
   ```

   Поле `id` преобразования — **точное бинарное имя класса**, а `ownerSha256` — закреплённый хеш JAR доверенного Java-плагина, а не самого агента. Другие преобразования классов в обратных вызовах доверенных хуков запрещаются. Внутренние компоненты обычных загрузчиков Fabric/Forge/Quilt не получают автоматически разрешений доверенных Java-плагинов. Подписанная политика является источником разрешений только для перечисленных типов. Неизвестные `.jar` в `mods/` и нативные библиотеки в `natives/` запрещаются. Остальные игровые файлы по-прежнему проверяются существующим подписанным InstallPlan/Manifest.

3. Выполните подпись вне клиентского устройства. Никогда не помещайте `guard-private.hex` в корневой каталог клиента:

   ```sh
   go run ./cmd/guard-policy-sign -mode sign -policy reviewed.json -private-key /secure/guard-private.hex -out signed-guard.json
   ```

4. Распространяйте **открытый** ключ по доверенному каналу под управлением оператора, отдельно от полезной нагрузки клиента. На клиенте задайте:

   ```sh
   export LAUNCHER_GUARD_COMPAT_PUBLIC_KEY_FILE=/operator-trusted/guard-public.hex
   export LAUNCHER_GUARD_COMPAT_REQUIRED=1
   launcher runtime client-factory guard-policy-install --client-dir /games/my-client --policy signed-guard.json --public-key /operator-trusted/guard-public.hex
   launcher runtime client-factory guard-policy-verify --client-dir /games/my-client --public-key /operator-trusted/guard-public.hex
   ```

   `guard-policy-install` сохраняет повышенный контрольный уровень эпохи, хеша и корня, затем атомарно записывает проверенную активную политику. Повторная установка тех же подписанных байтов идемпотентна. Изменение содержимого при прежней эпохе, откат эпохи, смена корня, истёкшая политика и отозванный код блокируются. Прерванная установка может блокировать запуск, пока оператор после проверки не удалит устаревший `.install-lock` и не завершит ту же либо более новую допустимую установку.

## Применение политики и отзыв

- До запуска JVM через ClientFactory `legacy-run` все явно разрешённые JAR и нативные файлы проверяются по SHA-256; расположение кода должно совпадать с подписанными путями. Все фактически используемые агенты и плагины совместимости и Trusted Java должны присутствовать в списке разрешений. Неизвестные исполняемые элементы в `mods/`/`natives/`, символические ссылки, изменение байтов и внедрение Java Agent через унаследованные параметры Java приводят к отказу в запуске.
- Rust Runtime выполняет соответствующие проверки области действия, хешей, отзывов, агентов и контролируемых каталогов до старта процесса Minecraft. Датчик Guard в Windows больше не делает безусловного исключения: аргумент `-javaagent:` разрешается только при совпадении с неотозванной проверенной записью подписанной политики. Отладчик, `-agentlib`, `-agentpath` и внедрение через окружение остаются запрещёнными.
- `premain` Trusted Java проверяет хеши JAR плагинов и при активной политике ограничивает обратные вызовы `MinecraftHook.transformMinecraftClass` точными парами `(SHA-256 плагина, имя класса)`. Запрещённая попытка изменения завершает JVM. При этом **не обеспечивается песочница для полностью доверенного стороннего кода**, способного использовать рефлексию либо собственные API Instrumentation.
- Чтобы отозвать JAR или преобразование, опубликуйте **новую подписанную эпоху**, указав SHA-256 в `revokedDigests` либо идентификатор класса в `revokedTransformations`. Отзыв учитывается перед последующими запусками. Уже идущие игровые сессии асинхронно не завершаются: это задача будущего этапа непрерывной политики Guard и сервера.

## Границы доверия и приёмки

Контрольная метка клиента хранится в `.launcher/guard/accepted.json`. Пользователь, полностью контролирующий свою учётную запись ОС, может удалить или заменить локальные файлы и переменные окружения. Требуйте политику от менеджера или установщика, находящегося под управлением развёртывания, защищайте закреплённый открытый ключ и в будущем релизе Server-Bound Guard внедрите серверное подтверждение эпохи политики. Клиент пользовательского режима не может превратить локальную защиту от отката в удалённый аппаратный якорь доверия. Нельзя утверждать, что один этот файл мешает злоумышленнику изменять собственную машину.

Локальные Go-тесты проверяют реальные подписи Ed25519, соблюдение хешей, подмену данных, истечение срока, отзыв, откат, символические ссылки и **настоящий запущенный процесс Java** с разрешёнными и запрещёнными преобразованиями классов. Сборки Rust/Guard Sensor для шести платформ, реальные подключения к Minecraft с модами, подпись релиза и независимые подтверждения установки остаются обязательными внешними приёмочными работами. Версия `0.50.2` остаётся **ЗАБЛОКИРОВАННОЙ для GA** до появления этих подтверждений.
