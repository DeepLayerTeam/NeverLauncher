# Launcher 0.31.10 — брокеры файловой системы, сети и секретов с ограниченной областью действия

Этот выпуск расширяет **принудительно изолированную среду Linux x86-64** из версии 0.31.9. Он не создаёт сетевые интерфейсы хоста и не монтирует общие каталоги хоста внутрь расширения. Все привилегированные операции проходят через существующий Extension Host Protocol с аутентификацией токеном по наследуемой паре Unix-сокетов. На сервере проверяются подписанная политика **и** действующий отзывной менеджер разрешений. Поля манифеста расширения не могут отключить ограничения namespaces, seccomp или cgroups.

## Настройка оператором

Запускайте API от **отдельного непривилегированного пользователя сервиса** с делегированным поддеревом cgroup v2. Настройте только те каталоги, доступ к которым действительно требуется через брокер:

```sh
LAUNCHER_EXTENSION_SHARED_ROOTS_JSON='{"reports":"/srv/launcher-extension-shares/reports"}'
```

Корневые каталоги должны быть абсолютными и существовать заранее. Каждый компонент пути должен быть настоящим каталогом, а не символьной ссылкой; корень `/` запрещён. Если изолированный пакет запрашивает неизвестный или неправильный общий корень, приложение блокирует доступ, не переключаясь на `trusted`. Храните секреты хоста **вне** общих каталогов. Отображение каталогов, заданное администратором, — доверенная конфигурация, пакет не может им управлять. Брокер использует разрешения непривилегированной учётной записи API.

## Пример подписанного манифеста

Манифест пакета по-прежнему защищён действующей подписью Ed25519, разрешениями с привязкой к версии и дайджестом согласования владельца. При установке или обновлении изменение политики изоляции либо запрашиваемых разрешений требует явного подтверждения администратора (0.31.8).

```json
{
  "permissions": ["storage:read", "storage:write", "http:outbound", "secrets:read"],
  "sandbox": {
    "version": "1", "mode": "isolated",
    "filesystemRead": ["package", "shared:reports"],
    "filesystemWrite": ["scratch", "shared:reports"],
    "networkOutbound": ["api.example.com:443"],
    "secrets": ["api_token"],
    "maxProcesses": 4, "maxMemoryBytes": 134217728,
    "maxCpuPercent": 25, "timeoutSeconds": 30
  }
}
```

Один запрос в манифесте не предоставляет доступ автоматически. Оператор должен отдельно подтвердить `storage:read`, `storage:write`, `http:outbound` и `secrets:read`. Отзыв любого из этих разрешений блокирует следующие операции брокера даже для уже работающего процесса.

## Операции Host Protocol

Изолированный процесс продолжает отправлять JSON методом POST на `/v1/capabilities/{name}` с существующими учётными данными Bearer конкретного экземпляра.

- `fs.read`: `{ "name": "reports", "path": "daily/summary.json" }` возвращает `{ "contentBase64": "..." }`.
- `fs.write`: `{ "name": "reports", "path": "daily/summary.json", "bodyBase64": "..." }` возвращает `{ "written": true }`.
- `http.fetch`: `{ "method": "GET", "url": "https://api.example.com/data" }` использует усиленный HTTPS-брокер. Имя хоста и порт должны **точно** совпадать с `networkOutbound`; перенаправления отключены; действуют проверка публичных IP, защита от DNS-rebinding и проверка имени в TLS-сертификате.
- `http.fetch` с `{ "method": "GET", "url": "https://api.example.com/data", "secretName": "api_token" }` выполняет **непрозрачную** операцию в заданной области: Backend получает секрет только данного расширения из текущего контекста и отправляет его в заголовке `Authorization: Bearer` на *подписанный и разрешённый* HTTPS-адрес. Токен не включается в ответ расширению. Конфликтующие заголовки `Authorization` отклоняются. **Прямой `secret.get` запрещён для изолированных пакетов**, даже если прежнее разрешение остаётся активным.

Разрешение `shared:<name>` не позволяет напрямую монтировать общий ресурс. Допустимы только относительные пути с разделителем `/`; `..`, `.`, абсолютные пути, пустые компоненты, символьные ссылки (в том числе у родительских каталогов) и специальные файлы отклоняются. Для чтения используются закреплённые файловые дескрипторы каталогов и `O_NOFOLLOW`. Запись выполняется через случайный временный файл и атомарный `renameat`, поэтому она не переходит по жёстким или символьным ссылкам за пределы общего каталога. Новым файлам назначаются права `0600`. Размер каждой операции чтения и записи ограничен 256 КиБ. Для scratch предусмотрен отдельный tmpfs с ограничением размера в пространстве имён Linux.

**Неподдерживаемые операции:** прямые TCP/UDP-сокеты в сеть хоста, непосредственное монтирование общих файловых ресурсов, получение любого секрета открытым текстом, произвольная подстановка секрета в заголовки, обратные вызовы и reverse RPC с Java-хостом, а также системная изоляция Windows/macOS. До реализации соответствующих этапов такие действия запрещаются. HTTP-загрузка поддерживает только HTTPS и не обращается к приватным или loopback-IP даже при наличии подобного хоста в подписанном манифесте.

## Приёмочные испытания

```sh
cd services/api
GOPROXY=off go test -race -tags launcher_nopgx -count=1 ./internal/extensionbroker ./internal/linuxsandbox ./internal/extensionpolicy ./internal/extensionhost
# В CI со всеми внешними зависимостями Go:
go test -race -count=1 ./internal/extensionbroker ./internal/linuxsandbox ./internal/extensionpolicy ./internal/extensionhost
# Только на специально подготовленном непривилегированном Linux-исполнителе с делегированными cgroups v2:
NL_RUN_LIVE_LINUX_SANDBOX=1 go test -tags launcher_nopgx -v ./internal/linuxsandbox -run TestLinuxIsolationLive0319
```

Тесты охватывают атаки с символьными ссылками, обходом каталогов и жёсткими ссылками, неполное указание целевого HTTPS-адреса, неразрешённое использование секретов, отзыв разрешений и отсутствие отображения ресурсов. Проверка cgroup/namespaces требует реального развёртывания Linux; успешные модульные тесты не подтверждают изоляцию на уровне ядра или полную готовность промышленного выпуска.
