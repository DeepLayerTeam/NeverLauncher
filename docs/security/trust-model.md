# Модель угроз и доверия

## Основные активы

Аккаунты, токены обновления и доступа, закрытые ключи устройств, ключи подписи JWT, подписи пакетов, объекты хранилища, идентификаторы ServerBridge, ключи обновлений, права и секреты расширений.

## Границы

| Граница | Риск | Обязательная защита |
| --- | --- | --- |
| Пользователь ↔ API | Подмена сессии, CSRF/XSS и подбор паролей | Auth, TLS, ограничение привилегий, ограничения частоты запросов, безопасные cookie и токены, аудит |
| Устройство ↔ Backend | Повторная отправка запроса и использование чужого ключа | Актуальность вызова-проверки, проверка владения private key, привязка идентификатору устройства, отзыв |
| Сервис ↔ хранилище | Подмена артефактов, выход за пределы допустимого пути | Подписанные манифесты, SHA-256, безопасные пути, доверенное хранилище |
| Обновление ↔ файловая система | Частично применённый релиз, обход запрета отката | Подготовка и проверка до замены, транзакции, recovery, запрет перехода на более раннюю версию |
| ServerBridge ↔ API | Подмена узла, повторы команд | Ключи узлов, одноразовые билеты, защита от повторного воспроизведения, разделение ролей |
| Расширения ↔ хост | Повышение прав и доступ к секретам | Возможности и разрешения, процессная изоляция, квоты и карантин |
| CI выпуска ↔ пользователи | Подмена бинарников и сертификатов | свидетельства проверки точного коммита, подписи, прозрачная цепочка поставки |

## Принципы

- **Безопасный отказ:** при отсутствии сертификата, ключа или подлинных свидетельств проверки операция не должна превращаться в PASS.
- **Не записывайте секреты в журналы:** токены/пароли/DSN необходимо редактировать до загрузки в CI или обращения о проблеме.
- **Происхождение ключа не равнозначно доказательству владения:** владение зарегистрированным ключом не означает автоматически подтверждённую аттестацию TPM/Secure Enclave.
- **Федеративная авторизация не подтверждает владение Minecraft:** Microsoft OAuth/OIDC не заменяет отдельный жизненный цикл проверки Minecraft Services.
- **Свидетельства кроссплатформенной проверки:** проверки Guard и системного хранилища ключей должны учитывать реальные особенности платформ.

Возможные уязвимости сообщаются согласно [SECURITY.md](../../SECURITY.md). Для релизной сертификации см. [release-certification.md](release-certification.md).
