# Ведомость приёмки вторым оператором

Заполняется **после реальных действий** на конкретном хосте и версии. Не публикуйте приватный отчёт, TLS-ключи, `/etc/launcher/*.key` и `.env`. Отсутствующие права доступа, ключи, аккаунты или отдельный хост фиксируются как **BLOCKED/NOT RUN**, не подменяются `PASS`.

| № | Операция | Требуемое свидетельство |
| --- | --- | --- |
| 1 | Чистая установка Minimal/Standard/Network-HA в заявленной топологии | source commit, image digest/binary hash, hostname, журналы и точная версия |
| 2 | TLS/HTTPS preflight | действительный hostname/CA, отсутствие обхода сертификата, действующий `/ready` |
| 3 | Первый владелец и сохранность данных | проверенная аутентификация и MFA, созданный проект, отказ повторного bootstrap |
| 4 | Backup off-host | согласованный снимок PostgreSQL/SQLite, blobs и секретов по границам топологии; SHA-256 |
| 5 | Restore на пустом независимом хосте | действительный вход старого владельца, проект, blob hash, сохранённый world, API `/ready` |
| 6 | Обновление БД | реальные миграции, проверка целостности, успешное восстановление после принудительного отказа |
| 7 | Component Upgrade | переключение backend/CLI/Bridge и проверка прежней версии при ошибке |
| 8 | HA/fencing | два API, два workers, failover на выполненной durable job, отказ устаревшего token |
| 9 | Network-HA Recovery | очищенные Redis leases, новые ServerBridge enrollment и контроль world restore |
| 10 | Observability | метрики, JSON logs, correlation ID и **доставленный** alert |
| 11 | Брендирование/поставка | шесть реальных конечных установщиков, подписи, BOM/SBOM/provenance и независимая аттестация |
| 12 | API/SDK и Minecraft | две версии backend, Go/TS/Java SDK, реальная авторизация и игровой join |

Сначала запустите [локальную сверку инструкций](README.md), затем [live-probe](installation.md) и сохраните защищённый JSON-отчёт. `status: passed` от live-probe подтверждает **только** состояние запущенных сервисов, двух SQLite-баз (для minimal) и HTTPS `/ready`. Пункты выше требуют отдельного evidence.

Результат второго оператора должен содержать дату и UTC-окно, версии, хеши фактических файлов, идентификатор хоста, тип топологии, что проверено вручную, результаты негативных действий, RTO/RPO **по реальным событиям**, открытые риски и заключение `PASS / BLOCKED / FAILED / NOT RUN`. После исправлений, которые меняют данные, подписи или поведение запуска, повторите соответствующую часть испытаний.

Для реального проведения основных четырёх операций используйте [Independent Acceptance 0.45.14](independent-acceptance-04514.md). Отчёты этапов не заменяют самостоятельную проверку MFA, Minecraft join и межхостовой HA.
