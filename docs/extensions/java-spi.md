# Launcher 0.48.3 — Java SPI и действующий реестр провайдеров расширений

Подписанное Java-расширение может определять типизированный контракт SPI, регистрировать несколько реализаций и выбирать провайдера во время выполнения. Это работающий **внутрипроцессный реестр, ограниченный одной контролируемой JVM расширения**, а не межмодульная шина служб, новая точка HTTP, установщик пакетов или способ обхода разрешений Go. JVM по-прежнему использует заблокированную загрузку зависимостей из вложенных JAR версии 0.48.2; `ru.launcher.sdk.*` загружается родительским загрузчиком.

## Промышленный API

Служба SPI — интерфейс Java, наследующий `JavaProvider`, например `GreetingProvider` с методом `greet(String)`. В `Extension.start(ExtensionContext ctx)`:

```java
ProviderService<GreetingProvider> greeting = new ProviderService<>(
    "example.greetings", GreetingProvider.class, SemVer.parse("1.1.0"));
ctx.providers().register(new ProviderDescriptor<>(greeting, "friendly",
    SemVer.parse("1.0.0"), ">=1.0.0 <2.0.0", "^1.0.0", Friendly::new));
ctx.providers().register(new ProviderDescriptor<>(greeting, "formal",
    SemVer.parse("1.0.0"), ">=1.0.0 <2.0.0", "^1.0.0", Formal::new));
ctx.providers().select(greeting.id(), "formal", Duration.ofSeconds(2));
String text = ctx.providers().call(greeting, p -> p.greet("Ada"));
```

`ProviderDescriptor` объявляет и поддерживаемый **диапазон версий интерфейса SPI**, и поддерживаемый **диапазон версий API подписанного расширения**. Неподдерживаемые версии, несовпадения интерфейсов служб, повторяющиеся ID провайдеров, выбор незарегистрированных реализаций и фабрики, возвращающие неверный тип, отклоняются. Совместимость проверяется до вызова фабрики; существующие проверки пакетов Go и закреплённых Java-библиотек независимо отклоняют конфликты байткода и пакетов. JAR не скачиваются динамически и не добавляются в основной classpath.

`select` — синхронная операция с ограниченным временем: она дожидается завершения параллельных аренд `call`, вызывает `stop` у старой реализации, создаёт и запускает новую и затем атомарно публикует её. Повторный выбор активного ID идемпотентен. При ошибке запуска кандидат очищается по возможности, и **активного провайдера не остаётся**; скрытого возврата к предыдущей реализации нет. Если необходимо сохранить выбранный ID, вызывающий код отвечает за это через существующий аутентифицированный брокер `runtime().config()` с соответствующими разрешениями; недоверенный локальный резервный файл не используется. Во время переключения новые вызовы немедленно отклоняются, а не направляются в частично запущенный экземпляр.

`ExtensionLifecycle.stop()` сначала вызывает обработчик остановки расширения, затем дожидается завершения и останавливает всех активных зарегистрированных провайдеров. Ошибки запуска расширения также закрывают уже запущенных провайдеров. Одновременные вызовы закрытия ожидают результат первой операции остановки. Обработчик Java, игнорирующий прерывание, может остаться в фоновом потоке-демоне, но **JDK не может принудительно завершить такой поток**: существующие надзиратель процессов Go и изоляция ОС остаются обязательными. Код провайдера обладает ровно привилегиями JVM расширения и должен обращаться к Backend через Go RuntimeServices; SPI не является песочницей безопасности.

## Работающая интеграция

```sh
sh sdk/java/core/build.sh test
sh examples/extensions/java-spi/build.sh
python3 examples/extensions/java-spi/test-runner.py
```

Пример собирает расширение и *отдельный закреплённый JAR библиотеки*, внедряет библиотеку в пакет хоста и запускает настоящий `java -jar` через аутентифицированный протокол хоста 1.0. Активный провайдер читается из документа конфигурации брокера (`spi.active`); неизвестное значение блокирует запуск. Интеграция проверяет вызов провайдера `formal`, переключение на `friendly` по существующему аутентифицированному RPC команды CLI, отклонение неизвестного идентификатора, сигналы активности, запуск и вызов CLI, корректное завершение и отказ до `/v1/ready` при неправильном сохранённом выборе. HTTP-сервер в запускаемом примере — тестовая среда интеграции; промышленная версия продолжает использовать настоящий хост Go и подписанный пакет.

Для установки подпишите `examples/extensions/java-spi/build/package` штатным процессом `nl extension pack` и установите через существующий проверяющий менеджер Extensions. Не развёртывайте неподписанные локальные тестовые сборки. Пример не заявляет произвольных провайдеров между расширениями, обнаружения сторонних модулей Maven или универсальных SPI аутентификации, содержимого и ServerBridge (они запланированы на будущие выпуски).

**Сертификация:** CI проверяет Java 17/21 на Ubuntu/macOS и контроль закреплённых библиотек в установленной версии Go. Локальная проверка на Java 21 не заменяет независимую сертификацию перехода PostgreSQL, действующие этапы допуска выпусков и приёмку подписанного нативного установщика. До прохождения этих этапов промышленный выпуск GA должен оставаться заблокированным по умолчанию.
