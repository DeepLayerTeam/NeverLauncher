# 0.48.6 — Java SPI содержимого и распространения

Поставляемый Java SDK содержит `ContentServices.CONTRACT` и `ContentProvider`. Подписанное активное расширение регистрирует конкретный провайдер через `ExtensionContext.providers()` и выбирает его. **Существующий** реестр провайдеров проверяет совместимость API, ограничивает жизненный цикл и обеспечивает корректное завершение работы. Публичного пути публикации неподписанных выпусков не добавлено.

## Работающие операции

- `source(projectId,path)` находит объект в существующем хранилище проекта с закреплёнными размером и SHA-256 либо HTTPS-URL. `runtime().content().readChecked(asset)` получает настоящие байты **только** через аутентифицированный брокер Go Host (`storage.read` / `http.fetch`) и перед возвратом проверяет размер и SHA-256. По-прежнему действуют разрешения, область проекта и отзыв доступа; для HTTPS применяются фильтры DNS/IP и подписанная политика исходящих запросов Go.
- `texture(projectId,profileId,kind)` получает закреплённые байты скина или плаща тем же путём и с той же проверкой. Это не открывает доступ к чужой приватной текстуре.
- `metadata(projectId,releaseId,original)` формирует дополнительные метаданные, но запрещает менять `signature`, `files`, проект, профиль, канал, версию, поколение и эпоху игрового доверия. Повторной подписи манифеста выпуска нет.
- `preparePackage(projectId,name,bytes)` преобразует байты выбранным Java-провайдером. Результат явно содержит `requiresSigning=true` и новый SHA-256. **После** преобразования обязательны существующие проверки целостности, подпись и допуск к публикации; автоматического создания выпуска нет.
- `delivery(projectId,path)` определяет проверенный источник содержимого. Публичного HTTP-перенаправления на непроверенный URL провайдера и передачи ему решения о доверии Minecraft нет.

Супервизор Go поддерживает аутентифицированные JVM RPC `content.health`, `content.source.resolve`, `content.texture.resolve`, `content.metadata.enrich`, `content.package.prepare`, `content.delivery.resolve`. Для чтения содержимого и метаданных требуется актуальное разрешение `release:read` на проект, для подготовки пакета — `release:prepare`. Разрешения повторно проверяются после каждого callback. Действуют список разрешённых команд, срок 1,8 с и ограничение RPC 64 КиБ; RPC пакета ограничен 24 КиБ, чтение объекта через брокер внутри JVM — 512 КиБ. Крупные промышленные объекты обрабатываются существующей цепочкой загрузки файлов, хранилища и распространения, а не callback-транспортом.

## Необязательная интеграция загрузки промышленных пакетов

В существующем аутентифицированном multipart-маршруте `POST /api/v1/packages/{packageId}/files` необязательное поле `contentExtensionId=org.example.content-spi` выбирает **запущенное Java-расширение в пределах проекта**, уже обладающее `release:prepare`. Синхронный Java RPC может обрабатывать файлы размером до 24 КиБ; более крупные загрузки проходят через неизменённый конвейер хранилища **без** этого поля. Backend сверяет переданный `sha256` с исходной загрузкой, вызывает преобразователь, заново проверяет разрешение расширения, сверяет новые байты/размер/SHA-256, сохраняет данные через `Storage.Save` и фиксирует оба дайджеста в аудите. При любой ошибке непреобразованный исходник в качестве запасного варианта не сохраняется. Уже подписанные или опубликованные пакеты преобразовывать нельзя. Проверка пакета, подпись Ed25519, подготовка и публикация по-прежнему обязательны.

Не задавайте `contentExtensionId` для полного игрового клиента и других крупных файлов: в этой версии **нет** потоковой передачи крупных объектов через JVM RPC. Функция не отменяет политику доставки или доверия и не переводит публичные загрузки игры на Java автоматически.

## Сборка и тестирование

```
sh sdk/java/core/build.sh test
sh examples/extensions/java-content-spi/build.sh
python3 examples/extensions/java-content-spi/test-runner.py
```

Пример содержит исполняемый JAR Java Host и дерево полезной нагрузки `.nlext`, пригодное для подписи. Для установки обязательны `nl extension pack`/`verify` и доверенный процесс издателя. Callback хоста проверяется с аутентифицированным HTTP loopback, настоящими исходными байтами, отклонением изменённого содержимого и отзывом разрешений во время работы.

## Границы и незавершённая приёмка

**Этот SPI не заменяет загрузку пакетов, публичное скачивание клиента, подпись релизов, проверку прав Minecraft и контроль владельца текстур.** Провайдер может предложить байты или метаданные, но не может придать доверие непроверенным артефактам. Выбранный провайдер участвует только в ограниченной административной загрузке при явном `contentExtensionId`. Остальные операции источников, текстур и доставки доступны через Java SDK и внутренний Go RPC, но **не перехватывают автоматически публичный путь распространения клиента**. Это работающий SPI с ограничениями, **а не** сертификат всего конвейера распространения. Для GA по-прежнему нужны независимый CI на JDK 17/21 и Go 1.27.3, нативная упаковка, миграции и Minecraft E2E.
