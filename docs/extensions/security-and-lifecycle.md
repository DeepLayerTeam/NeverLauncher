# Безопасность и lifecycle расширений

Extensions не должны получать произвольный доступ к файловой системе, произвольным токенам пользователей, сетевым адресам или управляющим действиям без явно предоставленного разрешения.

## Минимальные правила

1. Проверять подпись и происхождение пакета до импорта.
2. Разделять *заявленные возможности* и *выданные разрешения*; не выдавать разрешения автоматически при обновлении.
3. Считать секреты непрозрачными — backend должен выдавать лишь разрешённый результат операции, не исходные учётные данные.
4. Ограничивать размер сообщений, время HTTP, количество запросов, ресурсные лимиты хоста, журналы.
5. Фиксировать аудит событий изменения прав, публикации и выхода процесса.
6. Обрабатывать crash/restart с ограничением частоты и без бесконечной регенерации неуспешной установки.
7. Поддерживать отключение, карантин и аварийный режим и возможность восстановления предыдущей версии.

Переменные окружения для host и секретов находятся в `deploy/production/env.production.example` и `.env.example` (`LAUNCHER_EXTENSION_*`). Для брокера секретов требуется криптографически случайный ключ, хранимый вне Git.

**Кроссплатформенная оговорка:** ограничения ресурсов и изоляция процессов на Linux, Windows и macOS имеют различную реализацию. Надёжность песочницы необходимо подтверждать тестами для каждой целевой ОС. См. [модель доверия](../security/trust-model.md) и `extensions/ga-targets.json`.
