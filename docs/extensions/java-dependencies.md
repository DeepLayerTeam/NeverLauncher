# 0.48.2 — упаковка модулей Java и зависимости

В выпуске добавлена поддержка **зависимостей JAR во время выполнения** в существующем жизненном цикле установки подписанных `.nlext`. Зависимости не загружаются из сети, classpath ядра лаунчера не меняется, альтернативный механизм установки не появляется, а расширение не получает дополнительных полномочий.

## Фактические пути установки и запуска

1. Соберите сторонние зависимости с закреплёнными версиями и сохраните полученные JAR. Соберите Java Extension Host обычным образом, включив классы SDK и файл класса самого расширения (скомпилированного с зависимостями, но **без включения их классов в классы хоста**).
2. Выполните `python3 scripts/java/package_dependencies_0482.py --host host.jar --output bundled-host.jar --library 'org.example:greeter@1.2.3@>=1.0 <2.0@path/to/greeter.jar'`. Для каждой дополнительной зависимости повторите `--library`. Автономный упаковщик копирует содержимое хоста, помещает зависимости в `META-INF/launcher/libs/` и формирует `META-INF/launcher/libraries.lock` с путём, координатами группы/артефакта, закреплённой версией SemVer, SHA-256 и ограничением API SDK. Координаты Maven не разрешаются; обращения к сети нет.
3. Поместите `bundled-host.jar` в обычный целевой путь `backend`/`cli`, укажите тот же путь в `launcher-extension.json` и создайте и установите подписанный `.nlext` с помощью **существующего проверенного процесса подписи издателя**. Не подписывайте только исходный JAR без зависимостей.
4. Существующий `extensionlifecycle.Manager.inspectPayload0305` проверяет извлечённый JAR хоста **до активации**. Инспектор Go отклоняет отсутствующие или не внесённые в lock вложенные JAR, дубли классов между хостом и библиотеками, переопределение защищённых пакетов, небезопасные записи, несовпадение SHA-256, запрещённые Class-Path/multi-release JAR, неподдерживаемые версии байткода и превышение размеров. Менеджер проверяет совместимость API каждой зависимости с `manifest.api` и наличие подходящей Java, включая Java 21 при необходимости.
5. `java -jar bundled-host.jar` запускает **тот же отдельный процесс JVM**, что и существующий супервизор с аутентификацией. SDK повторно проверяет lock-файл и вложенные данные, извлекает библиотеки в временный каталог с доступом только владельцу и запускает расширение через изолированный загрузчик классов с приоритетом дочернего загрузчика. Классы SDK, хоста и JDK по-прежнему загружаются родительским загрузчиком. Ссылки расширения разрешаются через вложенные зависимости без изменения classpath ядра. Каталог и загрузчик закрываются после завершения.

**Границы безопасности:** загрузчик классов изолирует видимость классов, **но не вредоносный Java-код**. Отдельная JVM, контроль ресурсов, подпись пакета издателем, проверка разрешений брокера и актуального доверия/отзыва остаются обязательными. Возможность не делает недоверенный байткод безопасным и не обеспечивает автоматическую поддержку любых форматов JAR/плагинов. Совместимость JNI и ресурсов не заявлена. Для SDK API действуют версии `1.0` или `3.7`, разрешённые существующим разборщиком манифестов. Зависимость расширения не может заменить `java.*`, `ru.launcher.sdk.*` и другие защищённые классы.

**Правила конфликтов:** разные версии одних координат запрещены; разные координаты с одинаковым файлом класса запрещены; вложенный JAR не может содержать класс внешнего JAR хоста. Изоляция действует **в пределах одного расширения**: отдельные процессы могут использовать разные версии библиотеки. Зависимости Java не разрешаются списком межрасширенных `dependencies` — он остаётся графом зависимостей установленных пакетов расширений.

**Ограничения:** не более 64 вложенных зависимостей, 16 МиБ на один сжатый JAR, 64 МиБ на все вложенные JAR, 4096 записей и 64 МиБ распакованных записей на каждый JAR. Внешние Class-Path, загрузка из сети и multi-release JAR запрещены. Проверка подписанного пакета инспектором Go действует независимо.

## Воспроизводимая интеграция

```
sh sdk/java/core/build.sh test
sh examples/extensions/java-dependencies/build.sh
javac --release 17 -cp sdk/java/core/build/classes -d sdk/java/core/build/test-classes sdk/java/core/src/test/java/ru/launcher/sdk/core/ModulePackaging0482Tests.java
java -cp sdk/java/core/build/classes:sdk/java/core/build/test-classes ru.launcher.sdk.core.ModulePackaging0482Tests examples/extensions/java-dependencies/build/package/backend/java-dependencies.jar
python3 examples/extensions/java-dependencies/test-runner.py
```

`java-dependencies` — настоящее Java-расширение: во время `Extension.start()` оно вызывает код из `greeter.jar`, выполняет аутентифицированное рукопожатие Go/JVM Host, передаёт `ready`, отвечает на RPC проверки состояния, отправляет heartbeat и завершает работу при остановке. Регрессионные тесты Go создают настоящие вложенные ZIP и проверяют конфликты, защищённые пространства имён SDK, некорректные манифесты и lock-файлы, SHA-256 и распознавание байткода Java. CI запускает JVM-тесты на JDK 17/21 под Linux и macOS, а также инспектор Go с закреплённой версией инструментов.

**Статус GA:** успешные тесты этой функции не подтверждают GA всего продукта 0.48.2. Независимые проверки миграций PostgreSQL, подписанных установщиков, обновлений прошлых версий и обязательные проверки выпуска из 0.48.0 остаются необходимыми. Заблокированные проверки не обходятся.
