# Minecraft совместимость

## Загрузчик Совместимость GA — 0.18.0

NeverLauncher 0.18.0 переводит Fabric/Quilt/Forge/NeoForge совместимость в GA как исполняемую runtime-гарантию, а не только релиз сертификат. Рабочий материализатор используют тот же поддержка политика, который связан с релиз сертификат: Fabric и Quilt — 48 сертифицированных Minecraft-линий каждая, Forge — 43 современный + устаревший 1.7.10/1.12.2, NeoForge — 22 линии. Всего политика содержит 163 уникальные loader/Minecraft комбинации с точный Java крупный и установка режим.

Конкретная версия Minecraft вне GA поверхность отклоняется до обращения к загрузчик Meta/Maven/installer. `latest-release` сначала разрешается через Mojang, затем полученная версия повторно проверяется отказ с блокировкой. `LOADER_COMPATIBILITY_RELEASE_CERTIFICATE.json` для 0.18.0 имеет `status=ga-certified`, хранит `runtimeSupportSha256`, `runtimeSupportEntries=163` и устаревший Forge привязка; `RELEASE_MANIFEST.json` повторяет поддержка SHA, а `release publish-check` требует совпадения с исполняемой политика текущего CLI. Полный 292-цель свидетельство, неизменяемый закрепление, нативный для загрузчика E2E, кроссплатформенный выполнение и усиление защиты остаются обязательными.

## Загрузчик Совместимость RC — 0.17.11

NeverLauncher 0.17.11 формирует `LOADER_COMPATIBILITY_RELEASE_CERTIFICATE.json` из точного релиз-привязанный набора `COMPATIBILITY_TARGETS.json`, `COMPATIBILITY_MATRIX.json` и `COMPATIBILITY_CERTIFICATION.json`. Это не декларативный манифест: сборка отказ с блокировкой останавливается, если не прошли все 292 обязательный цели или невозможно детерминированно пересчитать полный корень всего цель свидетельство.

Сертификат фиксирует SHA-256 совместимость сертификация, матрица и цели, детерминированный корень по каждому цель evidence/pin/JRE/проверка tuple, точный исходник commit/run, покрытие 292/292, счётчики по семействам (Vanilla 109, Fabric 53, Quilt 53, Forge 50, NeoForge 27), шесть настольное приложение OS/architecture пар, Java 8/16/17/21/25, область и все обязательные инварианты 0.17.7–0.17.10. Поле `certificateId` является SHA-256 полной нормализованной идентичность сертификата.

Комплект релиза записывает SHA-256 RC в `RELEASE_MANIFEST.json`, помечает RC как обязательный артефакт и включает его в `SHA256SUMS`; поэтому внешняя Ed25519 релиз подпись покрывает полный загрузчик совместимость сертификат. `nl release publish-check` пересчитывает RC из встроенный совместимость свидетельство и отклоняет отсутствующий или изменённый сертификат.

## Загрузчик Усиление защиты — 0.17.10

NeverLauncher 0.17.10 требует вышестоящий проект-независимый повторное воспроизведение для текущий Fabric 26.3, Quilt 26.3, Forge 26.3 и NeoForge 26.2 Linux x64 цели. Неизменяемый разрешение блокировка связывается с адресуемый по содержимому SHA-256 кэш; только кэш материализация не имеет права обращаться к изменяемый разрешатель. Forge/NeoForge дополнительно восстанавливают закреплённый установщик без `.sha1` вспомогательный процесс и используют долговременный обработчик журнал: проверен сбой выходные данные принимаются, неполные карантин и rerun. PASS требует `loaderCacheVerified`, `loaderUpstreamRecovery`, а Forge/NeoForge также `loaderInstallerRecovery` и `loaderProcessorRecovery`; комплект релиза повторно проверяет четыре `loaderHardeningTargets`.

## Совместимость Усиление защиты — 0.16.11

`0.16.11` усиливает уже исполняемый materialization/runtime путь без добавления фиктивных совместимость цели. Артефакт кэш считается доверенным только после повторной проверки ожидаемого SHA-1/size; повреждённые записи переводятся в ограниченный карантин. Прерванный `.nlpart` продолжается через HTTP Диапазон только при валидном `206 Content-Range`; итоговый файл всё равно публикуется только после полного Mojang SHA-1/size проверка. Полностью скачанный и уже совпадающий `.nlpart` может быть атомарно восстановлен без сети.

Проверен точная версия Mojang метаданные хранится отдельно с SHA-1/SHA-256/size/identity привязка и используется только как outage восстановление для конкретной версии. `latest`, `latest-release` и снимок селектор не получают устаревший резервный вариант; если авторитетный манифест успешно отвечает, но версии в нём нет, локальный снимок также не resurrected. Ресурс индекс и server/client артефакты используют контрольная сумма-привязанный локальный кэш, а corrupt копирует не перезаписываются молча.

Нативный архивы имеют ограничения на запись счётчик, на-запись uncompressed размер и total extracted байты; traversal/symlink/non-regular записи отклоняются. Нативный сначала строятся в подготовка и только после полной проверки transactionally заменяют `natives/<os>/<arch>`; устаревший виртуальный ресурсы и `resources/` проходят тот же staging/swap принцип, поэтому ошибка построения не уничтожает предыдущий рабочий дерево. Удалённый URL политика отклоняет учётные данные, fragments и небезопасные закрытый literal вышестоящий проект без явный opt-в.

Управляемый Java запись схема `1.2` дополнительно хранит SHA-256 фактического Java исполняемый и повторно проверяет его до `java -version`. Adoptium/Managed JRE запросы имеют ограниченный повторить для временный HTTP/сеть ошибка, перенаправления не могут понизить HTTPS, повреждённые архивы карантин, а уже полностью скачанный проверен частичный может быть атомарно продвигать после сбоя.

Реальный клиент E2E II для 0.16.10 дополнительно требует пять соответствовать client/server пары:

| Minecraft | Java | соответствовать цель |
| --- | ---: | --- |
| 1.7.10 | 8 | `vanilla-1.7.10-linux-x64` |
| 1.17.1 | 16 | `vanilla-1.17.1-linux-x64` |
| 1.20.4 | 17 | `vanilla-1.20.4-linux-x64` |
| 1.21.10 | 21 | `vanilla-1.21.10-linux-x64` |
| 26.3 | 25 | `vanilla-26.3-linux-x64` |

Для этих цели `actualClient=true` недостаточно. CI получает `downloads.server` из той же проверен Mojang `version.json`, проверяет сервер JAR, запускает его на том же точный Java крупный, направляет реальный клиент на временный localhost port и требует фактический мир подключение. Свидетельство содержит `vanilla-server-install.json`, `matching-server.json` и сервер журнал; `serverVersionMatched`, `serverHealthy` и `clientJoinedServer` должны быть `true`.

NeoForge остаётся обязательным на 1.21.1/Java 21 с `scope=integration`; Fabric с 0.17.1 и Quilt с 0.17.2 сертифицируются полными линиями 1.14–26.3, а Forge Современный с 0.17.3 — основанный на обработчиках линией 1.13.2–26.3. Для всех трёх широких loader-линий 1.21.1 сохраняет интеграционный область. Для загрузчик цели изменяемый `latest-stable` разрешается до выполнения цель, а опубликованный результат обязан содержать конкретную неизменяемый версию загрузчик.

## Исполняемые область

`client` используется для исторический Vanilla, Fabric, Quilt и Forge релиз цели, где совместимость подтверждается фактическим клиент запускать без Paper интеграционный мир-подключение. Для каждого такого цель CI выполняет рабочий путь:

```text
official Mojang version metadata
 -> materialize client.jar/libraries/assets/natives
 -> local SHA-256 package verify
 -> resolve Compatibility Engine metadata
 -> verify exact target Java major
 -> launch real Minecraft main class on the native host (Xvfb on Linux)
 -> require process to stay healthy until certification window or exit successfully
 -> store runtime log + machine-verifiable evidence
```

Это не метаданные-только контроль: `neverruntime certify-vanilla` запускает фактический материализованный клиент. Для pre-1.6 метаданные материализатор строит `assets/virtual/pre-1.6`, NeverRuntime формирует устаревший сессия ID для `${auth_session}` и разрешает `${game_assets}` и передаёт фактический виртуальный-ресурсы путь. Для устаревший метаданные без `arguments.jvm` Совместимость Движок добавляет лаунчер JVM базовая линия (`java.library.path`, лаунчер идентичность и путь классов), поддерживает `${user_properties}`/`${profile_properties}`, а только классификатор нативный библиотеки не попадают в путь классов как несуществующие JAR. Release-диапазон 1.0–1.16.5 получает разрешённый Java 8 даже при отсутствии поля `javaVersion`.

`integration` сохраняет полный рабочий E2E:

```text
upstream metadata / installer
 -> materialization
 -> local SHA-256 package verify
```

Процесс `.github/workflows/compatibility.yml` устанавливает Java каждого цель отдельно от Java 21 сборка инструментарий, фиксирует реальный исполняемый и обнаруживать крупный, запускает цель и публикует `compatibility-result.json` вместе с свидетельство. Агрегатор отклоняет отсутствующий/дублированный цель, Java несоответствие, область несоответствие, несовпадение commit/run ID, изменяемый загрузчик результат и неполный реальный клиент свидетельство.

Для `>= 0.17.3` Forge Современный дополняет Quilt Совместимость II, Fabric Совместимость II и GA; сама Vanilla GA обслуживание revision v3 требует минимум 109 обязательных Vanilla цели / 104 уникальных Vanilla релизы и JRE аттестация для каждого PASS: SHA-256 фактического `java`/`java.exe`, поставщик, среда выполнения версия, VM, `java.home`, точный Java крупный и хост OS/arch. Обязательный основа сохраняет полный Устаревший Vanilla v1 сетка из 53 релиз ID `1.2.1`–`1.16.4` на Java 8, v2 Java-переход сетка (`1.17` на Java 16; `1.18`, `1.18.1`, `1.19`, `1.19.1`, `1.19.2`, `1.19.3`, `1.20`, `1.20.3` на Java 17) и добавляет v3 релизы `1.21.11` на Java 21 и `26.2` на Java 25. Все v1/v2/v3 additions обязаны быть Linux/x86_64 клиент цели. `matrix.json` агрегирует конкретный `jreBase`, а релиз сертификат повторно связывает этот набор с цель свидетельство.

Для продукт версия `>= 0.16.2` сохраняется Базовая линия II. Начиная с `0.16.3`, агрегатор и CLI сертификация релиза отказ с блокировкой требуют десять Java 8 линейка релизов цели 1.7.10–1.16.5. Для `>= 0.16.4` дополнительно обязательны pre-1.7 цели `1.0`, `1.1`, `1.2.5`, `1.3.2`, `1.4.7`, `1.5.2`, `1.6.4`, `1.7.10`. Для `>= 0.16.6` обязательна Java 16/17 линия `1.17.1`, `1.18.2`, `1.19.4`, `1.20.1`, `1.20.2`, `1.20.4`. Для `>= 0.16.7` дополнительно обязательна Java 21 линия `1.20.5`, `1.20.6`, `1.21`, `1.21.1`–`1.21.10`. Для `>= 0.16.8` обязательны Java 25 цели `26.1`, `26.1.1`, `26.1.2`, `26.3`; материализатор и NeverRuntime независимо отклоняют отсутствующий или неверный `javaVersion.majorVersion`. В `0.17.0v3` тем же отказ с блокировкой рабочий путь отдельно закреплены `1.21.11`/Java 21 и `26.2`/Java 25. Для `>= 0.16.9` `26.3` дополнительно обязателен на Linux/Windows/macOS x64+ARM64 с точным хост-платформа свидетельство и архитектура-изолированный нативный. Для `>= 0.16.10` пять репрезентативный Linux/x64 Vanilla цели обязаны иметь `matchingServer=true` и доказанный подключение на проверен Mojang сервер той же версии. Для `>= 0.16.11` релиз политика дополнительно фиксирует совместимость усиление защиты, а репозиторий контроль требует resumable контрольная сумма-проверен загрузка, точная версия метаданные восстановление без устаревший псевдонимы, quarantine/transactional нативный и Управляемый Java исполняемый целостность. В `0.17.0v1` материализатор и NeverRuntime также отказ с блокировкой фиксируют Java 8 для всей Устаревший Vanilla 1.x линии до `1.16.5` и отклоняют метаданные без исполняемых `arguments.game`/`minecraftArguments`. Java покрытие — `8/16/17/21/25`; все пять Vanilla/loader семейство и точный цель привязка обязательны. Удалить любую обязательную линейка релизов или соответствующий сервер цель из `targets.json` и получить зелёный релиз невозможно.

## Сертификация релиза

При сборке официального релиз CLI повторно валидирует `matrix.json` вместе с `compatibility/targets.json` и создаёт `COMPATIBILITY_CERTIFICATION.json`. Для 0.17.3 сертификация дополнительно фиксирует полные Fabric и Quilt 1.14–26.3 сетка, основанный на обработчиках Forge 1.13.2–26.3 сетка и конкретный разрешённый Загрузчик версии; Vanilla GA часть фиксирует required/passed цели, не менее 109 Vanilla цели / 104 уникальных релиз ID, полный 53-релиз Устаревший Vanilla сетка, полный v2 Java 16/17 сетка, обязательные `1.21.11`/Java 21 и `26.2`/Java 25, пять обязательный соответствующий сервер пары, Java крупный, конкретный сертифицированный JRE собирает (vendor/runtime/SHA-256/OS/arch/target счётчик), область, SHA-256 цель определение и матрица, исходник фиксация и Действия запуск ID; политика дополнительно связывает релиз с Совместимость II GA JRE основа.

`nl release publish-check` отказ с блокировкой повторно вычисляет сертификация и для 0.17.3 дополнительно требует политика suffixes `fabric-compatibility-II-0.17.1-stable-1.14-through-current-actual-client`, `quilt-compatibility-II-0.17.2-stable-1.14-through-current-actual-client` и `forge-modern-0.17.3-processor-based-1.13.2-through-current-actual-client` и `forge-legacy-0.17.4-real-1.12.2-universal-fmltweaker-actual-client` поверх всех Совместимость II GA политика контроли. Цель определение, матрица и сертификация включаются в релиз подпись граница. CI комплект без матрица совместимости может существовать как сборка кандидат, но не проходит официальный публикация-проверка.
