# История изменений NeverLauncher

> Здесь фиксируются изменения исходного кода. Запись о версии **не означает**, что её установщики опубликованы или прошли независимую сертификацию.

[Главная](README.md) · [Релизный центр](docs/releases/README.md) · [Описание 1.0.0](docs/releases/1.0.0.md)

## 1.2.4 — AI Admin Copilot

- Admin Panel: потоковый помощник по выбранному проекту через существующий AI Gateway, явное согласие на передачу вопроса, учёт стоимости, отмена и строгий разбор предложений только после завершённого ответа.
- Проверяемые действия публикации и отката: предварительная проверка Backend, HMAC-подтверждение конкретного payload на 120 секунд, RBAC и свежая MFA, ручное подтверждение, устойчивая очередь, аудит и восстановление потерянного ответа без автоматического повтора.
- Регрессионные тесты подмены плана, SSE, ограничения действий, идемпотентности и HTTP-маршрутов. [Инструкция](docs/operations/ai-admin-copilot.md).

## 1.2.3 — AI Diagnostics

- Локальная диагностика текущего состояния NeverLauncher и импорт до пяти текстовых логов Minecraft, JVM, загрузок и модификаций; ограниченное чтение больших файлов, распознавание конкретных признаков, безопасные рекомендации и отображение ограничений анализа.
- Обезличенный отчёт только из фиксированных категорий и ограниченных числовых полей, без исходных строк, путей, имён файлов и секретов. Предпросмотр и явное согласие перед переносом в новый черновик AI-чата; существующие авторизация, потоковые ответы и контроль расходов сохранены.
- Диагностика доступна локально без входа и сети; существующие отчёты поддержки не изменены. Регрессионные проверки включены в CI. [Инструкция](docs/operations/ai-diagnostics.md).

## 1.2.2 — AI Chat Workspace

- Desktop: отдельный AI-чат с нативным HTTPS/SSE-транспортом Tauri и проверкой сессии из OS keyring, потоковой генерацией, отменой, персональной статистикой бюджета и обработкой ошибок доступа, сети и учёта расходов. Запросы не повторяются автоматически.
- Локальная история диалогов с разделением по Backend, аккаунту, проекту и профилю; восстановление прерванных запросов без повторной отправки, создание и удаление диалогов.
- Явное согласие на передачу текста и ограниченного контекста выбранного проекта; предпросмотр полей, лимит UTF-8 и подбор недавних завершённых сообщений. Без чтения файлов и передачи ключей.
- Регрессии SSE, истории, контекста и HTTP-клиента. [Инструкция](docs/operations/ai-chat-workspace.md).

## 1.2.1 — AI Backend Integration

- Опциональный серверный OpenAI Responses API: поток текстовых ответов SSE, фиксированная модель, проверка действующей локальной сессии и разрешённых ролей.
- Постоянный транзакционный учёт PostgreSQL/SQLite: резервирование стоимости, общий и персональный месячный бюджет, лимит запросов, расчёт по usage; неопределённые расходы не освобождаются автоматически.
- Защита ключа API, ограничение входных данных, отмена и тайм-аут, безопасные ошибки, пользовательская и глобальная статистика; настройки Compose и SSE reverse proxy.
- Автоматические тесты HTTP-провайдера, SQL-учёта и контроля доступа. Реальная приёмка требует ключа OpenAI и настроенных тарифов. [Инструкция](docs/operations/ai-backend.md).

## 1.2.0 — Auto-Updates GA

- Stable по умолчанию; добровольный Beta с отдельным ключом, отдельной лентой и GitHub prerelease. Beta выбирает наиболее новый доступный стабильный или тестовый выпуск. Возврат в Stable не понижает установленную версию.
- Нативная проверка привязки предложения, неполной загрузки и готового пакета к выбранному каналу. Сохраняются проверка подписей, совместимости и транзакционное восстановление.
- GitHub Release Delivery публикует только полный проверенный набор шести платформенных пакетов, проверяет принадлежность каналу и никогда не назначает Beta последним стабильным релизом. Версии X.Y.Z уникальны для обоих каналов.
- Проверки доставки, подписей, восстановления и интерфейса подключены к release gate на Windows, Linux и macOS. Реальная приёмка требует подписанных пакетов владельца. [Инструкция](docs/operations/native-updater.md).

## 1.1.4 — Update Recovery

- Прерванные загрузки: ограниченный нативный буфер, продолжение только для того же предложения с сильным ETag и точным Content-Range; безопасное скачивание с нуля при изменении ресурса. Полная проверка подписи сохраняется.
- Различение временных сбоев и отклонённых пакетов, повторное скачивание, блокировка повторной автоматической загрузки после неподтверждённой установки.
- До выхода Desktop CLI проверяет подписанный набор компонентов, совместимость протоколов, поколение и политику доверия. При отказе установки выполняется восстановление журнала без принудительного снятия активной блокировки; перезапуск только после проверки установленного набора. Диагностика в update.log.
- Исправлена проверка журналов macOS без файловых транзакций; регрессии восстановления и приёмка в CI. [Инструкция](docs/operations/native-updater.md).

## 1.1.3 — Update Experience

- Автоматическая проверка обновлений при запуске и по сохраняемому интервалу (6 часов, 24 часа или неделя); повтор после временной ошибки, ручная проверка и уведомление независимо от открытого экрана.
- Скачивание с отображением размера и прогресса, отдельная проверка подписи, версии и платформы; опциональное автоматическое скачивание без автоматической установки.
- Отдельное подтверждение установки и перезапуска; скачивание не блокирует игру, но установка по-прежнему требует завершения Minecraft и других нативных операций.
- Описание релиза из CHANGELOG публикуется в `latest.json` и GitHub Release и отображается в Desktop как обычный текст. [Настройка и приёмка](docs/operations/native-updater.md).

## 1.1.2 — GitHub Release Delivery

- GitHub Actions: защищённая сборка шести комплектов Desktop/Guard/Runtime с постоянными ключами доверия; MSI, DEB и PKG создаются из фактических итоговых пакетов, с Authenticode/RFC3161, GPG или Developer ID Installer и нотариальным заверением.
- Раздельные задания подписи и публикации: Tauri-подписи с привязкой версии и имени, полный `latest.json`, SHA-256 и привязка к коммиту; запрет неполного выпуска, downgrade и перезаписи релиза. Draft публикуется только после проверки загруженных GitHub assets.
- Исправлена нативная production-сборка Tauri: frontend встраивается через `custom-protocol`. Добавлены регрессии и реальная тестовая сборка DEB с GPG. [Настройка GitHub и приёмка](docs/operations/github-release-delivery.md).

## 1.1.1 — Native Updater

- Desktop: Tauri Updater 2.14.1, проверка стабильной SemVer, загрузка по HTTPS с ограничением размера, проверка подписи и подписанной версии, проверка состава цели и передача подлинного пакета существующему транзакционному установщику Desktop/Guard/Runtime.
- Интерфейс проверки, явного подтверждения и прогресса; исключена установка произвольного пути и SHA-256 из WebView. Блокировка запуска игры и игровых операций во время установки.
- Генерация проверенной ленты из окончательных подписанных пакетов и регрессионные тесты; [настройка и приёмка](docs/operations/native-updater.md).

## 1.1.0 — Additional Auth

- Admin Panel: браузерный вход SkiF4er ID с PKCE, TOTP/recovery и WebAuthn, просмотр, привязка и отвязка идентичностей через то же ядро, что и Desktop.
- Дополнительный точный HTTPS callback для Admin Panel, привязка браузерной транзакции к Backend и инициирующей сессии, одноразовое поглощение callback, удаление кода из адресной строки, запрет сетевых перенаправлений credentials.
- Сессии Admin: привязка к Backend, проверка действительности и ротация без повторного refresh при неопределённом ответе, подтверждённый отзыв либо явное сообщение о локальном выходе. Роли определяет Launcher, а не Keycloak.
- Desktop: запрет перезаписи существующей нативной сессии новым входом и отзыв при несогласованном ответе. Добавлены HTTP-интеграция, браузерный E2E с фикстурой, режим реального Keycloak smoke и нативный loopback-тест. Фактический GA-допуск требует запуска всех проверок. [Настройка](docs/authentication/skif4er-id.md).

## 1.0.4 — Authentication Security

- Локальное MFA после SkiF4er ID: одноразовый challenge TOTP/recovery или WebAuthn; локальная сессия выдаётся только после подтверждения. Токен транзакции остаётся в Rust.
- Проверка актуальной политики MFA при использовании и ротации сессии SkiF4er ID; отказ при ошибке чтения хранилища; отзыв при недостаточном уровне локальной аутентификации.
- Атомарное поглощение callback и MFA challenge, защита повторного TOTP при входе SkiF4er ID, проверка контекста passkey, issuer callback и неоднозначных параметров, аудит отказов без секретов.
- Logout подтверждает фактический отзыв сессии; чувствительные ответы OIDC, MFA и refresh не кэшируются. [Настройка и приёмка](docs/authentication/skif4er-id.md).

## 1.0.3 — Desktop Authentication

- Нативный жизненный цикл сессии: браузерный вход с отменой, локальные токены только в системном хранилище, проверка при запуске, автоматическая проверка и ротация access/refresh с учётом ключа устройства.
- WebView получает access token и метаданные, но не refresh token; парольный вход также выполняется нативным HTTP-клиентом без перенаправлений.
- Безопасное завершение сессии: локальное удаление до сетевого отзыва; отдельная индикация неподтверждённого серверного выхода. При сетевом сбое до ротации сохранённые credentials остаются в хранилище; неоднозначный результат ротации требует нового входа.
- Защита от одновременного обновления credentials и устаревших ответов изменения access token. Инструкции: [SkiF4er ID](docs/authentication/skif4er-id.md).

## 1.0.2 — Account Linking

- Управление связанными идентичностями в Desktop: просмотр, браузерная привязка SkiF4er ID к действующей локальной сессии, подтверждаемая отвязка.
- Привязка требует свежей аутентификации Launcher и нового подтверждения Keycloak; защита от дублирования, переноса чужой идентичности и повторного использования callback.
- Отвязка требует свежего локального входа с паролем, удаляет сохранённые credentials и отзывает связанные сессии. Новая привязка получает новый ID.
- Инструкции и ограничения: [SkiF4er ID](docs/authentication/skif4er-id.md).

## 1.0.1 — SkiF4er ID Integration

- Подключение Keycloak OIDC, браузерный вход Desktop и выдача защищённой локальной сессии через существующее ядро федерации.
- Настройка: [SkiF4er ID](docs/authentication/skif4er-id.md).

## 1.0.0 — кандидат на общедоступный выпуск

**Направление:** допуск к выпуску на поддерживаемых целевых платформах.  
**Состояние:** механизмы проверки реализованы в исходниках; фактическая публикация зависит от независимой приёмки.

### Согласование версии

- Основные продуктовые пакеты Admin, Desktop, CLI, Runtime/Guard и конфигурации совместимости синхронизированы с `VERSION=1.0.0`.

### Проверки и подписи

- Подписание промышленного выпуска требует независимо подписанных реальных E2E-01–18 и точных исходных байтов шести нативных установщиков: Windows x64/ARM64, Linux x64/ARM64, macOS x64/ARM64.
- Две отдельные Linux-подписи также обязательны; отсутствие данных блокирует выпуск.
- Go-компонент сборки и проверки релиза сверяет SHA-256 и размеры этих восьми файлов.
- Обязательные ресурсы включаются в `RELEASE_MANIFEST.json`, защищённый `SHA256SUMS` и подписью выпуска.

### Подготовка и публикация

- Исполняемый этап `publication_ga.py stage` проверяет независимое одобрение Ed25519, закреплённый SHA-256 индекса и каждый пакет, переносит настоящие файлы в подготавливаемый выпуск. Ошибка копирования откатывает частичный перенос; перезапись пакетов запрещена.
- Перед сетевой публикацией Python повторно проверяет подписи, конечные байты, обязательный отчёт `SUPPORTED_PLATFORM_GA_1000.json`, CI и подписанный выпуск.
- Изменение только номера версии не позволяет обойти эту проверку.
- Защищённые GitHub Actions принимают отдельно заверенные свидетельства GA 1.0.0, привязанные к точному исходному SHA; ключи и источники закрытых свидетельств не копируются в публичный пакет.

### Ограничение выпуска

**Это рабочий код релизного шлюза, не выданный сертификат.** Пока физическая независимая приёмка E2E-01–18, подписанные нативные пакеты и все обязательные задания CI не завершены для одного точного коммита, общедоступная публикация GA заблокирована.
