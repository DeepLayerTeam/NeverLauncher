# История изменений NeverLauncher

> Здесь фиксируются изменения исходного кода. Запись о версии **не означает**, что её установщики опубликованы или прошли независимую сертификацию.

## 1.1.0 — Additional Auth

- Admin Panel: браузерный вход SkiF4er ID с PKCE, TOTP/recovery и WebAuthn, просмотр, привязка и отвязка идентичностей через то же ядро, что и Desktop.
- Дополнительный точный HTTPS callback для Admin Panel, привязка браузерной транзакции к Backend и инициирующей сессии, одноразовое поглощение callback, удаление кода из адресной строки, запрет сетевых перенаправлений credentials.
- Сессии Admin: привязка к Backend, проверка действительности и ротация без повторного refresh при неопределённом ответе, подтверждённый отзыв либо явное сообщение о локальном выходе. Роли определяет Launcher, а не Keycloak.
- Desktop: запрет перезаписи существующей нативной сессии новым входом и отзыв при несогласованном ответе. Добавлены HTTP-интеграция, браузерный E2E с фикстурой, режим реального Keycloak smoke и нативный loopback-тест. Фактический GA-допуск требует запуска всех проверок. [Настройка](docs/authentication/skif4er-id.md).

## 1.0.4 — Authentication Security

- Локальное MFA после SkiF4er ID: одноразовый challenge TOTP/recovery или WebAuthn; локальная сессия выдаётся только после подтверждения. Токен транзакции остаётся в Rust.
- Проверка актуальной политики MFA при использовании и ротации сессии SkiF4er ID; отказ при ошибке чтения хранилища; отзыв при недостаточном уровне локальной аутентификации.
- Атомарное поглощение callback и MFA challenge, защита повторного TOTP при входе SkiF4er ID, проверка контекста passkey, issuer callback и неоднозначных параметров, аудит отказов без секретов.
- Logout подтверждает фактический отзыв сессии; чувствительные ответы OIDC, MFA и refresh не кэшируются. [Настройка и приёмка](docs/authentication/skif4er-id.md).

## 1.0.3 — Desktop Authentication

- Нативный жизненный цикл сессии: браузерный вход с отменой, локальные токены только в системном хранилище, проверка при запуске, автоматическая проверка и ротация access/refresh с учётом ключа устройства.
- WebView получает access token и метаданные, но не refresh token; парольный вход также выполняется нативным HTTP-клиентом без перенаправлений.
- Безопасное завершение сессии: локальное удаление до сетевого отзыва; отдельная индикация неподтверждённого серверного выхода. При сетевом сбое до ротации сохранённые credentials остаются в хранилище; неоднозначный результат ротации требует нового входа.
- Защита от одновременного обновления credentials и устаревших ответов изменения access token. Инструкции: [SkiF4er ID](docs/authentication/skif4er-id.md).

## 1.0.2 — Account Linking

- Управление связанными идентичностями в Desktop: просмотр, браузерная привязка SkiF4er ID к действующей локальной сессии, подтверждаемая отвязка.
- Привязка требует свежей аутентификации Launcher и нового подтверждения Keycloak; защита от дублирования, переноса чужой идентичности и повторного использования callback.
- Отвязка требует свежего локального входа с паролем, удаляет сохранённые credentials и отзывает связанные сессии. Новая привязка получает новый ID.
- Инструкции и ограничения: [SkiF4er ID](docs/authentication/skif4er-id.md).

## 1.0.1 — SkiF4er ID Integration

- Подключение Keycloak OIDC, браузерный вход Desktop и выдача защищённой локальной сессии через существующее ядро федерации.
- Настройка: [SkiF4er ID](docs/authentication/skif4er-id.md).

## 1.0.0 — кандидат на общедоступный выпуск

**Направление:** допуск к выпуску на поддерживаемых целевых платформах.  
**Состояние:** механизмы проверки реализованы в исходниках; фактическая публикация зависит от независимой приёмки.

### Согласование версии

- Основные продуктовые пакеты Admin, Desktop, CLI, Runtime/Guard и конфигурации совместимости синхронизированы с `VERSION=1.0.0`.

### Проверки и подписи

- Подписание промышленного выпуска требует независимо подписанных реальных E2E-01–18 и точных исходных байтов шести нативных установщиков: Windows x64/ARM64, Linux x64/ARM64, macOS x64/ARM64.
- Две отдельные Linux-подписи также обязательны; отсутствие данных блокирует выпуск.
- Go-компонент сборки и проверки релиза сверяет SHA-256 и размеры этих восьми файлов.
- Обязательные ресурсы включаются в `RELEASE_MANIFEST.json`, защищённый `SHA256SUMS` и подписью выпуска.

### Подготовка и публикация

- Исполняемый этап `publication_ga.py stage` проверяет независимое одобрение Ed25519, закреплённый SHA-256 индекса и каждый пакет, переносит настоящие файлы в подготавливаемый выпуск. Ошибка копирования откатывает частичный перенос; перезапись пакетов запрещена.
- Перед сетевой публикацией Python повторно проверяет подписи, конечные байты, обязательный отчёт `SUPPORTED_PLATFORM_GA_1000.json`, CI и подписанный выпуск.
- Изменение только номера версии не позволяет обойти эту проверку.
- Защищённые GitHub Actions принимают отдельно заверенные свидетельства GA 1.0.0, привязанные к точному исходному SHA; ключи и источники закрытых свидетельств не копируются в публичный пакет.

### Ограничение выпуска

**Это рабочий код релизного шлюза, не выданный сертификат.** Пока физическая независимая приёмка E2E-01–18, подписанные нативные пакеты и все обязательные задания CI не завершены для одного точного коммита, общедоступная публикация GA заблокирована.
