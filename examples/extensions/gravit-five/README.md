# Пять сценариев нативного переноса исходников Java Gravit — 0.49.5

Каталог содержит **работающие перенесённые исходники**, а не загрузчик произвольных JAR GravitLauncher без изменений. Используются имеющиеся Java Extension Host/SDK Launcher и брокер Go; напрямую изменять объекты кучи Go нельзя. Доверенный игровой хук — дополнительный Java-агент с **полным доверием**, работающий внутри JVM игры, **а не песочница расширения**.

## Сборка и локальная приёмка JVM

```sh
sh examples/extensions/gravit-five-0495/build.sh test
```

Тест собирает настоящие исполняемые JAR Java Host и отдельный плагин JVM-агента, запускает Java-процесс, отправляет аутентифицированные RPC и callback хуков, проверяет реальный PBKDF2-SHA256 и неизменяемый UUID, собирает неподписанный ZIP из содержимого брокера с проверенными дайджестами, проверяет запрет сохранения профиля, JSON-состояние и его миграцию через имитируемый брокер, а затем запускает JVM с `-javaagent`, преобразующим синтетический класс `net.minecraft`. Подделанный дайджест плагина, изменённая библиотека, чтение чужого проекта, неверные учётные данные/хеши и неразрешённые изменения загрузчика должны отклоняться. Python-брокер в этой приёмке **имитируется**; изменения Go данным тестом не покрываются.

## Развёртывание в настоящую установку

1. Скопируйте PostgreSQL/проект и JSON-состояние каждого расширения, импортируйте поддерживаемых пользователей Gravit и игровой контент средствами 0.49.2–0.49.4, затем проверьте UUID, хеши источников и пробную миграцию.
2. Проверьте `launcher-extension.json`. Соберите Java JAR, упакуйте через существующий Launcher `extension pack` и доверенную Ed25519-подпись. Установите в **отдельную доверенную JVM с областью проекта**, явно выдайте `events:subscribe`, `events:sync`, `project:read`, `storage:read`, `storage:write`, `cli:contribute`. Ограничьте доступ ОС: Java-расширение с этими правами сейчас не изолировано от всех ресурсов файловой системы/сети хоста.
3. Настройте существующий документ брокера `runtime.config` `legacy-identities` как JSON-карту имён пользователей. Каждая запись содержит `uuid` (постоянный канонический Minecraft UUID), `name`, `scheme: "pbkdf2-sha256"`, `iterations` (210000–2000000), `saltHex` (16–64 байт) и `hashHex` (32 байта). **Не сохраняйте пароли открытым текстом.** Работают только поддерживаемые PBKDF2; остальные хеши Gravit требуют утверждённого сброса пароля или отдельно проверенного провайдера. Исторический токен обновления нельзя превращать в сеанс Launcher.
4. Настройте `legacy-assets`: каждый путь `libraries/...`, `mods/...`, `optional/...` соответствует `{projectId,version,sha256,size}` существующего файла в аутентифицированном хранилище брокера Go. Ключ `bundle:<projectId>` содержит до 24 точных путей. Перед подписью расширение считывает файлы, проверяет размер/хеш и создаёт ограниченный неподписанный ZIP. Публикуйте только через обычную цепочку подписания и политик; Java-провайдер сам доверенные пакеты не выпускает. Установка загрузчика и Runtime Minecraft остаются в ответственности ядра, использующего ранее перенесённый профиль.
5. Активируйте новую синхронную подписку Go `profile.before-save`. Подтвердите **отказ** в создании/изменении, если хук запрещает операцию или подписанный Java Host недоступен. Успешные операции всё равно проходят транзакции и проверки ревизий Backend.
6. Зарегистрируйте разрешённый `game-hook.jar` с закреплённым SHA-256 через доверенную цепочку запуска JVM-агентов. Включённый хук меняет ровно одну фиксированную тестовую константу класса: это **работающая демонстрация**, не универсальная карта Minecraft и не обход античита. Для промышленной среды необходим проверенный преобразователь проекта и испытания точной матрицы Minecraft/JDK/загрузчиков.
7. Проверьте `ported-status`, `ported-save` и обновление с callback `state.migrate` 0.49.4→0.49.5. Существующий обновлятор Go сохраняет контрольные снимки собственных документов расширений и откатывает их при сбое. Внешняя БД и игровые миры в такой снимок не входят.

## Область действия и блокеры релиза

Пять локальных сценариев исполняются и проверены на OpenJDK 21, **но задача проверки пяти сложных доработок Gravit на независимой принятой реальной установке PostgreSQL ещё не выполнена**. Для промышленного выпуска требуются сборка Go 1.27.3, реальная установка PostgreSQL/Backend/Java Host, тесты RBAC и отзыва, подписанные `.nlext` и агенты, настоящие входные данные Gravit, запуск/подключение Minecraft, обновление/перезапуск/отзыв/откат реального проекта и независимые подтверждения. Тестовый JVM-класс — не настоящий игровой клиент. Универсальная бинарная совместимость Gravit API/ABI не заявлена.
