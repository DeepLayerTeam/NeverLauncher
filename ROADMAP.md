# Дорожная карта Launcher

План развития после `0.37.0`: релизный конвейер доведён до защищённой автоматической публикации GitHub Releases; **фактическая шести-платформенная GA-сертификация и публикация требуют успешного запуска защищённых процессов CI на точном хеше исходного коммита**. Это направления работы, **не обещание сроков, версий и завершённой реализации**. Приоритеты меняются по результатам тестов и обратной связи.

| Приоритет | Направление | Критерий готовности |
| --- | --- | --- |
| P0 | CI и релизные контракты | Все обязательные задания проходят на одном точном SHA коммита; сертификаты собраны и проверены |
| P0 | Испытания Windows/Guard на устойчивость к атакам | Негативные тесты корректно отклоняют неподходящие случаи; результаты подтверждены свидетельствами проверок на соответствующих платформах |
| P1 | Безопасность промышленной эксплуатации | Секреты, подписи, TLS, RBAC, восстановление и расширения проходят аудит и негативные тесты |
| P1 | Реальная Minecraft-совместимость | Опубликованные значения `required` подтверждены реальными клиентскими прогонами, остальные ясно помечены NOT CERTIFIED |
| P2 | Полный путь администратора | Проекты/каналы/серверы/пакеты управляются через UI без обязательных ручных вызовов API |
| P2 | Клиентские функции | Интерфейс необязательных модов, текстуры, диагностика и запуск клиента проходят сквозные проверки |
| P2 | Официальная Minecraft-аутентификация | Фактическая цепочка сервисов и право владения игрой подтверждены интеграционными тестами без подмены Microsoft OIDC |
| P3 | SDK и расширения | Стабильные интерфейсы, примеры, границы изоляции, жизненный цикл и проверки совместимости |
| P3 | Документация и сопровождение | Руководства соответствуют поведению, определены ответственные лица и доступны воспроизводимые инструкции |

## Порядок выпуска

Исправление → модульные и контрактные тесты → интеграционные и сквозные тесты → матрицы шести платформ → точный SHA коммита → независимое GA-разрешение → репетиция с побайтовой сверкой → `RELEASE_MANIFEST.json` + подпись → `release publish-check` → проверяемый пробный запуск → `required-production-ci` → проверка повторно загруженных артефактов выпуска GitHub Releases → публичная публикация. Ни одна успешно пройденная проверка работоспособности сама по себе не разрешает публикацию промышленного релиза.

Открытые задачи отслеживайте через [GitHub Issues](https://github.com/DeepLayerTeam/Launcher/issues); возможности реального клиента описаны в [COMPATIBILITY.md](COMPATIBILITY.md).

Документированный процесс и порядок безопасного запуска: [Публикация промышленного релиза 0.37.0](docs/releases/0.37.0-production-publication.md).
